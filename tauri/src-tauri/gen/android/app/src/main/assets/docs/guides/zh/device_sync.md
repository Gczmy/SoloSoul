# 设备同步

SoloSoul 的设备同步功能让你在**同一局域网**内的多台设备之间安全地同步档案（Profile）、对象、模板、回收站记录以及附件文件。所有同步数据均通过 **Noise XX** 端到端加密传输，SoloSoul 团队或任何中间网络设备都无法解密你的内容。

<!--TIP-->
同步是完全可选的。即使关闭同步，你的本地数据依然完整可用，SoloSoul 始终坚持本地优先（Local-First）设计。
<!--/TIP-->


## 一、同步前准备

1. **同一账号**：两台设备必须使用同一个 `account_id` 才能成功同步。最简单的方式是用同一组账号数据启动两个实例（本地联调可参考文末「开发者调试」）。
2. **同一局域网**：mDNS 自动发现要求设备处于同一 Wi-Fi 或局域网。
3. **最新版本**：建议将两边应用保持在相同大版本，避免因数据格式差异导致同步失败。


## 二、启用同步

1. 进入「设置」→「设备同步」。
2. 打开顶部的「启用同步」开关。
3. 页面会显示本机的 **设备名**、**fingerprint（指纹）** 与 **监听地址**，例如：
   ```
   Your device name: SoloSoul-a1b2c3d4
   Your fingerprint: a1b2c3d4...
   Your listen address: 192.168.1.10:54321
   ```
   指纹是本设备的 Noise 长期公钥摘要，用于配对时人工比对；监听地址为操作系统分配的随机端口。

### 自动同步

打开「自动同步」开关后，SoloSoul 会在以下时机自动触发与已信任设备的同步：

- 应用切回前台时
- 本地数据变更后（10 秒防抖）
- 每 60 秒周期检查

自动同步开关会持久化保存，应用重启后仍然生效。

### 同步 UI 偏好（可选）

「同步 UI 偏好」勾选框控制是否将**外观设置**（主题模式、配色方案、主题色、侧边栏布局等）随设备同步。默认不勾选；勾选后，其他设备同步时会应用你的外观偏好。

<!--TIP-->
UI 偏好属于个人观感，不同设备可用不同外观。需要多设备一致的外观时才建议勾选。
<!--/TIP-->

<!--WARNING-->
**绝对不要信任你不认识或无法物理核对的 fingerprint**。攻击者可能冒充你的设备，只有在确认对端设备显示相同 fingerprint 后才点击「信任并配对」。
<!--/WARNING-->


## 三、配对与信任

SoloSoul 采用 **TOFU（Trust On First Use）** 信任模型：第一次遇到某台设备时，必须显式确认 fingerprint。

### 自动发现（mDNS）

1. 启用同步后，SoloSoul 会通过 mDNS（Bonjour/Avahi）在局域网广播自己，同时监听其他设备。
2. 「已发现设备」列表会展示实时扫描命中的设备（含设备名、地址、客户端类型图标）。
3. 点击某台已发现设备可打开**设备详情**：若该设备已在已知设备列表中，会直接复用已知设备的详情（含信任状态与同步操作）；否则以「新设备」形态展示并提供「立即同步」。
4. 首次连接时，系统会弹出「配对设备」对话框，显示：
   - 设备名 / node_id
   - 对端地址
   - 对端 fingerprint
5. 核对该 fingerprint 与对方设备屏幕显示一致后，点击「信任并配对」。
6. 信任是双向的：你也需要在对端设备上信任本机。

### 手动输入地址

如果 mDNS 因企业网络、VPN 或防火墙无法工作，可以使用手动地址兜底：

1. 在「与设备同步」输入框中填入对端地址，例如 `192.168.1.12:54321` 或 `127.0.0.1:54321`。
2. 点击「同步」。
3. 如果这是首次连接，系统同样会弹出配对对话框，确认 fingerprint 后信任。

### 已知设备与在线状态

- **已知设备**：已配对/持久化的设备列表，显示最近同步时间；当前在局域网可发现且最近 300 秒内有通告的设备标记为**在线**（显示地址），其余显示为**未在局域网发现**。
- **离线 ≠ 关机**：在线状态仅反映 mDNS 实时发现结果，不代表对方设备离线。应用在页面停留期间会周期性刷新设备状态。

<!--TIP-->
对方设备的监听端口由操作系统随机分配，不会直接显示在 UI 上。双实例联调脚本（`scripts/dev-two-instances.sh`）和日志输出会提供端口信息。
<!--/TIP-->


## 四、同步内容与冲突解决

### 同步的数据表

| 数据类型 | 说明 |
|---------|------|
| 档案（Profiles） | 加密数据本身不传输，只同步 base64 编码的密文；接收方用本地 data_key 重新加密存储。 |
| 对象（Objects） | 包含 `is_deleted` 标志，删除状态会传播。 |
| 用户模板（User Templates） | properties_json 解密后以 JSON 同步，接收方重新加密。 |
| 回收站（Trash Items） | 删除记录本身即是业务 tombstone，直接同步。 |
| 附件（Attachments） | 数据库记录同步后，再单独按 64KB 分块传输文件本身，并校验 sha256。 |

### 冲突解决

SoloSoul 使用 **Hybrid Logical Clock（HLC）** 记录每条记录的修改时间，冲突解决规则为 **Last-Write-Wins（LWW）**：

```text
remote 胜出当且仅当：
  remote.wall_time_ms > local.wall_time_ms
  或 wall_time 相等且 remote.counter > local.counter
  或 wall_time、counter 均相等且 remote.node_id > local.node_id
```

当对端记录的 HLC 不新于本地时，该记录会被标记为「冲突」并在「同步活动」面板展示：
- 记录所在表与 ID
- 本地 HLC 与远程 HLC
- 胜出方（通常为 `local`）

冲突面板**不会显示任何明文数据**，仅展示元信息供你判断是否需要手动干预。

### 删除墓碑

`profiles` 和 `user_templates` 硬删除时会写入 `sync_tombstones` 墓碑表。设备 A 删除后，设备 B 同步时会根据墓碑删除本地对应记录，并保留远程 HLC 作为权威删除时间。


## 五、同步历史面板

每次同步完成后，页面下方的「同步历史」面板会记录最近 10 次结果，包含：

- 总体统计：`examined / applied / skipped / conflicts`
- 按表明细：`{table}: {applied}+{skipped}/{examined}`
- 冲突列表（如有）
- 附件传输统计：`sent / received / bytes`
- 附件错误提示（如有）

这让你可以追踪哪些数据被应用、哪些因本地更新被跳过，以及附件是否完整到达。


## 六、大库分块流式同步

当某个表（例如对象表）包含大量记录时，SoloSoul 会自动将其拆分为多个 `Batch` 消息分页传输：

- 每批最多 100 条记录（受 Noise 单条消息 64KB 限制）。
- 发送方每发送一批后更新 `sync_watermarks`，记录对端已消费到的最大 HLC。
- 接收方逐批应用，避免一次性加载全表到内存。
- 如果中途网络断开，下次同步会从上次 watermark 继续，减少重复传输。


## 七、安全与隐私

- **端到端加密**：所有同步消息都经过 Noise XX 握手后的 `TransportState` 加密。
- **本地优先**：同步前数据已加密存储在本地；同步过程中传输的也是密文或重新加密的记录。
- **无云端**：同步不经过 SoloSoul 服务器，完全是局域网 P2P。
- **显式信任**：未信任设备无法完成同步，必须人工核对 fingerprint。
- **审计日志**：启用/禁用同步、信任/撤销设备、同步完成等事件会写入本地审计日志。


## 八、常见问题

### 两台设备无法自动发现

- 确认两边使用同一 `account_id`（同一账号数据）。
- 确认在同一局域网，且 mDNS（UDP 5353）未被防火墙拦截。
- 尝试使用 `host:port` 手动同步。

### 同步提示 "Peer is not trusted" / "Peer not trusted"

- 先在接收方信任发送方的 fingerprint，再在发送方信任接收方。
- 信任状态持久化在本地 `sync_peers` 表中，应用重启后仍然有效。

### 附件同步失败

- 检查对象 `__attachments` 字段是否完整包含 `id`、`objectId`、`fileName`、`sizeBytes`。
- 检查附件文件是否存在于 `SOLOSOUL_DATA_DIR/<account_id>/attachments/<object_id>/<attachment_id>/`。
- 查看「同步活动」中的附件错误提示。

### 同步后部分数据没过来

- 打开「同步活动」查看 `skipped` 数量。如果本地记录的 HLC 更新，对端旧记录会被跳过，属于正常冲突解决。
- 确认对端确实已保存该数据且其 HLC 大于本地。


## 九、开发者调试

如果你需要在本机调试两台设备同步：

```bash
cd tauri
bash scripts/dev-two-instances.sh
```

该脚本会：
- 使用 `SOLOSOUL_DATA_DIR` 分别指定两个独立数据目录。
- 使用不同的 `SOLOSOUL_VITE_PORT` / `SOLOSOUL_VITE_HMR_PORT` 避免端口冲突。
- 复制同一账号到两个目录，保证 `account_id` 一致，即可在本机验证端到端同步（发现、配对、双向同步、附件、删除墓碑传播）。
