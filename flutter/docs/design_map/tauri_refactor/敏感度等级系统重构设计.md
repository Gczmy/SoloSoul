# 敏感度等级系统重构设计

> **文档状态**：活跃  
> **最后更新**：2026-06-05  
> **适用范围**：Tauri + Rust 重构阶段  
> **关联文档**：《02_设计哲学.md》（用户主权、安全默认）

---

## 1. 问题诊断

### 1.1 当前矛盾

SoloSoul 当前设计中存在一个**可被绕过的安全漏洞**：

```
用户想查看一个 critical 级别的字段（如护照号码）
    ↓
系统要求密码验证 → 用户不知道密码
    ↓
用户进入 设置 → 敏感度设置
    ↓
将 "护照号码" 从 critical 降级为 public
    ↓
无需密码即可查看
```

**根本原因**：保护数据访问的机制（敏感度等级）本身**没有被保护**。

### 1.2 当前实现的三层来源

敏感度等级目前在三个地方有定义，造成"多份真理"：

| 来源 | 位置 | 优先级 | 问题 |
|------|------|--------|------|
| **字段实例** | `PropertyDefinition.sensitivity`（存储在 Profile JSON 中） | 最高（直接存储） | 每个字段各自为政，修改Profile时可能意外改变 |
| **用户覆盖** | `AccountStyle.fieldSettings`（账户级别 Map） | 次高（运行时覆盖） | 修改无需二次验证，可被用于绕过 |
| **注册表默认** | `FieldRegistry.defaultFields`（代码硬编码） | 最低（fallback） | 不是权威，只是初始化建议 |

**解析优先级**（`effectiveSensitivityProvider`）：
```dart
临时揭示 > 用户覆盖 > 注册表默认 > 遗留字段 > public
```

### 1.3 具体问题清单

| # | 问题 | 影响 |
|---|------|------|
| 1 | `PropertyDefinition` 存储自己的 `sensitivity` | 数据与策略耦合，同一份 Schema 在不同账户可能表现不同 |
| 2 | `AccountStyle.fieldSettings` 修改无二次验证 | 进入设置页需密码，但页内修改敏感度直接生效 |
| 3 | 降级 critical 字段仅需确认对话框 | 确认对话框不是安全验证，只是 UX 确认 |
| 4 | 升级/降级操作无审计记录 | 用户无法追溯谁、何时、为何修改了字段敏感度 |
| 5 | 无修改历史 | 无法回滚误操作，无法查看字段敏感度变更轨迹 |

### 1.4 敏感度等级数量的统一

**现状**：项目中存在两种敏感度等级定义，互不兼容：

| 来源 | 等级数量 | 定义 |
|------|---------|------|
| 现有代码（`sensitivity_enums.dart`） | **4 级** | `public` / `internal` / `sensitive` / `critical` |
| 设计文档（`02_设计哲学.md` 等） | **6 级** | `public` / `internal` / `private` / `sensitive` / `restricted` / `critical` |

**分析与决策**：

6 级方案的问题：
- `internal` 与 `private` 的差异过于细微（都是"模糊显示"，仅解锁方式不同），用户难以区分
- `sensitive` 与 `restricted` 的差异过于细微（都是"完全遮盖 + 验证"，仅验证强度不同），实际使用中会混淆
- 增加用户认知负担，设置页面变得复杂
- 现有代码、测试、插件系统均基于 4 级实现，迁移到 6 级改动巨大

4 级方案的优势：
- 与现有代码完全一致，无需修改 `sensitivity_enums.dart`、插件 Host Functions、测试用例
- 层级清晰，用户容易理解：公开 → 内部 → 敏感 → 受限
- 4 级已覆盖所有安全场景：
  - `public`：始终可见
  - `internal`：轻微模糊，点击展开
  - `sensitive`：完全遮盖，需生物识别/密码
  - `critical`：完全遮盖，需密码 + 操作确认

**决策：统一采用 4 级方案。**

6 级文档中的 `private` 和 `restricted` 合并到相邻级别：
- `private`（模糊 + 解锁）→ 归入 `internal`（轻微模糊，点击展开）
- `restricted`（完全遮盖 + 重新验证）→ 归入 `sensitive`（完全遮盖 + 生物识别/密码）

**后续行动**：
- 本文档及所有 Tauri 重构文档统一使用 4 级
- `02_设计哲学.md` 中的敏感度分级系统描述将在重构完成后更新为 4 级
- `跨平台UI设计系统.md` 中的敏感度色彩编码表已使用 6 级，需同步修正为 4 级

## 2. 设计原则

### 2.1 唯一真理来源（Single Source of Truth）

**所有字段的敏感度等级必须来自一个且仅一个权威来源。**

```
❌ 错误：字段实例自己决定自己的敏感度
❌ 错误：代码默认值 + 用户覆盖 + 字段实例 三份来源
✅ 正确：一份加密的敏感度映射表，运行时统一查询
```

### 2.2 修改即访问（Modify = Access）

**修改字段敏感度等级的行为，等同于访问该字段当前敏感度的数据。**

- 将 `critical` 降级为 `public` → 等同于"我现在要看这个 critical 字段"
- 因此：**降级操作需要等同于查看 critical 字段的验证强度**

### 2.3 审计不可绕过（Audit Cannot Be Bypassed）

**任何敏感度等级的变更都必须生成审计记录，且审计记录本身不能被删除或篡改。**

## 3. 重构方案

### 3.1 架构：敏感度映射表（Sensitivity Map）

引入 `SensitivityMap` 作为唯一真理来源：

```
Vault 数据结构
├── account.json           # 账户元数据
├── profile.enc            # 加密 Profile 数据（字段值）
│   └── 不再包含 sensitivity 字段 ← 废弃
├── sensitivity_map.enc    # 加密敏感度映射表（新增）
│   └── { "field_id": "sensitivity_level", ... }
└── sensitivity_log.enc    # 敏感度变更历史（新增）
    └── [ { timestamp, field_id, old, new, reason }, ... ]
```

#### 3.1.1 SensitivityMap 结构

```rust
// crates/solosoul-core/src/sensitivity/map.rs

/// 敏感度映射表 —— 唯一真理来源
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct SensitivityMap {
    /// 版本号（用于未来迁移）
    pub version: u8,
    /// 字段 ID → 敏感度等级
    pub entries: HashMap<String, SensitivityLevel>,
    /// 最后修改时间
    pub last_modified_at: DateTime<Utc>,
}

impl SensitivityMap {
    /// 创建默认映射（基于 FieldRegistry 默认值）
    pub fn default_from_registry() -> Self {
        let mut entries = HashMap::new();
        for field in FieldRegistry::default_fields() {
            entries.insert(field.field_id.clone(), field.default_level);
        }
        Self {
            version: 1,
            entries,
            last_modified_at: Utc::now(),
        }
    }

    /// 获取字段敏感度（运行时查询）
    pub fn get(&self, field_id: &str) -> SensitivityLevel {
        self.entries.get(field_id).copied().unwrap_or(SensitivityLevel::Public)
    }

    /// 更新字段敏感度（需要密码验证后调用）
    pub fn set(&mut self, field_id: &str, level: SensitivityLevel) {
        self.entries.insert(field_id.to_string(), level);
        self.last_modified_at = Utc::now();
    }
}
```

### 3.3 修改保护策略

#### 3.3.1 分级验证规则

| 操作 | 目标敏感度 | 需要的验证 | 理由 |
|------|-----------|-----------|------|
| 降级 | `critical` → `sensitive` | **密码重新验证** | 等同于访问 critical 数据 |
| 降级 | `critical` → `public` | **密码重新验证 + 降级确认** | 等同于永久解除 critical 保护 |
| 降级 | `sensitive` → `public` | **密码重新验证** | 等同于访问 sensitive 数据 |
| 降级 | `sensitive` → `internal` | **密码重新验证** | 等同于访问 sensitive 数据 |
| 降级 | `internal` → `public` | 无需额外验证 | 无安全风险 |
| 升级 | `public` → `internal` | 无需额外验证 | 加强保护，无风险 |
| 升级 | `public` → `sensitive` | 无需额外验证 | 加强保护，无风险 |
| 升级 | `public` → `critical` | **升级确认对话框** | 防止误操作，但不需要密码 |
| 升级 | `sensitive` → `critical` | **升级确认对话框** | 防止误操作，但不需要密码 |

**核心规则**：
- **降级 = 访问**：降级操作需要等同于访问该字段当前等级的验证
- **升级 = 安全**：升级操作不需要额外验证（因为这在加强保护）
- **critical 降级最严格**：降级 critical 字段需要密码 + 确认，且 5 分钟内不能再次降级同一字段（防止暴力绕过）

#### 3.3.2 冷却期机制

```rust
/// 同一字段的敏感度降级冷却期
const DOWNGRADE_COOLDOWN_SECONDS: u64 = 300; // 5 分钟

/// 降级前检查冷却期
fn check_downgrade_cooldown(
    log: &SensitivityLog,
    field_id: &str,
    new_level: SensitivityLevel,
    old_level: SensitivityLevel,
) -> Result<(), SensitivityError> {
    if old_level <= new_level {
        return Ok(()); // 升级无需冷却
    }
    
    // 查找最近对该字段的降级操作
    if let Some(last_entry) = log.entries.iter().rev().find(|e| {
        e.field_id == field_id && e.old_level > e.new_level
    }) {
        let elapsed = Utc::now().signed_duration_since(last_entry.timestamp);
        if elapsed.num_seconds() < DOWNGRADE_COOLDOWN_SECONDS as i64 {
            return Err(SensitivityError::DowngradeCooldown {
                remaining_seconds: DOWNGRADE_COOLDOWN_SECONDS - elapsed.num_seconds() as u64,
            });
        }
    }
    
    Ok(())
}
```

## 4. 技术实现

### 4.1 Rust 核心

```rust
// crates/solosoul-core/src/sensitivity/mod.rs

pub mod map;
pub mod log;
pub mod resolver;

use crate::vault::VaultStore;

/// 敏感度管理器（注册为 Tauri State）
pub struct SensitivityManager {
    vault: Arc<VaultStore>,
}

impl SensitivityManager {
    /// 加载敏感度映射表
    pub fn load_map(&self) -> Result<SensitivityMap, SensitivityError> {
        let encrypted = self.vault.read_file("sensitivity_map.enc")?;
        let plaintext = self.vault.decrypt(&encrypted)?;
        let map: SensitivityMap = serde_json::from_slice(&plaintext)?;
        Ok(map)
    }

    /// 保存敏感度映射表
    pub fn save_map(&self, map: &SensitivityMap) -> Result<(), SensitivityError> {
        let plaintext = serde_json::to_vec(map)?;
        let encrypted = self.vault.encrypt(&plaintext)?;
        self.vault.write_file("sensitivity_map.enc", &encrypted)?;
        Ok(())
    }

    /// 获取字段敏感度（运行时查询）
    pub fn get_field_level(&self, field_id: &str) -> Result<SensitivityLevel, SensitivityError> {
        let map = self.load_map()?;
        Ok(map.get(field_id))
    }

    /// 更新字段敏感度（需要密码验证）
    pub fn update_field_level(
        &self,
        field_id: &str,
        new_level: SensitivityLevel,
        password: &str,
        reason: Option<String>,
    ) -> Result<(), SensitivityError> {
        // 1. 验证密码
        self.vault.verify_password(password)?;
        
        // 2. 加载当前映射
        let mut map = self.load_map()?;
        let old_level = map.get(field_id);
        
        // 3. 检查降级冷却期
        if new_level < old_level {
            let log = self.load_log()?;
            check_downgrade_cooldown(&log, field_id, new_level, old_level)?;
        }
        
        // 4. 更新映射
        map.set(field_id, new_level);
        self.save_map(&map)?;
        
        // 5. 记录变更日志
        let mut log = self.load_log()?;
        log.entries.push(SensitivityLogEntry {
            timestamp: Utc::now(),
            field_id: field_id.to_string(),
            field_name: FieldRegistry::get_name(field_id).unwrap_or(field_id).to_string(),
            old_level,
            new_level,
            reason: reason.unwrap_or_default(),
        });
        self.save_log(&log)?;
        
        Ok(())
    }
}
```

```rust
#[tauri::command]
pub async fn sensitivity_get_map(
    state: State<'_, SensitivityManager>,
) -> Result<SensitivityMap, String> {
    state.load_map().map_err(|e| e.to_string())
}

/// 更新字段敏感度（需要密码验证）
#[tauri::command]
pub async fn sensitivity_update_field(
    state: State<'_, SensitivityManager>,
    field_id: String,
    new_level: String,  // "public" | "internal" | "sensitive" | "critical"
    password: String,
    reason: Option<String>,
) -> Result<(), String> {
    let level = SensitivityLevel::from_str(&new_level)
        .map_err(|_| "Invalid sensitivity level".to_string())?;
    state.update_field_level(&field_id, level, &password, reason)
        .map_err(|e| e.to_string())
}

/// 获取敏感度变更历史
#[tauri::command]
pub async fn sensitivity_get_log(
    state: State<'_, SensitivityManager>,
    limit: Option<usize>,
) -> Result<Vec<SensitivityLogEntry>, String> {
    let log = state.load_log().map_err(|e| e.to_string())?;
    let entries = log.entries.into_iter().rev().take(limit.unwrap_or(100)).collect();
    Ok(entries)
}

/// 批量更新敏感度（设置页面批量操作）
#[tauri::command]
pub async fn sensitivity_batch_update(
    state: State<'_, SensitivityManager>,
    updates: Vec<FieldSensitivityUpdate>,
    password: String,
) -> Result<Vec<FieldSensitivityResult>, String> {
    // 验证密码一次，批量应用
    state.vault.verify_password(&password)?;
    
    let mut results = Vec::new();
    for update in updates {
        let result = state.update_field_level(&update.field_id, update.level, &password, update.reason);
        results.push(FieldSensitivityResult {
            field_id: update.field_id,
            success: result.is_ok(),
            error: result.err().map(|e| e.to_string()),
        });
    }
    
    Ok(results)
}
```

```typescript
import { create } from 'zustand';
import { invoke } from '@tauri-apps/api/core';

interface SensitivityStore {
  // 完整敏感度映射表（进入管理页面后加载）
  sensitivityMap: Map<string, SensitivityLevel>;
  // 变更历史
  changeHistory: SensitivityLogEntry[];
  
  // Actions
  loadMap: () => Promise<void>;
  updateField: (fieldId: string, level: SensitivityLevel, password: string, reason?: string) => Promise<void>;
  loadHistory: (limit?: number) => Promise<void>;
  
  // 运行时查询（组件级，不依赖完整 map）
  getFieldLevel: (fieldId: string) => Promise<SensitivityLevel>;
}

export const useSensitivityStore = create<SensitivityStore>((set, get) => ({
  sensitivityMap: new Map(),
  changeHistory: [],
  
  async loadMap() {
    const map = await invoke<SensitivityMap>('sensitivity_get_map');
    set({ sensitivityMap: new Map(Object.entries(map.entries)) });
  },
  
  async updateField(fieldId, level, password, reason) {
    await invoke('sensitivity_update_field', {
      fieldId,
      newLevel: level,
      password,
      reason,
    });
    // 刷新本地 map
    await get().loadMap();
    // 刷新历史
    await get().loadHistory(100);
  },
  
  async loadHistory(limit = 100) {
    const history = await invoke<SensitivityLogEntry[]>('sensitivity_get_log', { limit });
    set({ changeHistory: history });
  },
  
  async getFieldLevel(fieldId) {
    // 优先从本地 map 查询
    const cached = get().sensitivityMap.get(fieldId);
    if (cached) return cached;
    // 否则 IPC 查询
    const level = await invoke<string>('sensitivity_get_field', { fieldId });
    return level as SensitivityLevel;
  },
}));
```

## 5. 数据迁移

### 5.1 从旧格式迁移

```rust
/// 迁移旧格式的敏感度数据到新的 SensitivityMap
pub fn migrate_sensitivity_from_legacy(
    profile_data: &ProfileData,
    account_style: &AccountStyle,
) -> SensitivityMap {
    let mut map = SensitivityMap::default_from_registry();
    
    // 1. 从 AccountStyle.fieldSettings 迁移用户覆盖
    for (field_id, level) in &account_style.field_settings {
        map.set(field_id, *level);
    }
    
    // 2. 从 Profile 中字段实例的 sensitivity 迁移（如果存在且与默认值不同）
    for obj in &profile_data.unified_objects.objects {
        for (prop_key, prop_value) in &obj.properties {
            let field_id = format!("{}.{}.{}", obj.page_id, obj.collection_id, prop_key);
            if let Some(instance_level) = prop_value.sensitivity() {
                let default_level = map.get(&field_id);
                if instance_level != default_level {
                    // 字段实例的敏感度与默认不同 → 视为用户覆盖
                    map.set(&field_id, instance_level);
                }
            }
        }
    }
    
    map
}
```

- 运行时从 `SensitivityMap` 查询
- 旧数据中残留的 `sensitivity` 字段被忽略（向前兼容）

## 6. 与现有系统的兼容性

### 6.1 修改权限的严格边界

**核心原则：只有用户本人（通过密码验证后）可以修改 SensitivityMap。任何插件、前端组件、系统逻辑均无权修改。**

```
┌─────────────────────────────────────────────────────────────┐
│                     谁可以修改敏感度？                       │
├─────────────────────────────────────────────────────────────┤
│ ✅ 用户本人                                              │
│    → 通过敏感度管理页面，输入密码后修改                      │
│    → 调用 sensitivity_update_field（必须传入密码）         │
│                                                              │
│ ❌ 插件                                                   │
│    → 插件只能读取敏感度（用于 Consent 授权判断）            │
│    → 插件无权限调用 sensitivity_update_field               │
│    → 插件 manifest 中无 sensitivity 相关声明               │
│                                                              │
│ ❌ 前端 UI 组件                                           │
│    → 揭示按钮、字段卡片、对象编辑器等只读 SensitivityMap    │
│    → 任何前端状态（Zustand、React state）均不写入 Vault     │
│                                                              │
│ ❌ 同步引擎                                               │
│    → 同步只传输 SensitivityMap 的副本，不触发修改           │
│    → 冲突解决时以本地 SensitivityMap 为准（本地优先）       │
│                                                              │
│ ❌ 导入流程                                               │
│    → 导入 sensitivity_map.enc 时，需用户确认后才覆盖        │
│    → 不自动覆盖，静默导入视为安全漏洞                       │
└─────────────────────────────────────────────────────────────┘
```

### 6.2 临时揭示（Temporary Reveal）

**临时揭示 ≠ 修改敏感度等级。**

现有功能：用户点击"揭示"按钮后，字段临时以 `public` 级别显示（持续 1 分钟）。

**重构后**：临时揭示是纯前端 UI 状态，**与 SensitivityMap 完全隔离**：

```typescript
// 前端：揭示状态与敏感度严格分离
interface RevealState {
  // 仅前端内存状态，不持久化，不写入 Vault
  revealedFields: Set<string>;
  expiresAt: Map<string, number>;
}

// 渲染时的判断逻辑
function shouldMask(fieldId: string): boolean {
  // 1. 查询真实敏感度（来自 SensitivityMap，不可修改）
  const realLevel = sensitivityMap.get(fieldId);
  
  // 2. 检查是否临时揭示（纯前端状态）
  if (revealState.revealedFields.has(fieldId)) {
    if (Date.now() < revealState.expiresAt.get(fieldId)!) {
      return false; // 临时揭示中，不遮盖
    }
    // 过期，自动移除
    revealState.revealedFields.delete(fieldId);
  }
  
  // 3. 按真实敏感度判断
  return realLevel === 'sensitive' || realLevel === 'critical';
}
```

**关键区别**：
| 维度 | 临时揭示 | 修改敏感度等级 |
|------|---------|--------------|
| 作用域 | 仅当前会话 | 永久生效 |
| 存储位置 | 前端内存（Zustand） | Vault 加密文件（sensitivity_map.enc） |
| 修改者 | 用户点击揭示按钮 | 用户通过敏感度管理页面 |
| 验证要求 | 按字段当前敏感度验证 | 密码重新验证 |
| 审计记录 | 不记录 | 记录到 SensitivityLog |
| 对其他设备影响 | 无 | 同步后生效 |

**导出筛选规则**：

```rust
/// 根据导出范围筛选 SensitivityMap
pub fn filter_sensitivity_map_by_scope(
    map: &SensitivityMap,
    scope: &ExportScope,
    profile: &ProfileData,
) -> SensitivityMap {
    let mut filtered = SensitivityMap::new_empty();
    
    // 收集导出范围内的所有字段 ID
    let selected_field_ids: HashSet<String> = collect_field_ids_from_scope(profile, scope);
    
    // 只保留与选中字段相关的敏感度条目
    for (field_id, level) in &map.entries {
        if selected_field_ids.contains(field_id) {
            filtered.entries.insert(field_id.clone(), *level);
        }
    }
    
    filtered
}
```

**导入时的处理**：

| 场景 | 行为 |
|------|------|
| 导入包不含 `sensitivity_map.enc`（旧版本 v1.0） | 跳过敏感度导入，保留当前账户配置 |
| 导入包含 `sensitivity_map.enc`，用户选择"覆盖" | 用导入包中的条目覆盖当前账户对应条目，当前账户其他条目保留 |
| 导入包含 `sensitivity_map.enc`，用户选择"合并" | 导入包中的条目与当前账户条目合并，冲突时以导入包为准 |
| 导入包含 `sensitivity_map.enc`，用户选择"忽略" | 不修改当前账户的敏感度配置 |
| 导入的字段在当前账户不存在 | 忽略该条目的敏感度配置（避免 orphaned entry） |

### 6.4 用户偏好与行为数据的敏感度分级 ← 新增

> **核心理念**：根据「我们不管理'文档'，我们管理'你'」，用户偏好设置、操作记录等"传统系统数据"在 SoloSoul 中一律视为用户数据，同样需要敏感度分级保护。
>
> 详见《用户数据边界定义与用户偏好存储方案.md》。

#### 6.4.1 偏好数据的敏感度分级

| 偏好字段 | 敏感度 | 理由 | 存储位置 |
|---|---|---|---|
| 主题模式（light/dark） | `public` | 可见于界面，无隐私风险 | `preferences.enc` |
| 强调色 | `public` | 可见于界面，无隐私风险 | `preferences.enc` |
| 字体大小 | `public` | 可见于界面，无隐私风险 | `preferences.enc` |
| 界面密度 | `public` | 可见于界面，无隐私风险 | `preferences.enc` |
| 触觉反馈 | `public` | 纯交互偏好 | `preferences.enc` |
| 默认语言 / locale | `internal` | 可推断用户所在地 | `preferences.enc` |
| 日期格式 | `internal` | 可推断用户文化背景 | `preferences.enc` |
| 货币格式 | `internal` | 可推断用户财务区域 | `preferences.enc` |
| 删除确认开关 | `internal` | 反映用户谨慎程度 | `preferences.enc` |
| 开发者模式 | `internal` | 可推断用户技术能力 | `preferences.enc` |
| 自动锁定超时 | `sensitive` | 可推断用户安全意识水平 | `preferences.enc` |
| 生物识别启用状态 | `sensitive` | 暴露安全策略，攻击者可针对性设计 | `preferences.enc` |
| **SensitivityMap** | `sensitive` | 直接暴露用户的安全策略和隐私边界 | `sensitivity_map.enc` |
| 插件授权记录 | `sensitive` | 暴露用户信任了哪些第三方代码 | `preferences.enc` |
| 插件个性化配置 | `internal` ~ `sensitive` | 取决于插件类型 | `preferences.enc` |

#### 6.4.2 行为数据的敏感度分级

| 行为数据 | 敏感度 | 理由 | 存储位置 |
|---|---|---|---|
| 操作日志（字段级 CRUD） | `sensitive` | 暴露用户查看了哪些敏感信息、何时查看 | `audit_log.enc` |
| 敏感度等级变更记录 | `sensitive` | 暴露用户的安全策略调整历史 | `audit_log.enc` |
| 导入/导出记录 | `sensitive` | 暴露数据迁移行为 | `audit_log.enc` |
| 插件调用记录 | `sensitive` | 暴露用户工作流 | `audit_log.enc` |
| Vault 解锁/锁定时间 | `sensitive` | 暴露用户的在线习惯 | `audit_log.enc` |
| 搜索关键词 | `sensitive` | 直接暴露用户关注点和兴趣 | `search_history.enc` |
| 搜索过滤器 | `sensitive` | 暴露用户搜索习惯 | `search_history.enc` |
| 最近访问记录 | `sensitive` | 暴露用户的使用模式 | `search_history.enc` |
| 密码验证失败记录 | `critical` | 安全事件，需最高保护 | `audit_log.enc` |

#### 6.4.3 统一存储规则

所有用户数据（身份、偏好、行为）使用同一加密体系：

```
~/.solosoul/{account_id}/
├── profile.enc              # 身份数据（已有）
├── sensitivity_map.enc      # 敏感度映射（已有）
├── preferences.enc          # 偏好数据（新增）← AES-256-GCM
├── audit_log.enc            # 审计日志（新增）← AES-256-GCM
├── search_history.enc       # 搜索历史（新增）← AES-256-GCM
└── attachments/             # 附件（已有）
```

**核心规则**：
- 所有 `.enc` 文件使用同一 Vault 主密钥加密
- Vault 锁定后，所有用户数据（包括偏好和行为记录）同时不可访问
- 不允许任何用户数据以明文形式存在于文件系统或浏览器存储中

#### 6.4.4 前端 Store 的敏感度保护

| Store | 数据类型 | 是否允许 localStorage 持久化 | 理由 |
|---|---|---|---|
| authStore | 认证状态 | ❌ 不允许 | 敏感状态 |
| vaultStore | Vault 状态 | ❌ 不允许 | 敏感状态 |
| profileStore | Profile 数据 | ❌ 不允许 | 用户身份数据 |
| settingsStore | 用户偏好 | ❌ 不允许 | 用户偏好数据（sensitive 级别） |
| searchStore | 搜索历史 | ❌ 不允许 | 用户行为数据（sensitive 级别） |
| uiStore | UI 状态（sidebarCollapsed 等） | ✅ 允许 | 纯 UI 状态，非用户数据 |
