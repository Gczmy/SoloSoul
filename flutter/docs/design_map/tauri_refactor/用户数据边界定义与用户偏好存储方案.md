## 核心理念：管理的是"你"

> **「我们不管理'文档'，我们管理'你'」** ——《01_产品使命.md》

SoloSoul 的定位不是"又一个笔记应用"或"密码管理器"。它是一个**个人数字孪生**——一个完整、结构化、可迁移、由你完全控制的数字自我。

这意味着：

| 数据类别 | 传统工具的归类 | SoloSoul 的归类 | 理由 |
|---|---|---|---|
| 护照号码、银行卡 | 用户数据 | ✅ **用户数据** | 你的身份信息 |
| 主题偏好（暗黑/明亮） | "应用设置" | ✅ **用户数据** | 你的审美选择，是"你"的一部分 |
| 自动锁定时间（5分钟/15分钟） | "应用配置" | ✅ **用户数据** | 你的安全习惯，是"你"的一部分 |
| 操作日志（何时查看了护照） | "系统日志" | ✅ **用户数据** | 你的行为痕迹，是"你"的历史 |
| 搜索历史 | "缓存数据" | ✅ **用户数据** | 你的兴趣与关注点 |
| 页面布局偏好（侧边栏宽度） | "UI状态" | ✅ **用户数据** | 你的使用习惯 |
| 插件授权记录 | "系统状态" | ✅ **用户数据** | 你的信任决策 |
| 编译日志、崩溃报告 | 系统日志 | ❌ **非用户数据** | 与"你"无关，纯技术数据 |

**关键原则**：凡是与用户个人相关、能反映用户个性/习惯/历史/选择的数据，无论传统分类中叫"设置""配置""日志"还是"缓存"，在 SoloSoul 中一律视为**用户数据**，受同等级别的保护。

```

├── 3. 行为数据（Behavioral Data） ← 新增明确纳入

│   ├── 审计日志（Audit Log）
│   │   ├── 插件数据访问记录

│   │   └── 异常行为检测记录
│   └── AI 对话历史（AI Conversation History） ← 新增
│       ├── 用户与 AI 的完整对话记录
│       ├── 对话元信息（时间、使用的模型、token 消耗）

│
└── 4. 关系数据（Relational Data）
    ├── 对象间关联（Relation）
    ├── 标签体系（Tag）
    └── 自定义分类（Collection 结构）
```

### 明确排除：非用户数据

以下数据**不属于**用户数据，不纳入加密保护和导出范围：

| 数据 | 理由 | 存储方式 |
|---|---|---|
| 编译日志 | 与"你"无关 | 明文日志文件，定期清理 |
| 崩溃报告（可选上传） | 纯技术诊断 | 用户明确同意后才收集，不包含任何用户内容 |
| 应用更新元数据 | 纯技术信息 | 明文缓存 |
| 插件市场索引（registry.json） | 公开数据 | 明文缓存 |
| 帮助文档缓存 | 公开数据 | 明文缓存 |

## 各类数据的敏感度分级

偏好数据和行为数据同样需要敏感度分级。不同类别的数据敏感度不同：

### 偏好数据的敏感度分级

| 偏好字段 | 敏感度 | 理由 |
|---|---|---|
| 主题模式（light/dark） | `public` | 可见于界面，无隐私风险 |
| 强调色 | `public` | 可见于界面，无隐私风险 |
| 字体大小 | `public` | 可见于界面，无隐私风险 |
| 界面密度 | `public` | 可见于界面，无隐私风险 |
| 默认语言 / locale | `internal` | 可推断用户所在地，但风险较低 |
| 日期格式 | `internal` | 可推断用户文化背景 |
| 货币格式 | `internal` | 可推断用户财务区域 |
| 自动锁定超时 | `sensitive` | 可推断用户的安全意识水平 |
| 生物识别启用状态 | `sensitive` | 暴露安全策略，攻击者可针对性设计 |
| 删除确认开关 | `internal` | 反映用户谨慎程度 |
| 触觉反馈 | `public` | 纯交互偏好 |
| 开发者模式 | `internal` | 可推断用户技术能力 |
| **SensitivityMap** | `sensitive` | 直接暴露用户的安全策略和隐私边界 |
| 插件授权记录 | `sensitive` | 暴露用户信任了哪些第三方代码 |
| 插件个性化配置 | `internal` ~ `sensitive` | 取决于插件类型 |
| LLM 提供商选择 | `internal` | 可推断用户使用习惯 |
| LLM 模型选择 | `internal` | 可推断用户技术偏好 |
| **LLM API 密钥** | **`critical`** | **等同于账户密码，泄露后攻击者可消耗用户额度、访问用户数据** |
| LLM API 基础 URL | `sensitive` | 可能暴露内部网络拓扑（自托管场景） |
| LLM 系统提示词 | `sensitive` | 可能包含用户的个性化习惯或隐含信息 |
| AI 辅助功能开关 | `internal` | 反映用户使用习惯 |
| AI 对话历史保留策略 | `internal` | 反映用户隐私意识 |

### 行为数据的敏感度分级

| 行为数据 | 敏感度 | 理由 |
|---|---|---|
| 操作日志（字段级） | `sensitive` | 暴露用户查看了哪些敏感信息、何时查看 |
| 搜索关键词 | `sensitive` | 直接暴露用户关注点和兴趣 |
| 最近访问记录 | `sensitive` | 暴露用户的使用模式 |
| Vault 解锁/锁定时间 | `sensitive` | 暴露用户的在线习惯 |
| 插件调用频率 | `internal` | 暴露用户工作流 |
| 密码验证失败记录 | `critical` | 安全事件，需最高保护 |
| AI 调用记录 | `sensitive` | 暴露用户使用了哪些 AI 功能 |
| **AI 对话历史** | **`sensitive`** | **用户可能与 AI 讨论敏感数据，对话内容本身可能包含身份信息** |
| AI 对话元信息（模型、token 消耗） | `internal` | 技术统计，无直接隐私风险 |

### 存储时的统一处理

所有用户数据（包括偏好和行为数据）在 Vault 中的存储遵循统一规则：

```rust
// Vault 中的用户数据分层存储
pub struct UserDataVault {
    // 第 1 层：身份数据（已有）
    pub profile_enc: EncryptedBlob,          // AES-256-GCM
    pub objects_enc: EncryptedBlob,          // AES-256-GCM
    pub attachments_enc: EncryptedBlob,      // AES-256-GCM
    
    // 第 2 层：偏好数据（新增）
    pub preferences_enc: EncryptedBlob,      // AES-256-GCM ← 新增
    
    // 第 3 层：行为数据（新增）
    pub audit_log_enc: EncryptedBlob,        // AES-256-GCM ← 新增
    pub search_history_enc: EncryptedBlob,   // AES-256-GCM ← 新增
    pub ai_conversation_enc: EncryptedBlob,  // AES-256-GCM ← 新增：AI 对话历史
    
    // 第 4 层：关系数据（已有）
    pub relations_enc: EncryptedBlob,        // AES-256-GCM
}
```

**核心规则**：所有 `.enc` 文件使用同一主密钥（Vault 主密钥）加密。Vault 锁定后，所有用户数据同时不可访问。

## 存储方案：全部加密

### 现有设计的缺陷

| 组件 | 当前设计 | 问题 | 修正方案 |
|---|---|---|---|
| `app_settings` 表 | SQLite `TEXT` 明文存储 | 用户偏好以明文存在于数据库文件 | 改为加密 blob 或独立 `.enc` 文件 |
| `operation_logs` 表 | SQLite 明文存储 | 操作痕迹可被直接读取 | 改为加密存储 |
| `settingsStore` | Zustand persist → `localStorage` | 用户偏好明文暴露在浏览器存储 | 移除 localStorage 持久化，改为 IPC → Rust 加密存储 |
| `uiStore`（部分） | Zustand persist → `localStorage` | 用户行为偏好明文暴露 | 同上 |

### 修正后的存储架构

```
用户设备
├── ~/.solosoul/{account_id}/
│   ├── config.json           # 明文：账户元信息（account_id, created_at）
│   ├── vault.db              # SQLite：加密后的 blob 存储
│   │   ├── profiles          # 加密 blob（profile_enc）
│   │   ├── unified_objects   # 加密 blob（objects_enc）
│   │   ├── user_preferences  # 加密 blob（preferences_enc）← 新增
│   │   ├── audit_logs        # 加密 blob（audit_log_enc）← 新增
│   │   ├── search_history    # 加密 blob（search_history_enc）← 新增
│   │   └── ai_conversation   # 加密 blob（ai_conversation_enc）← 新增
│   ├── attachments/          # 独立加密文件
│   ├── sensitivity_map.enc   # 加密：字段级敏感度配置
│   └── audit/                # 审计日志（独立文件，可选）
│       └── plugin_audit.log  # 加密：插件访问审计
│
└── 前端（Tauri WebView）
    ├── localStorage          # 仅存储：非敏感 UI 状态（如 Toast 队列）
    │   └── ❌ 不再存储：settings、searchHistory、userPreferences
    └── Memory（Zustand Store）# 运行时状态，Vault 锁定后清空
```

```rust
/// 用户数据的统一抽象
/// 
/// 核心理念：管理的是"你"，所有与用户相关的数据都是 UserData。
pub trait UserData: Sized + Serialize + for<'de> Deserialize<'de> {
    /// 数据类型标识
    fn data_type() -> UserDataType;
    
    /// 默认敏感度等级
    fn default_sensitivity() -> SensitivityLevel;
    
    /// 加密存储
    fn encrypt(&self, key: &VaultKey) -> Result<EncryptedBlob, CryptoError>;
    
    /// 解密读取
    fn decrypt(blob: &EncryptedBlob, key: &VaultKey) -> Result<Self, CryptoError>;
}

/// 用户数据类型枚举
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum UserDataType {
    Identity,       // 身份数据
    Preference,     // 偏好数据
    Behavioral,     // 行为数据
    Relational,     // 关系数据
}

impl UserData for UserPreferences {
    fn data_type() -> UserDataType { UserDataType::Preference }
    
    fn default_sensitivity() -> SensitivityLevel { SensitivityLevel::Sensitive }
    
    fn encrypt(&self, key: &VaultKey) -> Result<EncryptedBlob, CryptoError> {
        let plaintext = serde_json::to_vec(self)?;
        key.encrypt(&plaintext)
    }
    
    fn decrypt(blob: &EncryptedBlob, key: &VaultKey) -> Result<Self, CryptoError> {
        let plaintext = key.decrypt(blob)?;
        Ok(serde_json::from_slice(&plaintext)?)
    }
}
```

### Vault 统一读写接口

```rust
// src-tauri/src/core/vault/user_data_storage.rs

impl Vault {
    /// 读取用户偏好
    pub fn load_preferences(&self) -> Result<UserPreferences, VaultError> {
        let blob = self.read_encrypted_blob("preferences.enc")?;
        UserPreferences::decrypt(&blob, &self.master_key)
    }
    
    /// 保存用户偏好
    pub fn save_preferences(&self, prefs: &UserPreferences) -> Result<(), VaultError> {
        let blob = prefs.encrypt(&self.master_key)?;
        self.write_encrypted_blob("preferences.enc", &blob)?;
        
        // 写入审计日志
        self.append_audit_log(AuditLogEntry {
            id: generate_uuid(),
            timestamp: Utc::now(),
            action: AuditAction::PreferenceUpdated,
            entity_type: Some("user_preferences".to_string()),
            entity_id: None,
            description: "用户偏好已更新".to_string(),
            performed_by: "user".to_string(),
            sensitivity_level: SensitivityLevel::Sensitive,
        })?;
        
        Ok(())
    }
    
    /// 读取审计日志
    pub fn load_audit_log(&self) -> Result<AuditLog, VaultError> {
        let blob = self.read_encrypted_blob("audit_log.enc")?;
        AuditLog::decrypt(&blob, &self.master_key)
    }
    
    /// 追加审计日志条目
    pub fn append_audit_log(&self, entry: AuditLogEntry) -> Result<(), VaultError> {
        let mut log = self.load_audit_log().unwrap_or_default();
        log.entries.push(entry);
        
        // 限制日志大小（默认保留 90 天或 10000 条）
        let cutoff = Utc::now() - Duration::days(90);
        log.entries.retain(|e| e.timestamp > cutoff);
        if log.entries.len() > 10000 {
            log.entries.drain(0..log.entries.len() - 10000);
        }
        
        let blob = log.encrypt(&self.master_key)?;
        self.write_encrypted_blob("audit_log.enc", &blob)
    }
    
    /// 读取搜索历史
    pub fn load_search_history(&self) -> Result<SearchHistory, VaultError> {
        let blob = self.read_encrypted_blob("search_history.enc")?;
        SearchHistory::decrypt(&blob, &self.master_key)
    }
    
    /// 追加搜索历史
    pub fn append_search_history(&self, query: &str, filters: Option<SearchFilters>, result_count: usize) -> Result<(), VaultError> {
        let mut history = self.load_search_history().unwrap_or_default();
        
        history.entries.push(SearchHistoryEntry {
            id: generate_uuid(),
            timestamp: Utc::now(),
            query: query.to_string(),
            filters,
            result_count,
        });
        
        // 去重：相同查询保留最新的一条
        history.entries.sort_by(|a, b| b.timestamp.cmp(&a.timestamp));
        history.entries.dedup_by(|a, b| a.query == b.query);
        
        // 限制数量
        if history.entries.len() > history.max_entries {
            history.entries.truncate(history.max_entries);
        }
        
        let blob = history.encrypt(&self.master_key)?;
        self.write_encrypted_blob("search_history.enc", &blob)
    }
    
    /// 读取 AI 对话历史
    pub fn load_ai_conversation(&self) -> Result<AiConversation, VaultError> {
        let blob = self.read_encrypted_blob("ai_conversation.enc")?;
        AiConversation::decrypt(&blob, &self.master_key)
    }
    
    /// 追加 AI 对话条目
    pub fn append_ai_conversation(&self, entry: AiConversationEntry) -> Result<(), VaultError> {
        let mut conversation = self.load_ai_conversation().unwrap_or_default();
        
        conversation.entries.push(entry);
        
        // 根据用户偏好中的保留策略清理旧记录
        let prefs = self.load_preferences()?;
        match prefs.ai_conversation_retention {
            ConversationRetentionPolicy::KeepAll => {}
            ConversationRetentionPolicy::KeepNone => {
                conversation.entries.clear();
            }
            ConversationRetentionPolicy::KeepLastN(n) => {
                if conversation.entries.len() > n as usize {
                    conversation.entries.drain(0..conversation.entries.len() - n as usize);
                }
            }
            ConversationRetentionPolicy::KeepDays(days) => {
                let cutoff = Utc::now() - Duration::days(days as i64);
                conversation.entries.retain(|e| e.timestamp > cutoff);
            }
        }
        
        let blob = conversation.encrypt(&self.master_key)?;
        self.write_encrypted_blob("ai_conversation.enc", &blob)
    }
    
    /// 清空 AI 对话历史
    pub fn clear_ai_conversation(&self) -> Result<(), VaultError> {
        let empty = AiConversation {
            version: 1,
            entries: Vec::new(),
            max_entries: 0,
        };
        let blob = empty.encrypt(&self.master_key)?;
        self.write_encrypted_blob("ai_conversation.enc", &blob)?;
        
        // 写入审计日志
        self.append_audit_log(AuditLogEntry {
            id: generate_uuid(),
            timestamp: Utc::now(),
            action: AuditAction::AiConversationCleared,
            entity_type: Some("ai_conversation".to_string()),
            entity_id: None,
            description: "AI 对话历史已清空".to_string(),
            performed_by: "user".to_string(),
            sensitivity_level: SensitivityLevel::Sensitive,
        })?;
        
        Ok(())
    }
    
    /// 调用 AI（安全封装）
    /// 
    /// 安全规则：
    /// 1. AI 绝不直接写入 Vault（只生成建议，用户确认后才执行）
    /// 2. 审计日志记录每次 AI 调用（不记录用户输入的原始内容）
    /// 3. API 密钥从 Vault 中读取，绝不暴露在内存中超过必要时间
    pub async fn call_ai(&self, user_input: &str) -> Result<AiResponse, VaultError> {
        let prefs = self.load_preferences()?;
        
        // 检查 AI 功能是否启用
        if !prefs.ai_features_enabled.conversation {
            return Err(VaultError::AiDisabled);
        }
        
        // 从 Vault 读取 API 密钥（critical 级别）
        let api_key = prefs.ai_api_key.ok_or(VaultError::AiApiKeyNotSet)?;
        
        // 构建请求（API 密钥在请求后立即从内存中清除）
        let response = match prefs.ai_provider {
            AiProvider::OpenAi => {
                self.call_openai(&api_key, user_input, prefs.ai_model.as_str()).await
            }
            AiProvider::Anthropic => {
                self.call_anthropic(&api_key, user_input, prefs.ai_model.as_str()).await
            }
            AiProvider::Ollama => {
                // 本地模型，API 密钥可能为空
                self.call_ollama(user_input, prefs.ai_model.as_str()).await
            }
            AiProvider::Custom => {
                let base_url = prefs.ai_api_base_url.ok_or(VaultError::AiBaseUrlNotSet)?;
                self.call_custom(&api_key, &base_url, user_input).await
            }
        }?;
        
        // 安全擦除 API 密钥（如果支持）
        // secure_wipe(&mut api_key);
        
        // 记录审计日志（不记录用户输入内容）
        self.append_audit_log(AuditLogEntry {
            id: generate_uuid(),
            timestamp: Utc::now(),
            action: AuditAction::AiCalled,
            entity_type: Some("ai".to_string()),
            entity_id: None,
            description: format!("AI 调用：provider={}, model={}", 
                format!("{:?}", prefs.ai_provider), 
                prefs.ai_model
            ),
            performed_by: "user".to_string(),
            sensitivity_level: SensitivityLevel::Sensitive,
        })?;
        
        // 如果用户启用了对话历史保留，保存对话
        if !matches!(prefs.ai_conversation_retention, ConversationRetentionPolicy::KeepNone) {
            self.append_ai_conversation(AiConversationEntry {
                id: generate_uuid(),
                timestamp: Utc::now(),
                role: AiRole::User,
                content: user_input.to_string(),
                model: prefs.ai_model.clone(),
                tokens_used: None,
                action_taken: None,
            })?;
            
            self.append_ai_conversation(AiConversationEntry {
                id: generate_uuid(),
                timestamp: Utc::now(),
                role: AiRole::Assistant,
                content: response.content.clone(),
                model: prefs.ai_model,
                tokens_used: response.tokens_used,
                action_taken: response.suggested_action,
            })?;
        }
        
        Ok(response)
    }
}
```

### 导入时：偏好数据提供三种策略

与身份数据相同，导入偏好数据时提供三种策略：

| 策略 | 行为 | 适用场景 |
|---|---|---|
| **使用当前配置** | 忽略导入包中的偏好数据 | 只想导入身份数据，保持现有设置 |
| **使用导入配置** | 导入包偏好完全覆盖当前偏好 | 新设备首次导入，或想完全同步旧设备设置 |
| **合并** | 导入条目与当前偏好合并，冲突时以导入为准 | 日常跨设备同步 |

**冲突处理示例**：
- 当前设备：主题 = dark，锁定超时 = 5min
- 导入包：主题 = light，锁定超时 = 10min，新增：开发者模式 = true
- 合并结果：主题 = light（导入覆盖），锁定超时 = 10min（导入覆盖），开发者模式 = true（新增）

### 行为数据的特殊处理

行为数据（操作日志、搜索历史、审计日志）导入时**只追加不覆盖**：

```rust
// 导入行为数据
fn import_behavioral_data(
    current: &mut AuditLog,
    imported: AuditLog,
) {
    // 追加所有导入条目
    for entry in imported.entries {
        // 去重：相同 id 跳过
        if !current.entries.iter().any(|e| e.id == entry.id) {
            current.entries.push(entry);
        }
    }
    
    // 按时间排序
    current.entries.sort_by(|a, b| a.timestamp.cmp(&b.timestamp));
}
```

理由：
- 操作日志是**时间序列**，不存在"覆盖"语义
- 两条记录都是真实的用户行为，都应该保留
- 导入时的审计日志追加本身也会生成一条新的审计记录

### AI 数据的特殊处理

#### AI 偏好导入策略

AI / LLM 偏好（`preferences.enc` 中的 `ai_api_key` 等）导入时遵循与普通偏好相同的三种策略（使用当前配置 / 使用导入配置 / 合并），但**API 密钥有特殊处理**：

| 策略 | API 密钥行为 | 理由 |
|---|---|---|
| **使用当前配置** | 保留当前设备的 API 密钥 | 不同设备的 API 密钥可能不同（如工作电脑 vs 家用电脑使用不同 key） |
| **使用导入配置** | 用导入包的 API 密钥覆盖当前 | 换设备时同步同一 key |
| **合并** | **API 密钥不合并，保留当前设备密钥** | API 密钥是设备级别的凭证，不应跨设备自动传播 |
