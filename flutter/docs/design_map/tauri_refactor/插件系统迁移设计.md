## 1. 现状诊断

### 1.1 已有实现（Flutter + Rust FFI）

SoloSoul 的插件系统是当前项目中最完整的 Rust 子系统之一，已有生产级代码实现：

| 模块 | 文件 | 核心职责 | 代码规模 |
|------|------|---------|---------|
| **生命周期管理** | `native/src/plugin/manager.rs` | 插件安装、执行、卸载、批量 Consent 授权、全局单例 | ~520 行 |
| **沙盒执行** | `native/src/plugin/sandbox.rs` | Wasmtime Store 隔离、Fuel 限制、Trap 捕获、内存清理 | ~170 行 |
| **Host Functions** | `native/src/plugin/host.rs` | 8 个安全接口、字段解密、Consent 通道、审计日志、网络代理 | ~1000 行 |
| **清单解析** | `native/src/plugin/manifest.rs` | manifest.json 验证、字段匹配（含通配符和数组索引）、网络策略 | ~350 行 |
| **会话管理** | `native/src/plugin/session.rs` | Session 注册/撤销/过期清理 | ~140 行 |
| **本地存储** | `native/src/plugin/store.rs` | 插件文件持久化（`~/.solosoul/plugins/`） | — |
| **Flutter UI** | `plugin_dashboard_page.dart` | 三 Tab 仪表盘（已安装/发现/日志）、插件卡片、结果对话框 | ~340 行 |

### 1.2 核心安全模型（已验证）

```
┌─────────────────────────────────────────────────────────────────┐
│                         Plugin Security Model                    │
├─────────────────────────────────────────────────────────────────┤
│  1. 安装时：manifest.json 验证 + SHA-256 wasm 校验              │
│  2. 执行前：批量 Consent 对话框（用户统一授权所有声明字段）      │
│  3. 运行时：Wasmtime Store 隔离 + Fuel 限制（10M/100M）         │
│  4. 字段访问：敏感度分级 → Public/Internal 直接通过            │
│                → Sensitive/Critical 需用户实时确认              │
│  5. 网络访问：默认阻断所有出站，仅白名单域名例外                │
│  6. 速率限制：10 次/分钟/字段（Release 下调至 10）              │
│  7. 审计日志：所有访问写入 ~/.solosoul/{account_id}/audit/plugin_audit.log（按账户隔离）│
│  8. TTL 过期：Store drop 后 Wasm 内存（含敏感数据副本）清零     │
│  9. Session 撤销：用户可随时强制终止插件运行                    │
└─────────────────────────────────────────────────────────────────┘
```

### 1.3 已知问题

| # | 问题 | 影响 | 优先级 |
|---|------|------|--------|
| 1 | `host.rs` 使用硬编码字段路径解析敏感度（`resolve_field_sensitivity`） | 新增字段需手动更新映射表，维护负担 | P2 |
| 2 | 插件结果通过 StreamSink 推送到 Dart，时序竞争保护用 sleep(100ms) × 3 | 不可靠，Tauri 的 Channel 机制更稳定 | P1 |
| 3 | 当前仅支持单 Profile，假设 `profiles.first()` | 多 Profile 场景会出错 | P2 |
| 4 | 日志写入 `/tmp/solosoul_rust.log`，全局 Mutex 保护 | 跨平台路径不统一，Tauri 有统一日志 API | P2 |
| 5 | `plugin_api_version` 未实际参与版本兼容性检查 | 高版本插件可能在低版本主软件上异常运行 | P2 |
| 6 | 对话框功能仅限白名单插件（`com.solosoul.official.doc-checklist`） | 扩展性不足 | P3 |

## 2. 迁移总体策略

### 2.1 核心原则：复用为主，微调为辅

插件系统的 Rust 核心代码（`native/src/plugin/` 全部 7 个文件）**质量高、架构清晰、测试覆盖充分**，迁移时以**整体平移**为主，仅做 Tauri 适配层替换：

| 组件 | Flutter 版本 | Tauri 版本 | 迁移方式 |
|------|-------------|-----------|---------|
| `PluginManager` | 全局单例 + Mutex | 相同，注册为 Tauri State | 平移 |
| `WasmSandbox` | wasmtime Engine | 相同 | 平移 |
| `SoloHostFunctions` | 8 个 Host Functions | 相同，Rust 逻辑不变 | 平移 |
| `PluginManifest` | serde_json 解析 | 相同 | 平移 |
| `PluginSessionManager` | Arc<Mutex<HashMap>> | 相同 | 平移 |
| **事件通道** | `StreamSink<PluginEvent>` (FRB) | `tauri::ipc::Channel<PluginEvent>` | 替换 |
| **日志** | 手写文件 + Mutex | `tracing` + `tauri-plugin-log` | 替换 |
| **全局单例获取** | `lazy_static!` + Mutex | Tauri `AppHandle` + State | 替换 |
| **前端 UI** | Flutter Widget | React 组件 | 重写 |

### 2.2 Crate 归属

根据《Crate拆分与Rust架构.md》，插件系统归属：

```
crates/
├── solosoul-core/          # 核心：PluginManager + WasmSandbox + HostFunctions
│   └── src/
│       └── plugin/
│           ├── mod.rs

│           ├── sandbox.rs      ← 平移自 native/src/plugin/sandbox.rs
│           ├── host.rs         ← 平移自 native/src/plugin/host.rs
│           ├── manifest.rs     ← 平移自 native/src/plugin/manifest.rs
```

## 3. IPC 接口设计（完整版）

### 3.1 命令接口

```rust
// crates/solosoul-tauri/src/commands/plugin.rs

use tauri::{ipc::Channel, State};
use solosoul_core::plugin::{PluginEvent, PluginManager};
use solosoul_types::plugin::{PluginInfo, PluginInstallResult, PluginRunParams};

/// 列出已安装插件
#[tauri::command]
pub async fn plugin_list(
    manager: State<'_, PluginManager>,
) -> Result<Vec<PluginInfo>, String> {
    manager.list_installed().map(|ids| {
        ids.into_iter()
            .filter_map(|id| manager.load_manifest(&id).ok())
            .map(|m| PluginInfo {
                plugin_id: m.plugin_id,
                name: m.name,
                version: m.version,
                description: m.description,
                publisher: m.publisher,
            })
            .collect()
    })
}

/// 安装插件（从文件路径）
#[tauri::command]
pub async fn plugin_install(
    manager: State<'_, PluginManager>,
    wasm_path: String,
    manifest_path: String,
) -> Result<PluginInstallResult, String> {
    let plugin_id = manager.install_plugin(wasm_path, manifest_path)?;
    let manifest = manager.load_manifest(&plugin_id)?;
    Ok(PluginInstallResult {
        plugin_id,
        name: manifest.name,
        version: manifest.version,
    })
}

/// 卸载插件
#[tauri::command]
pub async fn plugin_uninstall(
    manager: State<'_, PluginManager>,
    plugin_id: String,
) -> Result<(), String> {
    manager.force_unload(&plugin_id)?;
    Ok(())
}

/// 执行插件（核心命令）
#[tauri::command]
pub async fn plugin_run(
    manager: State<'_, PluginManager>,
    plugin_id: String,
    params: Option<String>,          // JSON 字符串，传入 initial_params
    channel: Channel<PluginEvent>,   // Tauri v2 Channel，替代 StreamSink
) -> Result<i32, String> {
    manager.execute_plugin(
        plugin_id,
        300,                          // session_ttl_seconds (默认 5 分钟)
        params,
        channel,                      // Channel 替代 StreamSink
    )
}

/// 响应 Consent 请求（用户在前端点击"授权"/"拒绝"）
#[tauri::command]
pub async fn plugin_consent_response(
    manager: State<'_, PluginManager>,
    request_id: String,
    approved: bool,
    value: Option<String>,
) -> Result<(), String> {
    manager.consent_response(request_id, approved, value)
}

/// 列出活跃 Session
#[tauri::command]
pub async fn plugin_list_sessions(
    manager: State<'_, PluginManager>,
) -> Result<Vec<SessionInfo>, String> {
    Ok(manager.list_active_sessions())
}

/// 强制撤销 Session
#[tauri::command]
pub async fn plugin_revoke_session(
    manager: State<'_, PluginManager>,
    plugin_id: String,
) -> Result<(), String> {
    manager.force_unload(&plugin_id)?;
    Ok(())
}
```

### 3.2 事件类型定义

```rust
// crates/solosoul-types/src/plugin.rs

use serde::{Deserialize, Serialize};

/// 插件事件（Rust → 前端，通过 Tauri Channel 推送）
#[derive(Debug, Clone, Serialize, Deserialize)]
#[serde(tag = "type", rename_all = "snake_case")]
pub enum PluginEvent {
    /// 请求用户授权字段访问
    ConsentRequest {
        request_id: String,
        plugin_id: String,
        plugin_name: String,
        field: String,
        sensitivity: String,
    },
    /// 授权超时
    ConsentTimeout {
        request_id: String,
    },
    /// 插件日志
    Log {
        level: String,
        message: String,
    },
    /// 批量授权结束标志（level = "batch_end"）
    BatchEnd {
        plugin_id: String,
    },
    /// 结构化结果（插件返回的数据）
    Result {
        json_data: String,
    },
    /// 进度更新
    Progress {
        percent: u8,
    },
    /// 执行完成
    Completed {
        exit_code: i32,
    },
    /// 执行错误
    Error {
        message: String,
    },
}

/// 插件信息（前端展示用）
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct PluginInfo {
    pub plugin_id: String,
    pub name: String,
    pub version: String,
    pub description: String,
    pub publisher: String,
}

/// 安装结果
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct PluginInstallResult {
    pub plugin_id: String,
    pub name: String,
    pub version: String,
}
```

## 4. Host Functions 完整定义

### 4.1 函数一览表

| Host Function | 签名 | 功能 | 安全限制 |
|--------------|------|------|---------|
| `solosoul_request_field` | `(field_id_ptr, field_id_len, out_ptr, out_cap) -> i32` | 请求读取用户数据字段 | manifest 声明 + 敏感度分级 + Consent + 速率限制 |

| `solosoul_get_timestamp` | `() -> i64` | 获取 Unix 时间戳（毫秒） | 无 |

### 6.3 插件执行事件流（前端）

```typescript
// 插件执行流程
async function runPlugin(pluginId: string, params?: object) {
  const channel = new Channel<PluginEvent>();
  
  // 监听事件
  channel.onmessage = (event) => {
    switch (event.type) {
      case 'consent_request':
        // 显示批量授权对话框
        showConsentDialog(event);
        break;
      case 'batch_end':
        // 批量授权结束，锁定对话框等待用户确认
        break;
      case 'log':
        appendLog(event.level, event.message);
        break;
      case 'result':
        // 解析 JSON 并按 type 渲染结果卡片
        renderResultCard(JSON.parse(event.json_data));
        break;
      case 'progress':
        updateProgress(event.percent);
        break;
      case 'completed':
        showCompletionStatus(event.exit_code);
        break;
      case 'error':
        showError(event.message);
        break;
    }
  };
  
  // 调用 Rust 执行
  await invoke('plugin_run', {
    pluginId,
    params: params ? JSON.stringify(params) : null,
    channel,
  });
}
```
