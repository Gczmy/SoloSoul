# L0 基础设施与平台层

> **层级定位**：与操作系统直接交互的能力层。提供原生 API 封装、构建体系、国际化基础。不持有任何业务逻辑，对上层（L1-L7）提供平台能力接口。
>
> **依赖方向**：仅依赖操作系统原生 API，不依赖上层任何层级。
>
> **Tauri 迁移方向**：大部分能力将被 Tauri 内置 API 或插件生态替代，部分需自定义 Rust 命令实现。

## L0.1 原生平台通道

### 1. macOS 原生通道（`NativeChannelService`）

**当前实现**：`lib/core/services/native_channel_service.dart` + iOS/macOS Swift handler

| 功能 | 描述 | 当前技术 | Tauri 替代方案 |
|------|------|---------|--------------|
| **菜单栏锁定回调** | 用户点击菜单栏"锁定"时触发 Vault 锁定 | `MethodChannel` + Swift `AppDelegate` | Tauri 菜单 API (`tauri::menu`) |
| **系统睡眠回调** | macOS 进入睡眠前提前锁定 Vault | `NSNotificationCenter` + `NSWorkspace.willSleepNotification` | Tauri `RunEvent::WindowEvent` + 系统事件监听 |
| **方法通道注册** | 初始化时注册所有原生方法处理器 | `methodChannel.setMethodCallHandler` | Tauri `invoke_handler` |

**接口契约（对 L7）**：
```dart
// Dart 端调用
NativeChannelService.initialize();
NativeChannelService.setLockCallback(() => authNotifier.lockVault());
NativeChannelService.setSleepCallback(() => authNotifier.lockVault());
```

**从零实现步骤**：
1. 在 Tauri 的 `src-tauri/src/main.rs` 中注册菜单项（"锁定 SoloSoul"）
2. 菜单项点击时通过 `app.emit("lock_vault", {})` 通知前端
3. 前端监听该事件并触发锁定逻辑
4. 通过 `core-graphics` 或 `cocoa` crate 监听系统睡眠通知，自动锁定

### 2. macOS QuickLook（`QuickLookService`）

**当前实现**：`lib/core/services/quicklook_service.dart`

| 功能 | 描述 | 当前技术 | Tauri 替代方案 |
|------|------|---------|--------------|
| **PPTX 预览** | 调用系统 QuickLook 预览 PowerPoint | `QLPreviewController` + Platform Channel | Tauri `shell.open` + 系统默认程序，或内嵌 Web 版 PPTX 解析器 |
| **初始化** | 预热 QuickLook 框架 | `QuickLookService().initialize()` | 无需预热，直接用系统打开 |

**从零实现步骤**：
1. Tauri 前端通过 `invoke('open_file_preview', { path })` 调用后端
2. Rust 后端调用 `opener::open(path)` 使用系统默认程序打开
3. 或在前端用 ` mammoth.js` / `pptxjs` 直接解析并渲染 PPTX

### 3. Apple Vision OCR（`AppleVisionOcr`）

**当前实现**：`lib/core/services/apple_vision_ocr.dart`

| 功能 | 描述 | 当前技术 | Tauri 替代方案 |
|------|------|---------|--------------|
| **Vision OCR** | macOS/iOS 原生文字识别（备用方案） | `VNRecognizeTextRequest` | Tauri 前端可直接使用浏览器端的 Tesseract.js，或 Rust 端 ONNX OCR（已存在） |

**决策**：Tauri 迁移时 Apple Vision OCR 可弃用，统一使用 Rust ONNX OCR（L3.5）。

### 4. 剪贴板监控（`ClipboardMonitorService`）

**当前实现**：`lib/core/services/clipboard_monitor_service.dart`

| 功能 | 描述 | 当前技术 | Tauri 替代方案 |
|------|------|---------|--------------|
| **敏感数据复制监听** | 检测用户是否复制了敏感字段 | 定时轮询剪贴板内容 | Tauri `clipboard-manager` 插件；或前端 `navigator.clipboard` API |
| **定时清理** | 复制后 N 秒清空剪贴板 | `Timer.periodic` | `setTimeout` + `navigator.clipboard.writeText('')` |

**接口契约（对 L7）**：
```dart
// 敏感数据复制时注册清理任务
ClipboardMonitorService.instance.scheduleClear(delaySeconds);
// App detached 时 dispose
ClipboardMonitorService.instance.dispose();
```

**从零实现步骤**：
1. 前端在复制敏感数据时调用 `navigator.clipboard.writeText(value)`
2. 同时启动 `setTimeout(clearClipboard, delayMs)`
3. 窗口关闭前（`beforeunload`）主动清空剪贴板
4. 更安全的方案：Rust 后端提供 `clear_clipboard` 命令，由后端直接操作系统剪贴板

### 5. 文件选择器

**当前实现**：`file_picker` 插件

| 功能 | 描述 | Tauri 替代方案 |
|------|------|--------------|
| **导入文件选择** | 选择要导入的文件 | Tauri `dialog.open` API |
| **导出路径选择** | 选择导出保存位置 | Tauri `dialog.save` API |
| **文件夹选择** | 选择扫描路径 | Tauri `dialog.open({ directory: true })` |

### 6. 路径获取

**当前实现**：`path_provider` 插件

| 路径类型 | 当前 API | Tauri 替代方案 |
|---------|---------|--------------|
| **应用文档目录** | `getApplicationDocumentsDirectory()` | `appDataDir()` (Tauri Path API) |
| **应用支持目录** | `getApplicationSupportDirectory()` | `appDataDir()` |
| **临时目录** | `getTemporaryDirectory()` | `tempDir()` |
| **下载目录** | `getDownloadsDirectory()` | `downloadDir()` |

**从零实现步骤**：
1. Tauri 前端通过 `invoke('get_app_paths')` 一次性获取所有路径
2. Rust 后端返回各平台对应的标准路径
3. 前端缓存路径，避免频繁调用

### 7. 包信息

**当前实现**：`package_info_plus` 插件

| 信息 | 当前 API | Tauri 替代方案 |
|------|---------|--------------|
| **应用版本** | `PackageInfo.fromPlatform()` | `getVersion()` (Tauri App API) |
| **构建号** | `packageInfo.buildNumber` | `tauri.conf.json` 中定义 |

## L0.2 原生安全存储

### 1. iOS/macOS Keychain（`flutter_secure_storage`）

**当前实现**：`FlutterSecureStorage`（iOS Options: `first_unlock_this_device`）

**存储内容**：
- 安全设置（JSON）
- 生物识别凭证
- 各账户的敏感小数据

**Tauri 替代方案**：
- **macOS**: `keychain` crate 直接操作 Keychain
- **iOS**: Tauri 尚未官方支持 iOS，但可用 `tao` + `wry` 的移动端分支
- **Windows**: `windows` crate + Credential Manager
- **Linux**: `secret-service` crate + D-Bus Secret Service

### 2. Fallback Secure Storage

**当前实现**：`lib/core/services/fallback_secure_storage.dart`

| 功能 | 描述 | Tauri 替代方案 |
|------|------|--------------|
| **Keychain 失败回退** | AES 加密后存文件 | 直接使用 Rust `aes-gcm` 加密后存文件；或 Tauri `stronghold` 插件 |

### 3. Rust Safe Storage

**当前实现**：`native/src/safe_storage.rs`

| 平台 | 后端 | Tauri 替代方案 |
|------|------|--------------|
| **macOS** | Keychain Services | `keychain` crate |
| **Windows** | Windows Credential | `windows` crate |
| **Linux** | Secret Service API | `secret-service` crate |

**从零实现步骤**：
1. Rust 后端实现 `safe_storage` module，封装各平台 Keychain/凭证管理器
2. 暴露 `tauri::command`：`write_secure(key, value)` / `read_secure(key)` / `delete_secure(key)`
3. 失败时回退到文件存储（用 Vault 密钥加密）

## L0.3 构建与分发体系

### 1. Rust 静态库编译

**当前流程**：
```bash
cd flutter/native
cargo build --release
# 输出: target/release/libsolosoul_core.dylib (macOS)
#       target/release/solosoul_core.dll (Windows)
```

**Tauri 目标流程**：
```bash
cd tauri/src-tauri
cargo tauri build
# Tauri 自动处理 Rust 编译 + 前端打包 + 安装包生成
```

### 2. 交叉编译脚本

**当前**：`build_rust.sh --all`（macOS Universal + Linux + Windows）

**Tauri 替代**：GitHub Actions 矩阵构建（`tauri-action`）
```yaml
strategy:
  matrix:
    platform: [ubuntu-latest, windows-latest, macos-latest]
```

### 3. macOS Release 构建

**当前**：`flutter build macos --release --obfuscate --split-debug-info=./debug_info/macos`

**Tauri 替代**：
```bash
cd tauri/src-tauri
cargo build --release
# 前端自动 Tree Shaking + 压缩
```

### 4. DMG 打包

**当前**：`build_dmg.sh`

**Tauri 替代**：`cargo tauri build` 自动生成 `.dmg`（macOS）、`.msi`（Windows）、`.deb`/`.AppImage`（Linux）

### 5. FFI 验证

**当前**：`validate_ffi.sh`（Rust 签名 ↔ Dart 声明一致性检查）

**Tauri 替代**：无需 FFI，Rust 与前端通过 IPC 通信，类型安全由 `tauri::command` 宏保证

### 6. 调试符号管理

**当前**：`debug_info/macos/`

**Tauri 替代**：`Cargo.toml` 中 `strip = true` 剥离符号；或单独保存 dSYM

## L0.5 国际化基础

### 1. ARB 翻译系统

**当前**：`lib/l10n/app_en.arb` / `app_zh.arb`

**Tauri 替代**：前端框架的 i18n 库
- **React**: `react-i18next` / `formatjs`
- **Vue**: `vue-i18n`
- **通用**: `i18next`

**迁移步骤**：
1. 将 ARB 文件转换为 JSON 格式（`en.json` / `zh.json`）
2. 前端 i18n 库加载对应语言包
3. 保持原有的 key 命名规范，减少迁移成本

### 2. 动态字段标签

**当前**：`FieldLabelResolver` + `translateFieldLabel()` — 内置类型字段不走静态存储，运行时从 ARB 读取

**Tauri 替代**：前端 i18n 库的 `t()` 函数，在组件渲染时动态翻译

### 3. Locale 切换

**当前**：`languageProvider` — 切换后无需重启

**Tauri 替代**：前端 i18n 库的 `i18n.changeLanguage()`，实时切换

## 接口契约（对 L1-L7）

L0 层对上层提供的接口可归纳为以下几类：

| 接口类别 | 具体能力 | 消费者 |
|---------|---------|--------|
| **文件系统路径** | 应用目录、临时目录、下载目录 | L1（数据存储）、L3（备份/附件）、L7（临时文件清理） |
| **安全存储** | Keychain 读写 | L2（生物识别凭证）、L7（安全设置） |
| **剪贴板** | 读写 + 定时清理 | L3（操作日志/字段复制）、L7（安全策略） |
| **系统通知** | 菜单点击、睡眠事件 | L7（自动锁定） |
| **文件选择** | 打开/保存对话框 | L3（导入/导出/备份）、L6（扫描配置） |
| **应用信息** | 版本号、构建号 | L7（版本检测）、L6（设置页） |
| **语言环境** | 当前 Locale、翻译字符串 | L4（状态）、L5/L6（UI 渲染） |

## 从零开始实现顺序

如果从零开始构建 SoloSoul 的 L0 层，建议按以下顺序：

1. **搭建 Tauri 项目骨架**（`create-tauri-app`）
   - 选择前端框架（建议 React）
   - 验证跨平台编译（macOS / Windows / Linux）
   
2. **实现基础路径服务**（Rust `tauri::command`）
   - `get_app_paths()` → 返回各平台标准路径
   
3. **实现安全存储封装**（Rust）
   - `write_secure(key, value)` / `read_secure(key)` / `delete_secure(key)`
   - 平台回退：Keychain → Credential Manager → Secret Service → 文件加密
   
4. **配置国际化基础**（前端）
   - 选择 i18n 库，加载 JSON 翻译文件
   - 实现 `t(key)` 函数，支持变量插值
   
5. **配置 CI/CD**（GitHub Actions）
   - `tauri-action` 矩阵构建
   - Rust test + 前端 test + E2E test
   
6. **实现剪贴板命令**（Rust + 前端）
   - `write_clipboard(text)` / `clear_clipboard()`
   - 前端 `setTimeout` 自动清理
   
7. **配置系统事件监听**（Rust）
   - 菜单栏"锁定"项
   - 系统睡眠前锁定（macOS/Windows/Linux 分别实现）

## 测试要点

| 测试目标 | 测试方法 | 预期结果 |
|---------|---------|---------|
| **路径获取** | 在各平台运行 `get_app_paths()` | 返回正确的平台标准路径 |
| **安全存储读写** | 写入 → 读取 → 删除 → 读取 | 写入成功、读取一致、删除后读不到、回退路径可用 |
| **Keychain 回退** | 模拟 Keychain 失败 | 自动回退到文件加密存储 |
| **Locale 切换** | 切换 en → zh → en | 所有 UI 文本实时更新，无闪烁 |
| **剪贴板清理** | 复制敏感数据，等待超时 | 剪贴板内容被清空 |
| **CI 构建** | Push 到 PR | 所有检查通过，产物生成成功 |
| **跨平台编译** | 在三个平台分别构建 | 均生成可运行安装包 |
