# ADR-005: 数据库迁移方案

> **状态**: 已采纳 ✅  
> **决策日期**: 2026-06-04  
> **决策人**: SoloSoul 架构组  
> **影响范围**: 数据持久化、Schema 兼容性、用户数据无损迁移

---

## 背景

当前 Flutter 客户端使用 **SQLite + SQLCipher** 进行数据持久化，通过 `flutter_rust_bridge` 由 Rust 代码操作数据库。

Tauri 迁移后，数据库仍由 **Rust 后端**直接持有，前端通过 IPC 访问。需要决策：
1. SQLite 绑定库选择（rusqlite vs sqlx vs diesel）
2. SQLCipher 集成方式
3. Schema 迁移策略
4. 旧数据兼容性

---

## 候选方案

### 方案 A: rusqlite + bundled SQLCipher（推荐）

**技术栈**: `rusqlite` with `bundled-sqlcipher` feature

```toml
[dependencies]
rusqlite = { version = "0.32", features = ["bundled-sqlcipher", "backup", "chrono"] }
```

**优势**:
- **与当前实现一致**: Flutter 端已使用 rusqlite，代码可直接迁移
- **SQLCipher 开箱即用**: `bundled-sqlcipher` feature 自动编译 SQLCipher
- **API 简单**: 同步 API，直接执行 SQL
- **备份支持**: `backup` feature 支持在线备份
- **零配置**: 不需要外部 SQLite/SQLCipher 安装

**劣势**:
- 异步支持有限（需要手动 spawn blocking）
- 不是 ORM，需要手写 SQL

---

### 方案 B: sqlx + sqlcipher

**技术栈**: `sqlx` with `runtime-tokio` + `sqlite`

```toml
[dependencies]
sqlx = { version = "0.8", features = ["runtime-tokio", "sqlite", "migrate"] }
```

**优势**:
- **编译时 SQL 检查**: `query!()` 宏在编译时验证 SQL
- **原生异步**: 完美集成 tokio
- **连接池**: 内置连接池管理

**劣势**:
- **SQLCipher 支持复杂**: 需要手动配置加密扩展
- **编译时检查需要数据库**: CI 需要运行数据库
- **学习曲线**: API 比 rusqlite 复杂
- **与当前代码不兼容**: 需要重写所有 SQL 代码

---

### 方案 C: Diesel + sqlcipher

**技术栈**: `diesel` with `sqlite` feature

**优势**:
- **完整 ORM**: 类型安全的查询构建器
- **迁移系统**: 内置 Schema 迁移
- **代码生成**: `diesel-cli` 生成模型代码

**劣势**:
- **过重**: SoloSoul 不需要完整 ORM
- **SQLCipher 支持差**: Diesel 对 SQLCipher 支持不完善
- **异步支持差**: Diesel 同步为主
- **学习成本高**: DSL 查询语法需要学习
- **与当前代码不兼容**: 完全重写数据访问层

---

## 决策：rusqlite + bundled SQLCipher

**选择原因**:
1. **代码复用最大化**: 当前 `flutter/native/src/vault/` 已使用 rusqlite，迁移成本最低
2. **SQLCipher 零配置**: `bundled-sqlcipher` 自动处理加密
3. **同步模型足够**: SoloSoul 是桌面应用，单用户，不需要高并发
4. **迁移风险最低**: Schema、SQL 语句完全复用

### 异步处理

```rust
use tokio::task;

// rusqlite 是同步的，在 tokio 中通过 spawn_blocking 调用
pub async fn query_profile(account_id: &str) -> Result<ProfileData, Error> {
    let db_path = get_db_path(account_id);
    task::spawn_blocking(move || {
        let conn = Connection::open(&db_path)?;
        let mut stmt = conn.prepare("SELECT * FROM profiles WHERE account_id = ?")?;
        let profile = stmt.query_row([&account_id], |row| {
            Ok(ProfileData {
                full_name: row.get("full_name")?,
                // ...
            })
        })?;
        Ok(profile)
    }).await?
}
```

## 旧数据兼容

### 数据目录结构（保持不变）

```
~/.solosoul/
├── accounts.json              # 账户列表（保持不变）
└── {account_id}/
    ├── config.json            # 账户配置（Salt + 验证令牌）
    ├── vault.db               # SQLCipher 加密数据库
    ├── vault.db-journal       # SQLite 日志
    ├── backups/               # 备份文件
    │   └── *.db
    └── attachments/           # 附件文件
        └── {file_id}.{ext}
```

**关键决策**: **数据目录结构完全保持不变**，新 Tauri 应用直接读取旧的 `~/.solosoul/` 目录。

这意味着：
- 用户升级后无需迁移数据
- 旧版本和新版本可以共存（但不可同时运行）
- 回滚到旧版本（Flutter）时数据仍然可用

### 版本兼容性检查

```rust
/// 检查数据库 Schema 版本
pub fn check_schema_version(conn: &Connection) -> Result<i32, Error> {
    let version: i32 = conn.query_row(
        "PRAGMA user_version",
        [],
        |row| row.get(0)
    )?;
    Ok(version)
}

/// 应用迁移
pub fn migrate_if_needed(conn: &Connection) -> Result<(), Error> {
    let current = check_schema_version(conn)?;
    let target = 6;  // 当前目标版本
    
    if current < target {
        apply_migrations(conn, current, target)?;
    }
    Ok(())
}
```

## 仓库层设计

```rust
// src-tauri/src/db/repositories/profile_repo.rs

use rusqlite::{Connection, Result};

pub struct ProfileRepository<'a> {
    conn: &'a Connection,
}

impl<'a> ProfileRepository<'a> {
    pub fn new(conn: &'a Connection) -> Self {
        Self { conn }
    }

    pub fn get_by_account(&self, account_id: &str) -> Result<Option<ProfileData>> {
        let mut stmt = self.conn.prepare(
            "SELECT * FROM profiles WHERE account_id = ?"
        )?;
        
        let mut rows = stmt.query([account_id])?;
        
        if let Some(row) = rows.next()? {
            Ok(Some(self.row_to_profile(row)?))
        } else {
            Ok(None)
        }
    }

    pub fn upsert(&self, data: &ProfileData) -> Result<()> {
        self.conn.execute(
            "INSERT INTO profiles (account_id, full_name, ...)
             VALUES (?1, ?2, ...)
             ON CONFLICT(account_id) DO UPDATE SET
             full_name = excluded.full_name,
             updated_at = datetime('now')",
            params![data.account_id, data.full_name, ...]
        )?;
        Ok(())
    }

    fn row_to_profile(&self, row: &rusqlite::Row) -> Result<ProfileData> {
        Ok(ProfileData {
            account_id: row.get("account_id")?,
            full_name: row.get("full_name")?,
            // ...
        })
    }
}
```
