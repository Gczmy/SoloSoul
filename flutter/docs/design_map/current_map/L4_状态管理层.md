# L4 状态管理层

> **层级定位**：基于 Riverpod 的全局状态容器，连接 L3 服务层与 L5 UI 组件层。每个 Provider 管理一块独立的状态域，提供不可变状态 + 变更方法。状态变更驱动 UI 重建。
>
> **核心原则**：状态不可变（通过 copyWith 生成新状态）；Provider 只负责状态管理，不直接操作 UI；敏感状态（如密钥）不存入持久化存储；跨 Provider 通信通过 `ref.read` / `ref.watch` 进行。
>
> **Tauri 迁移方向**：前端状态管理从 Riverpod 迁移到前端框架原生方案（React 用 Zustand/Redux，Vue 用 Pinia，Svelte 用 Store）。部分状态（如 Vault 状态）可下沉到 Rust 后端，由后端主动 `emit` 事件通知前端。

### 1.2 状态定义

```dart
enum AuthState {
  uninitialized,    // Vault 未初始化
  locked,           // Vault 已锁定
  unlocked,         // Vault 已解锁
  loading,          // 操作中（解锁/创建中）
  error,            // 错误状态
}

@freezed
class AuthStateData with _$AuthStateData {
  const factory AuthStateData({
    required AuthState state,
    String? selectedAccountId,
    String? errorMessage,
    bool? hasAccounts,          // 是否存在任何账户
  }) = _AuthStateData;
}
```

### 1.3 核心 Provider：`authNotifierProvider`

**类型**：`AsyncNotifier<AuthStateData>`

| 方法 | 触发条件 | 行为 |
|------|---------|------|
| `unlockVault(password)` | 用户输入密码点击解锁 | 调用 L3.2 → 成功则 `state = unlocked` + 加载 Profile |
| `lockVault()` | 用户点击锁定 / 自动锁定 / 系统睡眠 | 调用 L3.2 → `state = locked` + 擦除敏感状态 |
| `createAccount(name, password)` | 用户创建新账户 | 调用 L3.1 → 成功后自动解锁 |
| `selectAccount(accountId)` | 用户切换账户 | 先锁定当前 → 加载新账户 Vault 状态 |
| `deleteAccount(accountId, password)` | 用户删除账户 | 调用 L3.1 → 成功后刷新账户列表 |
| `updateOperation(desc)` | 每次操作后 | 更新 `last_operation_desc`（用于账户列表展示） |

### 1.4 敏感页面访问控制

```dart
// sensitivePageAccessProvider
// 管理敏感页面的访问权限（1 分钟有效期）

final sensitivePageAccessProvider = StateNotifierProvider<
  SensitivePageAccessNotifier,
  SensitiveAccessState
>((ref) => SensitivePageAccessNotifier());

class SensitiveAccessState {
  final bool isGranted;
  final DateTime? grantedAt;
  
  bool get isExpired {
    if (grantedAt == null) return true;
    return DateTime.now().difference(grantedAt!).inMinutes >= 1;
  }
}
```

**使用方式**：
```dart
// 进入敏感页面前检查
if (!ref.read(isSensitiveAccessGrantedProvider)) {
  await showPasswordVerificationDialog(context);
}
```

`authStorageProvider` 负责：
- 保存最后选中的账户 ID
- 保存账户列表缓存（非敏感）
- 使用 `FlutterSecureStorage` 或 Fallback

## L4.2 Profile 状态

**核心实现**：`lib/presentation/providers/profile_provider.dart`

### 2.1 核心 Provider：`profileNotifierProvider`

**类型**：`AsyncNotifier<ProfileData?>`

| 方法 | 触发条件 | 行为 |
|------|---------|------|
| `loadProfile(accountId)` | Vault 解锁后自动调用 | 从 L1.3 加载 → 更新状态 |
| `saveProfile()` | 数据变更后 | 调用 L1.3 保存（带 500ms debounce） |
| `clearProfile()` | Vault 锁定时 | 状态置为 null，释放内存 |
| `updateProfile(updates)` | 用户修改数据 | `copyWith` 生成新状态 → 触发保存 |

### 2.2 自动保存（Debounce）

```dart
Timer? _saveDebounceTimer;

void scheduleSave() {
  _saveDebounceTimer?.cancel();
  _saveDebounceTimer = Timer(const Duration(milliseconds: 500), () {
    _doSave();
  });
}
```

- 用户连续输入时，每 500ms 只保存一次
- 关键操作（如删除对象）可强制立即保存：`saveProfile(immediate: true)`

### 2.3 字段历史状态

```dart
// fieldHistoriesProvider

## L4.3 Unified Object 状态

**核心实现**：`lib/presentation/providers/unified_object_*.dart`

### 3.1 文件结构

```

### 3.2 核心 Provider：`unifiedObjectProvider`

**类型**：`StateNotifierProvider<UnifiedObjectNotifier, List<UnifiedObject>>`

| 方法 | 行为 |
|------|------|
| `addObject(object)` | 添加到列表 → 触发缓存重建 |
| `updateObject(id, updates)` | 找到对象 → `copyWith` → 更新 → 重建缓存 |
| `deleteObject(id)` | 软删除（`isDeleted = true`）→ 重建缓存 |
| `restoreObject(id)` | 取消软删除 → 重建缓存 |
| `permanentlyDelete(id)` | 从列表移除 → 重建缓存 |
| `reorderObjects(orderedIds)` | 按新顺序更新 `order` 字段 |
| `reset()` | Vault 锁定时清空所有状态 |

### 3.3 预计算缓存：`unifiedObjectCacheProvider`

```dart
class UnifiedObjectCache {
  final Map<String, UnifiedObject> objectById;
  final Map<String, List<UnifiedObject>> itemChildren;
  final Map<String, List<UnifiedObject>> workspaceChildren;
  final List<UnifiedObject> rootObjects;
}
```

**缓存重建触发条件**：
- `unifiedObjectProvider` 的任何变更
- 后台异步重建，不阻塞 UI

**使用方式**：
```dart
final cache = ref.watch(unifiedObjectCacheProvider);
final currentObject = cache.objectById[objectId];
final children = cache.workspaceChildren[objectId];
```

### 3.4 辅助 Provider

| Provider | 用途 |
|----------|------|
| `objectByIdProvider(id)` | 按 ID 获取单个对象（Family Provider） |
| `childrenProvider(parentId)` | 获取某对象的子对象列表 |
| `rootObjectsProvider` | 获取根级对象列表（排除 page 类型） |

  final accountStyle = ref.read(accountStyleProvider);

### 6.3 核心方法

## Tauri 迁移策略

### 状态管理层映射

| Riverpod 概念 | React 替代方案 | Vue 替代方案 |
|--------------|---------------|-------------|
| `StateProvider<T>` | `useState<T>` / Zustand store | `ref<T>` / Pinia state |
| `StateNotifierProvider` | Zustand store + actions | Pinia store + actions |
| `FutureProvider<T>` | `useQuery` (TanStack Query) | `useAsyncState` |
| `StreamProvider<T>` | `useMutation` + WebSocket | — |
| `Provider<T>` | 普通常量 / Context | `computed` |
| `Family Provider` | Hook 参数 / 动态 key | 带参数的 store |

### 状态下沉策略

| 当前状态 | Tauri 方案 | 理由 |
|---------|-----------|------|
| `AuthState` | **Rust 后端持有** + `emit` 事件 | 安全边界，前端不应判断 Vault 状态 |
| `VaultState` | **Rust 后端持有** + `emit` 事件 | 同上 |
| `ProfileData` | 前端状态（加载后缓存） | 数据量大，不适合频繁 IPC |
| `UnifiedObject[]` | 前端状态（加载后缓存） | 同上 |
| `LlmConfig` | 前端状态（API Key 加密存 Rust） | Key 存 Rust，配置参数存前端 |
| `SearchIndex` | 前端状态（内存索引） | 搜索响应快，无需每次 IPC |
| `ScanState` | 前端状态 | 扫描进度实时更新，前端维护 |

### IPC 事件流设计

```rust
// Rust 后端主动推送的事件
app.emit("vault_state_changed", VaultStatePayload { state: "locked" });
app.emit("profile_updated", ProfileSummaryPayload { id, name, updatedAt });
app.emit("object_changed", ObjectChangePayload { action: "update", objectId });
app.emit("sync_progress", SyncProgressPayload { percent, currentFile });
app.emit("plugin_event", PluginEventPayload { sessionId, event_type, data });
```

```typescript
// 前端监听
listen('vault_state_changed', (event) => {
  if (event.payload.state === 'locked') {
    navigate('/login');
    clearSensitiveState();
  }
});
```

## 从零开始实现顺序

1. **Auth State**
   - 定义 `AuthState` 枚举
   - 实现登录/解锁/锁定/创建账户的 action
   - 监听 Vault 状态变化，自动路由跳转

2. **Profile State**
   - 定义 `ProfileData` 类型
   - 实现加载/保存（带 debounce）
   - Vault 锁定时自动清空

3. **Unified Object State**
   - 定义 `UnifiedObject` 类型
   - 实现 CRUD + 软删除 + 恢复
   - 实现预计算缓存（O(1) 查询）

4. **Sensitivity State**
   - 定义全局字段注册表
   - 实现账户级覆盖
   - 提供 `getEffectiveSensitivity()` 辅助函数

5. **LLM State**
   - 配置状态（持久化）
   - 会话列表 + 当前会话消息
   - 流式消息追加逻辑

6. **Scan State**
   - 状态机（idle → scanning → preview → importing → completed）
   - 进度跟踪
   - AI 映射状态

7. **其他状态**
   - 搜索状态（关键词 + 结果 + 过滤）
   - 同步状态（设备列表 + 日志）
   - 插件状态（列表 + 搜索 + 标签）
   - 操作日志状态
   - 回收站过滤状态
   - 语言状态（持久化）
