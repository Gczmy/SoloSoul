## 1. 核心理念

> **「我们不管理'文档'，我们管理'你'」** — 产品使命

凡是与用户个人相关的数据，无论传统分类叫"设置""配置""日志"还是"缓存"，在 SoloSoul 中一律视为**用户数据**，受同等级别的加密保护。

---

## 2. 用户数据的四大类别

### 2.1 身份数据（Identity Data）
- Profile 字段、UnifiedObject、附件、自定义类型定义
- 存储：`profile.enc`、`objects.enc`、`attachments/`

### 2.2 偏好数据（Preference Data）— 等同于用户数据
- 视觉偏好：主题、颜色、字体、界面密度
- 行为偏好：自动锁定超时、生物识别、删除确认
- 内容偏好：语言、日期格式、时区
- 敏感度偏好：SensitivityMap、默认策略
- 插件偏好：已安装列表、授权记录
- AI/LLM 偏好：提供商、模型、**API 密钥（critical 级别）**

### 2.3 行为数据（Behavioral Data）— 等同于用户数据
- 操作日志（CRUD、敏感度变更、导入导出）
- 搜索历史（关键词、过滤器）
- 审计日志（插件访问、密码验证）
- AI 对话历史

### 2.4 关系数据（Relational Data）
- 对象间关联、标签体系、自定义分类

---

## 3. 明确排除的非用户数据

| 数据 | 理由 | 存储 |
|------|------|------|
| 编译日志 | 与"你"无关 | 明文日志文件 |
| 崩溃报告 | 纯技术诊断 | 用户明确同意才收集 |
| 应用更新元数据 | 纯技术信息 | 明文缓存 |
| 插件市场索引 | 公开数据 | 明文缓存 |
| 帮助文档缓存 | 公开数据 | 明文缓存 |

---

## 4. 存储架构：全部加密

```
~/.solosoul/{account_id}/
├── config.json              # 明文：仅账户元信息（account_id, created_at）
├── vault.db                 # SQLite：加密 blob 索引
├── profile.enc              # 身份数据（AES-256-GCM）
├── objects.enc              # 统一对象（AES-256-GCM）
├── preferences.enc          # 偏好数据（AES-256-GCM）← 新增
├── audit_log.enc            # 审计日志（AES-256-GCM）← 新增
├── search_history.enc       # 搜索历史（AES-256-GCM）← 新增
├── ai_conversation.enc      # AI 对话历史（AES-256-GCM）← 新增
├── sensitivity_map.enc      # 敏感度映射表（AES-256-GCM）
├── sensitivity_log.enc      # 敏感度变更历史（AES-256-GCM）
└── attachments/             # 独立加密文件
```

**核心规则**：所有 `.enc` 文件使用同一 Vault 主密钥加密。Vault 锁定后所有用户数据同时不可访问。

## 5. 现有设计的修正

### 修正 1：`app_settings` 明文表 → 加密文件

```sql
-- ❌ 旧设计
CREATE TABLE app_settings (
    account_id TEXT PRIMARY KEY,
    settings_json TEXT NOT NULL  -- 明文 JSON！
);

-- ✅ 新设计：独立加密文件 preferences.enc
```

### 修正 2：`settingsStore` localStorage → IPC 加密存储

```typescript
// ❌ 旧设计：Zustand persist → localStorage（明文暴露）
export const useSettingsStore = create(persist(...));

// ✅ 新设计：通过 IPC → Rust Vault 加密读写
export const useSettingsStore = create(immer((set) => ({
  loadSettings: async () => {
    const settings = await commands.userDataGetPreferences();
    set({ settings });
  },
  updateSetting: async (key, value) => {
    await commands.userDataUpdatePreference(key, value);
  },
})));
```

### 修正 3：`operation_logs` 明文表 → 加密文件

操作日志不再存储在明文 SQLite 表中，改为加密的 `audit_log.enc`。

## 6. 前端 Store 敏感度保护规则

| Store | localStorage 持久化 | 理由 |
|-------|---------------------|------|
| authStore | ❌ | 认证状态 |
| vaultStore | ❌ | Vault 状态 |
| profileStore | ❌ | 身份数据 |
| settingsStore | ❌ | 用户偏好（sensitive） |
| searchStore | ❌ | 行为数据（sensitive） |
| uiStore | ✅（仅非敏感部分） | sidebarCollapsed、Toast 队列（非用户数据） |

---

## 7. 偏好与行为数据的敏感度分级

关键条目：

| 数据 | 敏感度 | 理由 |
|------|--------|------|
| 主题/字体/密度 | `public` | 可见于界面 |
| 语言/日期/货币格式 | `internal` | 可推断文化背景 |
| 自动锁定超时 | `sensitive` | 暴露安全意识水平 |
| 生物识别启用状态 | `sensitive` | 暴露安全策略 |
| SensitivityMap | `sensitive` | 暴露全部字段安全策略 |
| 插件授权记录 | `sensitive` | 暴露信任决策 |
| **LLM API 密钥** | **`critical`** | 等同于账户密码 |
| 操作日志（CRUD） | `sensitive` | 暴露数据访问行为 |
| 搜索历史 | `sensitive` | 暴露关注点 |
| 密码验证失败记录 | `critical` | 安全事件 |
| AI 对话历史 | `sensitive` | 可能包含身份信息 |

## 8. AI 数据特殊处理

> **审批决策（2026-06-05）**：AI 功能**默认禁用**，用户主动开启后以下规则生效。

- **LLM API 密钥**：`critical` 级别，导出时默认不勾选，勾选时强制安全警告
- **AI 对话历史**：`sensitive` 级别，加密存储于 `ai_conversation.enc`
- **AI 调用审计**：记录 provider/model/timestamp，不记录用户输入内容
- **AI 功能开关状态**：存储于 `preferences.enc` 中的 `ai_features_enabled` 字段，默认全部 `false`
- **风险告知**：用户首次开启任何 AI 功能时，展示风险告知对话框并写入审计日志
- **数据外传控制**：AI 对话内容由用户逐条确认后发送，不自动上传
