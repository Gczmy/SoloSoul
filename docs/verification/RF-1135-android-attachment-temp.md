# RF-1135：Android 附件打开、分享的临时目录

状态：完成。此项不关闭 RF-312 的完整性能、多端和硬件验收。

Android API31 的公开 PDF 预览经实际界面输入触发后失败。失败后的单独命令诊断返回“准备临时目录失败”和“权限拒绝”两个类别；这次额外 JS 请求明确排除于原生性能样本。失败发生在 Rust 准备解密目录时，尚未进入 Android 原生 PDF 渲染器。

原实现对所有平台使用 `std::env::temp_dir()`。Android 打开和分享现在分别用 Tauri 的 `app_cache_dir()` 提供私有缓存基目录；桌面仍传系统临时目录。共享解密函数不再自行决定平台目录，不修改进程全局 `TMPDIR`。名称校验、每次 UUID 子目录、Unix 目录/文件权限及原有 30 分钟延迟清理保持。

[Rust 官方说明](https://doc.rust-lang.org/std/env/fn.temp_dir.html)列出了 Android 13 以下可能使用 `/data/local/tmp` 的行为。独立 Rust ELF 探针在本轮被 Android 拒绝执行，已清理其唯一远端文件；不能将该失败当作系统临时目录取值或目录创建结果。根因证据来自产品命令的实际错误类别。

## 保留的失败

- 首轮私有根的 `/data/data` 与 `/data/user/0` 别名检查错误；后续增加 canonical、设备及 inode 一致性检查。
- 第二轮错误等待 Android PDF 的 WebView 遮罩；实际产品使用原生 Activity。
- 第三轮受限构建进程无法连接 Gradle 本机守护进程；同源码在正常主机进程的新目录重建成功。
- 第四轮正确观察原生入口后捕获产品打开失败提示。
- 第五轮保留真实 UI 失败，再单独获取后端错误类别，不计为成功原生操作或性能结果。
- 独立 ELF 的执行权限拒绝，不用于证明产品命令根因。

七轮实际运行全部结束后，原包、UID、完整私有数据及系统 blur 均已恢复。独立读取每对本机恢复 TAR，216 条目的内容、链接和权限一致；数据内容不写入报告。APK、库、密钥、数据库和私有备份不入库。

修复后首轮探针误设文本PDF页数为1，且误要求原始位图背景不透明；修正时的一次Kotlin语法编译失败和后续扫描占位白页被当作非空内容失败均保留。最终探针检查文本PDF实际2页、透明位图在窗口合成后的文字/白底、原生两帧绘制和扫描占位白页的已知内容；生产修复APK未为探针问题再次修改。
