## 场景与判断

`--scenario lifecycle` 复用两个实际账户的创建、偏好保存与切换，然后检查：

- A：森林深色、增强玻璃、`#112233`、1 个公开对象；系统浅色时仍使用显式深色偏好。
- B：冷灰浅色、局部玻璃、`#ffee00`、0 个对象；系统切换到深色时仍使用显式浅色偏好。
- 每个账户执行真正的 `ActivityScenario.recreate()`；断言 Activity 与 WebView 都不是原实例，不接受只重读旧 DOM。若重建后锁定，通过生产密码界面解锁，不能直接注入会话。
- 重新检查身份、加密保存的五项外观偏好、对象数量、CSS 与画布底色、原生系统栏图标模式、实际原生 `Configuration.uiMode`、最终截图正文和操作文字像素。操作对比至少 4.5:1、可见且命中；增强画布不能覆盖正文，局部档位不能留有上一账户画布。

这不是进程冷启动：Android 进程 / Rust runtime 没有 force-stop 后重开。A 的系统浅色与原始系统浅色一致；实际前向主题变化发生于 B 的浅→深，驱动收尾再恢复深→浅。该场景证明显式账户偏好与系统冲突时的稳定性和真实 Activity/WebView 重建，不能冒称覆盖所有系统模式或进程重启矩阵。
