## 实际缺陷及修复

- 修复前真实状态栏高 63 个物理像素，而首页品牌从约 42px 开始，存在约 21px 重叠。`before-native` 保存实际失败及截图，不把初次失败算作通过。
- `AndroidSafeArea` 在业务 MainActivity 的 WebView 创建钩子中读取 systemBars / displayCutout 与实际窗口、WebView 边界，只交付尚未由系统排除的覆盖量。背景仍铺到窗口边缘；控件使用共享安全区变量，网页环境值与原生值取最大值，避免重复留白。
- 支持文档开始脚本的 WebView 在新文档加载前重新交付几何；脚本只写布局长度，限制主文档，不增加 JS 到原生桥、账户或网络能力。旧 WebView 有加载完成回退，但该分支未在本轮设备上验证。
- 320px 紧凑样式曾把安全区覆盖为固定 12px，现改为安全区与常规留白的最大值。844×390 的导航轨道收紧间距、保留完整触控区；更矮视口允许轨道滚动。
- 第一次修复包测试误采了业务隐藏且 inert 的“更多”菜单项。`first-supported` 保留失败；后续只排除明确隐藏项，不以屏外、不可命中或越界为理由排除控件，首页至少 8 个目标的要求保留。
- `second-supported` 取得旋转和登录帧，但解锁按钮下沿仍超过键盘约 2.6px。仅调留白不足以覆盖不同视口；最终认证布局在聚焦及视觉视口变化后将当前解锁区域整体带入视口，矮屏只收紧装饰留白，不缩小文字、图标或操作命中区。几何在生产 WebView 视觉提交后读取，避免用旋转或 IME 前的帧判断。

## 前端检查和失败历史

最终完整 Vitest 259 文件 / 2321 项、移动首页 / 登录 / 附件浏览器 28 项、Chromium 材质 / 顶栏 / 预览 33 项、触摸预览 16 项、Python 驱动 13 项均退出 0。类型检查包含在最终 Tauri 构建中；项目 Lint 仍只有原 syncStore:838 警告，格式与差异检查通过。新浏览器用例验证安全区长度消费、320 / 390px、844×390 轨道、400px 登录视口，以及三种照片预览按钮；这些模拟长度不作为原生缺口证明。

`browser-failure-context` 保留原 320px 留白覆盖、登录按钮越界、隐藏菜单误采、预览通知失败等日志。预览检查最初同时出现测试提醒和延迟自动备份提醒，容器中心落在两条提醒间的非交互间隙；增加短暂等待仍失败。测试现明确提供最近提醒时间以隔离自动提醒，继续由真实通知组件显示待测提醒，命中、占位、交接和缩放断言保持；两项目完整重跑通过。该浏览器场景是合成提醒，不能替代原生真实备份提醒证据。

`final-native-source` 与其 SHA256 清单冻结最终源文件；驱动拒绝测试基于实际通过报告构造越界、不可命中、缺 IME、丢历史和高度未恢复的负例。`first-supported-source` 的测试文件由后续源码撤回可见项过滤而重建，仅作失败定位参考，不声称是构建前冻结。历史账户、编辑键盘和通知验收仍对应各自 APK，不冒充本次重跑。
