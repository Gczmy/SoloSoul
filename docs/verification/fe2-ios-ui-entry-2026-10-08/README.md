## 结果与来源

- 独立 XcodeGen UI 测试项目不链接 SoloSoul，也不注入网页脚本或替换 IPC，通过 `XCUIApplication(bundleIdentifier:)` 操作已安装的生产 WKWebView。
- 使用上一阶段 iOS Debug 模拟器二进制 `b7c5ae8b372980d5de03b76f5e9c23e2362d28e5f38db8f94cde3b75fdd14749`，与此前 iOS 主题矩阵一致。未将其称为当前工作区新构建。
- `initial/` 构建退出0，原生测试1项失败、0跳过、执行退出65；欢迎页“下一步”实际可点击，随后测试错误等待“返回”。中文源文案实际是“上一步”。此结果是测试定位错误，不证明产品无法进入下一步。
- `corrected/` 构建退出0，原生测试 **1项通过、0失败、0跳过、执行退出0**。真实点击“下一步”，出现“上一步”；截图与可访问性层级已核对，当前为“创建第一个对象”引导页，未声称执行存储目录选择、账户创建或解锁。
- 两组各完整备份并逐项比较恢复99项测试应用目录 / 文件内容 / 链接 / 权限，包括根目录权限。初始系统外观恢复并复读确认，模拟器均恢复Shutdown，新增探针Host与Runner卸载。私有备份仅在本机 `/tmp`，没有复制进仓库。

## 下一步与限制

已有无账户主题矩阵不证明完整账户界面。本次原生 UI 入口为后续使用当前源码构建包验证账户创建、解锁、首页及预览提供可执行路径，不能关闭这些任务。

当前 `status_bar_plugin.rs` 在 iOS 上实际忽略样式命令；`theme.ts` 只将已解析模式传入这一命令。Tauri2.11.2窗口 `set_theme` 明确不支持iOS。需在完整页面上验证原生状态栏与应用固定主题、跟随系统及预览主题的关系，再选择原生适配；不能直接覆盖 UIKit 外观后破坏 WKWebView 系统主题事件。

公开目录保留两次原始 XCTest 日志、构建日志、恢复回执、测试结果摘要、实际截图、层级和执行代码。原 xcresult 包留在各次 `/tmp` 目录，已导出附件。完整重构仍为8完成、6待验证，macOS完整窗口验收仍需手动解锁；此入口不证明iOS Liquid Glass、完整账户界面、系统栏通过或实体设备性能。
