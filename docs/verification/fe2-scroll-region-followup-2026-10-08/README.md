## 根因和修复

- 旧实现只选一个最近的容器。横向子区域会抢走仍能接收纵向滚轮的正文高亮。现在分别寻找横/纵有效容器，滑块也按方向着色。
- 旧方向键处理无条件使用document.activeElement；正文残留焦点会覆盖当前侧栏指针区域。现在只有Tab明确进入键盘导航，或尚无指针位置时，才按焦点判定。
- 补上失焦恢复后保留指针坐标、滚轮、滚动、样式/隐藏属性、资源加载和尺寸变化时的重新判定。遮罩/对话框继续阻止命中后方正文；单行输入和原生选择器不抢占页面滚动条。
- 直接悬停/拖动原生滑块的CSS反馈独立可用，原生伪元素不必有单独DOM节点。

## 证据

修复前独立生产hook夹具8项中4项失败：横向子区与键盘焦点错位各在Chromium/WebKit复现。普通登录页持续异步重绘曾掩盖状态更新遗漏，所以改为独立hook夹具，不以此替代真实App整体验证。

最终30项通过：16项定向滚动回归，加原有14项对象/登录/历史键盘整体验证。定向范围涵盖真实滚轮使正文滚动、侧栏、横向子区、textarea、遮罩、窗口focus/blur事件、样式改变后新增可滚动内容、直接滑块悬停、Tab/Option+Tab键盘导航和实际绘制。TypeScript、hook ESLint、格式及diff检查通过。

截图像素验证6组全部通过：两引擎中正文横纵均有效时均为RGB17；移到横向子区后正文纵向保持RGB17、正文横向变为RGB198；直接悬停水平滑块恢复RGB17。采样为固定合成几何场景，深色由整体回归及当前截图补充。

初次像素采样误把Chromium启动参数默认隐藏的滑块当白色；最终移除测试进程的--hide-scrollbars。WebKit的locator.hover会尝试把滑块坐标滚入内容，改用直接窗口坐标。失败记录保留，区别于产品缺陷。WebKit默认Tab跳过按钮，测试使用macOS Option+Tab，不修改系统键盘设置。
