选择器返回后的暗色文本预览，DOM声明返回按钮与标题为 RGB(221,216,200)、顶栏为 RGB(42,38,32)，但实际帧主要前景为 RGB(205,200,185)、底色为 RGB(39,35,30)。既有误差8以内、至少6个标题/图标像素的严格判据未通过。实际文本和按钮可见，不将颜色差异描述为已经确认的内容消失或闪黑。

同一客户端包的直接附件夹具对照已通过暗色文本、图片预览颜色检查，但在后续相册截图时原8秒备份提醒自然到期，整组失败。该对照没有走系统选择器，不作为真实导入通过组。

临时诊断保留检查时的原始系统帧、只读DOM祖先与命中、原生视图祖先、窗口状态及WebView自身Canvas绘制。可逆比较后恢复原值：

- 连续后续帧仍存在相同RGB差异。
- 关闭父级及预览自身的模糊，没有改变该差异。
- 预览移到body再恢复原父节点和位置，没有改变该差异。
- 关闭WebView自动深色处理及View的Force Dark，没有改变该差异；最终助手复读设置值确实从AUTO(1)变为OFF(0)，之后恢复。
- 临时补充 `color-scheme` meta及改为软件绘制，没有改变该差异，meta与原layer type均恢复。
- WebView自身绘制也包含该差异；原生窗口表面和视图祖先alpha为1，IME已隐藏、窗口已聚焦。

这些是在当次旧WebView、模拟器和公开测试账户内的诊断结果，不足以断定所有设备或所有缓存状态的根因。干预帧不计产品通过；原始帧及像素门槛始终保持。未据未经证实的假设修改主题、玻璃、Portal或绘制模式，未通过提高文字亮度或降低门槛掩盖问题。后续需继续定位真实选择器返回后的WebView绘制状态，再做API31完整浅深预览与fallback验收。
