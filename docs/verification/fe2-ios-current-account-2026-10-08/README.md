## 保留的失败与修正

- `initial-container/`：助手构建退出0；生产包安装后系统迁移数据容器，驱动错误要求原目录不变，UI未开始。恢复操作指向已不存在的旧目录，原驱动明确报告未恢复；后续实际新目录99项与原备份完全相同，`container-relocation-audit.json` 保留独立核对，不改写原失败。
- `relocation-query/`：重启后simctl返回已不存在的旧 app/data 路径，驱动在读取Info.plist时失败，尚未备份或进入UI。外观、助手清理和停机操作成功，未改动账户数据。此处只记录观察到的旧路径，不断言其系统原因。
- `registration-fixed/`：正常simctl install重新注册当前包，首次实际UI已完成创建、首页及锁定；测试用“主密码”查找登录输入框，但实际可访问名称为“输入密码”，1失败、0跳过、退出65，完整恢复成功。此轮使用 `relocation-query/` 已编译助手，Host/Tests/project来源逐项相同，不冒称第三次重编译。
- 最终仅修正测试输入框名称并增加实际“解锁”表单断言，仍要求完整首次密码提交成功。重新编译助手并按原创建/锁定/解锁流程执行，未修改产品源代码以通过测试。前三轮日志、回执和失败截图保留；UI失败的57个附件与最终10个附件各自保持原来源。
