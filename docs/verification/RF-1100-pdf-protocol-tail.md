# RF-1100 PDF截图调用尾序修复

本项修复非默认性能校验器对当前SDK行程的误拒绝。原生PDF截图与关闭守卫完成后，行程还读取认证快照并验证主frame/loader；旧Node校验器未计入末尾的`Runtime.evaluate`、`Page.getFrameTree`。现在仍逐项比较完整尾序，包含这两个固定调用，不允许任意追加、丢弃或重排守卫。

## 验证结果

- 原始两档PDF组共五份原生成功证明被旧校验器拒绝；修改后的严格离线复核通过，并独立校验全部截图的字节数、SHA、PNG尺寸和固定文字区域。原组退出码均为1，旧100组的首页失败仍保留，没有改记为通过。
- 修复前红测8项中3项失败：完整证明误拒绝、缺少认证守卫误接受、暂态子frame后稳定截图误拒绝。修复后8项通过，七种遗漏/交换/重复/额外调用仍拒绝。
- 完整固定Node入口最终217项：216通过、0失败、1项既有符号链接权限skip。两次默认沙箱运行各有一个既有PowerShell子进程超时；与此前F检查一致的子进程权限下完整通过，测试和15秒预算均未改。失败日志保留；非配对重复运行不证明权限是超时原因。
- 同一EXE重新运行两档各三次完整原生组：5000组3/3、exit0；100组2/3、exit1。新100组失败停在首页，前后端登录尝试均为0、可信文本事件为0，虽然SDK记录了一次`Input.insertText`；尚未证明输入焦点、布局变化或应用认证的根因。
- EXE SHA为`b2f05a723d6af33cbd5ff6f6d307dffda734c7706ec4396083f966fa1010cdab`，103582208字节。旧临时包预检发现94资源中91份缺失，新组尚未启动即拒绝；独立新包从当前仓库复制全部94份并核验相同SHA，EXE字节保持。缺失原因未确定。原生Rust、React、依赖未改，不重复其已匹配检查。

## RF-312保留的独立失败

当前原始普通5000组sample002和PDF100组sample003，认证记录均显示`root-read`完成后`maintenance-admission`中断，未进入KDF。OCR模型安装源码没有该目录activity准入；更新源偏好会在网络等待期间保留activity，是下一步候选，但本次未辨认真实活跃worker，不能把候选当成已确认原因。新增无可信文本的首页超时另行归因。

临时认证审查器只支持普通行程的四种应用路径，对PDF结束后的`/settings/attachments`拒绝仅表明其审查范围不匹配；未放宽该契约，也不将这个拒绝归因到应用认证失败。实际PDF准入继续由原生和PDF专用校验器判断。

## 保全与边界

18个隔离实例全部终止后，fresh CIM重新检查170条PID/birth或辅助PID状态；只清理120个精确缓存目录和6个私有链接，缓存工具未终止额外进程。247份根级证明、204份Vault文件和18份日志副本前后逐字节核对，Vault不在删除清单。临时驱动的命令解析、Windows扩展路径比较和缺少保全清单等拒绝均记录，拒绝阶段未删除缓存。
