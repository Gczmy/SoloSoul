## 验证范围

浏览器测试只使用模拟 Tauri IPC 和合成账户/字段/插件数据，检查真实 CSS 布局、交互及主题。Android、iOS、macOS、Windows 的前端平台分支可在浏览器中覆盖；这不等于相应原生 WebView、GPU 合成或真机操作已验收。未连接 Android 真机，涉及首页玻璃的设备表现需在目标机复核。

## 逐项结果

### 1. 回收站受保护字段

`ValueContainer` 将按钮独立为 action 槽，值与按钮垂直居中；换行判断只读取文本高度，避免 48px 触控区触发整行展开。`ProtectedTrashValue` 共用于普通值、动态字段和回收站快照，关键字段仍须原有密码验证，不更改敏感度策略。历史查看器沿用不带 action 的布局。

类型检查、定向 ESLint、16 项既有字段保护/快照测试通过。首次 Vitest 有一个 fork worker 启动超时，6 项已执行用例通过；限定 `--dir src --pool=threads --maxWorkers=1` 后未完成的 10 项通过。Playwright 首次自动启动服务超时，改为直接启动本地 Vite 后继续布局矩阵，不将这些环境失败当作产品缺陷。

Vite 首次预构建结束后，Android、iOS、macOS、Windows 四个平台的实际文字/按钮中心偏差均小于 1px，短字段不再误判为多行；Android 触控区保持至少 48px。已检查 Android 和 Windows 截图。

### 2. 首页加强玻璃首帧

`AndroidLiquidArtwork` 在 `useLayoutEffect` 中初始化渲染器；渲染器用初始实际位置判断是否可见，并同步完成首绘后才切换到画布。后续仍按需重绘，保留离屏停绘、后台暂停和上下文恢复；没有开启 `preserveDrawingBuffer` 或常驻动画循环。

10 项生命周期单测及定向 ESLint 通过。浏览器深浅主题各连续返回首页三次，首个可见帧已就绪；上下文恢复/离屏/锁定和原生通知主题两个既有场景通过。首轮浏览器用例遇到依赖预构建期间的启动错误，服务就绪后重跑通过。真实 Android WebView/GPU 表现仍需目标机复核。

### 3. 登录卡片与 PIN 窄屏布局

登录卡片以共享变量统一正常解锁区域的 160px 最小高度，非登录 PIN 对话框保留原 152px 回退。密码视图删除空的外部错误槽，表单间距从 16px 缩至 8px，正常输入框至按钮的空白从约 72px 缩至 28px；真实错误仍显示并可撑开。PIN 六格改为响应式等宽网格，保留桌面最大格宽，避免窄屏挤出内边距。

9 项登录单测、类型、定向 ESLint 通过。Android 320/390px、iOS 390px、macOS/Windows 1100px 五组浏览器检查通过：三种正常方式整卡高度差不超过 2px，密码至按钮间距不超过 32px，PIN 不横溢。已检查 Android 窄屏 PIN 和密码截图。

### 4. 更新横幅与配对前景色

更新、重试、安装使用主题填色主操作；取消、跳过等接入次要操作，关闭保持图标操作。Android 为 48px 胶囊形触控区，桌面保留紧凑尺寸。新增普通/悬停两组强调色前景 token，Android 使用 Material 配对色，其他平台按最终色值选择可读的黑/白前景；细边界避免自定义纯白按钮融入横幅。共享 OCR 横幅同步修复。

浏览器自定义色验证发现：登录、系统主题重应用及外观页漏传 `customAccentHex`，未登录偏好缓存和 Rust DTO 也遗漏字段。已补齐参数、缓存、明文偏好读写及兼容旧 JSON 的默认值，没有增加新的设置入口。

原相关 62 项前端用例通过，补链路后另运行 settingsStore/hook/配色共 40 项（其中配色 12 项与前一组重复）；类型、定向 ESLint、Rust 单文件格式检查通过。直接抽取实际 `settings.rs` DTO 与原有三项测试，使用实际 serde 依赖编译执行，默认值、旧配置兼容和 camelCase 往返均通过；完整 Tauri Cargo 测试仍在重编依赖，不能将 DTO 契约检查当作完整原生测试。

Android/macOS/Windows 深浅主题及三组自定义色，共 9 组浏览器测试通过：更新/重试/安装的文字和图标对比至少 4.5，填色或边框对横幅至少 3，桌面悬停状态也满足检查。已检查 Android 与 Windows 代表截图。测试使用模拟更新事件，没有实际下载或安装。
