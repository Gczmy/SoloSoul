## 验证范围

浏览器测试只使用模拟 Tauri IPC 和合成账户/字段/插件数据，检查真实 CSS 布局、交互及主题。Android、iOS、macOS、Windows 的前端平台分支可在浏览器中覆盖；这不等于相应原生 WebView、GPU 合成或真机操作已验收。未连接 Android 真机，涉及首页玻璃的设备表现需在目标机复核。

## 逐项结果

### 1. 回收站受保护字段

`ValueContainer` 将按钮独立为 action 槽，值与按钮垂直居中；换行判断只读取文本高度，避免 48px 触控区触发整行展开。`ProtectedTrashValue` 共用于普通值、动态字段和回收站快照，关键字段仍须原有密码验证，不更改敏感度策略。历史查看器沿用不带 action 的布局。

类型检查、定向 ESLint、16 项既有字段保护/快照测试通过。首次 Vitest 有一个 fork worker 启动超时，6 项已执行用例通过；限定 `--dir src --pool=threads --maxWorkers=1` 后未完成的 10 项通过。Playwright 首次自动启动服务超时，改为直接启动本地 Vite 后继续布局矩阵，不将这些环境失败当作产品缺陷。

Vite 首次预构建结束后，Android、iOS、macOS、Windows 四个平台的实际文字/按钮中心偏差均小于 1px，短字段不再误判为多行；Android 触控区保持至少 48px。已检查 Android 和 Windows 截图。

### 2. 首页加强玻璃首帧

`AndroidLiquidArtwork` 在 `useLayoutEffect` 中初始化渲染器；渲染器用初始实际位置判断是否可见，并同步完成首绘后才切换到画布。后续仍按需重绘，保留离屏停绘、后台暂停和上下文恢复；没有开启 `preserveDrawingBuffer` 或常驻动画循环。

10 项生命周期单测及定向 ESLint 通过。浏览器深浅主题各连续返回首页三次，首个可见帧已就绪；上下文恢复/离屏/锁定和原生通知主题两个既有场景通过。首轮浏览器用例遇到依赖预构建期间的启动错误，服务就绪后重跑通过。真实 Android WebView/GPU 表现仍需目标机复核。

### 3. 登录卡片与 PIN 窄屏布局

登录卡片以共享变量统一正常解锁区域的 160px 最小高度，非登录 PIN 对话框保留原 152px 回退。密码视图删除空的外部错误槽，表单间距从 16px 缩至 8px，正常输入框至按钮的空白从约 72px 缩至 28px；真实错误仍显示并可撑开。PIN 六格改为响应式等宽网格，保留桌面最大格宽，避免窄屏挤出内边距。

9 项登录单测、类型、定向 ESLint 通过。Android 320/390px、iOS 390px、macOS/Windows 1100px 五组浏览器检查通过：三种正常方式整卡高度差不超过 2px，密码至按钮间距不超过 32px，PIN 不横溢。已检查 Android 窄屏 PIN 和密码截图。

### 4. 更新横幅与配对前景色

更新、重试、安装使用主题填色主操作；取消、跳过等接入次要操作，关闭保持图标操作。Android 为 48px 胶囊形触控区，桌面保留紧凑尺寸。新增普通/悬停两组强调色前景 token，Android 使用 Material 配对色，其他平台按最终色值选择可读的黑/白前景；细边界避免自定义纯白按钮融入横幅。共享 OCR 横幅同步修复。

浏览器自定义色验证发现：登录、系统主题重应用及外观页漏传 `customAccentHex`，未登录偏好缓存和 Rust DTO 也遗漏字段。已补齐参数、缓存、明文偏好读写及兼容旧 JSON 的默认值，没有增加新的设置入口。

原相关 62 项前端用例通过，补链路后另运行 settingsStore/hook/配色共 40 项（其中配色 12 项与前一组重复）；类型、定向 ESLint、Rust 单文件格式检查通过。直接抽取实际 `settings.rs` DTO 与原有三项测试，使用实际 serde 依赖编译执行，默认值、旧配置兼容和 camelCase 往返均通过。

完整 Tauri Rust 测试目标编译和链接成功。原始测试程序启动遇到本机 Windows 加载器错误 `0xc0000139`；仅对测试 exe 副本嵌入项目现有应用 manifest 后，真实 `commands::settings::tests::test_ui_preferences` 三项全部通过（其余 482 项过滤）。未修改工具链、原始测试产物或产品启动配置，临时副本与独立 DTO 验证程序均已清理。

Android/macOS/Windows 深浅主题及三组自定义色，共 9 组浏览器测试通过：更新/重试/安装的文字和图标对比至少 4.5，填色或边框对横幅至少 3，桌面悬停状态也满足检查。已检查 Android 与 Windows 代表截图。测试使用模拟更新事件，没有实际下载或安装。

### 5. 导出选择与共享按钮

文档格式、标签和云盘目标复用 `FilterChip`，提供 `aria-pressed` 及清晰的填色/边框选中态；Android 使用 48px 胶囊和 Material 容器配色，桌面保留平台圆角。标签文字使用高对比主题前景，避免桌面强调文字叠在浅色选中底上。格式切换仍保持单选，原有导出确认与权限流程不变。

导入导出动作统一使用共享 `Button`，主操作有明确强调色，取消使用次要按钮，风险继续操作使用 warning 变体；忙碌期间禁用重复点击。导出页导航选择也适配 Android，警告操作组允许窄屏换行，移除旧动作样式。按钮审查同时覆盖共享主/次/图标按钮、工具栏、筛选项、下拉选中项和徽标；下拉菜单、徽标与主题预览徽标不再固定白字。导航卡片、菜单行、开关保留各自的交互形态。

类型、定向 ESLint、TransferButton/Button/格式扩展名共 20 项单测通过。Android/iOS/macOS/Windows 深浅主题共 8 组浏览器测试通过：五种格式可切换且只有一个激活，文字对比至少 4.5，Android 选择控件不小于 48px，选项未溢出视口。桌面首轮检查发现选择态 CSS 优先级覆盖前景，修复后四组桌面复跑通过；已检查 Android 深色截图。

### 6. 回收站列表勾选框定位

Android/iOS 的列表勾选框、对象图标和元信息共用一个垂直居中的 header，操作按钮保留下一行。桌面原本居中，继续保留紧凑横向布局。长名称截断与多行元信息不会将勾选框挤到卡片顶部。

3 项卡片单测、类型及定向 ESLint 通过，Android/iOS/macOS/Windows 四组浏览器检查的图标/勾选框中心偏差小于 1px，点击勾选框不会打开详情。已查看 Android 截图。

### 7. 平台勾选框与原生交互

共享勾选框改用原生 input 接收标签点击、Space、禁用和混合状态；显示区域与命中区域分开，Android 为 20px 标记/48px 目标，iOS 为 20px/44px，桌面保留紧凑尺寸。勾选标记使用配对前景，支持 focus-visible、forced-colors 和减少动画偏好。

逐一核查调用点，显式提供选择回调并阻止勾选事件冒泡到父行/卡片；Space/Enter 不会触发父卡片打开。水印设置两处父 label 的点击回调迁至 input，避免文本点击重复切换。补充无文本标签控件的名称，调整附件行最小高度和说明文字缩进。外观、模板和云同步中的普通 checkbox 统一迁移；SecuritySettingsPage 两处自绘开关和 ToggleSwitch 仍作为开关保留。

39 项相关单测、类型及定向 ESLint 通过。四平台深浅主题共 8 组浏览器测试通过：命中区边缘可选择，视觉尺寸正确，勾选对比至少 4.5，Space 可来回切换且不会打开详情，焦点轮廓可见。回收站补充名称及明确 onChange 后定向复跑通过。另两项既有 Android 外观测试通过，覆盖偏好重载、锁定、减少动画与高对比玻璃回退。
