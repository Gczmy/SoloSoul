# 对象级文档导出（Word/docx）功能设计与实现方案

> 状态：已实现（2026-08-10 落地，实现偏差见 §7）
> 日期：2026-08-10

## 1. 需求背景

将对象（Object）的内容导出为 Word 等可读格式，便于打印、归档、分享。支持**选择多个对象以多页形式导出为一个文档**（每个对象占一页）。

### 用户已确认的决策

| 决策点 | 结论 |
|--------|------|
| 导出格式 | **本期仅 docx，但预留格式选择入口与 UI**：格式选择器本期只有 Word(docx) 可选，PDF/HTML 以「即将支持」禁用态占位；IPC 契约带 `format` 参数，二期加格式时前端 UI 与命令签名不变 |
| 附件处理 | **附件清单附录**：每个对象文末列出附件名/大小/类型，文件不嵌入 |
| 敏感字段 | **确认后全量明文 + 分级确认**（规则见 §3.1 第 4 步） |
| 本次交付 | 仅设计文档，实现另行安排 |

## 2. 现状调研

### 2.1 可复用资产（已核实锚点）

- **多选 UI**：`tauri/src/components/transfer/ObjectSelectionTree.tsx`——页面→对象→附件三级勾选树，含全选/级联；驱动模式见 `tauri/src/components/export/ExportSection.tsx:130-147`（`selectedPageIds/selectedObjectIds/expandedPages/expandedObjects` + `onTogglePage/onToggleObject` 回调）。
- **范围数据**：`export_get_scope_tree`（`tauri/src-tauri/src/commands/export_import/export.rs:5-`）已返回按 section_type 分组的页面→对象树。
- **对象内容**：`object_get` IPC（`tauri/src-tauri/src/commands/object/mod.rs:581-601`，AES-GCM 解密在 `spawn_blocking` 内）→ `ObjectData`（`tauri/src/stores/objectStore.ts:40-61`：`id/name/typeId/properties/sensitivityLevel/templateId/createdAt/updatedAt/tags/propertyLabels`）。
- **字段拍平**：`flattenProperties`（`tauri/src/components/object/objectDetailUtils.ts:18`）把 properties 拍平为 `{key,label,value,fieldId}` 列表，`ObjectDetailFieldsList.tsx` 同款渲染顺序。13 种 PropertyType（`tauri/src/types/template.ts:6-19`），字段内容为**纯文本**（multiline 为长字符串，无富文本/Markdown），排版简单。
- **properties 特殊键**：`__fields`（对象内嵌字段定义）、`__deprecatedFields`、`__attachments`（附件元数据）——不当普通字段导出。
- **保存管道**：桌面 `saveWithPause`（`tauri/src/lib/dialog.ts:22-32`，AGENTS.md 强制封装，自动暂停自动锁定）；Android content:// 走 `prepareStagedDownloadPath` / `copyStagedFileToDest`（`tauri/src/lib/mobileFileTransfer.ts:74-101`），`tauri/src/pages/settings/ExportImportPage.tsx:300-327` 是该模式在导出场景的完整示范。
- **docx 生成底座**：docx 本质是 ZIP + OOXML，`zip 2.2` 已在 `tauri/src-tauri/Cargo.toml:59`，零新依赖即可生成；全平台（含 Android）兼容。
- **既有安全决策**：`docs/design_map/16_导入导出功能设计.md:186-206`「明文导出（未来）」已有审批决策（2026-06-05）——三重确认 + `chmod 600`。本功能是该决策的首个落地场景。
- **密码验证对话框**：统一使用 `tauri/src/components/forms/PasswordVerificationDialog.tsx`（AGENTS.md 约定，禁止复制对话框代码）。

### 2.2 技术路径评估（为何选 Rust 生成 docx）

| 路径 | 评估 |
|------|------|
| **Rust 生成 docx（选中）** | `zip` 已备，手写 WordprocessingML 即可；纯文本字段排版 OOXML 需求简单；全平台兼容；保存管道现成 |
| Rust 生成 PDF | 无现成库；printpdf 纯 Rust 但中文需内嵌 CJK TTF（打包体积大）；typst 质量高但依赖与编译成本大。**列二期** |
| 前端 HTML 打印转 PDF | 项目无 `window.print` 用法；Tauri/Android WebView 打印支持不可靠；需新增 jspdf/html2canvas 类依赖。匹配度最低 |
| 前端 `docx` npm 包 | 需新增前端依赖，产物落盘仍要走 Rust，相比 Rust 直接生成无优势 |

## 3. 设计方案

### 3.1 交互流程

1. **入口**：导出/导入页（`ExportImportPage`）新增「导出为文档」区块（或独立 Tab），复用 `ObjectSelectionTree` 勾选对象（页面级全选级联到对象）。
2. **格式选择器**（为二期预留）：下拉/分段控件列出 Word(docx)（可用）、PDF（禁用，标注「即将支持」）、HTML（禁用，标注「即将支持」）；默认选中 docx。保存对话框扩展名与默认文件名随格式变化（本期恒为 `.docx`，`SoloSoul_导出_YYYYMMDD_HHmm.docx`）。
3. 选择保存路径（`saveWithPause`）。
4. **第一重确认**：风险警告对话框（明文导出警示：文档将以未加密形式保存，任何能打开该文件的人都可读）。
5. **敏感度分级第二重（二者只出现一个）**：先调预检 IPC `export_document_preflight(object_ids)` 返回所选对象字段的最高敏感度（Rust 侧依据模板 `TemplateProperty.sensitivityLevel` 判定，含对象内嵌 `__fields`）：
   - 含 `critical` 字段 → 弹 `PasswordVerificationDialog` 主密码解锁框（**不再弹二次确认框**，即使同时含 sensitive）；
   - 含 `sensitive`（无 critical）→ 弹二次确认框（无需密码）；
   - 仅 public/internal → 无额外确认。
6. 调 `export_objects_document`（`format: "docx"`）→ Rust 生成 docx 落盘（`chmod 600`）→ **第三重：写审计日志**。
7. Android：保存目标为 content:// 时走 stage 中转（复用现有模式）。

### 3.2 docx 生成（Rust，建议新模块 `commands/export_import/export_docx.rs`）

最小 OOXML 包结构（`zip` crate 写入）：

```
[Content_Types].xml
_rels/.rels
word/document.xml
word/styles.xml        （可选最小样式集）
```

文档结构（**多对象 = 多页**）：

1. 封面/标题段：应用名、导出时间、对象总数。
2. 每个对象：
   - 分页符 `<w:br w:type="page"/>`（首个对象前不加）；
   - 对象名（Heading 1）；
   - 元信息段：模板名、创建时间、更新时间、标签；
   - 字段表格（两列：字段标签 / 值），字段顺序与 `flattenProperties` 拍平顺序一致；字段标签取 `propertyLabels` / 模板定义；
   - 附件清单小节：名称 / 大小 / 类型列表（无附件则省略）。

实现要点：

- **XML 转义**：`& < > " '` 必须转义；值中 OOXML 不允许的控制字符（`<0x20` 除 \t\n\r）过滤。
- 特殊键 `__fields` / `__attachments` / `__deprecatedFields` 不作为普通字段导出。
- 多选顺序 = 勾选树中页面→对象的展示顺序（前端传 `object_ids` 时即按此顺序）。
- 敏感字段值全量明文写入（用户确认后），文档内不做掩码标注。

### 3.3 IPC 契约（按多格式预留设计，二期加 PDF/HTML 时签名不变）

```rust
export_document_preflight(object_ids: Vec<String>)
    -> Result<{ maxSensitivity: "none" | "sensitive" | "critical" }, String>

export_objects_document(object_ids: Vec<String>, save_path: String, format: String)
    -> Result<{ objectCount: u32, fileSizeBytes: u64 }, String>
```

- `format` 本期仅接受 `"docx"`，其他值返回 "not supported yet"（二期在 Rust 端加分支即可）。
- 校验 Vault 已解锁；逐对象 `load_object` 解密（`spawn_blocking`，同 `object_get`）。
- 写文件用「临时文件 + rename」避免半截文件；Unix 设权限 `0600`。
- 审计日志操作类型 `export_document`，记录格式与对象数，**不记录字段内容**（脱敏规范）。
- 两个命令在 `tauri/src-tauri/src/lib.rs` invoke_handler + ACL 列表注册。

## 5. 测试方案

- **Rust 单测**：
  - docx 包结构：zip 可读、含 `[Content_Types].xml`/`word/document.xml`；
  - `document.xml` 含对象名、字段标签与值、附件清单条目；
  - XML 转义（含 `&<>` 的字段值）；控制字符过滤；
  - 分页符数量 = 对象数 − 1；多对象顺序保持；
  - 空 `object_ids` 报错；`format = "pdf"` 返回 not supported；
  - preflight：含 critical → `critical`；仅 sensitive → `sensitive`；全 public/internal → `none`。
- **前端测试**：选择/确认流程（含 critical 只弹密码框、仅 sensitive 只弹二次确认框的分支断言）。
- **验证命令**：`cd tauri && npm run check-all`。
- **人工验证**：docx 产物用 Word / WPS / 手机 Office 打开验证排版与中文显示。

## 6. 明确不做的范围

- PDF / HTML 的**导出实现**（格式选择器 UI 与 IPC `format` 参数本期预留，禁用态展示「即将支持」；PDF 二期需评估 printpdf/typst + CJK 字体内嵌）。
- 图片/附件文件嵌入文档正文。
- Markdown 渲染排版（字段按纯文本导出）。
- 导出模板自定义（页眉页脚/字体/样式设置）。
- CLI（`solosoul_cli`）侧文档导出。

## 7. 实现记录与偏差

> 2026-08-10 实现落地。除以下偏差外均按本设计执行，验证：`cargo check --tests` 通过（本机 `cargo test` 因预先存在的 0xc0000139 DLL 加载问题无法启动，CI 在 ubuntu 运行）、`tsc`/`eslint` 通过、`vitest` 全量通过（69 文件 604 用例）、ACL 一致性 194 命令。

1. **入口采用独立 Tab 而非区块**：设计 §3.1 第 1 步允许「区块或独立 Tab」，实现选择了独立 Tab——`ExportImportTabBar` 新增 `document` tab（`settings:export_as_document`，FileText 图标），与加密导出（export）区分清晰。
2. **敏感度判定补充 `property_labels` 来源**（评审 P221）：设计 §3.1 称「依据模板 `TemplateProperty.sensitivityLevel` 判定，含对象内嵌 `__fields`」。评审发现对象创建时 `inherit_property_fields` 注入的 `__fields` **不含** `sensitivityLevel`（仅模板同步路径写入），新建对象的敏感度权威来源是 `property_labels`——若不纳入，敏感字段会被静默明文导出。`object_max_sensitivity` 现按 ①`property_labels` → ②`__fields` → ③模板 三级合并取最高。
3. **preflight 与写盘整体移入 `spawn_blocking`**：设计 §3.3 要求逐对象解密走 `spawn_blocking`。preflight 的对象加载+判定、export_objects_document 的加载+生成+写盘（临时文件+rename+chmod 600）均整体移入阻塞任务；`vault` 为 `Arc`，闭包内 clone、闭包外保留供审计日志使用。
4. **保存路径扩展名规范化**：`resolve_docx_path` 统一追加 `.docx` 后缀（复用 `validate_export_dest` 白名单校验，已提升为 `pub(crate)`）。
5. **前端 `togglePage` 避免嵌套 updater**（评审 P221）：页面/对象两组集合一起变更，基于当前闭包快照独立计算后再分别 `setState`，避免 StrictMode 双调用下级联状态重复切换。
6. **docx 生成细节**：最小 OOXML 包 `[Content_Types].xml` / `_rels/.rels` / `word/document.xml` / `word/styles.xml`（Heading1/Heading2/Normal）；封面段含应用名+导出时间+对象数；字段表格两列；附件清单「名称（大小，类型）」；XML 转义 `&<>"'` + 控制字符（<0x20 除 \t\n\r）过滤；分页符数 = 对象数 − 1。
7. **审计日志脱敏**：`export_document` 仅记录 `format=docx objects=N`，不含字段内容与对象名（与 `export_execute` 既有规范一致）。
