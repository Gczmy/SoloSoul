# 附件「照片集」相册功能设计与实现方案

> 状态：待开发（存放于 `docs/next_dev/`，实现完成后按实际情况更新或迁入正式文档）
> 日期：2026-08-10

## 1. 需求背景

移动端查看附件照片时，当前只能逐张「点开预览 → 关闭返回 → 再点下一张」，多张照片浏览体验割裂。需要相册式体验：

**一个照片集入口**：点进照片集后出现所有照片的预览网格 → 点击预览图进入全屏显示（左上角返回按钮，点击返回网格）→ 全屏时左右滑动切换上一张/下一张。

### 用户已确认的决策

| 决策点 | 结论 |
|--------|------|
| 照片集入口位置 | **两个入口**：对象详情页（该对象的照片集）+ 全局附件管理器（全 Vault 照片集，或按对象分组） |
| 网格布局 | **移动端固定 4 列**；**桌面端自适应列数**铺满可用宽度（`auto-fill + minmax` 响应式网格） |
| 全屏滑动切换 | 支持（左右滑动切上一张/下一张） |
| 大图/缩略图方案 | **Rust 端生成预览图**（解码 → 缩放 → 重编码 → data URL） |
| 本次交付 | 仅调研设计文档，实现另行安排 |

## 2. 现状调研

### 2.1 预览组件（桌面/移动共用一套）

`tauri/src/components/attachment/AttachmentPreviewOverlay.tsx`（443 行，全内联 style）：

- 图片/PDF 经 IPC `fs_read_file_as_data_url`（`tauri/src-tauri/src/commands/fs.rs:258-293`）整文件读入内存 → base64 → 拼 `data:{mime};base64,...` 直接塞进 `<img src>`。**10 MiB 上限**（`fs.rs:13` `MAX_DATA_URL_SIZE`），超限直接报错——手机原图普遍超限。
- 安全约束：只用 `item.vaultPath`；空路径或 `content://`/`file://` URI 直接报错（:24-26, :82-87）；PDF data URL 有 `data:application/pdf` 前缀守卫（:95-98）。
- **无触摸手势**：无 swipe、无 pinch zoom、无双击放大；缩放仅工具栏按钮（:373-440）与 Ctrl/Cmd+滚轮（:153-160），scale 范围 0.1–5。
- `useEffect([item])`（:52-112）在 item 切换时自动重置 scale/loading/error，天然支持「换 item 重新加载」，但**无竞态保护**（快速切换时慢 IPC resolve 会覆盖新 item 的结果）。
- 打开时 `syncStatusBarStyle('dark')`，关闭恢复主题状态栏（:62-68）。移动端 PDF 强制降级为系统应用打开（:73 + 调用方守卫）。

### 2.2 数据流：集合数据现成可得

两个预览入口目前都只传**单个 item**，但调用方手里已有完整列表：

- 对象详情：`AttachmentViewer.tsx:545`，`items` / `displayItems`（`attachment_list` IPC）即天然照片集。
- 全局附件管理器：`GlobalAttachmentManager.tsx:236`，数据为树形 `displayPages → objects → attachments`，可按 `item.objectId`（`attachmentManagerTypes.ts:5`）分组组装。

图片判定唯一入口 `previewItemByMime()`（`tauri/src/lib/attachmentUtils.ts:77-88`）：`mimeType.startsWith('image/')` 或扩展名 ∈ {png, jpg, jpeg, gif, webp, svg} → `'image'`。筛照片集时 `previewItemByMime(item) === 'image'` 即可。

### 2.3 手势/动画基础设施

- framer-motion `^12.40.0`（package.json:37）已在依赖中，19 个文件在用，但**全是 opacity/transform 过渡 + AnimatePresence 进出场，无 `drag` / 滑动手势先例**。需从零引入 `drag="x"` + `onDragEnd` 翻页判定模式。
- 现成触摸基础设施仅 `useLongPress.ts`（长按）。
- **全局样式坑**：`tauri/src/styles/global.css:260` 在 `html, body` 设 `touch-action: manipulation`（注释明写"移动端禁止双指缩放"）——做 pinch zoom 必须在 overlay 容器覆写 `touch-action`。

### 2.4 其他

- 附件列表项**无缩略图**（`AttachmentListItem.tsx:36-38` 仅显示 `Image` 图标），照片网格是全新 UI。
- i18n：预览文案在 `tauri/src/locales/{zh-CN,en-US}/common.json:90-96`（namespace `common`）。
- 测试：`AttachmentPreviewOverlay.test.tsx`（113 行，mock `fs_read_file_as_data_url` 契约），改造需同步。
- Rust 侧 `image = "0.25"` 已是 workspace 依赖（`tauri/Cargo.toml:57`，solosoul-core OCR 在用）；src-tauri 尚未直接依赖，需加 `image = { workspace = true }`。

## 3. 设计方案

### 3.1 Rust 缩略图/预览图命令（核心后端增量）

新命令（`tauri/src-tauri/src/commands/fs.rs`）：

```rust
#[tauri::command]
pub async fn fs_read_image_preview<R: tauri::Runtime>(
    app: tauri::AppHandle<R>,
    path: String,
    max_dim: u32,
) -> Result<String, String>
```

- 复用 `resolve_allowed_path` 路径白名单；`image` crate 解码 → 任一维度超过 `max_dim` 按最长边等比缩放 → 重编码 JPEG（质量 ~80）→ base64 → `data:image/jpeg;base64,...`。
- 解码在 `tokio::task::spawn_blocking` 中进行，避免阻塞运行时。
- 两级尺寸约定（由前端传入）：
  - **网格缩略图** `max_dim ≈ 256`：每张缩略图仅几十 KB，支撑网格一次渲染几十张。
  - **全屏预览** `max_dim ≈ 1600`：仅当原图超限时缩放；小图可直接走原图 `fs_read_file_as_data_url`。
- **内存动机**：现有方案每张图是整文件 base64 字符串（比原文件大 ~33%）驻留 JS 堆且无法像 blob URL 那样释放；网格场景直接爆内存。缩略图路径是唯一可行解。
- 解码失败（含 HEIC——`image` crate 不支持）→ 返回错误，前端降级占位图。

### 3.2 照片集网格（新组件 `PhotoAlbumGrid`）

- **布局分平台**：
  - 移动端：固定 4 列 `grid-template-columns: repeat(4, 1fr)`。
  - 桌面端：`repeat(auto-fill, minmax(160px, 1fr))` 自适应列数，缩略图保持合适大小铺满可用宽度。
- 网格项统一 `aspect-ratio: 1/1` + `object-fit: cover`；间距/圆角沿用现有视觉规范。
- 数据源：调用方传入 `items.filter(previewItemByMime(item) === 'image')`；对象详情页传该对象列表，全局页传全部（或按对象分组渲染组头）。
- **懒加载**：缩略图按需 IPC 加载（`IntersectionObserver` 或简单分批），内存中仅保留可视区附近缩略图；加载失败显示占位块（`Image` 图标）。
- **入口 UI**：
  - 对象详情附件区加「照片集」入口按钮/卡片（仅当该对象含照片时显示）。
  - 全局附件管理器加同语义入口。
  - 进入方式可以是全屏相册页（移动端推荐）或页面内切换视图（桌面可接受），实现时按现有 overlay/页面模式取其一。

### 3.3 全屏查看器（扩展 `AttachmentPreviewOverlay` 或新 `PhotoViewerOverlay`）

- 左上角返回按钮（lucide `ArrowLeft`）返回网格；顶部显示计数「{current}/{total}」（新 i18n 键）。
- **左右滑动切换**：framer-motion `drag="x"` + `dragConstraints` + `onDragEnd` 阈值判定翻页，`AnimatePresence` + `custom` 做方向性滑动动画；桌面端补左右方向键监听。
- 仅 **scale ≤ 1（未放大）** 时响应横向 swipe——放大后容器 `overflow: auto`（:356）滚动优先，避免手势冲突。
- **加载策略**：仅缓存当前 ±1 张；index 入 effect 依赖 + stale 标记丢弃过期 resolve，修复现有竞态问题。
- 保持 `syncStatusBarStyle('dark')` 打开/恢复逻辑；保留现有缩放按钮。
- 复用现有「点背景关闭」在桌面端；移动端以左上角返回为主。

## 5. 潜在坑与对策

| 坑 | 对策 |
|----|------|
| 10 MiB data URL 上限，手机原图普遍超限 | Rust 端 `fs_read_image_preview` 缩放后返回（本方案核心） |
| 网格几十张整图 base64 驻留 JS 堆爆内存 | 缩略图 max_dim≈256（每张几十 KB）+ 懒加载仅保留可视区附近 |
| `global.css:260` 全局 `touch-action: manipulation` 禁双指缩放 | 本期不做 pinch zoom；后续做时在 overlay 容器覆写 `touch-action` |
| 横向 swipe 与放大后容器滚动抢手势 | 仅 scale ≤ 1 时响应 swipe |
| 快速连续滑动时慢 IPC resolve 覆盖新图（现有竞态） | index 入 effect 依赖 + stale 丢弃；仅缓存 ±1 张 |
| 点背景关闭在移动端误触 | 移动端以左上角返回按钮为主 |
| HEIC 无法被 `image` crate 解码 | 网格显示占位块；全屏降级「使用系统应用打开」 |
| Android 状态栏样式 | 保持现有 `syncStatusBarStyle` 打开/恢复逻辑 |
| 缩略图每次进入相册重复解码 | 首版内存缓存（Map<attachmentId, dataUrl>）；磁盘缓存列为后续优化 |

- **Rust**：`fs_read_image_preview` 单测——生成测试图（image crate 编码 PNG/JPEG 到临时目录）→ 验证缩放尺寸、输出 data URL 前缀、路径白名单拒绝、超限文件处理、非法图片报错。
- **前端**：
  - `AttachmentPreviewOverlay.test.tsx` 同步新 props/行为；
  - `PhotoAlbumGrid` 测试——image 过滤、点击回调、懒加载触发、失败占位；
  - 全屏查看器测试——onNavigate 翻页、计数渲染、stale 竞态丢弃。
- **验证命令**：`cd tauri && npm run check-all`（tsc + lint + vitest + cargo fmt/clippy/test）。
- **Android 实机**：手势与相册体验需实机验证，随下一次 debug 构建人工确认。

## 7. 明确不做的范围

- 视频/音频相册（`video/*` 仍走「系统应用打开」）。
- pinch 双指缩放、双击放大（列为后续可选增强）。
- HEIC 解码。
- iOS 专项适配。
- 缩略图磁盘缓存（首版仅内存缓存）。
- 照片集内的批量操作（删除/转发选择模式，后续可叠加）。
