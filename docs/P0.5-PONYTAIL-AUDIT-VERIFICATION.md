## 5. 新发现的问题与已修复的回归

### 5.1 已修复的回归（本次验证中由我修复）

#### A. `Dialog.tsx` 条件调用 React Hooks（由 P0-3c 重构引入）

**问题**：原重构将 `if (!isOpen) return null;` 放在两个 `useEffect` 之前，违反 React Hooks 调用顺序规则，会导致组件状态异常。

**修复**：将 `if (!isOpen) return null;` 移到所有 Hooks 之后。

**文件**：`tauri/src/components/ui/Dialog.tsx`

#### B. `PluginBadge.tsx` 条件调用 React Hooks（近期 UI 改动引入，非 audit 项）

**问题**：`if (!contractTypeId) return null;` 在 `usePluginStore` 之前，同样违反 Hooks 规则。

**修复**：将 `usePluginStore` 调用提前到 early return 之前。

**文件**：`tauri/src/components/template/PluginBadge.tsx`

## 6. 潜在风险

1. **原生 `Dialog` 的关闭行为**：当前实现依赖 `close` 事件回调触发 `onClose()`。若父组件在关闭动画/状态更新期间卸载，需确保无重复 `close` 调用。当前代码已通过 cleanup 移除监听器，风险较低。
2. **`ExpandableSection` 的 `actions` 点击拦截**：使用 `e.target.closest('[data-actions]')` 判断，若动作按钮本身有嵌套子元素，事件目标可能不是按钮，存在极小概率的误拦截。可考虑在按钮上统一 `data-action` 标记并检查祖先。
3. **`SelectCheckbox` 未替换**：继续维护自定义组件增加负担，且可访问性（a11y）不如原生 checkbox。建议后续替换。
4. **前端 lint 未清**：PR check 会失败，无法合并。
