# RF-312：UI 交换协议的两项候选验证

本文记录两项未接入的旧候选，其阶段来源为 `15a453120` 对应的 92 份来源及 174 项验证。后续显式 Java 传输的时钟、拒绝及接入结果见[Observer UID 文件传输](RF-312-owned-ui-transport.md)；RF-312 完整采集对照仍未通过。

## 合并发布前检查

尝试将请求、回复、临时文件与错误标志的四次检查合并到一个 Observer UID 子进程，保持原检查顺序、交换及稳定读取流程。180 项相关测试在正常宿主通过；首轮沙箱内 Git shell 启动返回 `0xc0000142`，十项错误及原日志保留，重跑前源码未变。

全新 API31／x86_64、2 CPU／2048 MiB、SwiftShader AVD，仅安装公开 Observer，按旧→新→新→旧执行四组各 12 次 Launcher 只读快照。48 份响应、62 份完整状态证明和 76 帧均独立回放，Observer PID 稳定。两个版本各五项陈旧请求／回复／临时文件／错误标志／检查顺序拒绝测试通过；全部六个控制通道及 Observer 正常清理，设置一致、SDK 正常退出、严格宿主后验归零。

| 指标 | 原协议 | 合并检查候选 |
| --- | --- | --- |
| 快照数 | 24 | 24 |
| 中位耗时 | 226.5 ms | 234.0 ms |
| 累计耗时 | 5.751 s | 5.279 s |

累计时间较小但总体中位数没有改善，组间波动明显，不能据此确认稳定收益。候选与六项新增测试撤回到本地归档；已用归档的 92 份来源重放全部原生证据，并核对其与 180 项测试来源一致。生产源码恢复原样，不将该试验当作已接入修复。

## 在 Observer UID 下常驻

第二个全新 AVD 试验让 UI 文件命令在已核验的 Observer UID 内常驻，原 `exchange` 与 `stable_read` 函数保持原字节，系统状态仍用原 SDK。仅允许固定 UI 文件操作，保留 45 秒原生交换上限与宿主总限。Android 原生 `sh -n` 检查通过；七项生命周期、UID／命名空间、脚本身份、到期拒绝、异常恢复及保留临时目录测试通过。首次测试中的 Python 绑定方法对象身份断言有误，修正测试后全量七项通过，原绑定源码未变，两个结果分别保留。

旧协议完成 12 次快照后，候选第一次交换（第 13 个请求）返回 65，完整 stderr 明确为 `/proc/uptime: Permission denied`。其余候选组及负向用例未执行，没有删除计时检查或重发该请求。19 个完整控制帧、15 份有效状态证明及失败原件回放通过；该前缀不能作为完整对照或性能样本。

两条已启动控制通道及 Observer 正常关闭、专用目录移除、设置一致、SDK 正常退出与严格宿主后验归零。异常路径没有取得 Observer 结束后的完整状态转储，不能把正常卸载回执替代该项证明。预检时沙箱的模拟器身份读取遭 socket 错误 10013，语法检查尚未执行；正常宿主完成身份与语法检查，两个记录分别保留。

下一步先在实际 Observer UID 下验证可用的单调计时与有界终止机制，核实具体设备实现、到期拒绝、子进程退出及原件保全，再继续常驻方案。完整两档采集、重复分布、启动两帧、应用本体时延、实际 IPC、观察开销和多端验收仍待完成。本次没有安装产品 APK、派发 UI 输入或读取正式 Vault，也不据此建议应用分页／懒加载。见[去标识摘要](rf312-ui-exchange-investigation-2026-10-17.json)。
