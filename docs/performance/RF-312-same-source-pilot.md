# RF-312：同源采集开关四格功能预跑

验证器来源 `c9a2e362a` 的 97 份文件、同一个 Java UI 包和默认 Release APK，完成采集开／关 × 100／5000 对象四格原生行程，共 48 个阶段。每格仅一轮，属于功能预跑；RF-312 保持未完成。冻结产品编译来源为 `305b86020`，与验证器版本分别记录。见[去标识摘要](rf312-same-source-pilot-2026-10-18.json)。

## 方法与范围

专用 API31／x86_64、2 CPU／2048 MiB、SwiftShader 环境，先运行开启组，再运行关闭组，每组固定 100→5000。两组原运行输入只差专用 AVD 名称，控制辅助类逐字节一致；都显式启用 `--composite-ui`，只有开启组启用 `--journey-memory`。每格实际派发相同的 33 次点击、3 次公开文本输入、1 次公开文件选择、1 次滚动和2次返回，观察请求数量按实际就绪等待保留。

工作负载窗口从 UI 通道就绪、进入采集上下文前，到采集上下文结束、清理通道前。两组都包括 UI 观察、核验及各自模式的初始化／收尾；关闭组不创建周期采样线程或目录，行程后的共同只读内存检查点位于这个窗口之外。不能把窗口耗时解释成应用本体时延。

原状态、身份、输入命中、虚拟视口、原生截图及正文像素验证保留。观察器总限 240 秒、阶段 45 秒、UI 状态 SDK 5 秒、内存点 20 秒及内存 SDK 10 秒均保持，服从更短的剩余预算。目标应用在测量行程中没有插桩或 JavaScript 注入；公开夹具准备与原 APK／UID／私有内容／权限／设置恢复分别核验。

## 失败保全与复核

另一次关闭组队列在 100 对象通过后，5000 对象设备身份预检因 Windows 拒绝本地 `commands.json` 原子替换而失败，该档尚未进行应用操作，也没有阶段或数值样本。原失败队列与 100 档前缀分别保留，完整队列仍判失败；父级原状态恢复、正常 SDK 退出及严格宿主后验归零独立回放通过。没有获得替换重试事件，不能据此认定锁的来源。

随后使用全新 AVD，保持同一来源、制品、输入规则和原预算，完整重跑关闭组 100→5000；表格仅取这次完整队列，没有把失败队列的 100 档拼入四格。

206 项相关回归与 97 份来源绑定。四格的原生状态、原严格内存解析、UID／进程出生和集合、双通道原始帧、原客户端响应验证器、PNG／物理正文及输入就绪均独立回放通过。开启组另逐项重放 24 个阶段边界、周期计划及原逻辑／物理 SDK 输出；拒绝与未消费成员保留。四格和父级原状态恢复、双通道及 Observer 正常关闭、SDK 正常退出、严格后验进程／监听归零和结束健康检查通过。
