# RF-312 已运行 AVD 的流式清单

历史取证复用了新建 AVD 的清单入口，遇到约 10 GiB 的稀疏镜像后一次读取整个文件。工具进程在尚未启动 SDK 时已观察到约 8.3 GiB 工作集，未完成准入；核实 PID、出生时间、无子进程及无 SDK 后，仅停止了该进程。原失败证据保留。

新增 `rf312_forensic_inventory.py`，提供 `digest_file(path)` 和 `inventory(root)`，供已运行 AVD 的取证调用方使用。它直接复用既有 canonical `frontend_build.entry` 的有界读取和打开后快照校验；普通路径、reparse 拒绝、文件身份、大小、写入时间、完整模式及属性的变化检测保持。Windows 文件名推导的可执行模式与句柄模式分别冻结，避免把两种视图的固有差异当成文件变化。

原新建 AVD 入口及默认运行读取器不改。清单形状仍为 `files`（相对路径→SHA-256）和 `directories`；保留空文件和所有子目录。该函数只读取文件，调用方负责冻结整轮输入和检查 SDK 状态；它不证明整个目录在同一瞬间的全局快照，也不授予模拟器进程身份。

## 验证

```powershell
python -B -m unittest discover -s docs/performance -p test_rf312_forensic_inventory.py -v
```

- 5 项回归覆盖空文件／多块摘要、每次读取有界且禁止 `read_bytes`、哈希中修改拒绝、完整目录形状和 Windows 可执行文件模式。真实 SDK 文件摘要匹配；公开包装器与实际使用的包装器函数 AST 相同，调用同一个 canonical 读取器。
- 同一失败 AVD 的 24 个文件共 14014604763 逻辑字节，完整摘要与已回读归档一致。取证 Python 进程观测峰值为 251645952 字节；它包含准入加载，只是工具内存证据，不是应用内存或性能改善。
- 初版流式草案误把路径与句柄模式直接比较，真实 SDK 文件被拒绝；其源件、诊断和失败保留。随后直接复用原校验器，未屏蔽属性或改写默认保护。

关联历史取证仍未通过：SDK 启动后，原门禁因 CIM 缺少模拟器可执行路径而拒绝继续，未读取历史 ANR，也未安装／启动应用或发送界面输入。正常关闭后的独立后验只使用已完整记录的 ADB 身份，确认当前全局 SDK 进程及相关监听为零；缺失的模拟器身份未补猜，原整轮失败未改写。
