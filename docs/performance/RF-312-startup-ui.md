# RF-312 Android 启动界面树读取

`uiautomator dump` 可在根节点尚未就绪时返回退出码 0，同时把明确的 `null root node` 错误写入 stderr。旧预检仅判断退出码，随后把 `exec-out cat` 返回的文件不存在文本当成 XML，导致诊断包启动验证提前失败。

新增 `rf312_startup_ui.py` 提供 `dump_ready(result, path)` 和 `read_tree(run_sdk, path)`：只将已观察到的零退出码、空 stdout、精确 null-root stderr 分类为“尚未就绪”；此时不读取 XML。成功输出必须绑定本轮完整路径，未知状态、混合错误、错误 nonce、畸形 XML 及非 hierarchy 根节点继续拒绝。

调用方提供已绑定专用 SDK／设备的 `run_sdk(label, argv, required=..., timeout=...)` 回调，返回捕获字节流的 SDK 结果。调用方负责以原统一截止时间约束全部 SDK 操作及操作后的超时检查；模块不持有、延长或重置计时器。返回 `None` 时只可在原预算内继续等待。本提交不自动安装应用或启动设备。

## 原生范围与边界

默认包对照按预期以 `observer-absent` 拒绝。相同诊断 APK 的全新实例经历一次 null-root 后成功读取启动元数据：29 次主文档传输尝试，原生元数据读取 2514418 ns；这是元数据读取成本，不是应用启动时延。公开模块与该次实际调用的模块逐字节一致。

两次通过的功能探测均验证原 APK／UID、私有目录内容／链接／权限与系统设置恢复，正常关机及宿主无残留通过；私有条目分别为 81 和 105。原冷启动超时、首次解析失败及清理拒绝记录保持原状态。

当前只完成空账户启动阶段；剩余阶段有意中止，不能把自定义 instrumentation 结果伪装成十二阶段或 JUnit 通过。完整 100／5000 物理行程、累计 IPC、同源观察开销、应用本体时延、全部归属进程及全程／峰值内存、启动两帧和多端仍待。旧默认包／库读取器及插桩拒绝门禁保持，RF-312 与 365/374 台账计数不关闭。
