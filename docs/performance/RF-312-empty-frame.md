# RF-312：空响应编码与两档完整界面行程

## 单项修复及同输出对照

[persistent_control.sh](rf312-default-observer/persistent_control.sh) 在原命令结束后检查两路输出均为可读的空普通文件，直接打印原 `RF312B` 空帧；保留原退出码。非空、不可读或非普通文件仍走原路径，原 `stat`／Base64、4 MiB／64 KiB 边界、16 KiB 输入、命令白名单及单调序号均保持。此改动减少空响应的外部进程与分散输出，不增加临时文件；没有修改产品、原观察器或内容读取器。

对照使用同一新 API31／x86_64 环境和公开文件，按 A/B/B/A/A/B 顺序运行，每组五轮热身后采 50 轮四种操作；六组共 1,200 个计时样本、1,368 个完整帧。PNG、16 KiB 二进制写入、缺失文件与非空错误也核对，所有返回码、输出／错误及 payload 指纹完全一致。三组配对的空操作中位耗时均下降。

每种实现每种操作各 150 样本：空 `exists` 中位 54.71→18.46ms，P95 68.13→24.64ms；空 `put` 中位 79.71→43.33ms，P95 96.65→51.31ms。非空 `size`／`read` 的实现未变，其中位分别为 61.23→60.75ms、62.17→61.54ms。六组共耗时 81.95 秒，原 180 秒边界保持；这些数据是固定公开文件控制链的对照，不是应用性能分布或完整观察器开销。

六个控制进程正常退出、临时目录与观察器移除、九项设置未改写，完整 DropBox 39 项无 ANR。首次宿主审计拒绝短期 SDK 助手进程，保留拒绝并等其自然退出，再只读确认宿主零残留。
