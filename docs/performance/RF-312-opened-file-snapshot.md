# RF-312：打开后绑定文件快照

此前默认库的Cargo编译退出0，但结束后的输入复核因文件属性在打开时变化而拒绝。追加诊断中，设备／文件身份、长度、写入时间、mode及内容保持，属性由`0x40020`变为`0x20`；存储提供方原因未证明。原失败回执及产物不改写。

## 修正与保护

`frontend_build.entry`先保留原普通文件及父目录reparse检查；打开后核对原核心身份，并绑定路径与句柄的设备、文件ID、长度、写入时间和完整属性。批处理文件的路径与句柄可能报告不同的mode，因此分别冻结、分别完整复核。哈希期间路径或句柄任何受保护字段变化仍拒绝，打开期间的核心身份变化和陌生句柄也拒绝。代码没有写入属性或屏蔽属性位。

新增8项回归覆盖打开阶段属性变化、批处理mode差异、两种视图各自的mode／属性变化、文件ID错配及打开期间身份变化；原内容突变、路径别名、父目录reparse、完整输入及生产资源门禁保持。当前完整309项唯一用例通过、零跳过。
