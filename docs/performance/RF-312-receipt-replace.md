# RF-312：有界提交本机 ADB 证据文件

2026-10-17，只修正本机`commands.json`原子替换遇到短期共享占用时直接失败的问题。原206项门禁、本次新增8项回归及46项未变源码测试，共260项有效门禁通过；真实Windows只读句柄回归验证了修复分支，没有执行设备命令。

`AdbRecorder`仍只执行一次原SDK命令，命令记录快照只序列化一次。只有Windows错误5／32／33允许重试同一临时文件到目标文件的替换；重试不超过0.25秒、最多26次替换尝试，且截止不晚于原命令截止。每次将要重试的拒绝先追加到本机事件日志，临时文件须仍为普通文件；其他错误、永久拒绝、期限耗尽或事件保存失败继续拒绝。设备请求不重放，返回值／输出不改，原SDK超时及其部分输出仍保留。

新增回归覆盖相同JSON字节、单次SDK调用、永久占用与剩余预算、局部时间上限、原超时身份／部分输出、事件写入失败、SDK非零退出和真实Windows读取句柄释放。此前用旧记录器复现的真实`WinError 5`及5000档失败均保留，具体原生占用者仍未定位。

新正式队列复用同一默认Release与原生读取／输入／恢复代码：100对象十二步及完整后置检查点通过，22条只读命令精确回放，串行合计PSS为242.62MiB，检查点1869.62ms。它仍只是一个行程后的点，不能据此推断产品内存改善、峰值或分布。

5000对象只完成启动和密码解锁。进入OCR前，备份提示仍显示时的只读滚动探测曾精确匹配；执行时滚动区域由`[0,511][1084,1572]`变为`[0,231][1084,1572]`，原最后匹配保护拒绝且明确未派发输入，后置采样未触达。观察器正常停止未通过，原严格审计拒绝保留，不重试该动作。

独立审计逐字复用原物理前缀／关闭断言，并核对3524个完整控制帧、387个原请求、386个已返回响应、23张截图及100档内存。两档各149项完整私有记录、原APK／UID／debug与九项设置恢复，所有观察器包移除，控制通道正常关闭且临时目录移除，完整DropBox107项无ANR，宿主零进程／监听。该局部审计不替代原严格审计，不将5000档正常停止或整组结果改判通过。

本轮原生没有再次观察到文件替换拒绝；重试分支由真实Windows句柄测试覆盖，不能声称已在原生队列中实际触发。下一项独立检查工具入口在备份提示自动消失期间的布局就绪，继续保留精确目标、单次输入、原期限和拒绝传播。
