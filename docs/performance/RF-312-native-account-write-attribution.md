# RF-312 Windows 账户清单写入阶段归因

本阶段只扩展非默认 `native-perf` 的五个固定子阶段，保持账户清单读锁、序列化、原子写、权限参数、错误传播和调用顺序。默认保存函数去除观测代码后的 token 摘要与基线一致；884 项 React 源码和 35 份 dist 保持，本阶段不声称重新运行前端检查。

100/5000 对象各三个 fresh root/profile 完整执行启动、主密码登录、工作区、搜索、应用锁定和再次解锁。每个样本两条 finished 认证流、两次 completed 后端登录均已独立复核。五个子阶段必须按序、互不重叠且位于唯一账户写入父阶段内部，原预算、真实输入和进程身份检查保持。

前端与后端时钟不相减，父子时长不相加；仅对同一后端时钟的五个互不重叠子阶段求和并保留间隙。completed 表示原调用返回，不独立证明权限命令退出状态或文件系统持久性。记录不包含主密码、请求响应正文、账户名称或自选路径。并发账户列表不强行配对，同步状态写入不表示 React 绘制完成。

本阶段 `diagnosticOnly=true`、`performanceMetrics=null`，用于归因，不能替代无观测器性能基线。两次权限调用的合计占账户写入父阶段 99.74%～99.83%；这尚未证明控制台创建成本或旧首页超时根因，产品优化需要独立受控对照。
