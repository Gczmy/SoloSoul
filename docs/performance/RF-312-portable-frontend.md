# RF-312：从显式源码快照重建生产前端

这是完整默认产物生成链的前端环节。入口不使用旧`dist`或预先打包的移动资源；它复制当前受版本控制的产品和插件市场源件、已安装的完整Node依赖，在全新目录执行原`npm run build`，生成供后续Rust及Android打包使用的前端和资源。

## 捕获输入

当前入口在Windows运行。准备Python 3.11以上、Node.js、npm CLI脚本和与项目锁文件对应的已安装Node依赖。产品及插件市场工作区须干净，插件市场HEAD须与主仓库记录的子模块提交一致；路径必须为普通路径，不能包含shell展开字符或当前代码页无法表示的字符。

```powershell
python -B docs/performance/rf312-default-observer/frontend_build.py capture `
  --workspace '<SoloSoul工作区>' `
  --node '<node.exe>' --npm-cli '<npm/bin/npm-cli.js>' `
  --python '<python.exe>' --dependencies '<已安装的node_modules>' `
  --output '<新的捕获目录>'
```

捕获所有`tauri`受版本控制文件、插件市场受版本控制文件、完整依赖树、三个工具及入口源件的大小／SHA-256。输入和工具变化、源件集合丢失、大小非整数、路径穿越、大小写别名或reparse均拒绝。`frontend-plan.json`保留本机绑定，不推送公开仓库。

已安装包记录必须逐项对应产品v3锁文件，版本、下载来源和完整性标记一致；实际`package.json`版本也须一致，直接必需依赖不能缺失。整个已安装依赖树另以文件SHA绑定；这项核验不声称重新计算了registry压缩包的完整性值。

## 隔离构建

```powershell
python -B docs/performance/rf312-default-observer/frontend_build.py build `
  --plan '<捕获目录/frontend-plan.json>' --output '<新的构建目录>'
```

入口逐份校验复制结果，将Node依赖也复制到新工作区，再执行原`npm run build -- --outDir ...`。NSIS资源、搜索索引、移动／桌面资源、TypeScript和Vite仍按产品脚本顺序执行。Python入口固定到已绑定解释器；npm缓存和临时文件在输出目录，只对构建进程生效。

构建可以更新复制工作区的三个NSIS位图及生成的搜索索引，逐项记录其实际大小／摘要；原工作区仍须保持全部原字节。其他受版本控制文件变化拒绝。新前端必须有生产模块入口，移动资源清单须精确覆盖全部文档与插件资源，逐文件核验大小／SHA、顺序及内容版本。原插件市场和依赖在构建后再次完整复核。

`frontend-result.json`中的`passed: true`才表示这一环节通过。它包含输入计划及入口SHA、实际命令／退出码、原始构建日志、生成资源与前端完整文件绑定，以及复制工作区路径，供后续产物生成步骤使用；失败结果与部分输出保留，不在原目录重试。

此入口尚不编译Rust或生产APK，也不安装应用、运行设备或接受性能样本；完整产物生成链及RF-312验收继续推进。
