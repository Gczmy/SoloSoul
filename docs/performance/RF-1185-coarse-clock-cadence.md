# RF-1185：粗粒度单调时钟的快照节拍

RF-312 的新一轮采集开启行程在前三次只读快照后被 `Snapshot cadence sleep returned prematurely` 拒绝，未完成首个阶段。当前宿主 Python 的 `monotonic` 实现为 `GetTickCount64()`，报告分辨率为 15.625 ms。20 次真实 175 ms 等待中，高精度 `perf_counter` 确认每次实际等待不少于 175 ms，但 15 次单调时钟读数仍落在原门槛之前。单次等待结束后立即拒绝，会把时钟量化误差误判成提前唤醒。

`SnapshotCadence.before()` 现在沿用同一时钟、原 175 ms 目标和原阶段截止时间，最多进行 32 次有界等待；每次等待后重新检查原目标。未达到门槛时不能发起快照，时钟回退、始终停滞及阶段到期仍拒绝，失败保留上一次成功快照时间。三个快照的 350 ms 单调时钟跨度及原有原生输入就绪检查继续生效。

206 项相关回归通过，覆盖量化时钟、提前返回后的继续等待、短阶段截止、停滞、回退及原通道拒绝行为。真实宿主旧／新各 20 次对照中，旧实现 15 次拒绝，修复后 20 次均达到原目标并在原截止时间内通过。这是验证器正确性证据，不是产品性能分布。

全新 API31／x86_64、2 CPU／2048 MiB、SwiftShader AVD 仅安装公开 Observer，完成四组各 12 次只读快照及 10 项协议拒绝。44 个相邻宿主间隔均达到原 175 ms 目标，四组原生观察跨度均至少 350 ms；62 份状态、76 个 UI 帧和 8 个辅助控制帧独立回放通过。九条控制通道及 Observer 正常清理，设置一致，SDK 正常退出，严格宿主后验归零。

原失败行程及其 97 份来源单独保留，使用归档来源回放 12 个控制帧、初始 UI 无观察者证明、4 份内存侧活跃状态、23 个逻辑读取及 15 个物理 SDK 读取。该前缀只有一个预启动点和一个有效内存点；轨迹、阶段覆盖和完整行程仍未通过。独立回放首次误要求 UI 活跃证明，而失败实际发生在首次 focused 检查之前；修正为实际前缀范围后通过，首轮脚本及拒绝记录保留。没有获得子行程结束后的完整无观察者证明；应用 APK／UID／私有状态及设置恢复、控制／Observer 清理和 SDK 严格后验分别核验通过。

本项改动仅为验证器及测试。RF-312 的 5000 档和采集关闭组在该失败轮中均未启动；下一步以新来源重新绑定并运行完整四格，再补重复样本及其他原要求。各代证据分别记录，不混合为性能样本。见[去标识摘要](rf1185-coarse-clock-cadence-2026-10-17.json)。
