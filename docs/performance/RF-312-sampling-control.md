# RF-312：独立选择采集与 UI 控制通道

采集开关现可独立于复合 UI 通道选择。新增可选 `--composite-ui`，关闭行程采集时也可沿用与开启组相同的控制通道；`--journey-memory` 保持原来自动使用复合通道的行为。默认两个开关均为关闭，沿用旧通道。两个参数必须为显式布尔值，非法值在文件或原生输入前拒绝。

本项接受的是模式接入、已完成窗口的同口径计时和严格拒绝行为。完整四格采集对照仍未通过，RF-312 保持未完成。

## 统一窗口与复跑

窗口从 UI 通道就绪、进入采集上下文之前开始，在采集上下文关闭、UI 通道清理之前结束，包含模式初始化、行程内观察／核验、采集和最终确认成本。行程后无观察器 PSS、APK／数据恢复与 UI 通道建立／清理在窗口之外。原始记录保留开始、结束及原总期限；超过原期限不能写成完整窗口。

`measured-workload-window.json` 与最终 UI 证据、驱动报告交叉绑定。窗口是工具工作负载的观测上界。应用本体时延、观察器因果开销和重复分布继续待验；失败时没有完整窗口，不用阶段和或旧样本补造。

复跑继续使用[严格默认有效状态输入与独立 AVD 准备流程](RF-312-default-supported-state.md)，按当前 `rf312_default_binding.sources()` 重建绑定。来源数量仍为 92，但四份内容已改变，旧 92 份来源回执不能直接当作新来源使用。公开 CLI 可用 `python -B docs/performance/rf312_default_state_driver.py --help` 查看必需参数。关闭组显式传入 `--composite-ui`，开启组在相同参数上增加 `--journey-memory`；固定顺序为 100→5000，两个模式使用新的等效配置 AVD。

系统状态命令上限 5 秒、内存 SDK 10 秒、点 20 秒、阶段 45 秒、UI 总限 240 秒及 512 次请求、2 秒／192 点均保持。完整 PID／UID／出生、状态、精确输入、物理像素和恢复保护保持；状态／内存解析器及原 71 份工具未改，产品与 Observer APK 保持。

## 两轮实际结果

174 项相关测试通过，无失败、错误或跳过。覆盖四种开关组合、原默认行为、实际 CLI 参数传递、非法类型拒绝，以及统一窗口在采集上下文之后记录、超过原期限不发布的行为。

API31／x86_64、2 CPU／2048 MiB、SwiftShader 的两轮顺序分别为关闭→开启、开启→关闭。声明的软件、数据集和硬件输入一致，运行输入只更换专用 AVD 名称；动态初始状态和系统调度仍可能不同。

首轮开启 5000 对象完成五阶段后，UI 状态的单次 SDK 命令触发原 5 秒上限；两个空的部分输出保留，不能证明没有插桩。55 点中 54 个非启动前数值点有效，五个边界只有捕获、没有最终确认；871 条逻辑读取、545 次实际 SDK、1090 份物理原件、286 个控制帧及八份不同 PNG／一份正文证明回放通过。根因未定，没有重发原失败命令或后续输入。

第二轮失败后的观察器正常关闭，控制通道未正常关闭，并按门禁保留异常临时目录；该项清理未通过。四个模式会话的应用私有内容／链接／权限、APK／UID／设置均恢复，SDK 正常退出，严格宿主后验进程／监听归零均回放通过。应用恢复与控制临时目录保留分别记录。

第二轮失败回放的首次汇总因漏采槽位不含 `logicalRawFiles` 键中止，原脚本和错误保留；只对已证明为零读取的漏采槽位修正汇总，重跑全部原件检查后通过，未修改原生数据或失败判定。
