# RF-312：默认 Release 实时首页计数与严格恢复

2026-10-16，独立观察器已在当前默认 Release 中实际输入公开密码，并从实时截图核验100和5000两个完整总数。100对象单组完成原流程恢复；5000对象在恢复入口遇到隔离ADB连接超时，整队列仍判定失败。随后独立严格恢复通过，**不追认原失败队列，不接受完整行程或性能分布样本**。

## 观测方法和实际结果

沿用525da2ea0编译产物，1795项原源件、默认custom-protocol、非debuggable APK及内部测试签名不变。API31/x86_64、WebView91.0.4472.114、2个虚拟CPU、2048MiB、SwiftShader；专用AVD由SDK生成新userdata，同一硬件配置，不复制旧运行数据。

输入前仍要求唯一且可见、启用的精确原生节点；密码输入还要求原生焦点和稳定可见IME。只读探测不发送输入，最终输入前仍重新匹配全部原字段。目标应用无测试runner或JavaScript注入；恢复用Debug主包和测试包仍按原流程安装核验。

首页计数改为绑定本次原生截图、应用前台与进程身份，再由Windows原生OCR读取完整数字。唯一My vault／Local vault上下文、主数字字号和列位置、同行objects单位、PNG字节／尺寸均必须匹配；不使用已知滞后的辅助功能总数，不进行模糊数字替换。占位符可在原期限内继续观察，错误数字、来源不符、超时或宿主识别失败直接拒绝。

## 宿主修正和边界验证

一次实际子进程报Get-FileHash不可用，单独重读同一截图又成功；不把它确定归因为某一模块加载故障。新入口仅对子进程固定Windows PowerShell系统模块目录，并用.NET计算前后SHA，避免该命令解析依赖，不改用户或系统环境。

最终60项协议、物理计数、期限、来源与宿主边界测试通过。在父进程模块目录故意设为不可用的条件下，原生OCR实际重读四张公开图：100／5000通过，占位符／登录图拒绝；父环境恢复。两档实时队列均保留应用上下文、完整数字和原期限证明；这些证据只接受像素计数门禁，不替代重复性能测量。

新建环境的完整DropBox预检为38项、无任何ANR条目。两档执行结束时92项，严格恢复结束时151项，均为完整未截断清单、无ANR条目，lastanr为本次启动以来无记录。

## 严格恢复与后续

5000对象失败后没有清空或卸载未恢复数据。独立恢复入口重新核验同一专用AVD、留存APK／UID／debug属性和原备份SHA，再安装原Debug包，调用既有完整恢复函数，逐项核验139项内容、链接、模式及根权限；9项系统字面设置相同。原失败报告和队列结果字节保持，恢复完成后仅卸载本次自有包。

首次宿主收尾审计仍发现模拟器生成的20秒延迟辅助进程，原拒绝保留；其自然退出后的同标准审计确认零自有进程和监听端口，受保护旧ADB身份保持。原始日志、截图、配方及私有TAR仅在本地保留；[结构化摘要](rf312-live-home-counter-2026-10-16.json)公开通用版本、计数、像素坐标和证据哈希，不含本机路径或进程／运行标识。

下一步在新队列推进完整默认行程：首次OCR、工作区和搜索、四类附件预览、锁定及重新解锁，再补重复分布、严格全进程内存、同源观测开销与IPC归因。保留本次恢复失败作为失败证据，不能只保留两张成功计数图。跨机器复跑仍需自己的SDK、专用AVD、同源产物和公开夹具绑定；当前本地配方尚非通用即用入口。RF-312保持待验证，363/372关闭数不变。
