# RF-121 Windows 偏好写入归因

当前两组深色验证的聚合 `user_data_update_preference` 区间计数出现 2 而非 1。主题保存与解锁后的备份提醒共用该命令；命令名和相近时刻不足以唯一归因。原失败继续保存，完整 RF-121/312 保持未验收。

RF-1123 仅为非默认 Windows `native-perf`、已配置的隔离 `sdk_journey` 添加后端记录。默认产品不包含记录器，前端 fetch 观察器和命令签名、偏好校验、持久化、同步触发不变。

记录器只将后端入口的键集合映射为三个固定类别：仅 `theme` 为 `theme`，仅 `lastBackupReminderAt` 为 `backup-reminder`，空集合、多键或其他键为 `other`。输出不含键字符串、值、账户标识、错误消息或请求/响应正文。账户是否匹配公开夹具只输出布尔值；不匹配使整份观察无效。

记录在入口开始，成功完成命令现有路径后标记 `completed`；提前返回错误或未完成的 Drop 标记 `interrupted`，尚未结束为 `running`。完成只表示该命令路径返回成功，不表示后台同步完成，也不额外证明持久化耐久性。并发命令保留各自序号和状态，不按完成先后重排。最多 256 次，溢出使观察无效，不静默丢弃后继续验收。

每个原有外观 SDK 检查点，在严格解析前端探针之后附加后端 `preferenceWrites`。字段绑定当前 runId、PID、覆盖命令和后端进程内单调时钟。记录器时钟从首次创建开始，不能和前端 `performance` 时钟相减；附加记录也不表示两个时钟同步。

独立解析器严格核对字段、身份、时间边界、连续序号、类别和终结状态。比较检查点时，已终结前缀不得改变，尚运行前缀只允许在此前检查点之后结束。新增记录必须在原后端检查点之后开始。与经原 IPC 合同验证的前端区间总数核对时，数量不符或新记录未全部完成即拒绝相关区间证明。保留 `other` 计数，不把它归入主题或备份提醒。

这些是分类和覆盖诊断，不提供未插桩性能基线，不证明逐条前后端命令按序配对。检查点存在采集间隔，边界或并发导致的不一致不得通过等待、补齐或拼接样本抹平。RF-1123 本身保留原聚合外观校验；只有取得当前 GUI 实测和完整独立证据后，才能决定 RF-121 下一步。

当前状态：RF-1123归因设施及其完整检查已完成，新GUI的四组Windows场景共12份完整行程、原聚合校验及窗口绑定通过，截图已逐图检查。六份深色样本在最后已观测检查点各有2次主题写入和1次备份提醒写入；两个待验区间各只包含1次主题写入。本轮没有重现旧2对1，因此旧失败的额外写入来源仍未唯一证明。

浅色两组没有这些归因检查点，汇总的空观察不证明没有偏好调用。分类证明保留独立诊断范围及accepted=false，原聚合验证本轮单独通过。完整RF-121/312、多平台、其他窗口状态和辅助功能矩阵仍未验收。见[本项验证记录](../verification/rf1123-preference-write-attribution-2026-10-11.json)。

## RF-1127：独立后续完成合同

真实窗口恢复补验中，两个早期检查点各出现一次已完成主题写入和一次仍运行的备份提醒。原总传输数与后端区间总数均为2，严格 `correlatePreferenceInterval` 继续拒绝原检查点；它的规则保持不变。

新增 `correlateSettledThemeInterval` 将原区间与后续完成证据分开。原区间必须与独立前端传输数一致，恰有一次已经完成的theme，其他项只能是backup-reminder。后续快照须为同runId/PID/进程单调时钟，并保留完整不可变ID前缀；原running项只允许在原检查点之后完成，最终必须completed。已终结项不能重写，未知类别或interrupted不能转为成功。后来新增的请求单独报告，不能补齐原区间计数。

原区间的 `allCompleted=false` 和running原件继续保留。该合同不跨JS与进程时钟换算、不等待补齐原计数、不改变观测预算，不证明逐条前后端配对、后台同步完成或持久化耐久性。调用者仍须核验整个行程身份、探针、实际选择的主题、快照顺序、偏好恢复和窗口像素。历史快照只能用于合同复核，不能称为本次新原生运行或完整RF-121验收。
