# RF-312 独立原生观察器

本目录公开当前观察器的原样Java／Manifest源码及参数化离线构建入口。观察器插桩自己的独立包，读取指定公开夹具应用与系统文档选择器；构建命令只生成本地测试产物。

本轮实际编译、签名和Manifest核验通过，生成DEX与冻结观察器完全一致；含空格输出路径通过，已有输出目录与缺失SDK均拒绝。原生完整行程仍待验收，见[执行记录](../RF-312-complete-default-entry.md)。

## 构建

准备Python 3、包含`java`／`javac`／`keytool`的JDK，以及Android SDK的API36平台和build-tools 35.0.0。替换下面的本机目录参数，在新输出目录执行：

```sh
python build_observer.py --sdk "<SDK目录>" --jdk "<JDK目录>" --output "<新的本地输出目录>"
```

可通过`--compile-sdk`和`--build-tools`指定已安装版本；当前实测为API36／35.0.0。脚本完成Java11编译、DEX、APK链接／对齐、生成内部测试签名、签名和内容回读；不会下载SDK或安装应用。产物包括APK、`package.json`和各步骤日志，测试签名材料保留在本地输出目录。

`package.json`记录实际源件、DEX、APK和签名摘要。不同测试签名会改变APK字节；源码和DEX摘要用于核对同一程序。应用的当前默认Release、恢复用Debug／测试包及公开合成Vault由完整行程入口另行准备。

## 协议与边界

观察器包名与instrumentation目标均为`org.solosoul.rf312observer`。只在专用公开测试AVD使用；调用方须先核验设备、APK、包缺席及公开数据，运行后按完整清单恢复。当前完整行程编排仍为本地冻结配方，尚需参数化公开。

启动参数`token`为新的32位小写十六进制命名空间。调用方在该包自己的`files/<token>/`目录按序原子发布`request-001.json`等文件，读取相应响应；`ready`表示连接就绪，`stop`／`stopped`完成正常停止。

| 请求 | 原生条件 |
| --- | --- |
| `snapshot` | 层级仅来自指定应用或文档选择器；其他根返回空层级，截图拒绝 |
| `inspect-target` | 只读核对唯一目标、焦点／IME及滚动或公开文件卡片条件 |
| `tap` | 精确唯一、可见、启用、可操作且在屏幕内的节点；单手指DOWN／UP |
| `type-public` | 仅空白聚焦输入框与两种固定公开合成文本，密码语义匹配 |
| `scroll` | 精确唯一可滚动节点，原生屏幕裁剪后的有界单手指手势 |
| `pick-public-file` | 指定公开文件命名空间、可聚焦原生卡片、唯一独立预览控件且触点避开该控件 |
| `back` | 仅指定应用或选择器的前台根 |

输入目标逐项匹配`package`、`class`、`text`、`content-desc`、`password`和`bounds`，执行前重新查询。观察器保持240秒／512请求及5000节点／200层深度上限；调用方还须保留45秒阶段期限、15秒就绪和10秒停止期限。构建成功不代表设备交互或性能采样通过。

## ADB 调用记录

`adb_control.py`提供`AdbRecorder(executable, serial, output)`。调用方先完成专用模拟器、包身份及公开夹具检查，再通过`run(*command, timeout=...)`执行原命令；它保留固定`127.0.0.1:5057`连接与显式设备，不重试、不重启服务，也不改变客户端启动方式。设备、输入、恢复及完整行程的门禁继续由调用方负责。

超时会先记录本次命令、原请求期限、实际耗时、`exitCode=null`和可取得的原始部分输出，再抛出同一个`TimeoutExpired`。成功及非零退出维持原结果语义；若保存证据失败，原超时仍是主异常。命令及部分输出可能带有本机信息，只保存在调用方指定的本地目录，不能直接作为公开摘要。

五项回归覆盖部分输出、异常保留、成功／非零退出、无界期限拒绝和证据写入失败。将当前进程的临时目录指向专用测试盘后，可在本目录运行：

```sh
python -B -m unittest discover -s . -p test_adb_control.py -v
```

## 正文与底部导航边界

`body_navigation.py`仅识别当前英文公开夹具的原生`Main navigation`容器，核对归属、可见／启用状态、容器类型、四个唯一可点击导航项及其边界。页面标题中的Home／Objects／Tools／Settings不参与判断；缺失、重复或不匹配时返回未就绪，调用方继续受原阶段期限约束，没有坐标或标题回退。

八项回归覆盖实际标题碰撞、容器／按钮歧义、缺失、错误归属／状态和越界几何。留存层级的只读复现已从0个恢复为1个正文候选，不派发输入；原生命中、焦点、手指事件及原预算由原入口继续验证。

```sh
python -B -m unittest discover -s . -p test_body_navigation.py -v
```

Tools 页的公开 OCR／Search 卡片通过 `tool_card_candidates` 与 `open_tool_card` 选择：必须是当前应用内可见、启用、可点击且原文精确匹配的原生 Button，中心还须高于已核验的导航栏。标题、仅描述匹配、缺失或不明确的导航均不提供猜测候选；多个卡片交给原唯一性检查，不按位置挑选。

卡片被底部导航遮挡时，复用原生滚动及原就绪过程，随后只派发一次精确点击，仍使用调用方原期限。原生层在输入前拒绝位置变化时，原异常继续向上传播，不捕获并重试该次点击。新增十项回归，加上原八项导航回归共十八项；同一命令可运行全部用例。

```python
from body_navigation import open_tool_card

open_tool_card(journey, 'OCR', deadline)
```

## 预览关闭范围与完成条件

`preview_scope.py`按当前公开文件名和原生工具栏的返回／编辑附件属性／关闭控件限定网页预览按钮，原生PDF使用同文件标题和精确资源ID。当前公开夹具均为可编辑附件的英文界面；缺少、重复或不匹配的工具栏不回退到背景Close。

`close_preview`调用既有入口的快照、唯一目标就绪检查和原生手指点击，沿用调用方的原期限。每种层只点击一次，原生PDF返回后仍有网页预览时继续关闭该层；三个跨至少350ms的观察及最终截图均确认预览控件消失、附件列表恢复后，才输出完成回执。背景附件名称本身不能证明预览已关闭。

十项测试覆盖实际三Close歧义、错误文件／归属／状态／几何、原生PDF，以及残留工具栏不重复点击、不误报完成和两层先后关闭。实际默认行程仍需独立验证。

```sh
python -B -m unittest discover -s . -p test_preview_scope.py -v
```

## PDF 正文补充 OCR 的原图绑定

`scaled_ocr.py` 仅为原生 PDF 正文提供固定半尺寸的 OCR 输入，依赖 Pillow。调用方先用原图及原严格读取器验证；只有正文未就绪时，才在同一阶段期限内额外识别一次半尺寸图。错误的完整数字、无效几何或归属错误仍直接拒绝，不以补充读取覆盖这些错误。首页计数、标题及页码继续使用原图回执。

`create_half_png` 保留原生截图，按两个实际尺寸向下取整到一半，用固定 Lanczos 生成新 PNG，拒绝覆写及重解析路径。`remap_half_receipt` 核对原图与半尺寸图各自的原生 OCR 哈希、语言、尺寸及有限词框，逐像素验证派生关系，再仅按实际尺寸比换算词框；识别出的文本保持原样，不拼接数字片段、替换字符或推测缺失内容。

调用方须保留原图、两份原始 OCR、派生 PNG 及返回的四项哈希／尺寸证明，并把换算回执送入原精确正文校验。终态审计重新生成派生像素、核对原回执并重建映射；正文接受仍绑定原生截图及原生 PDF 图像区域，页码另用原图的实际控件几何和精确像素文字核验。离线诊断通过不能替代完整原生行程。

九项回归覆盖奇数尺寸的坐标映射、文本及原件保持、不修正拆分或错误数字、拒绝覆写、错误输入绑定、非半尺寸及修改像素、非法词框、错误语言／引擎和非法 PNG。将临时目录指向专用测试盘后运行：

```sh
python -B -m unittest discover -s . -p test_scaled_ocr.py -v
```

## 连接停顿的被动现场采集

`socket_stall_watch.py` 在调用记录超过一秒未更新时，最多每五秒保存一次 Windows ADB 进程与 5057 端口连接状态。采集只执行有十秒上限的只读 CIM／TCP 查询，不执行 ADB 命令、不发送输入、不停止或重启进程，也不重试工作请求。停顿记录本身不表示连接失败，须与实际错误和现场状态核对。

调用方先完成原有设备、服务进程和公开夹具身份检查，再以真实服务与工作进程 PID 构造 `windows_capture`，将 `wait_for_worker` 用于原来的进程等待位置。它不增加工作进程期限，返回真实 `wait()` 退出码；采集超时、错误、元数据暂时不可读或输出目录已存在均只影响诊断。已完成的档位记录不再触发采集，整个等待仍以进程句柄为准。

调用方保留原输入、读取、恢复和验收门禁。原始进程命令行及连接快照仅保存在本地，公开摘要只保留计数、结论与证据哈希。十项回归验证退出码保持、采集失败不打断工作进程、停顿采集限频、档位终态不替代进程终态、拒绝覆写及有界只读采集。

```sh
python -B -m unittest discover -s . -p test_socket_stall_watch.py -v
```


## 有界持久控制与原接口接入

`persistent_control.py` 的 `Control(process, output)` 接收调用方自己创建的三路二进制管道进程及全新证据目录。先核验专用环境、观察器包／UID、自有临时根与 `persistent_control.sh` 哈希，再通过 `shell -T -e none` 启动固定脚本。`RF312B` 只允许固定操作、严格文件名、有界 payload 和单调序号；两路字节各自用长度及规范 Base64 保留，只接受 framing 的 LF／CRLF，不修改业务字节。阻塞读写、截断或序号错误后不重连、不复用或重放，保留原始回执，只结束自有管道客户端。

`persistent_adapter.py` 的 `binding` 仅在原观察器已验证且正常就绪后接入，限定原文件命令和焦点／进程／插桩状态／启停命令，未识别命令拒绝且不回退 SDK。显式验证 Windows SDK 的换行方式后，仅复现固定 shell 输出的序列化，二进制 `exec-out` 内容不变。退出先恢复原回调，再正常关闭控制管道，原入口随后负责观察器停止和完整恢复；临时目录存在未知或存活残留时保留并拒绝清理验收。

`SnapshotCadence.before(deadline)` 在原阶段期限内限制快照开始间隔至少 175ms，保留原三次／350ms 稳定要求及 512 次请求、45／240 秒预算。十四项编码／管道及十二项适配／节奏用例，加上原 170 项门禁共 196 项通过。真实公开文件诊断 1,000 轮、2,013 帧通过；完整原生接入已运行到 Tools 滚动前，只读目标几何变化导致队列停止，不能据此宣称两档完整行程通过。

```sh
python -B -m unittest discover -s . -p test_persistent_control.py -v
python -B -m unittest discover -s . -p test_persistent_adapter.py -v
```
