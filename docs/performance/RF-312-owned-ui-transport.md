# RF-312：Observer UID 文件传输与原生时钟

新增显式选择的 Java 文件传输，解决 Observer UID 无权读取 `/proc/uptime` 以及重复 `run-as` 的开销。产品、Observer APK、原状态／内存读取器及原时间上限保持不变。版本 1 输入继续使用旧传输；版本 2 输入同时绑定构建回执和实际 JAR，并要求启用 composite 通道。

## 时钟与拒绝条件

真实 Android SDK 编译的辅助类在实际 Observer UID 下调用 `SystemClock.elapsedRealtimeNanos()`。它与原整数秒计时保持相同的 `floor(startSeconds) + 45` 截止方式，没有改用墙钟或增大上限。该框架时钟的单调性及包含休眠的语义见 [Android 官方文档](https://developer.android.com/reference/android/os/SystemClock)。

专用 API31／x86_64、2 CPU／2048 MiB、SwiftShader 环境完成三次短计时、250 ms 和原 45 秒到期拒绝、五项 UID／路径／模式／重复文件拒绝。独立回放核验原生时钟、进程退出、14 份状态证明及完整原件。早期两次失败分别为设备 JAR 身份不符，以及取证脚本误将 SDK 的 CRLF 与原生文件 LF 要求字节相等；原件均保留，未把部分结果改记为整轮通过。后续先以固定 stdout／stderr 字节确认 SDK 序列化，再按该明确规则校验，原始数据不改写。

另一个全新环境中，旧协议和 Java 协议各执行一次真实缺失回复场景，均在原宿主 45 秒内收到原生 71 拒绝帧，保留请求、没有回复，没有重试或宿主超时。8 帧、7 份状态证明、所有专用目录移除、Observer 正常结束、SDK 正常退出及严格宿主后验归零均独立回放通过。

## 协议与接入

Java 只处理固定的 ping、稳定文件读取、请求／回复交换和关闭。请求、回复、临时文件、错误标志按原顺序检查；请求原子发布，回复保留原有大小、稳定性、完整帧及截止检查。拒绝时只能保留有界的字节前缀，不能把它当作完整响应。辅助类没有目标应用、UI、网络或子进程执行 API。

Python 绑定建立两个专用通道：UI 文件操作进入经哈希与完整设备读回确认的 Java 辅助类；窗口、进程及应用生命周期操作进入原 shell 控制器。原状态读取仍通过原 SDK 及完整转储解析。路由固定，错误不切换通道、不重发输入；两个通道必须各自正常关闭，恢复原回调后才由原 Observer 会话清理。异常或未知残留保留取证。

```powershell
python -B docs/performance/rf312_owned_ui.py --jdk <JDK目录> --android-jar <android-36/android.jar> --d8 <build-tools/lib/d8.jar> --output <全新构建目录>
```

重新生成当前来源的回归和 adapter 输入，使用 `schemaVersion: 2`，保留原有 `runtimeInputs`、`runtimeInputsSha256` 和完整 `sourceSha256`，增加 `ownedUiPackage`（绝对路径）及 `ownedUiPackageSha256`。回执绑定 Java／绑定器／构建器源码、真实编译工具、JAR 和成功编译步骤；不接受额外归档成员或测试桩。随后沿用原 driver 与 `--composite-ui`，采集开／关使用同一个包；没有包时沿用版本 1。宿主 JVM 协议测试可单独运行：

```powershell
python -B docs/performance/rf312-owned-ui/protocol_tests.py --jdk <JDK目录> --output <全新测试目录>
```

该测试使用明确的 Android 测试桩，只证明协议分支，不证明原生 UID 或时钟；测试桩不会进入真实构建。

## 验证范围

私有原型按旧→新→新→旧完成各 12 次 Launcher 只读快照；48 份响应、10 项拒绝、62 份状态证明和 76 帧独立回放通过。原协议 24 次快照中位 211.5 ms、累计 5.594 s；Java 原型中位 63 ms、累计 1.565 s。这个结果只属于该只读传输探针，不能作为产品时延、采集开销或跨来源完整性能样本。

公开接入实现沿用相同 Java 源码，真实编译 DEX 与原生探针 DEX 字节一致。190 项相关回归及 14 项宿主 JVM 协议测试通过。首次相关回归中旧 AST 测试没有执行新增参数赋值，修正测试以运行真实赋值和调用后全量通过，首轮记录保留。当前来源的原生双通道复验结果见[去标识摘要](rf312-owned-ui-transport-2026-10-17.json)。

当前 97 份来源在另一个全新环境重新完成旧→新→新→旧的 48 次快照和 10 项拒绝；62 份状态证明、76 个 UI 帧及 8 个原辅助控制帧独立回放通过，包含两次实际窗口读取。原协议中位 242 ms、累计 5.779 s；新通道中位 63 ms、累计 1.472 s。九条控制通道及 Observer 正常清理、设置一致、SDK 正常退出、严格宿主后验归零通过。此来源与前述私有原型分别记录，不合并为重复性能分布。

提交前统一绑定器换行并移除测试文件的末尾空行，确认 AST 相同；以最终暂存来源重新完成全部相关回归、真实构建及全新 AVD 原生复验，前代原件保留。暂存区 97 份来源与该轮证据逐字节一致。

本项没有安装产品 APK、派发 UI 输入或读取正式 Vault。固定 100／5000 对象的完整采集开／关、重复分布、启动两帧、应用本体时延、实际 IPC、观察成本和多端要求仍未完成；RF-312 与完成计数不因此关闭，也不据此建议产品分页或懒加载。
