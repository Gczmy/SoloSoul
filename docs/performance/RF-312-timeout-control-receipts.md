## 修正与验证

此前`subprocess.run`抛出`TimeoutExpired`后直接跳过调用记录，留下的命令清单缺少关键失败行。[可复查记录组件](rf312-default-observer/adb_control.py)先保存超时回执及部分stdout／stderr，再抛出原异常；`exitCode=null`，不伪造进程退出状态。成功和非零退出维持原语义，证据写入失败也不替换原超时。命令清单按完整文件原子更新。

新增五项回归通过，连同原协议及身份保护共123项；实际ADB CLI回执通过。源码与本轮冻结驱动使用的组件逐字节一致。原localhost监听、客户端启动方式、原生命中／输入和恢复检查、15秒就绪／10秒停止／45秒阶段／240秒观察器期限保持；无重试或服务重启。

实际默认队列恰好留下1次超时调用：阶段期限只剩约4.5875ms，原回执、命令和stdout／stderr文件均保留；两份部分输出实际为0字节，不宣称捕获到非空内容。该超时发生在阶段耗尽后，未归为前次观察器ready超时。
