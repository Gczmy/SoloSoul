# RF-312：完整 UI 行程中的只读内存采样

新增显式 `--journey-memory` 模式，使用同一默认 APK 和公开 100／5000 对象夹具。它在十二步行程中记录串行 PSS／RSS 证据。组件与严格拒绝路径已验证；当前完整原生队列未通过，尚无本模式的完整行程基线样本。

## 使用

按[默认有效状态入口](RF-312-default-supported-state.md)准备新的专用环境、原严格运行输入和适配配置。适配来源扩展为 88 份，包括复用的合并 UI 交换模块、固定 shell 及其回归；原 71 份默认工具、产品包与严格读取器保持。内存读取使用原 SDK 命令。新开关默认关闭，关闭时不创建内存线程或采样目录，并继续使用原 UI 通道。

在原默认驱动参数后追加：

```text
python -B docs/performance/rf312_default_state_driver.py <原完整显式参数> --journey-memory
```

保持 100→5000 顺序、独立新输出及原恢复／退出要求。旧 83 份源码和输入已完整保全，并通过旧读取器的实际加载校验；历史原件可用原版本回放，不将旧结果改标为新增模式。

启用时，原 session 仍拥有唯一的 UI 观察器、安装和清理，宿主客户端复用已验证的单次合并交换协议；客户端继承同一截止时间、请求序号、输出和原生进程。退出时将实际请求计数交回原 session。没有启动目标诊断采集器或载入 JavaScript，原响应验证、命中稳定、物理截图和内容检查均保留。

## 采样口径

- 先在应用未运行时确认独占 UID、完整进程清单和实际状态；缺席使用 `not-running`／空值，不记零内存。
- 周期计划为每 2 秒一个槽位，最多 192 个记录。繁忙或失败的槽位保留原序号、计划时间、原始字节及错误，不重试替换。实际开始／结束时间另存，不能把计划间隔当成所有点的实际间隔。
- 十二个阶段结束时各提交一个异步完整采样请求，记录阶段标记时点与原截止时间；UI 继续推进。每个实际采样仍须在对应阶段原四十五秒截止时间与观察器 240 秒总限内完成；每点最多 20 秒，每条 SDK 命令最多 10 秒，均服从更短的剩余原预算。原 512 次观察请求、截图、物理正文及其他 UI 门禁保持。
- 最多十二个边界请求，按原阶段顺序逐项采集，最后统一确认全部实际回执，确认同样不能超出原总限。延期的是主线程确认，不是采集期限。采样可能与后一 UI 阶段重叠，因此记录标记到采集的延迟，不将阶段后采样当作静止于该阶段时的内存值。
- 使用独立 SDK 记录器和单个 worker，避免与 UI 命令台账并发写入。采集器不向目标应用插桩、执行 JavaScript、输入或修改系统设置；原生 UI 观察器仍只插桩自身。
- 复用原 `android-process-memory.py` 的进程／renderer 服务绑定、内核 UID／PID／出生、前后集合及数值验证。额外核对采样前后完整 Linux UID 清单；同 UID 的未登记进程、遗漏的 renderer UID 进程或未覆盖后代均拒绝，不能静默漏算。
- 两份有效系统状态转储只允许原 UI 观察器，并绑定其实际 PID；原主进程生命周期跨点保持。原字节、退出码、stderr、失败及超时部分输出均记录。

## 结果与结束

`journey-memory/points/NNN/` 保存每点命令、原始输出和结果；`journey-memory-sdk/commands.json` 保存独立 SDK 台账。`boundary-NN.request.json`／`.ack.json` 分别保留排队标记和实际确认。阶段记录通过序号和 SHA 绑定对应完整检查点；未完成阶段保留请求标记，不伪造已确认数值。最后一个阶段及全部采集完成后，主线程在原总限内确认所有回执，停止 worker，再清理 UI 控制通道和观察器；原行程后无插桩 PSS 检查点和全部私有状态／APK／UID／设置恢复继续执行。

`journey-memory/result.json` 分别记录完整阶段检查点、周期拒绝、漏采槽位、时间范围和已接受点的最大串行 PSS。所有计划周期槽位须有记录，worker 停止、十二个边界和 UI 调用方确认全部完成，才能接受该轨迹。周期中的拒绝仍是拒绝，轨迹包含的间隙不能解释为已覆盖的数值。

串行采样不是同一瞬间的原子快照，也不能证明精确连续峰值。共享 WebView、zygote 和系统进程在声明范围之外。UI 完成时间包含观察、并行采样及核验开销，整轮还需最终确认；不把它解释为应用本体时延。开／关采集的比较、重复分布及其余 RF-312 验收仍按原范围独立完成。
