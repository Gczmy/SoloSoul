# RF-312 有界 Android 启动主线程取证

显式诊断采集器新增可选 `startupThreadStacks=true` 参数。缺省不采样；其他参数值拒绝。该模式只用于排查启动失败，不能作为性能或完整 IPC 验收。

## 运行与读取

使用 [采集器构建入口](RF-312-ipc-collector.md) 生成并精确绑定新 APK，不能复用旧 APK 的原生证据。生产者绑定 83 份源码，包含采样读取器及测试。启动目标插桩时增加 `-e startupThreadStacks true`，其余包、公开夹具、私有数据备份、进程身份、独立 UI 观察及原时限要求不变。

采集器发布原生 `ready.json` 后，从独立线程读取主 Looper 线程堆栈。总窗口最多 8 秒、最多 80 份快照、每份最多 128 帧，间隔不超过 100 毫秒的休眠；实际采样间隔还包含堆栈读取和写盘时间。首个元数据检查点成功后停止采样。每份记录包含固定 run、PID／UID／出生时间、主线程身份、原生读取时钟、Java 线程状态、是否截断及符号信息，没有方法参数或请求内容；数据及 SHA-256 标记分别写入并同步。

必须在已核实的目标进程停止后、恢复或卸载之前保存本轮 nonce 目录。只读取已知平面文件，逐项校验标记与摘要；不提取 tar 路径、符号链接或未知成员。已提交快照只能形成从 1 开始的连续前缀，末尾未提交文件可保留但不计入有效记录。

```python
from rf312_startup_stack import validate

proof = validate(records, run_id=run_id, expected_process=native_ready_process)
assert proof["forensicStackPrefixAccepted"]
assert not proof["performanceSampleAccepted"]
assert not proof["actualIpcAccepted"]
```

读取器严格检查类型、身份、序号、时钟、符号长度和原生帧标记。它不接受完整行程，也不授予清理其他目录或进程的权限。采样、独立观察、SDK 和写盘会影响运行，线程状态 `RUNNABLE` 也不能作为 CPU 利用率。

## 验证结果与原失败

24 项公开 Python 回归、4 项查询回归、实际编译／签名／检查九步通过；本机独立适配及归档校验的 43 项回归通过。新 APK 仅 DEX 内容变化，其余三项内容不变；实际编译清单仍被原默认读取器精确拒绝。

新的 API31／x86_64、2 CPU／2048 MiB 隔离模拟器通过原 SDK 身份和静默门禁、原生桌面及无 ANR 预检。100 对象公开夹具实际保存 70 份完整快照、1304 帧，读取窗口 7931320190 ns；143 份目录文件摘要及全部 151 个控制帧独立回放通过，无未提交尾项或采样错误。该窗口描述取证过程，不是应用启动耗时。

本轮原生行程仍为失败，首个 IPC 检查点未通过：实际 `dumpsys activity instrumentation` 返回退出码 0，但正文是 `Unknown command: instrumentation`，诊断代码因此未能核实两条插桩身份。该输出不能作为“没有插桩”的证据。当前默认行程及内存工具也使用此命令，后续必须补充有效状态来源，不能仅用未命中包名证明插桩缺席；既有数值、失败和原始证据保留，不重标为新的直接身份验收。

子步骤恢复 APK 还发生一次 ADB 连接超时，未生成其恢复后私有目录归档。外层按原输入成功恢复 APK／UID 和全部 137 项私有内容、链接、权限及设置，移除自有包和取证目录，正常关闭 SDK；原 45 秒内第 8 次只读严格后验归零，离线重放通过。原生父回执保留失败，不用兜底恢复将其改为成功。

本次终态未出现 ANR；此前 FocusEvent 超时未被本轮复现或解释。实际堆栈包含 Chromium 启动、渲染和消息队列等待，不能据此宣称确定了瓶颈。下一项修复状态读取来源，再继续真实 100／5000 十二阶段及其余 RF-312 指标。见[去标识摘要](rf312-startup-stack-2026-10-17.json)。原始堆栈、归档、进程信息、截图、APK 和本机路径仅留本地。
