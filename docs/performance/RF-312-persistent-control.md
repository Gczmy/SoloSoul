## 单项修复

[控制通道](rf312-default-observer/persistent_control.py)与[固定远端脚本](rf312-default-observer/persistent_control.sh)复用一次已建立的客户端连接，避免测量过程每次读取都新建本机 TCP 连接。`RF312B` 使用单调序号、退出码、分离的两路字节长度及严格 Base64。仅 framing 行尾接受 LF／CRLF，解码后的文件及错误字节不做修改；拒绝非规范编码、截断、错误序号、无界输出和任意命令。未知执行结果使通道失效，不重连或重放；只停止调用方自有的管道进程。

[接口适配](rf312-default-observer/persistent_adapter.py)只识别原观察器文件操作和既定焦点、进程、插桩状态及启停查询，不提供通用 SDK 回退。固定 shell 输出复现现场已验证的 Windows SDK 换行序列化，`exec-out` 文件字节保持原样。原观察器 APK、内容读取器和精确输入检查均保持。退出作用域先恢复原回调，再由原入口正常停止观察器并恢复完整数据；失败输入不换连接再发一次。

快照开始间隔至少 175ms，防止较快的传输造成无意义轮询。原三个观察跨至少 350ms、512 次观察请求上限、45 秒阶段期限和 240 秒总体期限均保留；等待不越过原 deadline 后再开始读取。完整调用方除传输作用域和两处采样语句外，全部原语句经 AST 对照保持，既有正文工具定位及补充 OCR 也保留。
