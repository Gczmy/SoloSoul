# RF-312 SDK 启动身份就绪

此前历史取证在首次 CIM 快照中捕获到 `ExecutablePath: null`，随后把这份不完整记录作为固定根身份交给原静默门禁，整轮被拒绝。新增 `rf312_launch_identity.wait_for_roots`，供显式诊断调用方在原预算内取得完整的实际 OS 记录；不从启动请求补写缺失字段，也不修改原静默或退出读取器。

## 调用契约

调用方在创建模拟器前固定原 240 秒单调时钟期限，并传入自己启动的 `adb.exe`、`emulator.exe` 两份规格。规格包含 `Name`、`ProcessId`、当前 Python `ParentProcessId`、`ExecutablePath`、由 `subprocess.list2cmdline` 生成的准确 `CommandLine` 和启动前的带时区 `BornNotBefore`。实际创建时间不能早于下界，路径和命令行必须与规格一致；名称、PID 或父进程不匹配立即拒绝。

只对已匹配记录中创建时间、路径或命令行的 `None` 等待下一份真实快照；已观察的字段退化或变化、重复身份、老进程生日均拒绝。`alive` 使用调用方持有的进程句柄，不能把字段缺失当成退出。每次读取、记录和等待均受同一个期限约束；返回后，原 `bootstrap_quiet.wait_for_quiet` 仍核验完整根、SDK helper 缺席及连续静默窗口。事件中的完整记录标记不等于 helper 所有权授权。
