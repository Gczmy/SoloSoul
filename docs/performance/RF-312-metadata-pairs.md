# RF-312：独立内存元数据查询合批

本项继续降低只读采样工具的往返开销。默认产品包、原 71 份工具及 `android-process-memory.py`／状态读取器保持；只改变可选 `--journey-memory` 模式的元数据传输。适配配置绑定 90 份来源，需重新生成配置，旧 88 份来源和回执仍按旧版本保留。

## 合批范围

仅合并原读取器中先连续读取、再共同校验的两个查询组：

- `dumpsys activity processes` 与固定应用的 `dumpsys activity services`。
- 同一数字 PID 的 `/proc/PID/stat` 与 `/proc/PID/status`。

应用 UID 查询、前后完整 UID 清单和每次 `meminfo --local -s PID` 均独立执行。UID／PID／出生校验仍在 `meminfo` 之前；内存值解析仍在后置身份读取之前。查询不跨点缓存，不重排校验，不提前预取内存，也不向目标 `IApplicationThread.dumpMemInfo` 发起请求。

正常主进程＋单 renderer 的完整点保持 16 条逻辑读取，改为 10 次实际 SDK 调用；启动前缺席点保持 7 条逻辑读取，改为 5 次 SDK 调用。其他合法进程数按原读取器的完整集合处理，不为满足计数而删进程。

## 传输与原件

每组使用一次原 SDK 非 PTY shell 调用。命令只允许固定清单或受限的十进制 PID，脚本不接受用户文本。两个成员分别在 stdout 与 stderr 中带有相同随机 nonce、序号和原退出码；每条输出保留原 SDK 字节，解析后仅按边界切片，不修正换行、不忽略 stderr。

每个 stdout 成员最多 4 MiB，stderr 成员最多 64 KiB；缺失／重复／错序／截断边界、退出码不一致、超界或未知输出拒绝。成员失败按原顺序交回读取方，未消费的第二条输出也保留。物理 SDK 超时的部分原件与已完整解码的成员错误分别记录，不把半个合批回复伪装为某条完整命令的输出。

- `points/NNN/commands.json` 继续记录逻辑查询及 `nativeEvidence` 引用。
- `points/NNN/native-sdk/` 保存每次真实 SDK 调用的命令、原始 stdout／stderr、哈希、时点、成员边界和结果。
- `journey-memory-sdk/commands.json` 是独立的真实 SDK 台账，需与每点原件核对；逻辑读取数不能称为 SDK 调用数。
- `native-sdk/result.json` 同时列出已消费和未消费成员。错误或提前拒绝后，不丢弃预取到的原始输出，也不回退重发。

周期 2 秒、上限 192 点、单点 20 秒、SDK 调用 10 秒、阶段 45 秒、总计 240 秒与 512 次 UI 请求均保持。两个成员共享更短的原 SDK／采样剩余预算；十二个异步边界及最终确认要求保持。
