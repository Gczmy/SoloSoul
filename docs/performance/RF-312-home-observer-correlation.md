# RF-312：首页像素与辅助功能节点对照

2026-10-16，已确认当前默认 Release 的首页会实际绘制正确的100和5000对象总数，而API31／WebView91的外部辅助功能树可能持续返回旧占位符。逐节点刷新、清除框架缓存和重建观察器连接均未形成可靠的完整队列。**三个队列继续拒绝，接受的性能样本为0；未登记首页统计产品缺陷，RF-312保持未完成。**

## 来源与实际结果

复用525da2ea0实际构建的默认非debuggable Release，APK SHA为`e16dd7cdb2e7c1084a9215f5cc1e5fda2a3d4d65687b42363727528629e7acfd`。本轮工作区HEAD为70192a22e，1795项产品输入继续一致，没有产品源码、feature、前端或APK变更。所有队列使用同一公开媒体夹具、专用API31/x86_64模拟器、2核／2048MiB／SwiftShader及WebView91.0.4472.114。

| 方法 | 实际执行 | 结果与图像对照 |
|---|---|---|
| 逐节点刷新 | 100对象一组 | 三对截图／树；分别刷新63、60、60节点，过期节点均0。后两张实际显示100，但刷新前后树仍为占位符；45秒门禁拒绝。 |
| 框架缓存清理 | 100→5000 | 100单组满足条件；5000四次图像实际均显示5000，节点仍是占位符，整队拒绝。不能从100单组推断方法可靠。 |
| 观察器连接重建 | 计划100→5000，实际只执行100 | 自身连接重建一次，随后出现过期节点；100拒绝后停止，没有启动5000。实际尾帧仍显示100。 |

分类按钮的真实辅助功能标签是“Identity 0 objects”，入口原先要求完全等于“Identity”也会错误拒绝。本轮修正为完整的名称／数字／单位匹配，保留首页总数必须精确等于公开夹具规模的断言。夹具对象类型是note，不能要求Identity分类数量等于总数。

29、31、34项协议测试分别通过，独立观察器均实际重新编译并核对源件／DEX／包签名。观察器只插桩自身包，目标应用未运行测试runner、未注入JavaScript；恢复用Debug主包／测试包仍按原流程安装并核对。原生唯一节点、物理边界、单手指DOWN／UP及公开密码输入检查保持。单阶段45秒、观察器240秒／512请求、正常停止10秒预算保持；截止时的短命令超时不单独归因于ADB性能。

Android文档说明[`AccessibilityNodeInfo.refresh()`](https://developer.android.com/reference/android/view/accessibility/AccessibilityNodeInfo#refresh())会请求视图当前状态；[Android12框架实现](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/android-12.0.0_r1/core/java/android/app/UiAutomation.java)中的`setServiceInfo`会清除客户端缓存。重新应用相同配置以及通过[公开连接入口](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/android-12.0.0_r1/core/java/android/app/Instrumentation.java)重建自身连接，在本轮仍不足以保证虚拟节点更新；不扩称通用缓存修复。

## 新观测通道准备

本机Windows原生OCR已实际读取四张公开截图：正确100、正确5000、占位符首页及登录表单。14项边界测试通过，校验截图字节SHA与物理尺寸、唯一My vault／Local vault上下文、唯一精确数字、主数字字号与列位置、同行objects单位；错误规模、重复数字、旧图绑定、越界／布尔坐标和非主统计字号均拒绝。不做O／0等模糊字符替换。

WinRT文件代理在沙箱内返回Access denied，随后仅对指定公开PNG执行授权范围内的沙箱外只读识别成功。识别与校验源码已保存，但**尚未接入新的实时原生队列**，不能用离线读图追认上述失败或作为性能样本。下一步用独立新队列，在原阶段预算内同时绑定前台、进程身份、实时截图与完整数字／区域条件，再验证两档解锁和后续完整行程。
