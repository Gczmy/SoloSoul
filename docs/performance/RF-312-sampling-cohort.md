# RF-312：六对采集开关重复的离线统计

本入口处理[公开原生队列](rf312-native-queue/README.md)提前冻结的六对重复，独立于旧五轮序列及旧私有四格预跑。它只读取经原生验收和独立回放核对的去标识投影，不启动 SDK、不派发输入，也不代替原读取器或原件回放。

## 统计口径

固定顺序为关→开、开→关交替三次；每种模式仍按 100→5000 对象执行。六对、十二个模式、二十四个档位全部保留，失败后不续接后档，也不以另一次环境替换缺失格。

每个模式有 `accepted`、`refused`、`awaiting-terminal-evidence` 三种状态。缺少终态验收证据只表示数据尚不可用，不能据此断言进程运行、退出或失败。进程状态仍须核对实际工具句柄。拒绝另外区分预检、行程、恢复、回放和宿主收尾；两个档位分别保留成功前缀、拒绝、未执行或待终态状态。

完整通过原生恢复与独立回放的模式才进入数值分布。失败模式已完成的前缀仍保留原数值与证据摘要，统计时排除；未执行或待终态格不会写成零，也不会计为有效样本。同一对的开、关均通过时才计算该对的开启减关闭差值，保留有符号结果。它是描述性差值，不代表采集的因果成本。

分别报告十二阶段、完整工作负载窗口、行程后串行 PSS 的有效样本数、中位数、最近秩经验 P95 和最大值。最多六个样本时，该经验 P95 等于最大值，不是总体尾部估计。工作负载窗口包含观察、核验及模式初始化／收尾，后置内存点另计，不能解释为应用本体时延。

开启组另保留各轮全部阶段边界、有效数值点、漏采槽位和实际周期拒绝。`allPeriodicCapturesSucceeded` 只描述实际发起的周期采集，允许同时存在漏采槽位；两者分别核对。串行已采样最大 PSS 不能证明原子总量或连续峰值。

## 首两对结果快照

十二个计划模式中，三个完整通过、一个预检拒绝、八个尚未执行；只有首对的开／关均完整通过。关闭组每档两轮有效样本，开启组每档一轮。下表的经验尾值仍只是小样本描述。

| 采集 | 对象数 | 有效／计划样本 | 窗口中位数（秒） | 窗口经验 P95（秒） | 后置串行 PSS 中位数（MiB） |
| --- | --- | --- | --- | --- | --- |
| 关闭 | 100 | 2/6 | 130.930 | 134.078 | 243.062 |
| 关闭 | 5000 | 2/6 | 121.882 | 122.484 | 276.496 |
| 开启 | 100 | 1/6 | 138.094 | 138.094 | 250.703 |
| 开启 | 5000 | 1/6 | 142.453 | 142.453 | 268.652 |

第二对开启组在应用测试前的只读准入探针遭遇 Windows socket 10013 权限拒绝，两个档位均未启动，没有记入数值或用新环境补跑替换。原拒绝、SDK 日志、原生父结果和严格清理证据均保留。随后关闭组在具备端口权限的执行环境中通过同一探针及全部原验收，未改变读取规则、字节处理或预算。

本次关闭组新增 24 个阶段、346 份 UI 状态证明及 8 份共同内存状态转储的独立回放；累计三个完整模式为 72 个阶段。回放没有执行 SDK 或派发输入。新六对统计 15 项、旧五轮统计 13 项回归全部通过，零跳过，输入另绑定四份代码／测试与实际测试日志摘要。测试在原生队列结束、SDK 清理后执行。

本地测试审计封装的 Windows 参数假设、投影脚本对原范围标志的错误假设，各有一次失败原件保留；修正的是本地封装和投影，不改统计器、原读取器或原生证据。这些失败不作为性能样本。`fullDefaultJourneyAccepted` 等原范围标志仍为 false；模式通过仅描述本轮 UI／恢复／独立回放验收。

## 来源与投影

[统计输入](rf312-sampling-cohort-input-2026-10-18.json)保留原生父结果、独立回放、阶段、共同内存检查点和拒绝证据的 SHA。公共绑定包含默认 APK／库、产品来源快照、97 份运行代码、12 份队列代码、两份额外启动身份源件、原内存读取器及测试、公开夹具、环境、原计划、Observer 和 Java UI 包。各模式必须使用同一绑定；原 240／45／5／20／10 秒预算不能改变。

投影的阶段取自 `supported-state-evidence.json`；工作负载窗口取自 `measured-workload-window.json`；后置 PSS 取自原共同检查点并与状态回放核对；完整轨迹的计数和拒绝取自 `independent-memory-r1.json`，同时绑定原轨迹 SHA。模式只有在父级原生结果和独立回放均通过、原恢复及严格宿主后验已核验时才能标为通过。投影摘要本身不证明这些条件，必须保留并先检查原件。

原计划 SHA 按原文件字节计算；运行、队列及额外启动来源按已公开的对应 SHA 映射计算规范 JSON 摘要。产品快照摘要覆盖运行输入的工作区与外部来源映射；夹具摘要覆盖两个 Vault 的全部冻结文件摘要及公开 OCR 图片摘要。环境摘要取自首对验收文档的通用环境快照，它不是每轮资源占用记录，也不能证明宿主负载完全一致。

## 复算命令

```powershell
python -B docs/performance/rf312_sampling_cohort.py `
  --input docs/performance/rf312-sampling-cohort-input-2026-10-18.json `
  --output $newSummaryPath
```

输出路径必须全新，建议位于 D 盘。命令绑定输入原字节及两个统计源件的 SHA，写入 LF JSON，拒绝覆盖已有结果。可以与[已归档统计结果](rf312-sampling-cohort-summary-2026-10-18.json)逐字段比较；原生时延不被复算耗时替代。在 TEMP／TMP 已设为 D 盘的测试进程中，可运行下列定向回归：

```powershell
python -B -m unittest discover -s docs/performance -p test_rf312_sampling_cohort.py -v
python -B -m unittest discover -s docs/performance -p test_rf312_repeat_summary.py -v
```

定向回归同时执行 `test_rf312_sampling_cohort` 和旧 `test_rf312_repeat_summary`，旧五轮入口的条件不变。
