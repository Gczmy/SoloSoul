# RF-312：状态读取与控制交换的成本排查

状态读取继续使用直接 SDK。隔离探测中，候选复合通道更慢，因此不接入默认行程；完整采集对照及 RF-312 保持未完成。

## 已有行程的实际开销

基于 `b8cdc1086` 的 92 份来源，逐项匹配此前两轮七个已启动场景的原始状态输出、解析结果与 SDK 账本，共复核 1059 份有效状态证明。五个完整场景的状态命令累计为 13.013～13.848 秒，常见单次中位数为 63～78 毫秒。两个失败场景分别保留 66／149 份证明，不能并入完整分布；原 5 秒超时的空部分输出仍不构成状态证明。

另对首轮关闭采集、100 对象的 342 次控制交换逐帧重解码，并与原始观察器响应逐字节比对。交换 RPC 累计 135.108 秒，响应内原生动作区间累计 22.654 秒。这是不同边界下的诊断分解；差额包含传输、文件协议、等待等成本，具体归因尚未证明，不能当作应用本体耗时或声称全部来自子进程创建。

## 新建 AVD 的同命令探测

API31／x86_64、2 CPU／2048 MiB、SwiftShader，使用全新隔离 AVD。未安装产品 APK 或 Observer；先实际检查 Launcher 截图、窗口归属、ANR 与 DropBox，再运行固定只读命令 `dumpsys activity processes`。

12 对读取交替采用 SDK→控制、控制→SDK，每种通道 12 次。临时候选为状态读取新增固定 `process-state` 操作，无自由命令、缓存、失败重发或回退。每次完整原始输出均由现有状态解析器核验，要求无活动插桩、存在 Launcher、空 stderr 与零退出码，保留原 5 秒上限。

| 通道 | 样本数 | 中位耗时 | 最小／最大耗时 |
| --- | --- | --- | --- |
| 直接 SDK | 12 | 78.0 ms | 62.0／203.0 ms |
| 候选复合通道 | 12 | 538.5 ms | 422.0／672.0 ms |

计时包含本次读取的回执写入和共同解析，不能与旧账本中仅 SDK 调用区间直接相减。候选没有显示收益，保持为本地实验，不进入仓库运行代码，也不据此解释此前偶发超时。

24 份状态原件、12 次 SDK 读取与 14 个控制帧（握手、12 次读取、关闭）均独立回放。控制正常关闭、专用临时目录移除、系统设置一致、SDK 正常退出，严格宿主后验进程／监听归零。临时协议的 34 项相关测试通过；已提交运行代码保持原 174 项验证的来源，无新增产品改动。

实验复用了外层执行器，原始清单中继承的 UI 派发／复合 UI 标志及预检对象顺序不作为本次行为证明；实际范围以专用探测回执、命令与控制帧为准。原清单保持原样，另存范围澄清与独立复核，未声称执行固定 Vault 行程。
