# RF-312 当前 Windows 原生后端子基线（2026-10-15）

当前源码的后端例程已完成 100/5,000 对象、每组操作 10 次的重复采样，80 个操作样本全部成功。它测量 Rust Vault 后端，不包含 GUI 启动、IPC、绘制、OCR、附件预览或内存，RF-312 的多端应用验收仍未完成。

## 来源与复跑

- Windows 11 Enterprise LTSC 10.0.26100，Intel Core i7-9700，8 核/8 线程，可见内存约 15.8 GiB；运行后核对的 Rust/Cargo 为 1.96.0。
- Release、`solosoul-core --no-default-features`。KDF 实际为 64 MiB、3 次、并行度 4；关闭媒体 features，不能视为默认 GUI 的性能。
- 每档使用一个自动清理的独立合成 Vault，写入 100/5,000 对象。每第 20 个对象含 `needle`，搜索返回 5/250，元数据列表返回 100/5,000；创建数据的时间不计入操作样本。
- 无编译与采样重叠，普通系统及应用后台活动未完全隔离。没有清除 OS/存储缓存，也没有系统冷启动测量。

在仓库 `tauri/` 目录运行：

```powershell
cargo run --locked --release -p solosoul-core --no-default-features --example perf_baseline -- --objects 100 --samples 10
cargo run --locked --release -p solosoul-core --no-default-features --example perf_baseline -- --objects 5000 --samples 10
```

每条命令最后一行是结果 JSON，此前可能有文件权限日志。例程使用临时合成账户，不读取默认用户 Vault。本轮两档均 exit 0，返回条数、实际 KDF、全部样本及临时目录清理已核验。

## 测量口径与结果

解锁先预热一次，每次样本执行真实锁定和主密码解锁，包含 KDF 与 Vault 打开。元数据列表、解密搜索各预热一次后连续取 10 次。最后释放原 Vault 与服务，再为每个账户目录样本创建新的独立服务、加载并列出账户；该项没有额外显式预热，存储缓存已因此前读写变热。

单位为毫秒，每格为中位数 / p95。中位数取中间两项均值，p95 用最近秩；n=10 时 p95 等于该组最大值。

| 操作                 |          100 对象 |        5,000 对象 |
| -------------------- | ----------------: | ----------------: |
| 独立服务账户目录载入 |     0.433 / 0.524 |     0.416 / 0.596 |
| 主密码解锁           | 235.784 / 277.970 | 239.394 / 350.378 |
| 元数据列表           |     0.247 / 0.460 |   11.161 / 11.650 |
| 解密搜索             |     0.677 / 0.715 |   38.333 / 40.074 |

当前主机上，5,000 对象的后端搜索中位数约 38 ms，解锁约 239 ms。这些时延没有包含前端排队、传输、渲染和可交互等待，不能推断实际页面响应或其他设备表现。相同算法下的更大数据、默认 GUI、移动设备及系统冷启动仍需独立采样。

RF-1158 将账户目录测量移到其他测量之后，生产根锁保持排他。与[2026-09-28 历史基线](RF-312-native-vault-baseline.md)的数值不作相减归因；当前证据不足以决定全路由懒加载或分页改造。
