## 3. 详细分析与操作指示

### 3.1 P0 级：最大削减，建议优先处理

#### P0-1 合并 `commands/rag.rs` 到 `commands/llm/rag.rs`

**问题**：`commands/rag.rs`（~384 行）包含 chunking、content hash、rebuild 标记等逻辑，而 `commands/llm/rag.rs` 负责 embedding API。两者同属 RAG 链路，却被拆成两个文件，造成跨文件跳转和维护成本。

**操作步骤**：
1. 将 `chunk_all_guides`、`compute_content_hash`、`needs_rebuild`、`mark_rebuilt` 迁入 `commands/llm/rag.rs`。
2. 更新 `commands/llm/rag.rs` 中的导入。
3. 删除 `commands/rag.rs` 及其在 `lib.rs` 中的 `pub mod rag;` 声明。
4. 更新 `invoke_handler` 中对应的命令注册。

**验证**：
```bash
cd /Users/zzc/PycharmProjects/SoloSoul_code/tauri
cargo fmt
cargo clippy -- -D warnings
cargo test
```

#### P0-4 AES 模块轻量整理（替代完整合并）

**问题**：`aes.rs`（SOLO blob 格式）与 `cipher.rs`（generic AES-256-GCM with AAD）是两个不同协议层。完整合并会破坏 `.solosoul` 导出格式兼容性，风险高。

**建议的低风险路径**：
1. 统一错误类型：将 `aes.rs` 的 `String` 错误替换为 `cipher.rs` 的 `CipherError`。
2. 在 `cipher.rs` 中重新导出 `aes.rs` 所需类型，统一对外错误风格。
3. 删除 `aes.rs` 中为兼容而重复的 `String` 分支。

**注意**：不要修改 `.solosoul` blob 格式，保持向后兼容。
