## 验收目标

- 窗口首个可见帧已有图标，进入解锁页不闪空白，不设置人为最短启动时长。
- 初始化失败、长时间等待与重试均有反馈；账户未确认时不展示工作区。
- 系统材质透过外壳，正文/输入/敏感字段保持可读；主题更新不以实色覆盖材质。
- 保留 macOS 窗口按钮与全屏、Windows 拖动/缩放/贴靠行为。
- 浅深色、透明关闭、高对比度、减少动态效果、Windows DPI 缩放均有对应验证。
- 所有实际验证和未完成验证分别记录，不以浏览器模拟替代原生系统材质验证。

## D07 Windows 深色登录背景（2026-09-12）

- 原生复现：Windows 的系统模式与应用模式均为浅色（`AppsUseLightTheme=1`、`SystemUsesLightTheme=1`），SoloSoul 自身选择深色。登录卡片正确变深，但卡片外 Mica 与原生标题栏仍为浅色。
- 原实现只直接写 DWM 深色属性，没有更新 Tauri/tao 保存的窗口主题。tao 0.35.3 在 `WM_SETTINGCHANGE` 时会依据保存的窗口主题重新应用 DWM 属性；未设置窗口偏好时继续采用系统主题，与前端显式深色不一致。
- 在应用 Mica/实色回退前调用 `window.set_theme(Some(...))`，同步已经解析的应用浅深色，让框架主题状态、原生重绘和页面配色一致。跟随系统模式仍由现有系统主题轮询解析，不改变全局 Windows 偏好。
- Rust fmt、严格 Clippy 通过；Vite 生产构建与生产包启动/Markdown E2E（1 项）通过。Windows 原生程序重建成功（7m58s）。
- 在同一 Windows 11 Build 26100、系统浅色/应用深色配置下重新启动本次构建：登录卡片、卡片外 Mica 背景和标题栏均为深色；最大化及恢复窗口后配色保持一致。核实运行路径为 `tauri/target/debug/solo_soul.exe`。未改动系统主题，本次不扩充系统偏好切换与其他系统版本的验收结论。

## D08 Windows 背景匹配主题配色（2026-09-12）

- D07 只解决原生浅深色一致性。Mica 仍取 Windows 壁纸色，暖石深卡片与偏冷背景不搭配；这次按用户要求使应用主题配色主导外壳。
- Windows Mica 在 `html` 底层仅叠加一次 90% 当前 `--bg-base`，保留 10% 原生材质透出。启动层、登录页和工作区共享该背景；`body`、`#root` 与启动层保持透明，避免多层重复着色。应用样式尚未加载时使用启动缓存色；实色回退也读取当前主题色。
- Windows 原生标题栏采用同一主题底色，高对比度时继续使用系统颜色。macOS 的原生材质透出规则保持原样。
- 同为深色或浅色时切换配色方案，除 CSS 配色外也刷新原生窗口，避免标题栏停留在上一方案。
- TypeScript、定向 ESLint、Rust fmt 与严格 Clippy 均通过。
- 生产包 E2E 共 7 项通过（新增 6 项）：暖石深、深海、森夜、柔奶油登录背景；同模式切换时背景与标题栏颜色一致；无 Mica 时切换不被启动缓存锁定。8 项启动 E2E 通过，覆盖缓存、首帧、材质透出与强制颜色回退。浏览器使用原生响应 mock，不代替真实 Mica 观感验收。
- Windows 程序重建通过（7m07s）。在 Windows 11 Build 26100 启动本次 `tauri/target/debug/solo_soul.exe`，暖石深登录页外侧背景及标题栏呈协调的暖棕色，卡片保持稍亮的同色系层次；最大化后配色保持一致。其他配色方案的动态切换由生产包 E2E 覆盖，本次原生视觉验收限定于当前暖石深配置。
- 依据：[Microsoft Mica](https://learn.microsoft.com/en-us/windows/apps/design/style/mica) 的系统主题/壁纸取色行为与 [DWM 标题栏颜色属性](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwmwindowattribute)。
