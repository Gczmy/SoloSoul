## 1. 背景与目标

### 1.1 产品诉求
- **云打包 (R1)**：用户登录百度网盘 / OneDrive 等云盘后，一键把数据打包上传到云盘指定位置。
- **云同步 (R2)**：自动把用户的云盘中 SoloSoul 数据保持最新（增量快照的定时发布/订阅，等价于「用云盘当离线消息总线」）。

### 1.2 零知识架构红线
> **上云的永远只有口令加密的快照包（`.solosoul` / 备份快照），活库（SQLite 目录树）绝不直接放同步目录**——会被双向同步写坏库。这是与项目「独奏生命数据，重塑数字原点」哲学兼容的唯一姿势。

### 1.3 现有可复用基础设施（调研时已确认）
| 能力 | 位置 | 说明 |
|------|------|------|
| 加密导出包 `.solosoul` | `crates/solosoul-core/src/export_import.rs` | Argon2id 口令派生 + AES-256-GCM，ZIP 内含 `manifest.json` + `payload.enc` + `attachments/*.enc` |
| 备份快照 `backup_create` | `src-tauri/src/commands/backup.rs` | Profile 级快照 |
| Android SAF 双向同步 | `state/app_state.rs` + `fs/saf_sync_driver.rs` + Kotlin 插件 | `syncDirToRemote` / `syncDirFromRemote` 已有驱动 |
| 桌面 OneDrive 白名单 | `commands/fs.rs:89-107` | `~/OneDrive`、`OneDrive - <Org>` 已在附件白名单内 (N010) |
| 设备同步引擎 | `crates/solosoul-sync/` | HLC 增量水印 + Noise XX + mDNS 局域网 P2P，增量协议/冲突检测可借鉴 |

## 3. Phase 2：云同步（进行中）

### 3.1 已完成：核心基础设施（提交 `704adf9f`）

#### 3.1.1 `CloudConnector` trait (`crates/solosoul-core/src/cloud_sync/mod.rs`)

```rust
#[async_trait]
pub trait CloudConnector: Send + Sync {
    fn connector_type(&self) -> &'static str;
    async fn test_connection(&self) -> CloudResult<()>;
    async fn ensure_dir(&self, remote_path: &str) -> CloudResult<()>;
    async fn upload(
        &self,
        remote_path: &str,
        reader: Pin<&mut (dyn AsyncRead + Send + Unpin)>,
        total_size: u64,
    ) -> CloudResult<(String, String)>; // (remote_path, etag)
    async fn download(
        &self,
        remote_path: &str,
        writer: Pin<&mut (dyn AsyncWrite + Send + Unpin)>,
    ) -> CloudResult<u64>;
    async fn list(&self, remote_path: &str) -> CloudResult<Vec<CloudObjectMeta>>;
    async fn delete(&self, remote_path: &str) -> CloudResult<()>;
    async fn head(&self, remote_path: &str) -> CloudResult<CloudObjectMeta>;
}
```

**设计原则**：
- 仅在 Vault 解锁态可用（凭证入 Vault 加密存储，主密钥派生）
- 上传内容**仅限** `.solosoul` 加密快照包（零知识承诺）
- 分片上传（RFC 4918 `PUT` + `Content-Range`），支持断点续传
- 云端布局：
  ```
  /SoloSoul/{account_id}/snapshots/{device_id}/{hlc}.solosoul
  /SoloSoul/{account_id}/latest.json  ← 索引文件
  ```

#### 3.1.2 `WebDavConnector` (`crates/solosoul-core/src/cloud_sync/webdav.rs`)

**支持标准 RFC 4918 服务器**：
- 坚果云 (`https://dav.jianguoyun.com/dav/`)
- Nextcloud / ownCloud
- Alist (聚合 40+ 网盘的 WebDAV 网关)
- 自建 WebDAV (nginx/apache + dav 模块)

**核心能力**：
- **Basic Auth**（Base64 `username:password`，配置入 Vault 加密存储）
- **分片上传**：8 MiB 默认分片，顺序 PUT + `Content-Range: bytes start-end/total`，兼容坚果云/Nextcloud/Alist
- **目录递归创建**：`ensure_dir` 逐级 MKCOL
- **PROPFIND 列表**：Depth: 1，解析 `<d:href>`/`getcontentlength`/`getlastmodified`/`getetag`/`resourcetype`
- **HEAD 请求**：获取单文件元数据（ETag/Content-Length/Last-Modified）

**配置结构** (`WebDavConfig`)：
```rust
pub struct WebDavConfig {
    pub base_url: String,      // 如 "https://dav.jianguoyun.com/dav/"
    pub username: String,      // 坚果云用邮箱，Nextcloud 用用户名
    pub password: String,      // 密码 / App Token
    pub root_prefix: String,   // 默认 "/SoloSoul/"
}
```

**工厂函数**：`create_connector(&CloudSyncConfig) -> Arc<dyn CloudConnector>`，当前仅支持 `webdav` 类型。

## 4. 核心技术要点汇总

### 4.1 零知识合规检查清单（每次上云代码变更必过）

| 检查项 | 通过标准 |
|--------|----------|
| 上云内容 | 仅 `.solosoul` 加密包 / 备份快照，无明文 Vault 文件 |
| 口令派生 | Argon2id（production：64 MiB / 3 iter / 4 lanes），前端密码确认框强制不等于主密码 |
| 密钥管理 | 包加密密钥 = `derive_export_key(password, salt)`，salt 随机 16 字节存 manifest |
| 凭证存储 | 云盘用户名/密码/Token 入 Vault 加密字段，仅解锁态解密，锁定即清零 |
| 传输加密 | HTTPS（WebDAV/Graph API 均强制 TLS），不落盘明文 |

### 4.2 大文件流式处理（避免 OOM）

- **导出**：`export_import::write_payload_to_temp` → 临时文件 → 流式加密进 ZIP（`encrypt_chunked_stream`）
- **上传**：`WebDavConnector::upload` 8 MiB 分片顺序 PUT，内存常驻 ≤ 16 MiB
- **下载**：`bytes_stream()` 流式写入 writer，不全量缓冲
- **导入**：流式解密 + 临时文件序列化（P026）

### 4.3 云端布局与版本管理

```
SoloSoul/
└── {account_id}/
    ├── snapshots/
    │   └── {device_id}/
    │       ├── {hlc_1}.solosoul
    │       ├── {hlc_2}.solosoul
    │       └── ...
    └── latest.json          ← 索引：device_id → {hlc, path, etag, size, uploaded_at}
```

**保留策略（GFS 简化版）**：
- 最近 N 份全量保留（默认 10）
- 每日：0 点最近一份
- 每周：周一最近一份
- 每月：1 号最近一份
- 清理时保留上述规则覆盖的快照，其余删除（DELETE 请求）

### 4.4 错误处理与重试

| 场景 | 策略 |
|------|------|
| 网络超时 | 上传分片重试 3 次（指数退避），下载流式重试 |
| 401/403 | 清除 Vault 中凭据 → 提示重新授权 |
| 409 冲突 | 上传前 HEAD 对比 ETag，不一致则跳过并记录冲突 |
| 磁盘空间不足 | 导出前 `export_estimate_size` 预估，空间不足提前拦截 |

### 4.5 移动端特殊处理

| 平台 | 方案 |
|------|------|
| Android | SAF DocumentsProvider（OneDrive/坚果云/Nextcloud App 均暴露 SAF）→ 现有 `TauriSafSyncDriver` 双向同步驱动直接复用，**无需 WebDAV 连接器** |
| iOS | FileProvider / iCloud Drive / Files App 暴露的文件夹 → 待调研 FileProvider Extension 方案 |

> **注意**：移动端云同步**不走 WebDAV/Graph API**，直接利用系统级文件提供者同步。桌面端无系统级同步器，故需 WebDAV/Graph API 连接器。

### 5.6 常见坑位提醒

| 坑位 | 避坑指引 |
|------|----------|
| `reqwest::StatusCode` 不能直接 `Error::from` | 用 `CloudSyncError::Internal(format!("HTTP {}", status))` |
| `resp.bytes_stream()` 需 `futures::StreamExt` | `use futures::StreamExt; while let Some(chunk) = stream.next().await { ... }` |
| `async-trait` 在 wasm32-wasip1 上需 `#[async_trait(?Send)]` | 目前仅桌面端编译（`#[cfg(not(target_arch = "wasm32"))]`），插件侧暂不引用 |
| `tokio::io::AsyncRead` + `Pin<&mut dyn ...>` | 函数签名用 `Pin<&mut (dyn AsyncRead + Send + Unpin)>` |
| WebDAV `PROPFIND` 命名空间 | 简易解析器已在 `parse_propfind_response`，完整场景建议引入 `xmltree` 或 `roxmltree` |
| 坚果云分片上传 | 单文件顺序上传分片，最后无需显式完成请求（上传完即完成），但需 HEAD 确认 ETag |
| `allowed_fs_bases` 修改需同步两处 | `attachment/mod.rs` 与 `fs.rs::desktop_fs_bases()` 注释已标注同步维护 |

### 7.2 发现并修复的三项协议缺陷

| # | 缺陷 | 根因 | 修复 | 严重度 |
|---|------|------|------|--------|
| 1 | **大文件上传被服务器 400 拒绝** | 原实现按 8MiB 分片对同一资源多次 PUT + `Content-Range`——RFC 4918 的 PUT 无部分写语义，wsgidav 直接 400；坚果云等真实服务器同样会失败 | 改为**单次流式 PUT**：`reqwest::Body::wrap_stream(ReaderStream::new(reader))`，请求体边读边发、内存常驻恒定，任意大小文件均适用。trait 签名改为接管所有权 `Pin<Box<dyn AsyncRead + Send>>` | 🔴 致命 |
| 2 | **list() 返回空列表** | PROPFIND 解析只认 `<d:` 小写前缀；wsgidav 输出 `<D:`（大写）、其他服务器可能 `ns0:`。且基路径比较未归一化前导 `/`，目录自身条目混入结果 | 新增 `strip_xml_ns_prefixes` 归一化任意前缀 + `percent_decode` 解码 href + 双方剥离前导斜杠后比较基路径 | 🔴 高 |
| 3 | **认证错误归类错误** | `test_connection` 把 401 归为 `ConnectFailed`，前端会误导用户「服务器不可达」而非「密码错误」 | 401/403 显式映射 `AuthFailed` | 🟡 中 |
