## 1. 设计理念：温暖的数字堡垒

SoloSoul 管理用户最私密的数字资产，界面必须传递**安全感**与**温度感**的平衡：

- **安全 ≠ 冰冷**：暖白 + 低饱和蓝灰，像一本精心装帧的个人手账
- **隐私 ≠ 隐藏**：敏感信息用分级遮罩（毛玻璃模糊 + 渐变蒙层），不是粗暴黑块
- **专业 ≠ 复杂**：操作路径不超过三步

### 三个设计原则

```
1. 内容优先，材质服务于内容
   玻璃/云母效果只能增强信息层级，不能干扰阅读

2. 平台原生，体验统一
   各平台用各自的材质语言，但交互逻辑、信息架构完全一致

3. 降级优雅，从不破碎
   不支持新材质的平台自动获得精心设计的回退方案
```

## 2. 材质决策矩阵

| 平台 | 系统版本 | 首选材质 | 回退材质 | 技术实现 |
|------|---------|---------|---------|---------|
| **macOS** | 15+ (Sequoia) | Liquid Glass | Acrylic 模糊 | CSS backdrop-filter + WebGL |
| **macOS** | 14 及以下 | Acrylic 亚克力 | 纯色 + 投影 | CSS backdrop-filter: blur() |
| **iOS** | 26+ | Liquid Glass | 标准模糊 | CSS backdrop-filter |
| **iOS** | 25 及以下 | 标准模糊 | 纯色层级 | CSS 模糊或预渲染纹理 |
| **Windows** | 11 (22H2+) | Mica Alt | Mica | Tauri 原生 DWM API |
| **Windows** | 10 | Acrylic | 纯色 + 投影 | CSS backdrop-filter |
| **Linux** | 不限 | 自定义模糊 | 纯色 | CSS backdrop-filter（视 compositor） |
| **Android** | 14+ | 原生模糊 | 纯色层级 | CSS / Canvas 模糊回退 |

## 3. 材质层定义

```
┌─ Layer 3: Content Glass（内容玻璃层）─┐
│  卡片、弹窗、浮层 — 最高模糊 + 折射高光  │
│  blur(40px) + saturate(180%) + 内发光   │
├─ Layer 2: Toolbar Glass（工具栏层）────┤
│  侧边栏、顶部栏 — 中等模糊              │
│  blur(20px) + 细微边框                 │
├─ Layer 1: Base Surface（基底材质层）───┤
│  窗口背景 — 平台决定                    │
│  macOS=液态玻璃 / Windows=Mica / 回退=纯色│
└────────────────────────────────────────┘
```

### 4.3 主题系统规范（Theme System）

SoloSoul 主题系统参考 Warp 终端的设计理念，在提供精致预设主题的同时，允许用户深度自定义视觉体验。所有主题配置通过 CSS 变量驱动，切换即时生效。

#### 4.3.1 预设主题

| 主题 ID | 模式 | 名称 | 说明 |
|---------|------|------|------|
| `warm-stone-light` | 亮色 | Warm Stone Light | 默认主题，暖石调（象牙白 + 低饱和蓝灰） |
| `warm-stone-dark` | 暗色 | Warm Stone Dark | 暗色主题，深灰基底 + 稍亮蓝灰强调 |
| `system` | 自动 | 跟随系统 | 根据操作系统主题设置自动切换亮/暗 |

#### 4.3.2 主题色自定义（Accent Color）

用户可替换默认 `--accent-primary` 主题色。提供 4 种预设色板 + 自定义 HEX：

| 预设色名 | 亮色模式色值 | 暗色模式色值 | 风格关键词 |
|----------|-------------|-------------|-----------|
| `ocean` | `#5B7C99` | `#7BA3C4` | 蓝灰（默认，信任、冷静） |
| `amber` | `#C4925C` | `#D4A76A` | 琥珀（温暖、活力） |
| `forest` | `#5B8C6F` | `#7AAF8F` | 森林绿（自然、安全） |
| `rose` | `#B06B7A` | `#D48A9A` | 玫瑰粉（私密、柔和） |
| `custom` | 用户自选 HEX | 用户自选 HEX | 任意色值，由用户通过取色器指定 |

**主题色替换范围**：
- 侧边栏当前页指示条、焦点环、主按钮背景
- 链接色、选中态复选框/开关
- 敏感度 `public` / `internal` 图标色调（保持色相但自动调整饱和度以确保可读性）

#### 4.3.3 背景自定义（Background）

参考 Warp 背景自定义能力，提供三级背景选项。背景仅作用于 `--bg-base`（全局画布层级）：

| 类型 | 选项 | 技术实现 | 说明 |
|------|------|---------|------|
| **纯色** | 12 种预设纯色 | CSS `background-color` | 包含 Warm Stone 系列、冷灰系列，保证与文字对比度 ≥ 4.5:1 |
| **渐变** | 6 种预设渐变 | CSS `linear-gradient` | 低饱和暖色渐变，如 `linear-gradient(135deg, #FAFAF8, #F0EDE8)` |
| **图片** | 用户自选本地图片 | `background-image` + 遮罩叠加 | 支持 JPG/PNG，自动叠加 `rgba(0,0,0,0.15)` 或 `rgba(255,255,255,0.15)` 可读性遮罩 |

> **安全约束**：背景图片**禁止使用在线 URL**（违反本地优先原则），仅允许读取本地文件系统路径（`~/.solosoul/themes/` 目录）。

#### 4.3.4 主题配置文件

主题配置属于**非敏感 UI 偏好**，存储于 Vault 外的明文文件 `ui_preferences.json`（登录前即可读取）。仅背景图片路径等可能涉及隐私的信息需额外注意：

```typescript
interface ThemeConfig {
  preset: 'warm-stone-light' | 'warm-stone-dark' | 'system';
  accentColor: 'ocean' | 'amber' | 'forest' | 'rose' | 'custom';
  customAccentHex?: string;       // 当 accentColor === 'custom' 时生效
  backgroundType: 'solid' | 'gradient' | 'image';
  backgroundValue: string;        // 色值、渐变 CSS 字符串、或本地图片绝对路径
}
```

#### 4.3.5 主题切换机制

- **即时生效**：修改主题配置后，通过 `document.documentElement.style.setProperty()` 即时更新 CSS 变量，无需刷新页面。
- **系统跟随**：当 `preset === 'system'` 时，监听 `prefers-color-scheme` 媒体查询（或 Tauri `theme-changed` 事件），自动在 `warm-stone-light` 与 `warm-stone-dark` 间切换。
- **材质自适应**：背景为图片或高饱和渐变时，自动提升玻璃层模糊强度（`blur(20px)→blur(40px)`）并降低内容层透明度，确保文字可读性。

#### 4.3.6 正例与反例

```css
/* 错误：硬编码色值，不支持主题切换 */
.button-primary { background: #5B7C99; }

/* 正确：使用 CSS 变量 */
.button-primary { background: var(--accent-primary); }

/* 错误：使用在线图片 URL（违反本地优先原则） */
.bg-base {
  background-image: url('https://example.com/bg.jpg');
}

/* 正确：使用本地图片路径 */
.bg-base {
  background-image: url('file:///Users/xxx/.solosoul/themes/bg.jpg');
}
```

```tsx
// 错误：直接修改 DOM 样式而非 CSS 变量
document.body.style.backgroundColor = '#FAFAF8';

// 正确：通过 ThemeProvider 统一更新 CSS 变量
setThemeConfig({ preset: 'warm-stone-dark', accentColor: 'amber' });
// → 自动执行：document.documentElement.style.setProperty('--accent-primary', '#D4A76A');
```

## 5. 敏感度色彩编码（4 级）

| 级别 | 图标 | 遮罩强度 | 验证要求 |
|------|------|---------|---------|
| `public` | `IconSensitivityPublic`（空心圆环，暖绿色描边） | 无遮罩 | 无需验证 |
| `internal` | `IconSensitivityInternal`（单点圆点，蓝灰色填充） | blur(2px)，点击展开 | 无需验证 |
| `sensitive` | `IconSensitivitySensitive`（实心圆点，琥珀色填充） | blur(8px) + 渐变蒙层 | 需生物识别/密码 |
| `critical` | `IconSensitivityCritical`（锁形图标，深红色填充） | blur(16px) + 深色蒙层 + 锁图标 | 需密码 + 操作确认 |

## 7. 图标与图像规范

### 7.1 核心规则

1. **禁止使用 Emoji 表情**  
   任何界面元素、图标占位、状态标记、空状态插图等，均不得使用 Unicode Emoji 字符（如 `🔔`、`🔒`、`🟢`、`✅` 等）。Emoji 在不同平台渲染不一致，且与 SoloSoul 专业、安全、温暖的品牌调性不符。

2. **所有需要图像表达的位置，使用高清自定义绘制图像**  
   替代 Emoji 的必须是符合 SoloSoul 品牌定位的、高清的、风格统一的绘制图像/图标：
   - **风格关键词**：安全、严谨、温暖、私密、精致
   - **视觉语言**：低饱和暖色、圆润几何、柔和投影、无尖锐边缘
   - **技术规格**：
     - 图标：SVG 矢量，统一 24×24dp 视图框，提供 1×/1.5×/2× 密度适配
     - 插图：SVG 或 2×/3× PNG，核心空状态插图宽度 ≥ 320px
     - 色彩：使用 Warm Stone 色板，禁止 Emoji 自带高饱和色

### 7.2 实现方法（业界主流）

| 场景 | 推荐方案 | 存放路径 |
|------|---------|---------|
| 功能图标 | 自定义 SVG Icon 组件库 | `src/components/icons/` |
| 敏感度标记 | 4 级专属 SVG 图标 | `src/components/icons/sensitivity/` |
| 空状态 / 引导插图 | 设计师输出 SVG/PNG | `public/illustrations/` |
| 状态徽章 | 带图标的 Badge 组件 | `src/components/ui/Badge.tsx` |
| 临时占位 | 使用 Lucide 图标并统一二次设计 | `lucide-react` + 本地封装 |

| `public` | 🟢 | `IconSensitivityPublic` | 空心圆环，暖绿色描边 |

### 7.4 页面图标唯一映射（唯一真理来源）

**核心原则**：同一事物（页面、功能、概念）在产品的**所有位置必须使用同一个图标**。图标的定义是产品的"唯一真理来源"（Single Source of Truth），任何引用该事物的地方都必须指向这个唯一来源。

#### 7.4.1 页面图标映射表

所有页面/功能的图标集中定义在唯一映射表中，**禁止**在组件中直接 import 图标组件：

```typescript
// src/lib/pageIcons.ts — 产品的唯一图标映射表（唯一真理来源）
import {
  IconHome, IconProfile, IconTravel, IconFinancial,
  IconProfessional, IconDocument, IconSearch, IconSettings,
  IconLock, IconPlugin, IconChat,
} from '@/components/icons';

export const PAGE_ICON_MAP: Record<string, React.ComponentType<{ size?: number }>> = {
  // 默认页面
  home:           IconHome,
  profile:        IconProfile,
  travel:         IconTravel,
  financial:      IconFinancial,
  professional:   IconProfessional,

  // 自定义页面
  custom:         IconDocument,

  // 工具功能
  search:         IconSearch,
  settings:       IconSettings,
  lock:           IconLock,
  plugins:        IconPlugin,
  ai_chat:        IconChat,
} as const;

// 获取页面图标的唯一入口
export function getPageIcon(pageId: string): React.ComponentType<{ size?: number }> {
  return PAGE_ICON_MAP[pageId] ?? PAGE_ICON_MAP.custom;
}
```

#### 7.4.2 图标可编辑性分级

SoloSoul 在保证软件严谨、安全、统一视觉风格的前提下，给予用户有限的图标自定义自由度。图标分为**系统固定**和**用户可编辑**两级：

| 分级 | 范围 | 说明 | 示例 |
|------|------|------|------|
| **系统固定（不可更改）** | 软件预置的所有默认页面、功能入口、系统级图标 | 由开发团队统一维护，用户无修改入口，确保品牌一致性和操作可预期性 | 主页、个人资料、旅行、财务、职业、锁定、搜索、插件、AI 对话、设置、帮助文档、敏感度标记、安全相关图标 |
| **用户可编辑（可更改）** | 用户创建的自定义内容 | 在创建或编辑时提供图标选择器，允许用户从预设图标库中挑选 | 自定义页面图标、自定义分区图标 |

**系统固定图标的强制范围**：

```
系统固定（不可更改）：
├── 默认页面
│   ├── 主页 (IconHome)
│   ├── 个人资料 (IconProfile)
│   ├── 旅行 (IconTravel)
│   ├── 财务 (IconFinancial)
│   └── 职业 (IconProfessional)
├── 侧边栏功能按钮
│   ├── 锁定 (IconLock)
│   ├── 搜索 (IconSearch)
│   ├── 插件 (IconPlugin)
│   ├── AI 对话 (IconChat)
│   └── 设置 (IconSettings)
├── 设置页面预置功能项
│   ├── 安全设置、外观设置、数据管理、导入导出、操作日志等
├── 系统级图标
│   ├── 帮助文档、敏感度标记、安全状态指示、加密/解锁图标
└── 所有密码输入框按钮（揭示/提示）

用户可编辑（可更改）：
├── 自定义页面图标 — 创建时提供图标选择器（默认 IconDocument）
└── 自定义分区图标 — 创建/编辑时提供图标选择器
```

**用户图标选择器规范**：

| 属性 | 规范 |
|------|------|
| **触发** | 创建/编辑自定义页面或分区时，点击图标区域 |
| **选择器** | 底部弹出的图标面板（BottomSheet），展示 20-30 个预设图标 |
| **图标库** | 从 `src/components/icons/customizable/` 中读取，均为 Lucide 图标二次设计 |
| **默认选中** | 自定义页面默认 `IconDocument`，自定义分区默认 `IconFolder` |
| **持久化** | 用户选择的图标 ID 随自定义页面/分区数据一起存储 |
| **渲染** | 读取时通过 `CUSTOM_ICON_MAP[iconId]` 动态渲染 |

```typescript
// src/lib/customIcons.ts — 用户可选图标库
export const CUSTOM_ICON_MAP: Record<string, React.ComponentType> = {
  document:   IconDocument,   // 默认
  folder:     IconFolder,
  book:       IconBook,
  bookmark:   IconBookmark,
  star:       IconStar,
  heart:      IconHeart,
  flag:       IconFlag,
  pin:        IconPin,
  briefcase:  IconBriefcase,
  graduation: IconGraduationCap,
  // ... 20-30 个预设图标
};

// 自定义页面数据结构
interface CustomPage {
  id: string;
  name: string;
  iconId: string;        // 用户选择的图标 ID，默认 'document'
  // ...
}

// 渲染时动态获取图标
const CustomIcon = CUSTOM_ICON_MAP[page.iconId] ?? CUSTOM_ICON_MAP.document;
<NavButton icon={<CustomIcon />} label={page.name} />
```

#### 7.4.3 强制使用规范

| 位置 | 正确做法 | 错误做法 |
|------|---------|---------|
| **侧边栏** | `<NavButton icon={<PAGE_ICON_MAP.travel />} />` | `<NavButton icon={<IconTravel />} />`（直接 import） |
| **主页快速入口** | `<QuickEntry icon={<PAGE_ICON_MAP.profile />} />` | `<QuickEntry icon={<IconUser />} />`（不同图标） |
| **页面内标题** | `<PageHeader icon={<PAGE_ICON_MAP.financial />} />` | `<PageHeader icon={<IconWallet />} />`（不同图标） |

#### 7.4.4 更改图标的正确流程（系统级）

## 8. 密码输入框组件规范（SecurePasswordInput）

密码输入是 SoloSoul 最核心的交互之一（解锁 Vault、修改密码、导出数据等场景）。组件必须在保证安全的前提下提供良好的可用性。

### 8.1 组件结构

```
┌─ SecurePasswordInput（完整版）───────────┐
│  [密码输入内容...]        [👁] [?]      │
└─────────────────────────────────────────┘
         ↑                    ↑   ↑
      密码文本（遮蔽/明文）  揭示  提示

┌─ SecurePasswordInput（仅揭示按钮）────────┐
│  [密码输入内容...]           [👁]        │
└─────────────────────────────────────────┘
```

> 注：示意图中的 `[👁]` `[?]` 仅用于说明位置，实际实现须使用自定义 SVG 图标，禁止直接使用 Emoji。
>
> **提示按钮为可选功能**：通过 `showHintButton` prop 控制，默认 `true`。在修改密码页面的"新密码"、"确认新密码"等场景中应设为 `false`。

### 8.2 揭示按钮（Toggle Visibility）

| 属性 | 规范 |
|------|------|
| **功能** | 点击切换密码遮蔽 / 明文显示状态 |
| **图标** | `Eye`（遮蔽状态，点击后显示明文）/ `EyeOff`（明文状态，点击后恢复遮蔽），Lucide 图标二次设计，统一风格 |
| **位置** | 输入框内部右侧，距右边缘 40px（位于提示按钮左侧） |
| **尺寸** | 点击热区 20×20px，图标内容 16×16px |
| **颜色** | 默认 `--text-tertiary`，hover `--text-secondary`，active `--text-primary` |
| **行为** | 默认密码遮蔽（`type="password"`）；点击切换为明文（`type="text"`）；再次点击恢复遮蔽；**输入框失焦（blur）后自动恢复遮蔽**，防止密码明文残留 |
| **可访问性** | `aria-label="显示密码"` / `aria-label="隐藏密码"`，`aria-pressed` 状态同步 |

### 8.3 提示按钮（Password Hint，可选）

| 属性 | 规范 |
|------|------|
| **功能** | 点击展示用户设置的密码提示词，帮助回忆密码 |
| **控制** | `showHintButton` prop，默认 `true`。设为 `false` 时不渲染提示按钮 |
| **图标** | `HelpCircle` 或自定义 `IconPasswordHint`，Lucide 图标二次设计 |
| **位置** | 输入框内部右侧，距右边缘 12px（仅揭示按钮时该位置无元素） |
| **尺寸** | 点击热区 20×20px，图标内容 16×16px |
| **颜色** | 同揭示按钮 |
| **行为** | 点击后弹出 Tooltip / 小型浮层，显示密码提示词文本；提示词文本样式为 Caption（11px），`--text-secondary`，最大宽度 240px，自动换行；浮层背景 `--bg-elevated`，圆角 8px，投影 `--shadow-md`；点击外部或再次点击按钮关闭浮层；**若用户未设置密码提示词，浮层内显示"无可用提示词"；若已设置，则显示提示词内容** |
| **可访问性** | `aria-label="查看密码提示"`，`role="tooltip"` |

### 8.4 输入框内部布局（CSS 参考）

```css
.secure-password-input {
  position: relative;
}

/* 完整版：揭示按钮 + 提示按钮 */
.secure-password-input.has-hint input {
  padding-right: 72px; /* 12px 边距 + 20px 图标 + 8px 间距 + 20px 图标 + 12px 边距 */
}

/* 精简版：仅揭示按钮（无提示按钮） */
.secure-password-input.no-hint input {
  padding-right: 48px; /* 12px 边距 + 20px 图标 + 16px 边距 */
}

.input-actions {
  position: absolute;
  right: 12px;
  top: 50%;
  transform: translateY(-50%);
  display: flex;
  gap: 8px;
  align-items: center;
}
```

### 8.5 正例与反例

```tsx
// 错误：无揭示按钮，用户无法确认输入内容
<input type="password" />

// 错误：使用 Emoji 作为按钮（违反图标与图像规范第 7.1 条）
<input type="password" />
<span onClick={toggle}>👁</span>

// 错误：提示按钮点击后无任何反馈（未处理空提示词状态）
<PasswordInput hint={passwordHint} onHintClick={() => {}} />

// 正确：完整版（揭示按钮 + 提示按钮）— 用于登录、解锁、当前密码输入
<SecurePasswordInput
  value={password}
  onChange={setPassword}
  hint={passwordHint}            // undefined | null | "" 时浮层显示"无可用提示词"
  showHintButton={true}          // 默认 true，可省略
  onRevealToggle={(visible) => log('password visibility changed')}
/>

// 正确：精简版（仅揭示按钮，无提示按钮）— 用于新密码、确认新密码输入
<SecurePasswordInput
  value={newPassword}
  onChange={setNewPassword}
  showHintButton={false}         // 不渲染提示按钮
/>
```

### 8.6 安全注意事项

1. **密码明文状态不持久化**：仅存在于组件本地 state，不可写入任何全局 Store 或 localStorage。
2. **失焦自动遮蔽**：输入框 `onBlur` 后无论当前状态如何，强制恢复 `type="password"`。
3. **提示词安全边界**：提示词仅用于帮助回忆密码，**绝不可包含密码本身**；提示词内容来自 `account.enc` 中存储的 `password_hint` 字段。
4. **屏幕阅读器**：读出"密码，已遮蔽"或"密码，已显示"，提示词浮层出现时触发 `aria-live="polite"`。

## 9. 侧边栏导航规范（SideNavigation）

### 9.1 布局结构

侧边栏为固定窄条（**64px 宽**），采用上下分区结构。两区之间使用 `flex: 1` 弹性空白自动分隔，不依赖硬编码高度。

```
│  [IconDocument]     我的项目 ← 自定义页面 │
│  [+]                添加页面            │

│  ─────── flex: 1 弹性分隔 ─────────────  │
│                                         │

│                                         │
└─────────────────────────────────────────┘
              ↑
       名称卡片从按钮右侧滑出
```

### 9.2 上下分区规则

| 分区 | 位置 | 包含页面 | 说明 |
|------|------|---------|------|
| **Primary Nav（上区）** | 顶部紧接 AppBar | 主页、个人资料、旅行、财务、职业、**自定义页面**、**添加按钮（+）** | 用户核心数据对象对应的默认页面；自定义页面由用户创建；"+"按钮用于创建新自定义页面 |
| **Secondary Nav（下区）** | 底部对齐 | 锁定、搜索、插件、AI 对话、设置 | 工具性功能入口，不直接展示数据内容 |

**注意**：
1. 上下分区是固定规则，新增页面时必须根据功能属性归入对应分区，禁止随意混排。
2. **下区按钮顺序固定（从上到下）**：锁定 → 搜索 → 插件 → AI 对话 → 设置。
3. **设置按钮始终位于下区最底部**。后续新增功能按钮时，首先保证设置按钮保持在最下方，新增按钮插入到设置按钮上方。
4. **上区自定义页面列表动态可变**：用户通过"+"按钮创建自定义页面，图标统一使用 `IconDocument`（文章/文档图标），自定义页面排列在默认页面下方、"+"按钮上方。

### 9.3 悬停名称卡片效果（Warp 风格）

鼠标悬停在侧边栏任意按钮上时，从按钮右侧滑出名称卡片：

| 属性 | 规范 |
|------|------|
| **触发** | `mouseenter` / `focus` |
| **动画** | 水平向右滑出 + 淡入（`opacity: 0→1`，`translateX: -4px→0`） |
| **缓动** | `ease-spring`（`cubic-bezier(0.34, 1.56, 0.64, 1)`） |
| **持续时间** | 200ms（进入），150ms（离开） |
| **卡片位置** | 按钮右侧，水平间距 8px，垂直居中对齐 |
| **卡片尺寸** | 自适应文本宽度，内边距 `8px 12px` |
| **卡片样式** | 背景 `Toolbar Glass`（`blur(20px)` + `saturate(180%)`），圆角 8px，阴影 `--shadow-md`，边框 `1px solid rgba(255,255,255,0.2)` |
| **文字样式** | Body（14px），`--text-primary`，`font-weight: 500` |
| **关闭** | `mouseleave` / `blur` 后淡出 |

### 9.4 按钮状态规范

| 状态 | 图标颜色 | 背景 | 左侧指示条 |
|------|---------|------|-----------|
| 默认 | `--text-secondary` | 透明 | 无 |
| 悬停 | `--text-primary` | `rgba(0,0,0,0.04)`（明亮）/ `rgba(255,255,255,0.06)`（暗色） | 无 |
| 选中（当前页） | `--accent-primary` | `rgba(91,124,153,0.08)` | 左侧 3px 竖条，`--accent-primary`，圆角 `0 2px 2px 0`，高度 20px |

### 9.8 自定义页面创建交互

用户通过上区底部的"+"按钮（`AddPageButton`）创建自定义页面。

#### 9.8.1 创建流程

**步骤 1：点击"+"按钮**

```
点击前：                      点击后：
┌─────────────┐              ┌─────────────┐
│ [职业]       │              │ [职业]       │
│ [+]          │      →       │ [IconDoc] [输入框..] │
│              │              │ [+]          │  ← 下移一个按钮距离
└─────────────┘              └─────────────┘
```

- **"+"按钮图标**：`Plus`（Lucide 图标二次设计），20×20px
- **按钮样式**：与导航按钮一致（48×48px 热区），hover 时背景高亮
- **点击后**：
  - 在"+"按钮上方插入一个默认 `IconDocument`（文章/文档图标，代表自定义页面）
  - 图标**可点击**打开图标选择器（从 `CUSTOM_ICON_MAP` 中选择），默认选中 `document`
  - 图标右侧滑出一个小型输入框（宽度约 120px）
  - "+"按钮**下移一个按钮的距离**（48px + 4px 间距），腾出空间
  - 所有移动具有流畅动画（`ease-spring`，300ms）

**步骤 2：选择图标（可选）**

- 点击默认 `IconDocument` 图标，弹出小型图标选择面板
- 面板展示 `CUSTOM_ICON_MAP` 中所有可用图标（4 列网格，32×32px 图标）
- 点击任意图标选中，面板自动关闭，输入框左侧图标更新为所选图标
- 如未操作，默认使用 `document` 图标
- 面板样式：背景 `--bg-elevated`，圆角 8px，阴影 `--shadow-dropdown`，边框 1px `--border-subtle`

**步骤 3：输入页面名称**

| 状态 | 输入框样式 |
|------|-----------|
| **聚焦** | 边框 `--accent-primary`，2px，圆角 6px |
| **占位符** | "页面名称"（zh-CN）/ "Page name"（en-US），`--text-tertiary`，Caption（11px） |
| **输入中** | Body（14px），`--text-primary` |
| **最大长度** | 20 个字符，超出禁止输入 |

**步骤 4：确认或取消**

| 用户行为 | 结果 |
|----------|------|
| **输入了内容 + 点击外部区域（onBlur）** | **确认创建**：新页面加入侧边栏上区，使用用户选择的图标（默认 `document`）+ 用户输入的名称；名称卡片显示页面名；点击可进入 `/workspace/custom/{id}` |
| **未输入内容 + 点击外部区域（onBlur）** | **取消创建**：图标和输入框消失，"+"按钮动画回到原位 |
| **按 Enter 键** | 同"点击外部区域"逻辑：有内容则确认，无内容则取消 |
| **按 Escape 键** | **强制取消**，不创建新页面 |

#### 9.8.2 动画规范

| 动画元素 | 效果 | 持续时间 | 缓动 |
|----------|------|---------|------|
| "+"按钮下移 | `translateY` 向下移动 52px | 300ms | `ease-spring` |
| 新图标出现 | `scale: 0→1` + `opacity: 0→1` | 200ms | `ease-spring` |
| 输入框滑出 | `translateX: -8px→0` + `opacity: 0→1` | 200ms | `ease-spring`，延迟 50ms |
| 取消时回退 | 上述动画反向，持续时间相同 | 200-300ms | `ease-spring` |

#### 9.8.3 自定义页面数据结构


### 9.9 自定义页面重命名交互

用户通过**双击**自定义页面按钮，触发原地重命名。

#### 9.9.1 触发方式

| 交互 | 行为 |
|------|------|
| **双击**自定义页面按钮 | 按钮区域变为可编辑状态，右侧滑出输入框 |
| 单击自定义页面按钮 | 正常导航到对应页面（不受影响） |

> **为什么是双击而非右键菜单**：双击是更直接的原地编辑模式，符合文件管理器的用户心智模型（如桌面双击重命名）。右键菜单增加一次额外点击，且移动端无右键概念。

#### 9.9.2 编辑状态

```
双击前：                      双击后：
┌─────────────┐              ┌─────────────┐
│ [📄] 旅行    │      →       │ [📄] [旅行..│  ← 输入框预填"旅行"
│ [📄] 学习    │              │ [📄] 学习    │
│ [+]          │              │ [+]          │
└─────────────┘              └─────────────┘
```

- **输入框位置**：图标右侧，与创建时的输入框样式完全一致
- **预填内容**：当前页面名称，文本全选（`select()`），方便直接覆盖输入
- **输入框样式**：与 §9.8 创建页面时的输入框一致
  - 聚焦边框：`--accent-primary`，2px，圆角 6px
  - 占位符：`--text-tertiary`，Caption（11px）
  - 输入文本：Body（14px），`--text-primary`
  - 最大长度：20 个字符

#### 9.9.3 确认与取消

| 用户行为 | 结果 |
|----------|------|
| **输入内容 + 按 Enter** | **确认重命名**：调用 `object_update` 持久化新名称到 Rust Vault |
| **输入内容 + 点击外部区域（onBlur）** | **确认重命名**：同 Enter 逻辑 |
| **未修改内容 + 点击外部区域** | **静默取消**：不发起更新，恢复原名显示 |
| **按 Escape 键** | **强制取消**：不发起更新，恢复原名显示 |
| **清空内容 + 确认** | **静默取消**：不允许空名称，恢复原名 |

#### 9.9.4 持久化

```typescript
// 重命名调用 object_update（统一使用 IPC 持久化）
const handleRenameConfirm = async (newName: string) => {
  const trimmed = newName.trim();
  if (!trimmed || trimmed === page.originalName) {
    // 空内容或未修改，取消
    setEditingPageId(null);
    return;
  }

  // 持久化到 Rust Vault
  await commands.objectUpdate({
    id: page.id,
    name: trimmed,
  });

  // 更新前端状态
  setCustomPages((pages) =>
    pages.map((p) => (p.id === page.id ? { ...p, name: trimmed } : p))
  );
  setEditingPageId(null);
};
```

> **注意**：必须使用 `object_update` IPC 命令持久化，禁止仅更新前端内存状态。重命名后若用户刷新页面，名称必须保持。

#### 9.9.5 动画规范

| 动画元素 | 效果 | 持续时间 | 缓动 |
|----------|------|---------|------|
| 输入框出现 | `scale: 0.9→1` + `opacity: 0→1` + `translateX: -4px→0` | 150ms | `ease-spring` |
| 输入框消失 | 上述反向 | 150ms | `ease-spring` |
| 名称更新反馈 | 按钮背景闪烁 `--accent-primary` 10% 透明度 | 300ms | `ease-out` |

#### 9.9.6 正例与反例

```tsx
// 错误：使用单击触发编辑（与导航冲突）
<NavButton onClick={() => setEditing(true)} />  // ❌ 无法导航

// 错误：未预填当前名称
<input value="" placeholder="输入新名称" />  // ❌ 用户看不到当前名

// 错误：未持久化到后端
setCustomPages(pages.map(...));  // ❌ 仅更新内存，刷新丢失

// 错误：右键菜单方式
<NavButton onContextMenu={() => showRenameMenu()} />  // ❌ 移动端不支持

// 正确：双击触发，预填名称，持久化
function CustomPageButton({ page }) {
  const [isEditing, setIsEditing] = useState(false);
  const [editName, setEditName] = useState(page.name);
  const inputRef = useRef<HTMLInputElement>(null);

  const handleDoubleClick = (e: React.MouseEvent) => {
    e.stopPropagation(); // 阻止冒泡到导航
    setIsEditing(true);
    setEditName(page.name);
    setTimeout(() => {
      inputRef.current?.focus();
      inputRef.current?.select(); // 全选文本
    }, 50);
  };

  const handleConfirm = async () => {
    const trimmed = editName.trim();
    if (trimmed && trimmed !== page.name) {
      await commands.objectUpdate({ id: page.id, name: trimmed });
      // 父组件更新列表
    }
    setIsEditing(false);
  };

  return (
    <NavButton
      icon={<CUSTOM_ICON_MAP[page.iconId] || CUSTOM_ICON_MAP.document />}
      label={isEditing ? undefined : page.name}
      to={isEditing ? undefined : `/workspace/custom/${page.id}`}
      onDoubleClick={handleDoubleClick}
    >
      {isEditing && (
        <input
          ref={inputRef}
          value={editName}
          onChange={(e) => setEditName(e.target.value.slice(0, 20))}
          onBlur={handleConfirm}
          onKeyDown={(e) => {
            if (e.key === 'Enter') handleConfirm();
            if (e.key === 'Escape') { setIsEditing(false); setEditName(page.name); }
          }}
          maxLength={20}
          autoFocus
        />
      )}
    </NavButton>
  );
}
```

## 10. 修改密码页面规范（ChangePasswordPage）

修改密码页面位于 `设置 → 安全设置 → 修改密码`。页面须同时支持**修改密码**和**单独修改密码提示**两种操作模式。

### 10.1 页面结构与输入框

页面包含 4 个输入框，根据场景使用不同组件：

| 顺序 | 输入框 | 组件 | 揭示按钮 | 提示按钮 | 必填 | 说明 |
|------|--------|------|---------|---------|------|------|
| 1 | 当前密码 | `SecurePasswordInput` | 有 | **有** | 是 | 验证当前用户身份；需要提示按钮帮助回忆密码 |
| 2 | 新密码 | `SecurePasswordInput` | 有 | 无 | 条件 | `showHintButton={false}`；为空时执行"仅修改提示词"模式 |
| 3 | 确认新密码 | `SecurePasswordInput` | 有 | 无 | 条件 | `showHintButton={false}`；必须与新密码完全一致 |
| 4 | 密码提示 | `<input type="text">` | 无 | 无 | 否 | **始终明文可见**，无需遮蔽；允许为空；用于帮助回忆密码 |

**布局**：4 个输入框垂直堆叠，间距 16px，每个输入框上方有 Label（12px，`--text-secondary`，`font-weight: 500`）。

> **为什么密码提示不用 SecurePasswordInput**：提示词本身的设计目的就是"提示给所有人看"，不需要保密遮蔽。使用普通文本输入框可降低用户认知负担，直接可见编辑内容。

### 10.2 密码要求提示

在新密码输入框的 Label 右侧放置密码要求提示：

```
新密码                    [ℹ] 密码长度不少于 8 位
[****************] [👁]
```

- **图标**：`Info` 或 `AlertCircle`（Lucide 图标二次设计），16×16px，`--text-tertiary`
- **文本**："密码长度不少于 8 位"
- **样式**：Caption（11px），`--text-tertiary`，与图标水平排列，间距 4px
- **位置**：Label 右侧，或输入框下方（与错误提示不冲突）
- **可访问性**：`aria-describedby` 将提示文本关联到新密码输入框

### 10.3 单独修改密码提示逻辑

页面须支持"仅修改密码提示"模式，无需同时修改密码：

```
当前密码：    [********]        ← 必须正确
新密码：      [        ]        ← 留空
确认新密码：  [        ]        ← 留空
密码提示：    [我的提示词]      ← 填写新提示词

[保存更改]                        ← 按钮可用
```

**保存规则**：

| 当前密码 | 新密码 | 确认新密码 | 密码提示 | 操作 |
|----------|--------|-----------|----------|------|
| 错误 | — | — | — | 拒绝，显示"当前密码错误" |
| 正确 | 空 | 空 | 任意 | **仅更新密码提示**（允许为空，即清除提示词） |
| 正确 | 有值 | 空 | 任意 | 拒绝，显示"请确认新密码" |
| 正确 | 空 | 有值 | 任意 | 拒绝，显示"请填写新密码" |
| 正确 | 有值（<8位） | 有值（<8位） | 任意 | 拒绝，显示"密码长度不少于 8 位" |
| 正确 | 有值 | 有值（不一致） | 任意 | 拒绝，显示"两次输入的密码不一致" |
| 正确 | 有值（≥8位） | 有值（一致） | 任意 | **同时修改密码和密码提示** |

### 10.4 保存按钮状态

- **禁用状态**（`disabled`）：当前密码为空 / 当前密码正在验证中
- **可用状态**（`enabled`）：当前密码验证通过，且满足上述 10.3 表格中的任一允许操作
- **加载状态**：点击保存后显示加载指示器，防止重复提交

### 10.5 错误提示规范

| 错误场景 | 显示位置 | 错误文本 |
|----------|---------|---------|
| 当前密码错误 | 当前密码输入框下方 | "当前密码不正确，请重新输入" |
| 新密码少于 8 位 | 新密码输入框下方 | "密码长度不少于 8 位" |
| 新密码与确认密码不一致 | 确认新密码输入框下方 | "两次输入的密码不一致" |
| 仅填新密码或确认密码其中之一 | 留空的输入框下方 | "请同时填写新密码和确认密码" |

错误文本样式：Caption（11px），`#C45B4A`（错误红色，对应 `--error` token），与输入框间距 4px。

### 10.6 成功反馈

- 仅修改密码提示：Toast 提示"密码提示已更新"
- 同时修改密码：Toast 提示"密码已修改，请使用新密码重新登录"
- 操作成功后清空所有输入框

### 10.7 正例与反例

```tsx
// 错误：缺少密码要求提示
<Label>新密码</Label>
<SecurePasswordInput value={newPassword} onChange={setNewPassword} />

// 错误：提示按钮未展示提示词或无可用提示词反馈
<SecurePasswordInput hint={undefined} showHintButton={false} />

// 错误：未支持单独修改密码提示（新密码为空时拒绝保存）
if (!newPassword || !confirmPassword) {
  throw new Error('新密码不能为空');  // 错误：应允许仅修改提示词
}

// 正确：完整实现，支持双模式
function handleSave() {
  if (!currentPasswordValid) return;

  const changePassword = newPassword && confirmPassword;
  const changeHint = passwordHint !== originalHint;

  if (!changePassword && !changeHint) {
    showToast('没有需要保存的更改');
    return;
  }

  if (changePassword) {
    if (newPassword.length < 8) {
      setError('newPassword', '密码长度不少于 8 位');
      return;
    }
    if (newPassword !== confirmPassword) {
      setError('confirmPassword', '两次输入的密码不一致');
      return;
    }
  }

  ipc.changePassword({
    currentPassword,
    newPassword: changePassword ? newPassword : undefined,
    passwordHint: changeHint ? passwordHint : undefined,
  });
}
```

| **界面文本** | 页面标题、段落说明、空状态文案 |
| **按钮文本** | 保存、取消、删除、确认、授权、拒绝 |
| **表单标签** | 名称、描述、当前密码、新密码 |
| **悬停提示** | 侧边栏名称卡片、按钮 Tooltip、图标 aria-label |
| **校验错误** | "不能为空"、"格式不正确"、"两次输入不一致" |
| **Toast / 通知** | "保存成功"、"密码已修改"、"操作失败" |

| **菜单项** | 右键菜单、下拉菜单、上下文菜单 |

| **敏感度级别** | "公开"、"内部"、"敏感"、"关键" |
| **帮助文本** | 密码要求提示、功能说明、引导文案 |
| **日期 / 时间** | "刚刚"、"3 分钟前"、日期格式模板 |

### 15.5 代码中使用规范

```tsx
// 错误：硬编码中文或英文文本
<button>保存</button>
<span>密码长度不少于 8 位</span>
<Dialog title="Confirm Delete" />

// 正确：使用 t 函数 + namespace
import { useTranslation } from 'react-i18next';
const { t } = useTranslation(['common', 'settings']);

<button>{t('common:button.save')}</button>
<span>{t('settings:security.password_requirement')}</span>

// 正确：带插值的动态文本（自动处理复数）
<span>{t('editor:field.item_count', { count: 5 })}</span>
// zh-CN: "共 5 项"
// en-US: "5 items"
```

### 15.6 开发规范（强制）

1. **禁止硬编码**：任何用户可见的文本必须使用 `t()` 函数，禁止在 JSX、CSS `content`、原生 DOM API 中直接写入中文或英文。
2. **禁止拼接字符串**：
   ```tsx
   // 错误
   <span>{"共 " + count + " 项"}</span>
   
   // 正确：使用插值
   <span>{t('common:item_count', { count })}</span>
   ```
3. **新功能同步加词条**：开发新页面 / 组件时，中英文词条必须与代码同时提交，禁止先写死文本再"后续补国际化"。
4. **词条复用优先**：通用文本统一放入 `common.json`，各领域文件禁止重复定义相同语义文本。
5. **key 语义化**：使用英文小写 + 下划线（如 `password_requirement_hint`），禁止拼音、缩写或无意义命名。
6. **后端错误码映射**：Rust 后端返回错误码（如 `WRONG_PASSWORD`），前端根据错误码映射为本地化文本，**后端不直接返回中文/英文错误字符串**。

```typescript
// src/lib/errorMessages.ts
const errorCodeMap: Record<string, string> = {
  'VAULT_LOCKED':   'auth:error.vault_locked',
  'WRONG_PASSWORD': 'auth:error.wrong_password',
  'FIELD_REQUIRED': 'validation:error.required',
  'INVALID_FORMAT': 'validation:error.invalid_format',
};

export function getErrorMessage(code: string): string {
  return t(errorCodeMap[code] || 'common:error.unknown');
}
```

### 15.7 设置页语言项

语言切换入口位于 **`设置 → 通用 → 语言`**：

- **组件**：单选列表（Radio Group）或下拉选择器
- **选项**：
  - `中文（简体）` — `zh-CN`
  - `English` — `en-US`
- **默认选中**：当前生效语言（首次启动时为系统检测语言，后续为用户上次选择）
- **即时生效**：用户切换后无需重启，`i18next.changeLanguage()` 即时更新全应用文本
- **视觉**：语言名称使用自身语言显示（即"中文"用中文显示，"English"用英文显示），避免用户因当前语言 unfamiliar 而无法切回

### 15.8 语言切换机制

| 属性 | 规范 |
|------|------|
| **首次启动** | 检测系统语言（`navigator.language` / Tauri OS API）；`zh-*` → `zh-CN`，其他所有语言 → `en-US` |
| **用户覆盖** | 用户在设置页手动切换语言后，**后续启动优先使用用户选择**，不再检测系统语言 |
| **存储位置** | 语言属于**非敏感 UI 偏好**，存储于 Vault 外的明文文件 `ui_preferences.json`。登录前即可读取，消除登录页语言割裂 |
| **读取时机** | 应用启动时**立即**读取 `ui_preferences.json` 中的 `language`；若未设置（首次启动），执行系统语言检测并写入明文偏好文件 |
| **即时切换** | `i18next.changeLanguage()` 即时更新，无需刷新页面；同时同步到 `ui_preferences.json` |
| **后端接口** | IPC 错误码与语言无关，前端负责本地化映射；数据字段名保持英文不变 |

**存储分层示例**：

```typescript
// 非敏感 UI 偏好（明文存储，登录前可读）
interface UiPreferences {
  language: 'zh-CN' | 'en-US';   // 明文存储于 ui_preferences.json
  theme: ThemeConfig;            // 明文存储于 ui_preferences.json
  sidebarWidth: number;          // 明文存储于 ui_preferences.json
}

// 敏感偏好（Vault 加密存储，解锁后可读）
interface SensitivePreferences {
  autoLockTimeout: number;       // 加密存储于 preferences.enc
  biometricEnabled: boolean;     // 加密存储于 preferences.enc
  // ...
}

// 启动流程（修复 Bug 2 的时序问题）
async function bootstrap() {
  // 第 1 步：登录前即可读取 UI 偏好
  const uiPrefs = await commands.loadUiPreferences();
  applyTheme(uiPrefs.theme);
  await i18next.changeLanguage(uiPrefs.language);
  
  // 第 2 步：用户登录后，加载敏感偏好
  const sensitivePrefs = await commands.userDataGetPreferences();
  set({ sensitivePreferences: sensitivePrefs });
}
  await i18next.changeLanguage(lang);
}
```
