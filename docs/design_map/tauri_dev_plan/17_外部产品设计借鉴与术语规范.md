## 2. 【P0 最高优先级】术语统一规范

### 当前术语混乱

| 概念 | Anytype 术语 | 当前代码 | 当前文档 | 问题 |
|------|------------|---------|---------|------|
| 数据条目 | **Object** | `UnifiedObject` | "对象"/"项目"/"条目" | 三个名称指同一事物 |
| 类型定义 | **Type** | `ObjectTypeDefinition` | "类型定义" | 名称过长 |
| 属性定义 | **Property** | `PropertyDefinition` | "属性"/"字段" | "字段"和"属性"混用 |
| 对象关系 | **Relation** | `RelationProperty` | "关系"/"关联" | 与 Property 概念重叠 |
| 对象集合 | **Collection** | `Collection` | "分区"/"Collection" | UI 叫"分区"，代码叫 Collection |

### 统一后的术语

| 概念 | 统一术语 | Rust 结构体 | TS 接口 | UI 显示 |
|------|---------|------------|--------|--------|
| 数据条目 | **Object** | `Object` | `Object` | "对象" |
| 类型定义 | **Type** | `Type` | `ObjectType` | "类型" |
| 属性定义 | **Property** | `Property` | `ObjectProperty` | "属性" |
| 对象关系 | **Relation** | `Relation` | `ObjectRelation` | "关联" |
| 对象集合 | **Collection** | `Collection` | `Collection` | "集合" |
| 属性值 | **Value** | `PropertyValue` | `PropertyValue` | "值" |
| 类型模板 | **Template** | `TypeTemplate` | `TypeTemplate` | "模板" |
| 动态筛选集合 | **SmartCollection** | `SmartCollection` | `SmartCollection` | "智能集合" |

### 统一后的 Rust 命名

```rust
// ✅ 统一后
pub struct Object {
    pub id: String,
    pub type_id: String,
    pub name: String,
    pub properties: HashMap<String, PropertyValue>,
    pub relations: Vec<Relation>,
}

pub struct Type {
    pub id: String, pub name: String,
    pub properties: Vec<Property>,
    pub template: Option<TypeTemplate>,
}

pub struct Property {
    pub id: String, pub name: String,
    pub property_type: PropertyType, // Text / Number / Date / Select / Relation
}
```

### 命名规则

| 规则 | 示例 |
|------|------|
| Rust struct: PascalCase | `Object`, `PropertyValue` |
| Rust enum variant: PascalCase | `PropertyType::Text` |
| TS interface: PascalCase | `Object`, `PropertyValue` |
| TS 属性: camelCase | `objectId`, `propertyType` |
| IPC 命令: snake_case | `object_create`, `object_list` |
| UI 中文: 简洁名词 | "对象"、"属性"、"集合" |

## 3. 值得借鉴的特性

### 借鉴 1：命令面板（Command Palette）— 高优先级

```
⌘K 唤起命令面板 → 搜索所有操作 → 选择执行
支持: 创建对象、跳转页面、运行插件、导出数据
```

### 借鉴 2：智能集合（Smart Collection）— 中优先级

```
基于筛选条件自动聚合对象的动态视图
如："所有证件" = type in [护照, 身份证, 驾照]
    "即将过期" = expiry_date < now + 90天
```

### 借鉴 3：对象类型模板（Type Template）— 中优先级

```
新建对象时选择模板，自动创建关联属性
如："护照"模板 → 自动添加 护照号码、签发日期、有效期 属性
```

## 4. 不借鉴的特性及理由

| 特性 | 来源 | 不借鉴理由 |
|------|------|-----------|
| 图视图（Graph View） | Anytype | 增加复杂度，对个人数据管理增益有限 |
| 块级编辑器 | Notion | SoloSoul 是结构化数据管理，非文档编辑 |
| 多人协作 | Notion/Anytype | 违背隐私优先（数据只属于个人） |
| AI 自动分类 | Warp | 需要上传数据到云端 |
| 插件市场 | VS Code | 不审核第三方插件，沙盒保证安全 |

## 5. AI 辅助功能（对齐 Manifesto 本地优先）

> **审批决策（2026-06-05）**：AI 功能**默认禁用**，用户需在设置中主动开启，首次开启时展示风险告知对话框。

### 默认状态

```
AI 功能开关：默认 = 关闭 ❌
  → 用户进入 设置 → AI 功能
  → 开启开关
  → 弹出风险告知对话框：
     "您即将启用 AI 辅助功能。根据您选择的 AI 服务商，
      您输入的内容将被发送到该服务商的服务器进行处理。
      SoloSoul 不会自动上传您的数据——您始终控制发送哪些内容。
      建议优先使用本地模型（Ollama），数据不会离开您的设备。"
  → 用户确认 → AI 功能启用
```

### 功能与数据流向

SoloSoul 的 AI 功能**优先本地**，云端 API 需用户主动选择：

| 功能 | 实现方式 | 数据流向 | 默认状态 |
|------|---------|---------|---------|
| 自然语言搜索 | 本地 embedding 模型 | 数据不离开设备 | 默认开启 |
| 智能填充 | LLM API（用户自选 Provider） | 用户控制发送哪些字段 | 默认关闭 |
| 命令生成 | LLM API（用户自选 Provider） | 仅发送命令上下文 | 默认关闭 |
| AI 对话 | LLM API 或 Ollama 本地 | 用户控制 | 默认关闭 |
| OCR 识别 | 本地 ONNX 模型 | 图片不离开设备 | 默认开启 |

### 安全红线

- ❌ SoloSoul 绝不自动上传用户数据到 AI 服务商
- ❌ AI 绝不直接写入 Vault（只生成建议，用户确认后才执行）
- ✅ LLM API 密钥 `critical` 级别加密存储
- ✅ 审计日志记录每次 AI 调用（不记录用户输入内容）
- ✅ 用户可随时关闭 AI 功能，AI 对话历史可清空

## 6. 术语迁移影响范围

| 范围 | 变更 |
|------|------|
| Rust 代码 | `UnifiedObject` → `Object`, `PropertyDefinition` → `Property` |
| TypeScript | `UnifiedObject` → `Object`, `unified_object_*` → `object_*` |
| IPC 命令 | `unified_object_list` → `object_list` 等 |
| 数据库表 | `unified_objects` → `objects`（需迁移） |
| UI 文案 | "分区" → "集合"，"字段" → "属性" |
| 文档 | 全文替换 |
