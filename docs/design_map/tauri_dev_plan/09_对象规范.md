# 25 — 对象规范（Object Specification）

> **前置阅读**：`07_数据库_服务层_Repository迁移.md`、`14_敏感度等级系统重构.md`、`06_数据组织模型架构决策.md`
> **Manifesto 对齐**：用户主权 | 隐私优先 | 最少惊喜
> **文档定位**：定义 SoloSoul 中"对象"（Object）的完整规范——属性系统、模板系统、历史记录、附件管理。对象是 SoloSoul 数据模型的核心原子单元。

---

## 1. 对象定位

### 1.1 对象必须被放置在页面中

对象是 SoloSoul 数据模型的最小业务单元，**必须归属且仅归属一个页面**（通过 `section_type` 字段）。

```
┌─────────────────────────────────────────┐
│  Travel Page                            │
│  ├─ 护照 · 张三      ← 对象            │
│  ├─ 签证 · 日本      ← 对象            │
│  ├─ 机票 · 东京      ← 对象            │
│  └─ 酒店 · 新宿      ← 对象            │
└─────────────────────────────────────────┘
```

**约束**：

| 规则 | 说明 |
|------|------|
| 对象必须归属页面 | `section_type` 字段不可为空，取值：`identity` / `travel` / `financial` / `professional` / `custom_{id}` |
| 对象不可游离 | 禁止创建不归属任何页面的对象（反例：草稿箱中的"未分类对象"） |
| 对象不可跨页 | 一个对象只能属于一个页面（多视角通过标签筛选实现，见文档 06） |
| 页面删除连带回收 | 删除页面时，页面内所有对象一并进入回收站（见文档 16 §2.1） |

> **反例**：
> ```typescript
> // 错误：创建无页面的对象
> await commands.objectCreate({ name: '临时笔记' }); // ❌ 缺少 section_type
>
> // 错误：对象同时属于两个页面
> object.section_type = ['travel', 'financial']; // ❌ section_type 是单值
> ```

### 1.2 对象与页面的关系

```
Page (页面)
  ├── 元数据：名称、图标、排序位置
  ├── 配置：页面级敏感度默认、标签预设
  └── Objects[] (对象列表) ← 扁平结构，见文档 06

Object (对象)
  ├── 元数据：ID、名称、创建/更新时间
  ├── 页面归属：section_type（所在页面）
  ├── 模板类型：type_id（对象模板，如 passport/id_card）
  ├── 属性：Properties[]（内置 + 自定义）
  ├── 标签：Tags[]（智能筛选用）
  ├── 敏感度：对象级 + 属性级
  ├── 历史：Snapshots[]（修改记录）
  └── 附件：Attachments[]
```

### 1.3 section_type 与 type_id 的职责分离

对象有两个不同维度的分类字段，**不可混用**：

| 字段 | 语义 | 取值示例 | 用途 |
|------|------|---------|------|
| **`section_type`** | **页面归属**——对象放在哪个页面 | `travel` / `financial` / `professional` / `custom_abc123` | Workspace 查询、页面筛选、回收站恢复定位 |
| **`type_id`** | **模板类型**——对象是什么类型的数据 | `passport` / `id_card` / `bank_card` / `visa` / `flight` | 模板匹配、属性预填充、图标选择 |

> **为什么需要两个字段**：
> - `type_id = 'passport'` 表示"这是一个护照对象"，用于加载护照模板（姓名/号码/签发国等属性）
> - `section_type = 'travel'` 表示"这个护照放在旅行页面"，用于侧边栏/主页展示
> - 一个 `type_id` 可以出现在多个 `section_type` 中（如身份证既可在 identity 页也可在 travel 页）
> - 一个 `section_type` 可以包含多种 `type_id`（如 travel 页有 passport/visa/flight/hotel 等）

**反例**：
```typescript
// 错误：用 type_id 同时承担页面归属职责
type_id: 'passport'  // 隐式假设护照在 travel 页面
// 问题：用户可能把护照放在 identity 页面作为身份验证材料

// 正确：两个字段各司其职
section_type: 'travel'  // 页面归属：旅行页面
type_id: 'passport'     // 模板类型：护照
```

**查询约束**：
```rust
// Workspace 查询：按页面归属筛选
fn list_objects_by_page(section_type: &str) -> Vec<Object>;

// 模板查询：按对象类型筛选
fn list_objects_by_type(type_id: &str) -> Vec<Object>;

// 组合查询：旅行页面中的所有护照
fn list_objects(page: &str, obj_type: &str) -> Vec<Object>;
```

## 2. 对象属性系统

### 2.1 属性结构

对象的属性分为两类：**内置属性**（软件预定义）和**自定义属性**（用户按需添加）。

```rust
// Rust 侧：Property 结构
struct Property {
    id: String,              // UUID
    name: String,            // 属性名（用户可见）
    property_type: PropertyType, // 数据类型
    value: PropertyValue,    // 具体值
    sensitivity: SensitivityLevel, // public/internal/sensitive/critical
    is_builtin: bool,        // 是否内置属性（内置不可删除，只可隐藏）
    is_required: bool,       // 是否必填
    order: i32,              // 展示顺序
    template_source: Option<String>, // 来源模板 ID（用户自定义属性可空）
}

enum PropertyType {
    Text,           // 单行文本
    MultilineText,  // 多行文本
    Number,         // 数字
    Date,           // 日期
    DateTime,       // 日期时间
    Boolean,        // 是/否
    Select,         // 单选（预定义选项）
    MultiSelect,    // 多选（预定义选项）
    Url,            // URL 链接
    Email,          // 邮箱
    Phone,          // 电话
    FileReference,  // 文件引用（指向附件）
}
```

### 2.2 内置属性

内置属性由软件预定义，**不可删除，只可隐藏**。每个对象类型（Type）有对应的一套内置属性。

| 对象类型 | 内置属性示例 |
|----------|-------------|
| 护照 | 姓名、护照号码、签发国、签发日期、过期日期、照片 |
| 身份证 | 姓名、身份证号、签发机关、有效期限、住址 |
| 银行卡 | 银行名称、卡号、有效期、CVV、持卡人 |
| 签证 | 签证类型、签发国、入境次数、签发日期、过期日期 |
| 机票 | 航空公司、航班号、出发地、目的地、出发时间、座位 |
| 酒店 | 酒店名称、地址、入住日期、退房日期、确认号 |

```typescript
// 内置属性定义示例（护照）
const PASSPORT_BUILTIN_PROPERTIES: PropertyDefinition[] = [
  { id: 'full_name', name: '姓名', type: 'Text', sensitivity: 'internal', is_required: true },
  { id: 'passport_number', name: '护照号码', type: 'Text', sensitivity: 'critical', is_required: true },
  { id: 'issuing_country', name: '签发国', type: 'Select', sensitivity: 'public', is_required: true },
  { id: 'issue_date', name: '签发日期', type: 'Date', sensitivity: 'internal', is_required: true },
  { id: 'expiry_date', name: '过期日期', type: 'Date', sensitivity: 'internal', is_required: true },
  { id: 'photo', name: '照片', type: 'FileReference', sensitivity: 'sensitive', is_required: false },
];
```

### 2.3 自定义属性

用户可为任何对象添加自定义属性：

```
┌────────────────────────────────────────┐
│  护照 · 张三                            │
│  ────────────────────────────────────  │
│  姓名          张三                     │
│  护照号码      ************            │  ← critical 级，已遮蔽
│  签发国        中国                     │
│  ────────────────────────────────────  │
│  [+ 添加属性]                           │
│    ├─ 文本                              │
│    ├─ 数字                              │
│    ├─ 日期                              │
│    ├─ 单选                              │
│    └─ ...                               │
└────────────────────────────────────────┘
```

**自定义属性规则**：

| 规则 | 说明 |
|------|------|
| 属性名 | 用户自定义，支持国际化（存储原始输入，按当前语言展示） |
| 属性类型 | 从预定义类型中选择（见 §2.1 PropertyType），创建后不可更改类型 |
| 敏感度 | 用户为每个属性独立设置敏感度等级（public/internal/sensitive/critical） |
| 必填 | 用户可设置是否必填 |
| 删除 | 自定义属性可随时删除，删除后数据丢失（需二次确认） |
| 排序 | 用户可拖拽调整属性展示顺序 |

> **安全约束**：自定义属性的敏感度等级变更遵循 §12 的"修改即访问"原则——将 `critical` 降级为 `public` 需要等同于查看 `critical` 数据的验证强度。

### 2.4 属性级敏感度

每个属性独立设置敏感度，与对象级敏感度分离：

```
对象：护照 · 张三
  敏感度：internal（对象级默认）
  
  属性：
    ├─ 姓名           internal      → blur(2px)，点击展开
    ├─ 护照号码       critical      → blur(16px) + 锁图标，需密码
    ├─ 签发国         public        → 始终可见
    └─ 照片           sensitive     → blur(8px) + 蒙层，需生物识别
```

> **与 §12 的对齐**：属性级敏感度使用与 §12 完全一致的 4 级系统和视觉规范。`SensitivityMap` 中存储的是属性级映射，而非对象级。

## 3. 模板系统

### 3.1 模板定位

模板是**预定义的属性集合**，用于快速创建同类对象。模板分为两类：

| 模板类型 | 来源 | 可编辑 | 可删除 |
|----------|------|--------|--------|
| **系统模板** | 软件内置 | 不可编辑 | 不可删除，可隐藏 |
| **用户模板** | 用户基于现有对象保存 | 可编辑 | 可删除 |

### 3.3 模板使用流程

```
创建对象时选择模板：

[+] 创建对象
  ├─ 📄 空白对象（无预定义属性）
  ├─ 📘 护照
  ├─ 📗 身份证
  ├─ 💳 银行卡
  ├─ 🛂 签证
  ├─ ✈️ 机票
  ├─ 🏨 酒店
  └─ ... 更多
```

- 选择模板后，对象自动填充该模板的内置属性
- 用户可在模板基础上增删自定义属性
- 基于模板创建的对象与模板解耦——后续模板变更不影响已创建对象

### 3.4 用户自定义模板

用户可将任何现有对象保存为模板：

```
对象详情页 → [⋮] 更多 → "保存为模板"

模板名称：[驾驶证（国际版）]
基于对象：驾驶证 · 张三
包含属性：
  [✓] 姓名
  [✓] 驾驶证号
  [✓] 准驾车型
  [✓] 初次领证日期
  [✓] 自定义属性：紧急联系人
```

**用户模板规则**：

| 规则 | 说明 |
|------|------|
| 模板名称 | 用户自定义，支持国际化 |
| 模板图标 | 从 `CUSTOM_ICON_MAP` 中选择 |
| 包含属性 | 用户可选择包含哪些属性（内置 + 自定义均可） |
| 属性值 | 模板中的属性值为空（不复制源对象的实际数据） |
| 编辑 | 可重命名、增删属性、调整顺序 |
| 删除 | 删除模板不影响基于该模板创建的对象 |

### 3.5 模板存储

```sql
-- 用户模板表（系统模板硬编码，不存数据库）
CREATE TABLE user_templates (
    id TEXT PRIMARY KEY,
    account_id TEXT NOT NULL,
    name TEXT NOT NULL,
    icon_id TEXT,
    properties_json TEXT NOT NULL, -- PropertyDefinition[] 序列化
    created_at TEXT,
    updated_at TEXT,
    FOREIGN KEY (account_id) REFERENCES profiles(account_id)
);
```

## 4. 对象 CRUD

### 4.1 创建对象

```typescript
interface CreateObjectRequest {
  name: string;                    // 对象名称
  section_type: string;            // 所属页面
  template_id?: string;            // 可选：使用的模板 ID
  tags?: string[];                 // 可选：初始标签
  properties?: PropertyInput[];    // 可选：初始属性值
}

interface PropertyInput {
  property_id: string;
  value: PropertyValue;
}
```

**创建流程**：
1. 用户选择页面 → 点击"创建对象"
2. 选择模板（或空白对象）
3. 填写对象名称和属性值
4. 确认创建 → `commands.objectCreate()` → Rust Vault 持久化
5. 对象出现在页面列表中

### 4.2 编辑对象

```typescript
interface UpdateObjectRequest {
  id: string;
  name?: string;
  tags?: string[];
  properties?: PropertyUpdate[];   // 增量更新：仅传修改的属性
}

interface PropertyUpdate {
  property_id: string;
  value: PropertyValue;            // 新值
}
```

**编辑规则**：

| 规则 | 说明 |
|------|------|
| 增量更新 | 只发送修改的属性，未修改的属性不传 |
| 历史记录 | 每次更新自动创建快照（见 §5） |
| 敏感属性 | 编辑 `critical` / `sensitive` 属性前需验证身份 |
| 并发控制 | 乐观锁——`updated_at` 时间戳比对，冲突时提示用户 |

### 4.3 查看对象

```typescript
interface GetObjectResponse {
  id: string;
  name: string;
  section_type: string;
  template_id?: string;
  tags: string[];
  properties: Property[];          // 完整属性列表（含值）
  sensitivity_level: SensitivityLevel;
  created_at: number;
  updated_at: number;
  attachment_count: number;
  history_count: number;
}
```

**查看规则**：

| 规则 | 说明 |
|------|------|
| 敏感属性遮蔽 | `sensitive` / `critical` 属性按 §12 规则遮蔽，需验证后查看 |
| 对象级敏感度 | 对象整体可设置敏感度，影响未单独设置敏感度的属性 |
| 只读不记录 | 查看对象不进入操作日志 |

### 4.4 删除对象

- 删除对象执行**软删除**（进入回收站，见文档 16 §2.1）
- 删除时对象完整数据（含属性、附件）保留
- 可从回收站恢复至原页面（见文档 16 §4.1）

## 5. 历史记录（快照）

### 5.1 快照机制

对象的每次**数据变更**自动创建快照，记录修改瞬间的完整状态。

```rust
// Rust 侧：ObjectSnapshot 结构
struct ObjectSnapshot {
    id: String,              // UUID
    object_id: String,       // 关联对象 ID
    timestamp: i64,          // 修改时间戳（Unix ms）
    triggered_by: String,    // 触发来源："user_edit" / "template_update" / "import" / "sync"
    data: EncryptedBlob,     // 完整对象数据加密快照（含所有属性值）
    diff_summary: String,    // 差异摘要（如"修改了护照号码、过期日期"）
}
```

**触发快照的场景**：

| 场景 | 是否触发快照 | 说明 |
|------|-------------|------|
| 用户编辑属性值 | ✅ 是 | 任何属性值变更 |
| 用户添加属性 | ✅ 是 | 新增自定义属性 |
| 用户删除属性 | ✅ 是 | 删除自定义属性 |
| 用户重命名对象 | ✅ 是 | 对象名称变更 |
| 用户修改标签 | ✅ 是 | 标签增删 |
| 用户修改敏感度 | ✅ 是 | 属性敏感度变更 |
| 用户查看对象 | ❌ 否 | 只读操作 |
| 附件上传/删除 | ❌ 否 | 附件独立管理，不触发对象快照 |

### 5.2 快照数据内容

快照存储对象在修改瞬间的完整数据：

```typescript
interface SnapshotData {
  name: string;                    // 对象名称
  tags: string[];                  // 标签
  properties: Property[];          // 所有属性（含值）
  sensitivity_level: SensitivityLevel;
  // 注意：不包含附件列表（附件独立管理）
}
```

### 5.3 历史记录查看

```
对象详情页 → [历史记录] 标签

┌──────────────────────────────────────────┐
│  历史记录（共 5 条）                       │
│  ──────────────────────────────────────  │
│  [现在]  当前版本                          │
│  ──────────────────────────────────────  │
│  14:32   修改了护照号码、过期日期           │
│  09:15   添加了属性"紧急联系人"             │
│  昨天    修改了签发日期                   │
│  3天前   初始创建                          │
└──────────────────────────────────────────┘
```

**历史记录交互**：

| 操作 | 行为 |
|------|------|
| 点击某条历史 | 展开显示该快照的完整属性值（与当前版本并列对比） |
| 恢复到此版本 | 将对象数据回滚到该快照状态，同时创建新快照记录"回滚到 [日期] 版本" |
| 对比两个版本 | 选择两条历史记录，高亮显示差异字段 |

### 5.4 快照存储策略

**默认策略：保留所有快照，永不自动删除。**

历史记录是用户数据的重要组成部分，默认不应丢失。用户可自主配置保留策略。

| 维度 | 默认设置 | 用户可配置选项 |
|------|---------|--------------|
| **保留数量** | 无限制（保留所有） | 50 条 / 100 条 / 200 条 / 无限制 |
| **保留时间** | 无限制（永不删除） | 30 天 / 60 天 / 半年 / 一年 / 永不删除 |
| **组合策略** | 无限制 | 数量 **或** 时间——任一条件触发即清理 |

**配置示例**：

```
设置 → 安全设置 → 历史记录保留策略

[○] 保留所有历史记录（默认）
[ ] 按数量限制：保留最近 [100 ▼] 条
[ ] 按时间限制：保留最近 [半年  ▼] 内
```

**清理机制**：
- 触发时机：应用启动时检查 + 每次创建新快照后检查
- 清理逻辑：按用户配置的策略，删除超出限制的最旧快照
- 保留"无限制"为默认选项，符合"用户主权"原则

**空间估算**：

| 场景 | 计算 | 年存储量 |
|------|------|---------|
| 轻度用户 | 50 对象 × 1 次/天 × 10KB | ~180 MB |
| 典型用户 | 100 对象 × 3 次/天 × 10KB | ~1.1 GB |
| 重度用户 | 200 对象 × 10 次/天 × 10KB | ~7.3 GB |

> 对于个人用户，即使重度使用，历史记录存储在本地磁盘也完全可接受。若用户担心空间，可配置限制策略。

```sql
-- 快照表
CREATE TABLE object_snapshots (
    id TEXT PRIMARY KEY,
    object_id TEXT NOT NULL,
    timestamp INTEGER NOT NULL,      -- Unix timestamp (ms)
    triggered_by TEXT NOT NULL,      -- user_edit / template_update / import / sync / rollback
    data BLOB NOT NULL,              -- 加密快照数据
    diff_summary TEXT,               -- 差异摘要（用户可见）
    FOREIGN KEY (object_id) REFERENCES unified_objects(id)
);

CREATE INDEX idx_snapshots_object ON object_snapshots(object_id, timestamp DESC);
CREATE INDEX idx_snapshots_timestamp ON object_snapshots(timestamp);
```

> **注意**：快照仅记录对象属性数据，不记录附件。附件有自己的独立生命周期管理。

## 6. 附件系统

### 6.1 附件定位

每个对象可独立绑定**任意格式、任意大小**的附件。附件是对象的附属文件，不是对象的属性数据。

```
对象：护照 · 张三
  ├─ 属性：姓名、护照号码、签发国、签发日期、过期日期...
  └─ 附件：
      ├─ [📄] 护照扫描件.pdf    (2.3 MB)
      ├─ [📷] 护照照片.jpg      (856 KB)
      └─ [📄] 签证申请表.pdf    (1.1 MB)
```

### 6.2 附件规则

| 规则 | 说明 |
|------|------|
| 格式限制 | **无限制**——支持任意文件格式（PDF、图片、视频、压缩包等） |
| 大小限制 | **无硬性限制**——实际受限于磁盘空间；单个文件 > 100MB 时显示警告提示 |
| 数量限制 | **无限制**——每个对象可绑定任意数量附件 |
| 存储位置 | `~/.solosoul/{account_id}/attachments/{object_id}/{attachment_id}` |
| 加密 | 附件文件本身**不加密**（文件名使用 UUID，避免信息泄露）；敏感附件建议用户单独加密后上传 |
| 命名 | 原文件名保留用于展示，存储时使用 UUID 作为实际文件名 |

> **关于附件加密的讨论**：附件文件本身不加密的原因——
> 1. 大文件加密/解密开销高，影响打开速度
> 2. 附件通常是已有加密格式的文件（如 PDF 密码保护、加密压缩包）
> 3. Vault 层已提供足够的访问控制（Vault 锁定后无法访问附件目录）
> 4. 若用户需要，可在未来版本增加"敏感附件加密"选项

### 6.5 附件删除策略

附件删除采用**对象属性级软删除**，**不进入全局回收站**。

#### 6.5.1 为什么不进入全局回收站

| 原因 | 说明 |
|------|------|
| **附件名无独立性** | `scan.pdf` 脱离对象上下文后无法辨识（"这是什么扫描件？"） |
| **对象视角更直观** | 用户从"护照 · 张三 → 已删除附件"查看，比"回收站 → scan.pdf"更有语境 |
| **管理负担** | 全局回收站堆满无意义的文件名，增加用户认知负担 |
| **恢复逻辑** | 附件恢复需绑定回特定对象，从对象内部操作更自然 |

#### 6.5.2 软删除实现

```rust
// Rust 侧：Attachment 结构增加软删除标记
struct Attachment {
    id: String,
    object_id: String,
    file_name: String,
    file_size: u64,
    mime_type: String,
    file_path: String,
    created_at: i64,
    deleted_at: Option<i64>,  // None = 正常，Some(timestamp) = 已软删除
}

// 软删除操作
async fn soft_delete_attachment(attachment_id: &str) -> Result<(), Error> {
    let now = current_time_ms();
    attachment_repo.update_deleted_at(attachment_id, Some(now)).await?;
    // 物理文件暂不删除，对象彻底删除时统一清理
    Ok(())
}

// 查询对象附件时过滤已删除
async fn list_object_attachments(object_id: &str) -> Result<Vec<Attachment>, Error> {
    attachment_repo
        .find_by_object(object_id)
        .await?
        .into_iter()
        .filter(|a| a.deleted_at.is_none())
        .collect()
}
```

#### 6.5.3 已删除附件的查看与恢复

对象详情页提供"显示已删除附件"开关：

```
附件 (2)                    [显示已删除 1]  ← 切换开关
───────────────────────────
[📄] 护照扫描件.pdf    2.3 MB   [👁] [✏️] [🗑️]
[📷] 护照照片.jpg      856 KB   [👁] [✏️] [🗑️]

─── 已删除 ─────────────────
[📄] 旧护照扫描件.pdf  1.8 MB   [↩️ 恢复] [彻底删除]
         ↑ 灰色文字，删除时间：2026-05-15
```

- **显示开关**：默认关闭，开启后列出已软删除的附件
- **已删除附件样式**：文件名灰色（`--text-tertiary`），显示删除时间
- **恢复按钮**：`↩️` 图标，点击恢复（`deleted_at = None`）
- **彻底删除**：`Trash2` 图标红色，点击二次确认后物理删除文件 + 删除数据库记录

#### 6.5.4 物理清理时机

| 时机 | 行为 |
|------|------|
| 对象**彻底删除** | 该对象下所有附件（含已软删除）一并物理删除 |
| 用户手动"彻底删除" | 单独删除某个已软删除附件的物理文件 |
| 自动清理（可选） | 对象彻底删除 30 天后，后台清理孤儿附件文件 |

```

### 6.7 附件与快照的关系

| 方面 | 规则 |
|------|------|
| 快照是否包含附件 | **否**——快照仅记录对象属性数据 |
| 附件是否有历史记录 | **否**——附件独立管理，无快照/历史记录功能 |
| 对象回滚时附件 | 对象回滚到历史版本时，附件列表保持不变 |
| 删除对象时附件 | 对象软删除时，附件保留在回收站中；对象彻底删除时，附件一并删除 |
| 空间管理 | 附件占用空间大，建议定期清理已删除对象的附件（对象彻底删除后自动清理） |

> **待定项**：未来可考虑为附件增加"版本历史"功能（同一附件多次上传保留历史版本），但当前版本不实现，避免空间膨胀。

- [ ] 用户可将现有对象保存为自定义模板
- [ ] 每次数据变更自动创建快照，记录时间戳和差异摘要
- [ ] 历史记录支持查看任意快照的完整数据
- [ ] 历史记录支持回滚到任意快照版本
- [ ] 默认保留所有历史快照，永不自动删除

### P2（增强 — 附件系统）
- [ ] 每个对象可绑定任意数量、任意格式的附件
- [ ] 对象卡片显示附件按钮（回形针图标），带数字徽章指示附件数量
- [ ] 点击附件按钮弹出附件卡片（不跳转页面），列出附件名/大小/上传时间
- [ ] 附件卡片每个附件有预览/编辑（重命名）/删除按钮
- [ ] 附件支持上传、预览（内建/系统）、下载、重命名、软删除、恢复、彻底删除
- [ ] 附件内建预览支持：纯文本、Markdown、CSV、图片、PDF
- [ ] 附件系统预览支持：macOS Quick Look、Windows 资源管理器、Linux xdg-open
- [ ] 附件独立表支持元数据索引查询（按对象、按 MIME 类型、按时间范围）
- [ ] 附件删除采用对象属性级软删除（`deleted_at` 标记），不进入全局回收站
- [ ] 对象详情页支持"显示已删除附件"开关，可恢复或彻底删除
- [ ] 对象删除时附件随对象进入回收站；对象彻底删除时附件一并删除
- [ ] `section_type` 与 `type_id` 职责分离，互不替代
