# 27 — 生物识别功能规范

> **前置阅读**：`05_密码学库选型与核心实现.md`（§8 密钥分层架构）、`15_用户数据边界与加密存储方案.md`（§4 存储分层）
> **Manifesto 对齐**：用户主权 | 隐私优先 | 安全默认
> **文档定位**：定义 SoloSoul 生物识别（Touch ID / Face ID / Windows Hello / 指纹）的完整功能规范，包括密钥体系、IPC 命令、注册/解锁/更新/删除生命周期、平台差异、UI 交互及错误处理。

---

## 1. 设计原则

| 原则 | 说明 |
|------|------|
| **密码不可替代** | 生物识别是便捷解锁手段，不替代主密码。修改密码、删除账户等关键操作必须使用主密码 |
| **会话密钥隔离** | 生物识别仅读取 Keychain 中存储的**会话密钥**，从不接触主密码或主密钥 |
| **密码变更自动失效** | 修改主密码后，旧生物凭证自动失效，提示用户重新注册 |
| **平台原生 API** | 各平台使用系统原生生物识别 API（LocalAuthentication / Windows Hello），不自行实现生物匹配 |
| **可用性优先** | 生物识别不可用时（传感器故障、平台不支持）优雅退化为密码输入 |
| **审计记录** | 所有生物识别解锁操作写入操作日志（记录时间戳和结果，不记录生物特征数据） |

## 2. 密钥分层与存储架构

### 2.1 密钥分层回顾

衔接文档 05 §8 的密钥分层：

```
Layer 1: 用户主密码 → Argon2id → 主密钥 (32-byte)
Layer 2: 主密钥 → HKDF-SHA256 派生 → 会话密钥 → 存入 OS Keychain
         ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
         生物识别读取路径 ↓
Layer 3: 生物识别验证 → 从 Keychain 读取会话密钥 → 解锁 Vault
```

**关键约束**：

| 约束 | 说明 |
|------|------|
| 会话密钥 ≠ 主密钥 | 密码学上隔离，会话密钥泄露不影响主密钥安全 |
| 永不存储主密码 | OS Keychain 中仅存储派生后的会话密钥，绝不存储用户的原始主密码 |
| 一次注册，多次使用 | 生物识别注册时写入会话密钥，之后每次解锁仅通过生物识别验证后读取 |

### 2.2 各平台 Keychain 存储方式

| 平台 | 存储机制 | 访问控制 | 说明 |
|------|---------|---------|------|
| **macOS** | `Security.framework` Keychain | `kSecAccessControlBiometryCurrentSet` + `kSecAttrAccessibleWhenUnlockedThisDeviceOnly` | Touch ID 验证后读取；设备间不迁移 |
| **iOS** | `Security.framework` Keychain | 同 macOS | Face ID / Touch ID 验证后读取 |
| **Windows** | `Windows Hello` + DPAPI | `NGUARD_PROTECTION_FINGERPRINT_RETINA_FACE` | Windows Hello 容器存储凭证 |
| **Linux** | 不支持原生生物识别 | — | Linux 平台不使用生物识别功能，设置页对应开关隐藏或置灰并提示"当前平台不支持" |

> **Tauri 实现策略**：通过 Tauri plugin 系统调用平台原生 API。macOS/iOS 使用 `local-auth` 或自定义 Swift/Objective-C 插件；Windows 通过 Rust 的 `windows-rs` crate 直接调用 Windows Hello API；Linux 直接返回"不支持"。

## 3. IPC 命令

### 3.1 命令总览（新增 5 个命令）

| 命令 | 说明 | 认证要求 |
|------|------|---------|
| `biometric_check_availability` | 检查当前平台是否支持生物识别 | 无 |
| `biometric_save_credential` | 保存生物识别凭证（会话密钥写入 Keychain） | 需主密码验证 |
| `biometric_unlock` | 通过生物识别解锁 Vault | 无（交互由系统处理） |
| `biometric_delete_credential` | 删除生物识别凭证 | 需主密码验证 |
| `biometric_test` | 测试生物识别是否正常工作 | 无 |

### 3.2 命令详细定义

```rust
/// 检查当前平台是否支持生物识别
/// 返回：{ available: bool, biometryType: BiometryType | null, error: string | null }
#[tauri::command]
pub async fn biometric_check_availability() -> Result<BiometricAvailability, String>;
```

```typescript
enum BiometryType { touchId = 'touchId', faceId = 'faceId', iris = 'iris', windowsHello = 'windowsHello' }

interface BiometricAvailability {
  available: boolean;
  biometryType?: BiometryType;  // 具体可用的生物识别类型
  error?: string;               // 不可用时说明原因（"硬件不支持"/"系统未设置指纹"/"驱动未安装"）
}
```

```rust
/// 保存生物识别凭证
/// 1. 验证主密码（确认用户身份）
/// 2. 从当前会话派生会话密钥
/// 3. 将会话密钥写入 OS Keychain（受生物识别保护）
/// 必须传入 password 以验证用户身份
/// silent=true 时不弹出系统生物识别对话框（用于密码变更后自动更新）
#[tauri::command]
pub async fn biometric_save_credential(
    account_id: String,
    password: String,
    silent: Option<bool>,  // 默认为 false；true 时跳过系统对话框，静默更新 Keychain
) -> Result<(), String>;
```

```rust
/// 通过生物识别解锁 Vault
/// 1. 弹出系统生物识别对话框（Face ID / Touch ID / Windows Hello）
/// 2. 验证成功后从 Keychain 读取会话密钥
/// 3. 使用会话密钥解锁 Vault
/// 失败场景：用户取消 / 验证失败 / Keychain 中无凭证 / 凭证过期
#[tauri::command]
pub async fn biometric_unlock(account_id: String) -> Result<(), String>;
```

```rust
/// 删除生物识别凭证
/// 必须传入 password 以验证用户身份（禁用状态也需要验证才能删除）
#[tauri::command]
pub async fn biometric_delete_credential(
    account_id: String,
    password: String,
) -> Result<(), String>;
```

```rust
/// 测试生物识别
/// 弹出系统生物识别对话框，验证通过后返回 success
/// 不执行任何解锁操作，仅用于设置页测试
#[tauri::command]
pub async fn biometric_test(account_id: String) -> Result<bool, String>;
```

## 4. 生命周期

### 4.1 注册流程

```
┌─ 设置页 ─────────────────────────────────┐
│  生物识别解锁          [关闭]             │
│  └── 点击开关 → 弹出密码验证对话框         │
└────────────────────────────────────────────┘

1. 用户点击生物识别开关（开启）
2. 弹出密码验证对话框（必须输入主密码）
   ↓ 密码验证通过
3. 调用 biometric_save_credential
   ↓   a. 验证主密码
       b. 获取当前会话密钥
       c. 弹出系统生物识别对话框（写入 Keychain 前二次确认）
   ↓ 凭证写入成功
4. 开关变为开启状态
5. 写入审计日志："生物识别解锁已开启（Face ID）"
6. 广播事件 "biometric-enabled"
```

**验证规则**：

| 场景 | 行为 |
|------|------|
| 密码验证失败 | 提示"密码错误"，开关维持关闭 |
| 系统生物识别对话框取消 | 提示"生物识别已取消"，开关维持关闭 |
| Keychain 写入失败 | 提示"保存失败，请重试"，开关维持关闭 |
| 已有凭证 | 覆盖写入（无需先删除）|

### 4.2 解锁流程

```
┌─ LoginPage ──────────────────────────────┐
│  [✔ 使用面容 ID 解锁]                     │
│  或                                       │
│  [使用主密码解锁]                          │
└────────────────────────────────────────────┘

1. 用户点击"使用 {biometricType} 解锁"
2. 调用 biometric_unlock
   ↓
3. 弹出系统生物识别对话框
   ↓ 验证成功
4. 从 Keychain 读取会话密钥
   ↓
5. 使用会话密钥解锁 Vault
   ↓ 成功
6. 跳转 HomePage
7. 写入操作日志："通过 Face ID 解锁"

   ↓ 验证失败
   a. 用户取消 → 返回登录页，不报错
   b. 验证失败 → 显示"验证失败，请重试或使用密码"
   c. 连续失败 3 次 → 系统自动退化为密码输入
   d. Keychain 无凭证 → 提示"生物识别未设置，请使用密码"
```

**解锁页面入口**：

```
┌──────────────────────────────────────────────┐
│                                              │
│              [账户图标/名称]                  │
│                                              │
│          [指纹/面容 图标]                    │
│      使用 Touch ID 解锁 SoloSoul              │
│                                              │
│  ┌────────────────────────────────────────┐  │
│  │           使用主密码解锁               │  │
│  └────────────────────────────────────────┘  │
│                                              │
└──────────────────────────────────────────────┘
```

| 元素 | 规范 |
|------|------|
| **生物识别图标** | 根据 `BiometryType` 显示对应系统图标（指纹/面容/人脸），大尺寸居中 |
| **提示文字** | "使用 {Face ID/Touch ID/Windows Hello} 解锁 SoloSoul"，系统对话框将叠加显示 |
| **备用入口** | "使用主密码解锁" 链接，点击跳转密码输入界面 |
| **首次加载** | 自动触发生物识别（不等待用户点击），可加快解锁速度 |
| **自动触发失败** | 若自动触发失败（如传感器被遮挡），降级为显示图标 + 手动点击解锁 |
| **锁定缓存** | 若用户连续失败 3 次（系统限制），隐藏生物识别图标，仅显示密码输入 |

### 4.3 禁用流程

```
┌─ 设置页 ─────────────────────────────────┐
│  生物识别解锁          [开启]             │
│  └── 点击开关 → 弹出密码验证对话框         │
└────────────────────────────────────────────┘

1. 用户点击生物识别开关（关闭）
2. 弹出密码验证对话框（必须输入主密码）
   ↓ 密码验证通过
3. 调用 biometric_delete_credential
   ↓   a. 验证主密码
       b. 从 Keychain 删除会话密钥
   ↓ 凭证删除成功
4. 开关变为关闭状态
5. 写入审计日志："生物识别解锁已关闭"
6. 广播事件 "biometric-disabled"
```

### 4.4 密码变更后的处理

修改密码成功后，系统自动执行：

```
用户修改主密码成功后
  ↓
1. Rust 后端检测到密码变更
2. 检查当前账户是否有生物识别凭证（biometricEnabled == true）
   ↓ 有凭证
3. 使用新主密码重新派生会话密钥
4. 调用 biometric_save_credential(silent=true) 静默更新 OS Keychain
   ↓ 静默更新成功               ↓ 静默更新失败
   ┌──────────────────┐        ┌──────────────────────────────┐
   │ 5a. 凭证更新完成  │        │ 5b. 标记旧凭证为过期         │
   │ 6a. 无需通知用户  │        │ 6b. 广播事件                │
   │     （完全无感）  │        │     "biometric-credential-  │
   └──────────────────┘        │      expired"                │
                               │ 7b. 前端收到事件             │
                               │ 8b. 设置页显示提示：          │
                               │     "密码已变更，需要更新     │
                               │      生物识别设置"           │
                               │ 9b. 生物识别开关显示           │
                               │     [需要更新]（橙色警告）    │
                               │ 10b. 用户点击开关 →          │
                               │      弹出密码验证对话框       │
                               │ 11b. 验证通过 → 调用          │
                               │      biometric_save_          │
                               │      credential(silent=false) │
                               │      写入新会话密钥           │
                               └──────────────────────────────┘
                               ↓ 用户忽略不更新
                               12b. 下次使用生物识别解锁时，
                                    biometric_unlock 检测到凭
                                    证过期，提示"密码已变更，
                                    请使用密码解锁后重新设置
                                    生物识别"，自动退化为密码
                                    输入界面
```

**凭证过期状态转换**：

| 状态 | 前端表现 | 后端行为 |
|------|---------|---------|
| `valid`（正常） | 开关正常显示开启状态 | Keychain 凭证可正常使用 |
| `auto-updating`（自动更新中） | 无表现（自动流程，前端不感知） | Rust 后端正在更新 Keychain 凭证 |
| `expired`（过期） | 开关显示"需要更新"（橙色警告），可点击重新注册 | 静默更新失败后标记；Keychain 凭证仍存在但标记为过期，`biometric_unlock` 返回过期错误 |
| `none`（无凭证） | 开关关闭 | Keychain 中无凭证 |

**自动更新安全分析**：

| 考量 | 说明 |
|------|------|
| **身份已验证** | 自动更新发生在密码修改流程中，用户已输入正确旧密码+设置新密码，身份已经过完整验证 |
| **无需要新授权** | 生物识别是用户之前主动开启的功能，自动更新只是更新凭证内容，不是改变用户的授权决策 |
| **平台可行性** | macOS/iOS 同进程更新已存在的 Keychain 项无需系统对话框；Windows Hello 可在已验证会话中无感更新 |
| **失败不阻塞** | 静默更新失败**不影响密码变更本身**——密码已成功修改，生物识别凭证降级为过期状态，用户可后续手动修复 |
| **审计完备** | 自动更新成功/失败均写入操作日志 |

## 5. 平台差异

| 场景 | macOS | iOS | Windows | Linux |
|------|-------|-----|---------|-------|
| 生物识别类型 | Touch ID | Face ID / Touch ID | Windows Hello（人脸/指纹/PIN） | 不支持 |
| API 集成 | `local-auth` Tauri plugin | `local-auth` Tauri plugin | `windows-rs` → `Windows.Security.Credentials.UI` | — |
| 多指纹/多人脸 | 系统管理，应用不感知 | 系统管理，应用不感知 | 系统管理，应用不感知 | — |
| 传感器故障 | `biometric_check_availability` 返回 `available=false` | 同左 | 同左 | `available=false` |
| 系统未注册指纹 | `available=false`，`error="系统未设置指纹"` | `available=false` | `available=false` | — |
| 恢复出厂设置后 | Keychain 凭证丢失 → `biometric_unlock` 返回凭证不存在错误 | 同左 | — | — |

**退化策略（Linux 平台）**：

| UI 元素 | 处理 |
|---------|------|
| 设置页生物识别开关 | 隐藏（不显示该设置项）或置灰 + Tooltip"当前平台不支持生物识别" |
| 登录页生物识别按钮 | 不显示，仅显示密码输入 |
| 敏感数据保护 | **sensitive 级别字段**在 Linux 上直接要求输入密码（退化为密码验证），不再有"生物识别快捷解锁"选项 |

| 元素 | 规范 |

## 7. 安全约束与审计

| 约束 | 要求 |
|------|------|
| 主密码不出 IPC | 所有需要密码的操作在 `biometric_save_credential` / `biometric_delete_credential` 时接收密码，但绝不通过 IPC 返回值或事件泄露密码 |
| 会话密钥不出 Rust | 生物识别解锁的会话密钥仅在 Rust 后端内存中使用，绝不通过 IPC 传递给前端 |
| 审计日志写入 | 每次生物识别解锁成功写入操作日志（类型、时间戳、结果），**不记录生物特征数据** |
| 密码变更强制处理 | 修改密码成功后自动静默更新生物识别凭证；自动更新失败时标记过期，确保旧凭证不可用 |
| 自动更新跳过系统对话框 | 密码变更流程中 `biometric_save_credential(silent=true)` 已验证用户身份，无需再次弹窗确认 |
| 连续失败锁定 | 系统生物识别 API 自行控制失败次数锁定（iOS/macOS 3 次后需密码），应用层不做额外限制 |
| 凭证不可导出 | 存储于 OS Keychain 的凭证标记为不可导出属性（`kSecAttrAccessibleWhenUnlockedThisDeviceOnly`） |

## 9. 完成标准

### P0（必须 — 生物识别核心流程）
- [ ] `biometric_check_availability` 返回正确的设备生物识别能力
- [ ] `biometric_save_credential` 写入会话密钥到 OS Keychain（受生物识别保护）
- [ ] `biometric_unlock` 通过系统对话框验证后从 Keychain 读取会话密钥并解锁 Vault
- [ ] `biometric_delete_credential` 从 Keychain 删除会话密钥
- [ ] 注册流程：密码验证 → 系统生物识别对话框 → Keychain 写入 → 开关开启
- [ ] 解锁流程：系统对话框 → Keychain 读取 → Vault 解锁 → 跳转首页
- [ ] 禁用流程：密码验证 → Keychain 删除 → 开关关闭
- [ ] 密码变更后自动静默更新生物识别凭证（`silent=true`），更新失败时标记过期
- [ ] 密码变更自动更新成功时用户无感知，无需弹出系统对话框

- [ ] 凭证过期后 `biometric_unlock` 返回过期错误并退化为密码输入
- [ ] 连续失败 3 次后自动退化为密码输入
- [ ] Linux 平台设置页生物识别开关隐藏/置灰，登录页不显示生物识别按钮
- [ ] 各平台测试通过：macOS Touch ID / iOS Face ID / Windows Hello
