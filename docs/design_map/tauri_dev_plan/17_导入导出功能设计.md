# 14 — 导入导出功能设计

> **前置阅读**：`07_数据库_服务层_Repository迁移.md`、`15_用户数据边界与加密存储方案.md`、`06_数据组织模型架构决策.md`
> **架构说明**：本规范中"对象"指 objects 表中的记录（见 06_数据组织模型架构决策.md — 扁平模型），不再使用旧 Profile 概念。导入导出均基于 `object_list` / `object_read` / `object_create` 接口。
> **Manifesto 对齐**：用户主权 | 隐私优先 | 安全默认
> **源文档**：`tauri_refactor/导入导出功能重构设计.md`

## 1. 设计原则

### 为什么细化到"对象层"为止，不开放字段级别？

1. **数据完整性**：护照对象包含姓名、国籍、护照号等字段，共同构成完整记录。导出"只有姓名和国籍的护照"无意义。
2. **关系完整性**：对象可能包含 RelationProperty 指向其他对象，字段级导出会产生孤立引用。
3. **用户体验**：字段级选择让导出 UI 极其复杂（每个对象展开几十个字段），违背"最少惊喜"。
4. **粒度足够**：对象级导出已满足"只导出护照"的实际需求。

### 导出范围的三层结构

```
身份数据
├── 页面层 → "导出我的所有旅行数据"
├── 对象层 → "导出我的护照"（可勾选多个对象）
└── 附件层 → "只导出扫描件，不导出照片"

偏好数据
├── 视觉偏好（主题、颜色、字体）
├── 行为偏好（锁定超时、生物识别、删除确认）
├── 内容偏好（语言、日期格式、时区）

行为记录
├── 操作日志（CRUD、敏感度变更）
├── 搜索历史
├── AI 对话历史
```

### 对象选择机制

扁平模型下，页面内的对象列表支持以下选择方式：

| 选择方式 | 说明 |
|---------|------|
| **手动勾选** | 页面列表中逐项勾选/取消 |
| **全选/反选** | 页面的批量操作按钮 |
| **按标签筛选后勾选** | 先按 `tags_json` 筛选（如"只显示标签为 `2025日本` 的对象"），再对筛选结果勾选 |
| **选择所有** | 勾选"页面"即选中该页面下的全部对象 |

```typescript
interface ExportScope {
  selectedPageIds: string[];          // 整页全选（section_type，如 travel/financial）
  selectedObjectIds: string[];        // 手工勾选的对象 ID
  selectedTags: string[];             // 按标签筛选（与 selectedObjectIds 交集生效）
  includeAttachments: boolean;        // 是否包含附件
  includePreferences: boolean;        // 偏好数据（P2）
  includeBehavioral: boolean;         // 行为记录（未来）
}
```

### 数据安全提示（P1）

导出包含 `sensitive`/`critical` 级别字段时，在导出确认界面显示警告横幅：
```
所选数据包含高敏感度字段，导出文件使用密码加密，请妥善保管。
```
LLM API 密钥作为 `critical` 级别字段，由通用敏感度警告覆盖，不单独处理。

### 实现优先级

| 功能 | 优先级 | 理由 |
|------|--------|------|
| 页面层 + 对象层导出（加密） | **P0（必须）** | 用户数据的核心备份/迁移路径 |
| 导入对象数据（含解密） | **P0（必须）** | 与导出配对，构成完整迁移闭环 |
| 导出密码（自定义密码） | **P0（必须）** | 导出文件加密安全底线 |
| 敏感度警告 | **P1（重要）** | 安全合规，但缺了不影响功能 |
| 导入密码提示词展示 | **P1（重要）** | 帮助用户回忆密码 |
| 导入预览 + 冲突检测 | **P1（重要）** | 提升导入 UX，避免数据覆盖 |
| 附件层导出 | **P2（增强）** | 依赖附件存储模块就绪 |
| 标签筛选导出（selected_tags） | **P2（增强）** | 依赖智能筛选功能就绪 |
| 偏好/行为数据导出 | **未来** | 数据边界还有待完善 |
| 明文 JSON 导出（三重确认） | **未来** | 合规场景，当前无实际需求 |
| 导入前自动创建静默备份 | **未来** | 备份功能独立，不应耦合在导入流程 |

## 2. 导出包格式

### P0 核心版

```
{scopeName}_export.solosoul (ZIP)
├── manifest.json           # 明文：版本、范围、时间、应用版本
│   ├── version: "2.0"
│   ├── export_scope: "partial" | "full"
│   ├── selected_pages: string[]
│   ├── selected_objects: string[]
│   ├── export_time: string
│   ├── export_platform: string
│   └── export_app_version: string
├── payload.enc             # 加密：所有选中对象的 JSON 数据（单文件，统一加密）
└── attachments/            # 可选（P2 实现）
    └── {fileId}.enc        # 每个附件独立加密
```

**简化理由**：加密 payload 即可保证数据安全，细分多个加密文件（preferences.enc、audit_log.enc、search_history.enc、ai_conversation.enc、sensitivity_map.enc 等）增加了开发成本和导入解析复杂度，收益微薄。P0 统一使用单一 `payload.enc`，未来扩展时如需新增数据类别，在 `manifest.json` 中通过 `extra_files` 字段声明。

### manifest.json 完整定义

```json
{
  "version": "2.0",
  "export_scope": "partial",
  "selected_pages": ["travel", "financial"],
  "selected_objects": ["obj_abc123", "obj_def456"],
  "export_time": "2026-06-07T14:30:00Z",
  "export_platform": "macos",
  "export_app_version": "2.1.0",
  "has_attachments": false,
  "extra_files": []
}
```

### 未来扩展版（P2+）

当需要支持 preferences、audit log 等额外数据时，在 ZIP 中新增对应加密文件：

```
{scopeName}_export.solosoul (ZIP)
├── manifest.json           # 新增 extra_files 描述所含文件清单
├── payload.enc             # 核心：所有对象的 JSON 数据
├── preferences.enc         # 用户偏好（可选）
├── audit_log.enc           # 审计日志（可选）
├── ai_conversations.enc    # AI 对话历史（可选）
├── attachments/
│   └── {fileId}.enc
```
> **附件支持依赖**：附件导入导出依赖附件存储模块就绪（见 09_对象规范 的附件系统），在附件系统未完成前，导入导出不处理附件。

## 3. 导出密码设计

### 密码模式（P0 仅支持自定义密码）

| 模式 | 优先级 | 说明 |
|------|--------|------|
| **使用自定义密码** | **P0** | 必须与主密码不同。最小 8 位。加密导出包的密钥由此密码派生 |
| **使用主密码** | **未来** | 复用 Vault 主密码。需评估导出包泄露风险 |

> **关键决策**：P0 仅支持自定义密码模式。导出文件离开本地设备后，如果复用主密码，导出包泄露 = 主密码泄露。导入导出应始终使用独立密码。

### 密码提示词（P1）

- 可选字段，最大 200 字符
- **明文**存储于 `manifest.json` 的 `password_hint` 字段（不加密），方便导入时展示
- 提示词不包含密码本身，安全可控

### 校验规则

| 场景 | 规则 |
|------|------|
| 自定义密码 | 最小 8 位，必须含字母+数字，两次输入一致 |
| 密码强度提示（P1） | 弱/中/强，弱密码需二次确认 |

### 明文导出（未来）

> **审批决策（2026-06-05）**：明文 JSON 导出需经过三重确认，且文件自动设置 `chmod 600`。

当前无实际需求，降级为未来。待需要时可参考以下流程实现：

```
用户选择"明文 JSON 导出"
    ↓
第一重：风险警告对话框
  "[警告] 明文导出意味着您的数据将以未加密的 JSON 格式保存..."
  [取消]  [我了解风险，继续]
    ↓
第二重：密码重新验证
  "请输入主密码以确认明文导出"
    ↓
第三重：审计日志记录
  明文导出操作写入 audit_log
    ↓
导出完成 → chmod 600
```

## 4. 导入功能

### P0 导入流程

```
① 选择 .solosoul 文件
② 输入导出密码 → 解密 payload.enc
③ 确认导入（全量覆盖当前账户数据）
④ 完成
```

### P1+ 增强流程

```
① 选择 .solosoul 文件
② 读取密码提示词（无需密码）并展示  ← P1 新增
③ 输入导出密码 → 解密预览            ← P1 增强
   ├── 展示即将导入的对象数量 + 名称列表
   └── 冲突检测：标记与现有对象冲突的条目
④ 导入策略选择                        ← P2 新增
   ├── 保留当前（跳过冲突条导入）
   ├── 覆盖（用导入包替换全量数据）
   └── 合并（导入覆盖冲突项，保留未冲突项）
⑤ 确认导入
```

### 跨范围引用处理

对象级导出时，RelationProperty 的目标对象可能不在导出范围内 → 导入时转为 `[引用对象未导出: {id}]` 文本备注。

## 5. IPC 命令

### P0 命令集

```rust
/// 获取导出范围树：返回按 section_type 分组的页面组 → 对象列表
/// 数据来源：object_list 查询（按 account_id + section_type 过滤）
#[tauri::command]
pub async fn export_get_scope_tree(account_id: String)
    -> Result<Vec<PageGroup>, String>;

/// 估算选中范围的导出大小
#[tauri::command]
pub async fn export_estimate_size(scope: ExportScope)
    -> Result<ExportEstimate, String>;

/// 执行导出：加密选中对象 → 写入 ZIP
#[tauri::command]
pub async fn export_execute(
    scope: ExportScope,
    password: String,
    password_hint: Option<String>,
    save_path: String,
) -> Result<String, String>;

/// 解析导入包：读取 manifest.json 基本信息
#[tauri::command]
pub async fn import_parse_package(file_path: String)
    -> Result<ImportPreview, String>;

/// 执行导入：解密 payload → 创建对象
#[tauri::command]
pub async fn import_execute(
    source_path: String,
    password: String,
) -> Result<bool, String>;
```

### P1+ 增强命令

```rust
/// 读取导入包的密码提示词（明文，无需密码）
#[tauri::command]
pub async fn import_get_password_hint(file_path: String)
    -> Result<Option<String>, String>;

/// 解密预览：解密后展示导入内容 + 冲突检测
#[tauri::command]
pub async fn import_decrypt_preview(
    file_path: String,
    password: String,
) -> Result<DecryptedImportPreview, String>;

/// 导入执行（带选择器和策略的完整版）
#[tauri::command]
pub async fn import_execute_advanced(
    selections: Vec<ImportSelection>,
    preference_strategy: String,
    source_path: String,
    password: String,
) -> Result<bool, String>;
```

## 6. 与备份服务的区别

| 维度 | 备份服务 | 导出服务 |
|------|---------|---------|
| 目的 | 本地时间点恢复 | 跨设备迁移、分享给第三方 |
| 范围 | 全量 | 可选（页面/对象（含附件）） |
| 加密密钥 | 当前 Vault 主密钥 | 独立导出密码（必须与主密码不同） |
| 存储位置 | `~/.solosoul/backups/` | 用户选择任意路径 |

## 7. 关键决策记录

| # | 决策 | 优先级 | 理由 |
|---|------|--------|------|
| 1 | 导出包统一使用单文件 `payload.enc`，不拆分多个加密文件 | **P0** | 降低开发成本和导入复杂度，数据安全不低于拆分方案 |
| 2 | 导出密码必须与主密码不同，不支持"复用主密码"模式 | **P0** | 导出文件离开本地后，复用主密码 = 主密码泄露 |
| 3 | 对象级导出不自动包含关联对象 | **P0** | 避免超出预期的数据泄露 |
| 4 | 密码提示词明文存储于 manifest.json | **P1** | 帮助用户回忆密码，不包含密码本身 |
| 5 | 不支持增量导出 | **当前** | 复杂度收益比不高 |
| 6 | 偏好/行为数据导出降级为 P2+/未来 | **P2+** | 数据边界还在定义中，不应绑定导入导出 |
| 7 | 导入前自动静默备份从导入流程中剥离 | **未来** | 备份功能独立，不应耦合在导入流程 |

## 8. 完成标准

### P0（必须完成）

- [ ] 三级范围选择器（页面/对象）正确工作，按 `section_type` 分组展示对象树
- [ ] `export_get_scope_tree` 查询 object_list，按 `section_type` 分组返回
- [ ] `export_execute` 加密选中对象为单文件 `payload.enc`，写入 ZIP
- [ ] 导出使用自定义密码（最小 8 位），与主密码独立
- [ ] `import_parse_package` 正确读取 manifest.json
- [ ] `import_execute` 解密 payload → 通过 object_create 导入

### P1（重要）

- [ ] 导入时读取密码提示词并展示（无需密码）
- [ ] 导入预览：显示即将导入的对象数量 + 名称列表
- [ ] 导入冲突检测：标记与现有对象冲突的条目
- [ ] 导出包含敏感度数据时显示警告横幅

### P2（增强）

- [ ] 附件层导出：选中对象的附件打包入 ZIP
- [ ] 对象级导出支持按 `tags_json` 标签筛选
- [ ] 导入策略选择（保留当前/覆盖/合并）
- [ ] 偏好数据导出（preferences.enc）

### 未来

- [ ] 行为数据导出（audit_log.enc / search_history.enc / ai_conversations.enc）
- [ ] 明文 JSON 导出（三重确认 + chmod 600）
- [ ] 导入前自动创建静默备份
