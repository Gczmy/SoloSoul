## 二、剩余差距（代码与文档仍不一致）

### 2.1 标签筛选导出：后端已支持，前端 UI 缺失

- **文档要求**（P1）：对象级导出支持按 `tags_json` 标签筛选
- **后端**：`ExportScope` 有 `selected_tags` 字段，`collect_scope_objects` 已实现标签交集过滤
- **前端**：`ExportImportPage.tsx` 中 `selectedTags` 始终传空数组 `[]`，且**没有任何标签筛选控件**

**差距说明**：后端能力已就绪，但前端未暴露该功能。用户无法按标签缩小导出范围。

---

### 2.2 密码提示词未校验是否包含密码本身

- **文档要求**（§3 密码提示词）：
  > 提示词**不得包含密码本身**（前后端均需做基础校验，如提示词与密码的相似度检测）

- **实际代码**：
  - 前端：`maxLength={200}` 限制长度，但没有与 `exportPassword` 的相似度比对
  - 后端：`export_execute` 接收 `password_hint`，直接写入 manifest，没有任何内容校验

**安全影响**：用户可能在提示词中直接写入密码（如密码是 `MyP4ssw0rd`，提示词是 `MyP4ss`），违反"安全可控"原则。

**建议修复**：
```rust
// 后端简单校验：如果提示词包含密码的子串（长度>=3），拒绝
if let Some(ref hint) = req.password_hint {
    if !hint.is_empty() && req.password.len() >= 3 && hint.to_lowercase().contains(&req.password.to_lowercase()[..3.min(req.password.len())]) {
        return Err("Password hint must not contain parts of the password".to_string());
    }
}
```

### 2.3 `export_scope` 值域仍出现 `"none"`

- **文档定义**：`"partial" | "full"`
- **实际代码**（`export_import.rs:436`）：
  ```rust
  "export_scope": if req.scope.selected_page_ids.is_empty() && req.scope.selected_object_ids.is_empty() { "none" } else { "partial" },
  ```

**问题**：虽然空选择在前后端都被拒绝（不会实际生成 `"none"` 的 manifest），但代码路径中存在规范未定义的值。属于防御性编程不足。

**建议修复**：直接写死 `"partial"`，因为空选择已在前面被拒绝。

---

### 2.4 `includeBehavioral` 完全缺失

- **文档接口**：`ExportScope.includeBehavioral: boolean`
- **实际代码**：前后端均无此字段

**说明**：文档将其标为"未来"功能，但接口定义中已存在。实现滞后于接口定义。当前无实际影响，但需记录。

---

### 2.5 `ImportPreview` 类型命名不一致

- **文档**：`ImportPreview`
- **代码**：`ImportPreviewResponse`

**说明**：字段基本一致（代码多一个 `file_path`），属于命名不一致。不影响功能，但建议统一。

---

### 2.6 前端 `ObjectSummary` 的 `tags` 字段为可选

- **文档**：`tags: string[]`（必需）
- **前端代码**（`ExportImportPage.tsx:30`）：`tags?: string[]`（可选）

**说明**：虽然不影响运行时（后端返回的 `tags` 始终存在），但类型契约不一致。

---

### 2.7 `export_get_scope_tree` 回退逻辑未在文档中定义

代码中对 `section_type` 为空的对象做了以下回退：
```rust
let st = if obj.section_type.is_empty() {
    if obj.collection_type.is_empty() {
        "identity".to_string()  // 硬编码默认
    } else {
        obj.collection_type.clone()
    }
} else {
    obj.section_type.clone()
};
```

**问题**：文档未提及此回退逻辑。`"identity"` 作为硬编码默认值可能在数据模型变化时失效。建议文档补充此脏数据处理策略，或将默认值改为 `"uncategorized"`。
