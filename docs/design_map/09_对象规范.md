## 1. 对象定位

### 1.1 对象必须被放置在工作区页面中

对象是 SoloSoul 数据模型的最小业务单元，**必须归属且仅归属一个页面**。

```
┌─────────────────────────────────────────┐
│  Travel Page                            │
│  ├─ 护照 · 张三      ← 对象            │
│  ├─ 签证 · 日本      ← 对象            │
│  ├─ 机票 · 东京      ← 对象            │
│  └─ 酒店 · 新宿      ← 对象            │
└─────────────────────────────────────────┘
```

**约束**：

| 规则 | 说明 |
|------|------|
| 对象必须归属页面 | `collectionType` 字段不可为空，取值：`identity` / `travel` / `financial` / `professional` / `{custom_page_id}` |
| 对象不可游离 | 禁止创建不归属任何页面的对象（代码层面通过必传 `collectionType` 校验） |
| 对象不可跨页 | 一个对象只能属于一个页面 |
| 页面删除连带回收 | 删除自定义页面时，页面内所有对象一并进入回收站 |

> **注意**：实际代码中 `section_type` 对应 Zustand store 中的 `collectionType` 字段（前端），后端 Rust 使用 `section_type`。前端通过 `ObjectWorkspacePage` 根据 `collectionType` 过滤展示。

### 1.2 对象与页面的关系

```
Page (页面) — 参见 §03 项目顶层结构
  ├── 元数据：名称、图标、排序位置
  ├── 配置：页面级敏感度默认、标签预设
  └── Objects[] (对象列表) ← 扁平结构

Object (对象)
  ├── 元数据：ID、名称、创建/更新时间
  ├── 页面归属：collectionType（所在页面，Rust 侧称 section_type）
  ├── 模板：templateId（关联到用户模板）
  ├── 属性：properties（Record<string, unknown> 扁平键值对）
  ├── 标签：tags[]（前端过滤用）
  ├── 敏感度：sensitivityLevel（继承自模板的属性级敏感度）
  ├── 历史：snapshots[]（快照列表，独立表）
  ├── 插件：contractTypeId（可选，绑定插件合约）
  └── 附件：attachments[]（独立于对象属性管理）
```

### 1.3 collectionType 与 templateId 的职责分离

对象有两个不同维度的分类字段，**不可混用**：

| 字段 | 语义 | 取值示例 | 用途 |
|------|------|---------|------|
| **`collectionType`** | **页面归属**——对象放在哪个页面 | `travel` / `financial` / `professional` / `custom_abc123` | Workspace 查询、页面筛选、回收站恢复定位 |
| **`templateId`** | **模板 ID**——对象使用的用户模板 | `tpl_passport` / `utpl_xxx` (用户模板) | 字段结构定义、属性预填充、图标选择 |

> **为什么需要两个字段**：
> - `templateId = 'passport'` 表示"这个对象使用了护照模板"（加载护照字段定义）
> - `collectionType = 'travel'` 表示"这个护照放在旅行页面"
> - 一个模板可以用于多个页面中的对象

### 1.4 实际 IPC 查询约束

```typescript
// 前端通过 Zustand store 调用 Tauri IPC
import { invoke } from '@tauri-apps/api/core';

// 按页面归属列出对象

  accountId,
  filter: { collectionType: 'travel' }   // 可选
});

// 按自定义页面 ID 列出
invoke<ObjectSummary[]>('object_list', {
  accountId,
  filter: { parentId: customPageId }
});

// 批量查询快照计数
invoke<Record<string, number>>('snapshot_count_batch', {
  objectIds: ['id1', 'id2', 'id3']
});

// 批量查询附件计数
invoke<Record<string, number>>('attachment_count_batch', {
  objectIds: ['id1', 'id2', 'id3']
});
```

## 2. 对象属性系统

### 2.1 属性结构

对象的属性以 **扁平 `Record<string, unknown>`** 形式存储（非设计文档中的 `Property[]` 结构）。属性值直接存储，字段元数据（类型、敏感度、顺序）由关联模板定义。

```typescript
// 实际前端类型定义 (tauri/src/types/template.ts)
export type PropertyType =
  | 'text'         // 单行文本
  | 'multiline'    // 多行文本
  | 'number'       // 数字
  | 'date'         // 日期（YYYY-MM-DD）
  | 'datetime'     // 日期时间
  | 'boolean'      // 是/否
  | 'select'       // 单选（预定义选项）
  | 'multiselect'  // 多选（预定义选项）
  | 'url'          // URL 链接
  | 'email'        // 邮箱
  | 'phone'        // 电话
  | 'file';        // 文件引用（指向附件）

export type SensitivityLevel = 'public' | 'internal' | 'sensitive' | 'critical';

export interface TemplateProperty {
  id: string;
  name: string;
  type: PropertyType;
  sensitivityLevel?: SensitivityLevel;  // 4 级敏感度
  sensitive?: boolean;                  // 遗留兼容字段
  options?: string[];                   // select / multiselect 的选项列表
  deprecatedAt?: string;                // ISO 8601 时间戳，软删除标记
  contractField?: boolean;              // 插件合约字段映射
}
```

**与设计文档的差异**：

| 差异点 | 设计文档 | 实际实现 |
|--------|---------|---------|
| 字段命名 | 大写 PascalCase（`Text`、`Number`） | 全小写 kebab-case（`'text'`、`'number'`） |
| 属性存储 | `Property[]` 数组，每项含 id/name/type/value | 扁平 `Record<string, unknown>`，值直接写入 |
| 字段元数据 | 存储在对象中 | 存储在 `UserTemplate.properties[]` 中 |
| 字段类型 | 无 `multiline`、`file`、`datetime` | 实际增加了 `multiline`、`file`、`datetime` |
| 字段类型 | `Phone` | `'phone'`（无独立验证逻辑，只做正则） |
| 敏感度 | 内置 `sensitive` boolean | 4 级 `sensitivityLevel`（public/internal/sensitive/critical） |
| 字段废弃 | 无 | `deprecatedAt` — ISO 时间戳，有值即为废弃 |

### 2.2 字段类型与对应的输入组件

实际前端渲染通过 `TemplateFieldInput` 组件实现，每种 `PropertyType` 映射到不同的 UI 控件：

| PropertyType | 渲染组件 | 输入类型 |
|-------------|---------|---------|
| `text` | `<input type="text">` | 单行文本 |
| `multiline` | `<textarea>` | 多行文本 |
| `number` | `<input type="number">` | 数字输入 |
| `date` | `<DatePicker>` | 日期选择（YYYY-MM-DD） |
| `datetime` | `<DatePicker includeTime>` | 日期时间选择 |
| `boolean` | `<input type="checkbox">` | 复选框 |
| `select` | `<select>` | 下拉单选 |
| `multiselect` | 多个 `<input type="checkbox">` | 多选列表 |
| `url` | `<input type="url">` | URL 输入 |
| `email` | `<input type="email">` | 邮箱输入 |
| `phone` | `<input type="tel">` | 电话输入 |
| `file` | `<input type="text">` | 文件引用文本 |

### 2.3 对象编辑器中的字段验证

编辑器（`ObjectEditorPage`）在保存前对字段做基础验证：

| 字段类型 | 验证规则 |
|---------|---------|
| `email` | 正则 `/^[^\s@]+@[^\s@]+\.[^\s@]+$/` |
| `url` | 尝试 `new URL()` 构造（缺少协议时自动补 `https://`） |
| `phone` | 正则 `/^[\d\s\-+()]{3,20}$/` |
| `date` | 正则 `/^\d{4}-\d{2}-\d{2}$/` |
| `number` | `Number.isNaN(Number(val))` |

### 2.4 属性级敏感度

每个字段通过模板的 `sensitivityLevel` 属性设置敏感度，与对象级敏感度分离：

```
对象：护照 · 张三
  模板：passport（定义各属性敏感度）
  
  字段：
    ├─ full_name            internal      → 阴影遮蔽（blur 5px），点击直接揭示
    ├─ passport_number      critical      → 需密码验证，PasswordVerificationDialog
    ├─ issuing_country      public        → 始终可见
    └─ photo                file          → 文件引用
```

**敏感数据揭示交互**（`ObjectDetailModal` 实现）：

| 敏感度 | 揭示方式 | 行为 |
|--------|---------|------|
| `sensitive` | Eye 图标 + "揭示" | 直接揭示，不验证密码（`useRevealState` hook） |
| `critical` | Lock 图标 + "解锁" | 唤起 `PasswordVerificationDialog`（支持密码/Touch ID/Face ID），计入审计日志 |

## 3. 模板系统

### 3.1 模板定位

模板是 **用户创建的属性集合定义**，用于快速创建同类对象。实际实现中**没有区分系统模板和用户模板**——所有模板都是用户创建的 `UserTemplate` 实体。

| 模板类型 | 来源 | 可编辑 | 可删除 |
|----------|------|--------|--------|
| **系统模板**（预定义） | 未单独实现 | — | — |
| **用户模板** | 用户手动创建或从对象保存 | 可编辑 | 可删除 |

> **重要变更**：设计文档建议的系统模板作为 Rust 侧硬编码常量，实际实现中模板完全由用户创建（通过 `TemplateManagerPage`）。可通过导入通用模板集作为基于模板创建的对象入口。

### 3.2 实际模板类型定义

```typescript
// tauri/src/types/template.ts — 完整的模板对应
export interface UserTemplate {
  id: string;
  accountId: string;
  name: string;                     // 模板名称（如"护照"、"身份证"）
  iconId?: string;                  // 图标标识（用于 resolveCustomIcon）
  properties: TemplateProperty[];   // 属性定义列表
  category?: string;                // 页面分类（identity/travel/financial/professional/自定义）
  createdAt: string;
  updatedAt?: string;
  contractTypeId?: string;          // 插件合约类型 ID（可选，绑定插件时使用）
}
```

### 3.3 模板使用流程（实际实现）

对象创建通过 `ObjectEditorPage` 完成：

```
点击"创建对象"按钮 → /editor?section={sectionType}
    ↓
显示该分类下的所有模板按钮（从 userTemplates 按 category 过滤）
    ↓
用户选择模板（或点 "管理模板" 跳转 TemplateManagerPage）
    ↓
自动填充模板字段（TemplateFieldInput 按 PropertyType 渲染）
    ↓
填写对象名称 + 字段值
    ↓
点击保存 → useObjectStore.createObject() → invoke('object_create')
    ↓
新对象出现在工作区页面
```

**关键实现细节**：

- 模板选择按钮使用 `color-mix` 背景色，选中时 `accent-primary` 边框
- 支持通过 `PluginBadge` 显示模板关联的插件合约
- 支持字段废弃回退展示（`deprecatedAt` 字段渲染为 `DeprecatedBadge` 并降低 opacity）
- 编辑对象时自动匹配模板（优先通过 `templateId`，回退到按属性键名匹配）
- 向后兼容旧版 `utpl_` 前缀的用户模板

### 3.4 模板 IPC 接口

```typescript
// 模板 Store (tauri/src/stores/templateStore.ts) 封装的 IPC 调用

// 列出所有用户模板
invoke<UserTemplate[]>('template_list');

// 创建模板
invoke<string>('template_create', {
  name, iconId, category, properties, contractTypeId
});

// 更新模板
invoke<void>('template_update', {
  templateId, name, iconId, category, properties
});

// 删除模板
invoke<void>('template_delete', { templateId });

// 获取单个模板
invoke<UserTemplate | null>('template_get', { templateId });

// 从对象保存为模板
invoke<string>('template_save_from_object', {
  objectId, templateName, iconId
});

// 检查字段使用情况（删除字段前确认）
invoke<{ active: number; softDeleted: number }>('template_check_field_usage', {
  templateId, fieldKey
});
```

### 3.5 字段废弃机制

模板字段支持**软删除（废弃）**而非物理删除，确保历史对象的旧字段仍然可展示：

- 字段添加 `deprecatedAt` 时间戳后，新创建对象不再展示该字段
- 已有该字段值的旧对象仍可查看和编辑（降 opacity + `textDecoration: line-through`）
- `DeprecatedBadge` 组件标识废弃字段
- 通过 `template_check_field_usage` 查询字段使用情况，辅助用户决定是否废弃

### 3.6 插件合约集成

模板通过 `contractTypeId` 绑定插件合约：

- 模板创建时可选关联 `contractTypeId`
- 使用该模板创建的对象自动继承 `contractTypeId`
- `ObjectDetailModal` / `WorkspaceObjectCard` / `ObjectEditorPage` 均展示 `PluginBadge`
- 属性字段的 `contractField` 标记该字段为插件合约字段（在 chip 中显示缩略图标）

## 4. 对象 CRUD

### 4.1 数据流架构

实际采用 **Zustand Store → Tauri IPC → Rust Backend** 三层架构：

```
前端组件 (ObjectEditorPage / ObjectDetailModal)
    ↓ 调用 Store 方法
Zustand Store (objectStore.ts)
    ↓ invoke()
Tauri IPC (commands/unified_object.rs)
    ↓
Rust Backend (Vault 加密存储)
```

### 4.2 前端数据类型

```typescript
// tauri/src/stores/objectStore.ts

// 列表摘要 — 用于 WorkspaceObjectCard 展示
export interface ObjectSummary {
  id: string;
  name: string;
  collectionType: string;         // 页面归属
  sectionType?: string;           // (可选，Rust section_type)
  sensitivityLevel: string;
  createdAt: string;
  updatedAt: string;
  isDeleted?: boolean;
  properties?: Record<string, unknown>;  // 扁平键值对
  tags?: string[];
  templateId?: string;
  templateType?: 'system' | 'user';
  contractTypeId?: string;         // 插件合约类型 ID
}

// 完整对象数据 — 用于详情/编辑
export interface ObjectData {
  id: string;
  accountId: string;
  name: string;
  collectionType: string;
  properties: Record<string, unknown>;
  sensitivityLevel: string;
  templateId?: string;
  templateType?: 'system' | 'user';
  createdAt: string;
  updatedAt: string;
  deletedAt?: string;
  tags?: string[];
  contractTypeId?: string;
}
```

### 4.3 创建对象

```typescript
// Store.createObject 方法
async createObject(input: {
  accountId: string;
  name: string;
  collectionType: string;              // 页面归属
  properties: Record<string, unknown>; // 字段值
  parentId?: string;                   // 自定义页面 ID
  iconName?: string;
  templateId?: string;                 // 使用的模板 ID
  templateType?: 'system' | 'user';
}): Promise<ObjectData>

// 底层 IPC
invoke<ObjectData>('object_create', { input });
```

**创建流程**（实际实现）：
1. 用户在工作区点击"创建"按钮 → 导航到 `/editor?section={sectionType}`
2. 页面加载该分类下的模板列表（按 `template.category` 过滤）
3. 用户选择模板 → 字段区域渲染对应的 `TemplateFieldInput` 控件
4. 填写对象名称 + 字段值
5. 点击保存 → Store 调用 `invoke('object_create')` → 成功后导航回工作区

### 4.4 编辑对象

```typescript
// Store.updateObject 方法
async updateObject(
  objectId: string,
  input: {
    name: string;
    properties: Record<string, unknown>;  // 完整属性值
  }
): Promise<void>

// 底层 IPC
invoke<ObjectData>('object_update', { objectId, input });
```

**编辑规则**：

| 规则 | 说明 |
|------|------|
| 全量更新 | 提交所有属性值（非增量），后端按需对比 |
| 历史记录 | 每次更新自动创建快照（见 §5） |
| 敏感属性 | 编辑 `critical` / `sensitive` 属性需要在揭示后操作 |
| 模板匹配 | 编辑时自动按 templateId + 属性键名匹配模板 |

### 4.5 查看对象

```typescript
// Store.getObject 方法
async getObject(accountId: string, objectId: string): Promise<void>
// 结果写入 store.currentObject

// 底层 IPC
invoke<ObjectData | null>('object_get', { accountId, objectId });
```

**查看规则**：

| 规则 | 说明 |
|------|------|
| 敏感属性遮蔽 | `sensitive` / `critical` 属性默认 `blur(5px)` 遮蔽，需揭示后查看 |
| `useRevealState` | 每个字段 ID 独立跟踪揭示状态（关闭模态框后重置） |
| 批量加载 | 工作区通过 `object_list` 加载摘要，需要详情时再调用 `object_get` |

### 4.6 删除对象

```typescript
// 软删除 → 进入回收站
invoke<void>('object_delete', { objectId });

// 列出回收站
invoke<ObjectSummary[]>('object_trash_list', { accountId });

// 从回收站恢复
invoke<void>('object_restore', { objectId, lang });

// 彻底删除（物理删除）
invoke<void>('object_purge', { objectId });
```

- 软删除后对象出现在回收站页面（`TrashPage`），可恢复至原页面
- 彻底删除不可逆，连带删除附件

## 5. 历史记录（快照）

> 本节内容基本与设计文档一致，快照系统通过 `HistoryViewer` 组件展示。

### 5.1 快照机制

对象的每次数据变更自动创建快照。实际实现通过 Rust 后端 `snapshot_*` 命令：

```typescript
// 批量获取快照计数（工作区 badge 展示）
invoke<Record<string, number>>('snapshot_count_batch', {
  objectIds: ['id1', 'id2', ...]
});

// 获取对象快照列表
// 通过 HistoryViewer 组件调用，显示时间线
```

### 5.2 实际 UI — HistoryViewer

- 以覆盖层形式弹出在 `ObjectDetailModal` 或工作区上方（`zIndex: 3100`）
- 时间线展示快照（时间戳 + diff 摘要）
- 点击快照可查看历史版本的数据
- 支持回滚到指定版本
- CRITICAL 字段在历史中同样需要密码揭示
- 继承当前模板的字段元数据（废弃字段、敏感度）

## 7. 对象 UI 规范

### 7.1 对象卡片（WorkspaceObjectCard）

对象在工作区页面以卡片形式呈现。组件位于 `tauri/src/pages/workspace/WorkspaceObjectCard.tsx`。

#### 7.1.1 卡片头部

```
┌──────────────────────────────────────────────────────────────┐
│ [模板图标]  对象名称  [页面标签]  [插件徽章]  [🕐3] [📎2] [✏️] [🗑️] │
│ ───────────────────────────────────────────────────────────  │
│  属性标签: 属性值  [属性标签: 属性值]  ...                      │
│  [标签1] [标签2] ...                                          │
└──────────────────────────────────────────────────────────────┘
```

| 元素 | 规范 | 实际 CSS |
|------|------|---------|
| **模板图标** | 左侧 22px，通过 `resolveCustomIcon` 渲染 | `flexShrink: 0` |
| **对象名称** | fontSize 14, fontWeight 600 | `overflow: hidden, textOverflow: ellipsis, whiteSpace: nowrap` |
| **页面标签** | 名称右侧小标签 | padding: `1px 5px`, border-radius: 4, background: `var(--bg-elevated)`, color: `var(--text-tertiary)`, fontSize: 10 |
| **插件徽章** | 若对象有 `contractTypeId` | `PluginBadge variant="full" size="sm"` |

#### 7.1.2 右侧操作按钮

| 按钮 | 图标 | 行为 | 徽章样式 |
|------|------|------|---------|
| **历史记录** | `Clock` (lucide-react) | 打开 HistoryViewer | 数字，`background: transparent`，`border: 1px solid var(--accent-primary)`，`color: var(--accent-primary)`，fontSize: 9 fontWeight: 700 |

| **编辑** | `Pencil` | 导航到 `/editor/{objectId}` | 无徽章 |
| **删除** | `Trash2` | 触发删除确认对话框 | 无徽章 |

**按钮样式**：
- 尺寸：32×32px，rounded 8px，背景透明
- Hover 历史/附件/编辑：`background: color-mix(in srgb, var(--accent-primary) 12%, transparent)` + `color: var(--accent-primary)`
- Hover 删除：`background: rgba(231,76,60,0.1)` + `color: #e74c3c`
- 徽章 99+ 截断：`count > 99 ? '99+' : count`

**CountButton 组件**：
- 每个按钮使用 `CountButton` 子组件统一渲染
- `position: relative` + `position: absolute` 定位徽章于右上角

#### 7.1.3 属性 Chips

```
[字段名: 字段值] border: 1px solid sensitivity_color
```

| 属性 | 规范 |
|------|------|
| 布局 | 横向 `flexWrap`，gap 6px，maxWidth 220px |
| 样式 | padding: `3px 8px`, borderRadius: 6, fontSize: 11, background: `var(--bg-toolbar)` |
| 敏感字段 | 值部分 `filter: blur(5px)`，显示 `••••`，border 使用 `getSensitivityStyle()` 的 `fg` 色 + `boxShadow` |
| 废弃字段 | `opacity: 0.6`, 字段名 `textDecoration: line-through` |
| 属性排序 | 按模板 `properties[].id` 顺序排序 |
| 空属性跳过 | 值为 null / undefined / "" 的不显示 |
| 插件字段 | 字段名前显示 `PluginBadge variant="icon"` |

#### 7.1.4 标签 Pills

- padding: `1px 7px`, borderRadius: 10, fontSize: 10, fontWeight: 500
- background: `rgba(91,124,153,0.08)`, color: `var(--accent-primary)`

- 卡片通过 `useDragToAttach` hook 支持拖入文件

#### 7.2.3 属性字段渲染

每行独立区域：

```jsx
<div style={{ background: 'var(--bg-toolbar)', borderRadius: 8, border: '1px solid var(--border-subtle)' }}>
  <SensitivityBadge level={sens} />
  <span>{getFieldName(f.key)}</span>
  {deprecated && <DeprecatedBadge />}
  <span>{revealed ? f.value : maskValue(f.value, fieldId, sens)}</span>
</div>
```

**敏感数据揭示交互**（关键安全逻辑）：

| 敏感度 | 按钮 | 点击行为 |
|--------|------|---------|
| `sensitive` | Eye + "揭示" | `useRevealState().reveal(fieldId)` — 直接揭示 |
| `critical` | Lock + "解锁" | `passwordVerify()` → `PasswordVerificationDialog` → 验证通过后 `reveal()` + 写入审计日志 |

- critical 揭示按钮背景：`rgba(220,38,38,0.06)`，Hover: `rgba(220,38,38,0.12)`
- sensitive 揭示按钮：与 accent 色一致
- 复制按钮：点击后颜色切换为 `#27ae60`，文本变为"已复制"，60ms 后恢复
- 废弃属性行：整体 opacity 0.7

**字段元数据 O(1) 查询**：

```typescript
// 通过 useMemo 缓存模板字段映射
const fieldMap = useMemo(() => {
  const tpl = templates.find(t => t.id === obj?.templateId);
  return new Map<string, TemplateProperty>(
    tpl?.properties.map(p => [p.id, p]) ?? []
  );
}, [templates, obj?.templateId]);

// O(1) 查询
getFieldProperty(fieldKey)   // → TemplateProperty | undefined
getFieldSensitivity(fieldKey) // → SensitivityLevel
isFieldDeprecated(fieldKey)   // → boolean
getFieldName(fieldKey)        // → string
```

**flattenProperties 工具**：将 `Record<string, unknown>` 转换为 `{ key, value }[]`，过滤 `__` 前缀的内部字段，按模板属性顺序排序。

### 7.3 对象编辑器（ObjectEditorPage）

组件位于 `tauri/src/pages/editor/ObjectEditorPage.tsx`。

#### 7.3.1 创建模式

- URL：`/editor?section={sectionType}` 或 `/editor?parentId={customPageId}`
- 按 `sectionType`/`parentId` 从 `userTemplates` 中过滤可用模板
- 模板选择按钮列表，支持点击切换
- 右侧提供"管理模板"入口（跳转 `TemplateManagerPage`，带回 `location.state.from` 返回）
- 如果分类下无模板，显示引导文字 + 跳转链接
- 自动选中第一个模板（`hasAutoSelectedRef` 防重复触发）

#### 7.3.2 编辑模式

- URL：`/editor/{objectId}`
- 通过 `getObject()` 加载对象数据
- 自动匹配模板（先按 `templateId`，再按属性键名 50% 匹配度）
- 向后兼容旧版 `utpl_` 前缀模板
- 编辑时禁用模板切换（保持字段一致性）

#### 7.3.3 字段渲染与验证

- 字段通过 `TemplateFieldInput` 组件渲染（自动匹配输入类型）
- 验证在保存前执行，显示红色错误提示（`#ef4444`）
- 字段 hint 根据类型显示（email/url/phone/date/number）
