## Crate 拆分策略

### Workspace 定义（Cargo.toml）

```toml
[workspace]
members = [
    "src-tauri",
    "crates/solosoul-crypto",
    "crates/solosoul-vault",
    "crates/solosoul-sync",
]
resolver = "2"

[workspace.dependencies]
# 密码学
argon2 = "0.5"
aes-gcm = "0.10"
zeroize = { version = "1.8", features = ["derive"] }
rand = "0.8"

# 数据库
rusqlite = { version = "0.32", features = ["bundled", "backup"] }

# 序列化
serde = { version = "1.0", features = ["derive"] }
serde_json = "1.0"

# 错误处理
thiserror = "1.0"
anyhow = "1.0"

# 异步
tokio = { version = "1.40", features = ["full"] }

# 日志
tracing = "0.1"
tracing-subscriber = "0.3"

# 测试
tempfile = "3"
```

### 拆分原则

| 原则 | 说明 |
|------|------|
| **单一职责** | 每个 crate 只做一件事（crypto 只做加密，vault 只做存储） |
| **无 Tauri 依赖** | `crates/` 下的 crate 不依赖 `tauri` crate，确保可独立测试 |
| **可复用** | `已废弃 工具复用，不绑定 GUI |
| **渐进拆分** | 初期所有代码在 `src-tauri/src/` 中，稳定后再提取到独立 crate |

### 依赖关系

```
src-tauri (Tauri App)
├── solosoul-crypto
├── solosoul-vault
│   └── solosoul-crypto
├── solosoul-sync
│   ├── solosoul-crypto
│   └── solosoul-vault
└── tauri (官方 crate)
```

## 前端目录结构

### 模块组织原则

```
按"旅程"组织 pages/，按"功能"组织 components/

pages/ 目录反映用户旅程（J1-J7），便于按旅程验证功能
components/ 目录反映 UI 层次（ui/layout/liquid-glass/data-display），便于复用
```

### 样式组织

```
不使用 CSS-in-JS 库（styled-components/emotion），原因：
1. 与 Liquid Glass 的复杂 CSS 效果不兼容
2. 运行时开销
3. 团队已有纯 CSS 经验（已废弃的 Web UI 项目）

采用方案：CSS Modules + 全局 CSS
- 组件级样式：Button.module.css（局部作用域）
- 全局样式：styles/*.css（Design Tokens、主题、动画）
- Liquid Glass：styles/liquid-glass.css（统一管理玻璃效果参数）
```

## 前后端边界定义

### 前端职责

| 职责 | 说明 |
|------|------|
| **UI 渲染** | React 组件树、页面布局、动画 |
| **用户交互** | 点击、输入、表单验证、导航 |
| **状态缓存** | Zustand 存储前端状态，减少 IPC 调用 |
| **IPC 调用** | 通过 `invoke()` 调用 Rust 命令 |
| **事件监听** | 通过 `listen()` 接收 Rust 事件 |
| **路由管理** | React Router 处理页面导航 |
| **本地化** | i18n 资源加载、语言切换 |

### 后端职责

| 职责 | 说明 |
|------|------|
| **业务逻辑** | 所有 CRUD、搜索、排序、过滤 |
| **数据持久化** | SQLite 读写、文件系统操作 |
| **密码学** | Argon2id、AES-GCM、密钥派生、安全内存 |
| **原生 API** | Keychain、生物识别、文件选择、系统通知 |
| **插件沙盒** | Wasmtime 执行环境 |
| **同步协议** | mDNS、Noise、CRDT |
| **日志记录** | 结构化日志、文件轮转 |

### 禁止越界

| 前端禁止 | 后端禁止 |
|---------|---------|
| ❌ 直接访问文件系统 | ❌ 操作 DOM |
| ❌ 直接访问数据库 | ❌ 渲染 UI |
| ❌ 持有密钥 | ❌ 处理路由导航 |
| ❌ 密码学运算（推导除外） | ❌ 管理前端状态 |
| ❌ 插件执行 | ❌ 本地化字符串处理 |

## 与当前 Flutter 项目的对照

| 当前 Flutter | Tauri 重构 | 说明 |
|-------------|-----------|------|
| `lib/` (Dart 前端) | `src/` (React 前端) | UI 层迁移 |
| `lib/core/services/` | `src-tauri/src/services/` | 服务层下沉 Rust |

## 从零搭建顺序

### Phase 1: 项目骨架（1-2 天）

1. **初始化 Tauri 项目**
   ```bash
   npm create tauri-app@latest solosoul -- --template react-ts
   ```

2. **配置 Workspace**
   - 根目录 `Cargo.toml` 定义 workspace
   - 创建 `crates/` 目录结构
   - 配置 Vite 6 + React 19

3. **配置开发工具**
   - ESLint + Prettier
   - Rust `cargo fmt` + `clippy`
   - TypeScript 严格模式
   - tauri-specta 生成 IPC 类型

### Phase 2: 核心库（3-5 天）

4. **提取 `solosoul-crypto`**
   - 从 `flutter/native/src/crypto/` 迁移 Argon2id + AES-GCM
   - 添加 `zeroize` 内存擦除
   - 单元测试

5. **提取 `solosoul-vault`**
   - 从 `flutter/native/src/vault/` 迁移 Vault 管理
   - SQLite + SQLCipher 集成
   - 单元测试

6. **配置 IPC 命令骨架**
   - 定义所有 `tauri::command` 函数签名（空实现）
   - tauri-specta 生成 TypeScript 类型
   - 前端 `src/lib/ipc.ts` 封装

### Phase 3: 前端基础（3-5 天）

7. **设计系统**
   - Design Tokens（tokens.css）
   - Liquid Glass CSS（liquid-glass.css）
   - 基础组件（Button, Input, Card）

8. **布局框架**
   - AppShell（Sidebar + Content）
   - AppBar
   - SideNavigation

9. **状态管理**
   - Zustand stores（auth, vault, profile, ui）
   - IPC 调用封装

### Phase 4: 功能迁移（5-10 天）

10. **按旅程逐个迁移页面**
    - J1: Bootstrap → Login → Home
    - J2: Home → Workspace → Editor → Search
    - J3: Settings → Security → Sensitivity
    - J4: DataManagement → ExportImport → Trash
    - J5: OCR → LLM → Plugin → Scan
    - J6: Sync
    - J7: DebugLog → About

### Phase 5: 测试与优化（3-5 天）

11. **测试**
    - Rust 单元测试
    - 前端组件测试（Vitest）
    - E2E 测试（Playwright）

12. **优化**
    - 包体积优化
    - 启动速度优化
    - Liquid Glass 性能调优
