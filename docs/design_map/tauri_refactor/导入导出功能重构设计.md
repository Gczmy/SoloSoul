## 1. 当前实现诊断

### 1.1 现有实现概览

当前 SoloSoul 的导入导出功能由 `ExportImportService` 实现，核心特征：

| 维度 | 当前行为 |
|---|---|
| **导出范围** | 全量导出：整个 Profile + 所有附件 |
| **导出粒度** | 无选择，一键导出所有数据 |
| **导入粒度** | Collection（分区）级别可选 |
| **加密方式** | 独立 exportKey（Argon2id 16MiB/3iter）重新加密所有数据 |
| **文件格式** | `.solosoul` ZIP 包（manifest.json + account.enc + profile.enc + attachments/） |
| **密码验证** | 导出时必须输入主密码（禁用生物识别） |
| **冲突处理** | 导入时按 collection 匹配名称，可合并到现有页面或创建新页面 |

### 1.2 代码结构


### 1.3 已知问题

#### ❌ 问题 1：导出无范围选择

```dart
// export_import_service.dart:35-45
Future<String?> exportPackage({
  required String accountId,
  required String password,
  ...
}) async {
  final profile = await ProfileStorageService.instance.loadProfile(accountId);
  // 直接导出整个 profile，没有选择范围
}
```

用户只能"全部导出"或"不导出"。如果只想分享护照信息给家人，或者只导出财务数据给会计师，无法做到。

#### ❌ 问题 2：导出包包含无关敏感数据

全量导出意味着 `.solosoul` 文件中包含所有数据——护照、银行卡、家庭住址、公司信息。即使用户只是想备份某个分区，也不得不导出全部。

这与"最小权限"原则冲突：导出包应该只包含用户明确选择要导出的数据。

#### ❌ 问题 3：导出加密强度与主密码相同

```dart
// export 使用 Balanced preset（16MiB / 3 iter）
final exportKey = await frb.frbDeriveKey(
  password: password,
  salt: exportSalt,
  memoryKib: 16384,   // 16 MiB
  iterations: 3,
  parallelism: 4,
);
```

如果用户选择导出"低敏感度"数据（如旅行计划），仍需要完整的主密码加密。可以考虑导出时根据数据最高敏感度调整 KDF 参数，但这会增加复杂度。暂时保持统一加密强度。

#### ❌ 问题 4：附件导出策略粗糙

```dart
// _collectAndReEncryptAttachments:648-679
for (final fileId in srcFileIds) {
  final bytes = await srcFile.readAsBytes();
  final encrypted = await frb.frbEncryptWithKey(plaintext: bytes, key: exportKey);
  await File(dstPath).writeAsBytes(encrypted);
}
```

附件是**全部导出**，没有选择。如果用户只导出某个 collection，应该只导出该 collection 引用的附件。

#### ✅ 已有优势

- 导入预览已按 collection 级别组织，有良好的选择基础
- 加密/解密逻辑完整，独立 exportKey 设计正确
- ZIP + checksum 的完整性校验可靠
- 冲突检测（ID 重复、名称匹配）已有基础实现

## 2. 设计原则

### 2.1 为什么细化到"项目层"为止，不到字段级别？

用户原话：*"更精细化的字段级别导出没什么作用，因为一般项目数据都是有关联的。"*

这个判断是正确的。原因：

1. **数据完整性**：一个"护照"项目包含姓名、国籍、护照号、签发日期、有效期等字段，这些字段共同构成一个完整的护照记录。导出"只有姓名和国籍的护照"是没有意义的。

2. **关系完整性**：项目可能包含 RelationProperty 指向其他项目。如果导出字段级别，关系字段的目标项目可能不在导出范围内，导致孤立引用。

3. **用户体验复杂度**：字段级别的选择会让导出 UI 变得极其复杂（每个项目展开几十个字段勾选），违背了"最少惊喜"原则。

4. **安全粒度足够**：项目级别的导出已经能满足"只导出护照"或"只导出银行卡"的需求，这是用户实际需要的粒度。

### 2.2 导出范围的三层结构

```
身份数据（Identity）      → "导出我的所有旅行数据"
├── 页面层（Page）         → "导出我的所有旅行数据"
│   ├── 分区层（Collection） → "导出我的护照和签证"
│   │   ├── 项目层（Item）    → "导出我的中国护照"
│   │   │   ├── 字段（Field）  → 不开放选择（完整导出）
│   │   │   └── 附件层（Attachment）→ "只导出扫描件，不导出照片"
│
偏好数据（Preferences）    → "导出我的应用设置"
├── 视觉偏好               → 主题、颜色、字体
├── 行为偏好               → 锁定超时、生物识别、删除确认
├── 内容偏好               → 语言、日期格式、时区
├── 敏感度偏好             → SensitivityMap、默认策略
└── 插件偏好               → 已安装列表、授权记录、个性化配置

行为记录（Behavioral Records） → "导出我的操作历史"
├── 操作日志               → CRUD、敏感度变更、导入导出
├── 搜索历史               → 关键词、过滤器
└── 审计日志               → 插件访问、密码验证
```

| 类别 | 粒度 | 典型场景 | 包含内容 | 可独立勾选？ |
|---|---|---|---|---|
| **身份数据** | 页面层 | 换设备迁移、全量备份 | 页面下所有分区、所有项目、所有附件 | ✅ 是 |
| **身份数据** | 分区层 | 分享给家人某类信息 | 分区下所有项目、所有附件 | ✅ 是 |
| **身份数据** | 项目层 | 导出单条记录给第三方 | 单个项目的所有字段、所有附件 | ✅ 是 |
| **身份数据** | 附件层 | 只分享扫描件，不分享照片 | 单个附件文件 | ✅ 是 |
| **偏好数据** | 类别层 | 同步设备设置 | 五类偏好（视觉/行为/内容/敏感度/插件） | ✅ 是 |
| **行为记录** | 类别层 | 保留操作历史 | 操作日志 / 搜索历史 / 审计日志 | ✅ 是 |

#### 勾选状态规则

| 用户操作 | 行为 | 上层状态 |
|---|---|---|
| 勾选页面 | 该页面下**所有分区、所有项目、所有附件**全部勾选 | 全选 ✓ |
| 勾选分区 | 该分区下**所有项目、所有附件**全部勾选 | 页面显示 indeterminate ☑ |
| 勾选项目 | 该项目下**所有附件**全部勾选 | 分区显示 indeterminate |
| 取消附件 | **仅取消该附件**，不影响项目/分区/页面的勾选状态 | 所属项目显示 indeterminate |
| 取消项目 | **仅取消该项目**，不影响分区/页面 | 所属分区显示 indeterminate |
| 取消分区 | **仅取消该分区**，不影响页面 | 所属页面显示 indeterminate |
| 页面勾选但下层全未勾选 | 导出**空页面**（只含页面元信息） | 全选 ✓（但下层全空） |

#### 部分勾选（Indeterminate）状态说明

```
[✓] 旅行记录              ← 全选（所有子项都勾选）

[☑] 旅行记录              ← 部分勾选（部分子项未勾选）
  [✓] 护照
    [✓] 中国护照
          - [✓] scan.pdf
          - [ ] photo.jpg   ← 此附件未勾选
    [✓] 香港特区护照
  [ ] 签证                 ← 此分区未勾选

[✓] 旅行记录              ← 全选但子项全空（导出空页面）
  [ ] 护照                 ← 分区未勾选
  [ ] 签证                 ← 分区未勾选
```

#### "空页面"导出场景

```
[✓] 旅行记录              ← 页面被勾选
  [ ] 护照                 ← 分区未勾选
  [ ] 签证                 ← 分区未勾选

导出结果:
├── 旅行记录页面（元信息：id, name, icon）
├── 无分区
├── 无项目
└── 无附件

→ 导入时得到一个"空的旅行记录页面"
→ 用户可以在该页面下手动创建新分区
```

### 3.3 范围筛选算法

```rust
// crates/solosoul-export/src/filter.rs

/// 导出范围定义
pub enum ExportScope {
    /// 全量导出
    Full,
    /// 页面级选择
    Pages { page_ids: Vec<String> },
    /// 分区级选择
    Collections { collection_ids: Vec<String> },
    /// 项目级选择
    Items { item_ids: Vec<String> },
    /// 附件级选择（最细粒度）
    Attachments {
        page_ids: Vec<String>,
        collection_ids: Vec<String>,
        item_ids: Vec<String>,
        attachment_ids: Vec<String>,
    },
}

/// 导出选择状态（前端树形组件传递）
pub struct ExportSelection {
    pub pages: Vec<PageSelection>,
}

pub struct PageSelection {
    pub page_id: String,
    pub selected: bool,          // true = 勾选（含全选和部分选）
    pub fully_selected: bool,    // true = 所有子项都勾选
    pub collections: Vec<CollectionSelection>,
}

pub struct CollectionSelection {
    pub collection_id: String,
    pub selected: bool,
    pub fully_selected: bool,
    pub items: Vec<ItemSelection>,
}

pub struct ItemSelection {
    pub item_id: String,
    pub selected: bool,
    pub fully_selected: bool,
    pub attachments: Vec<AttachmentSelection>,
}

pub struct AttachmentSelection {
    pub attachment_id: String,
    pub selected: bool,
}

/// 根据导出选择筛选 ProfileData
pub fn filter_profile_by_selection(
    profile: &ProfileData,
    selection: &ExportSelection,
) -> Result<(ProfileData, Vec<String>), ExportError> {
    let all_objects = profile.unified_objects.objects.clone();
    let mut selected_object_ids = HashSet::new();
    let mut selected_attachment_ids = HashSet::new();
    
    for page_sel in &selection.pages {
        if !page_sel.selected {
            continue;
        }
        
        // 页面本身总是被包含（即使是"空页面"导出）
        selected_object_ids.insert(page_sel.page_id.clone());
        
        for col_sel in &page_sel.collections {
            if !col_sel.selected {
                continue;
            }
            
            // 分区本身总是被包含
            selected_object_ids.insert(col_sel.collection_id.clone());
            
            for item_sel in &col_sel.items {
                if !item_sel.selected {
                    continue;
                }
                
                // 项目本身总是被包含
                selected_object_ids.insert(item_sel.item_id.clone());
                // 收集项目的所有后代（子项目）
                collect_descendants(&all_objects, &item_sel.item_id, &mut selected_object_ids);
                
                // 收集被选中的附件
                for att_sel in &item_sel.attachments {
                    if att_sel.selected {
                        selected_attachment_ids.insert(att_sel.attachment_id.clone());
                    }
                }
            }
        }
    }
    
    // 过滤对象列表
    let filtered_objects: Vec<UnifiedObject> = all_objects
        .into_iter()
        .filter(|o| selected_object_ids.contains(&o.id))
        .collect();
    
    // 保留被引用的自定义类型
    let used_type_ids: HashSet<String> = filtered_objects
        .iter()
        .filter_map(|o| o.type_id.clone())
        .collect();
    
    let filtered_types: Vec<ObjectTypeDefinition> = profile
        .unified_objects
        .custom_types
        .clone()
        .into_iter()
        .filter(|t| used_type_ids.contains(&t.id))
        .collect();
    
    let filtered_profile = ProfileData {
        identity: profile.identity.clone(),
        travel: profile.travel.clone(),
        financial: profile.financial.clone(),
        professional: profile.professional.clone(),
        preferences: profile.preferences.clone(),
        unified_objects: Some(UnifiedObjectData {
            objects: filtered_objects,
            custom_types: filtered_types,
        }),
    };
    
    Ok((filtered_profile, selected_attachment_ids.into_iter().collect()))
}

/// 递归收集所有后代对象 ID
fn collect_descendants(
    objects: &[UnifiedObject],
    parent_id: &str,
    result: &mut HashSet<String>,
) {
    let children: Vec<String> = objects
        .iter()
        .filter(|o| o.parent_id.as_ref() == Some(&parent_id.to_string()))
        .map(|o| o.id.clone())
        .collect();
    
    for child_id in children {
        result.insert(child_id.clone());
        collect_descendants(objects, &child_id, result);
    }
}
```

### 3.4 附件筛选算法（四级勾选）

```rust
/// 根据用户选择的附件 ID 列表筛选附件
/// 
/// 附件可以被独立勾选：
/// - 项目被勾选 → 默认该项目所有附件被勾选
/// - 用户可以取消某个附件 → 该附件不导出
/// - 上层（项目/分区/页面）显示 indeterminate 状态
pub fn filter_attachments_by_selection(
    selected_attachment_ids: &[String],
    all_attachment_file_ids: &[String],
) -> Vec<String> {
    all_attachment_file_ids
        .iter()
        .filter(|id| selected_attachment_ids.contains(*id))
        .cloned()
        .collect()
}

/// 构建附件选择树（用于前端展示）
pub fn build_attachment_selection_tree(
    item: &UnifiedObject,
) -> Vec<AttachmentSelection> {
    let mut selections = Vec::new();
    
    // 从 attachments 数组收集
    for att in &item.attachments {
        selections.push(AttachmentSelection {
            attachment_id: att.file_id.clone(),
            selected: true,  // 默认勾选
        });
    }
    
    // 从 properties 中的 attachment 类型字段收集
    for (key, prop) in &item.properties {
        if let PropertyValue::Attachment { file_id, .. } = prop {
            selections.push(AttachmentSelection {
                attachment_id: file_id.clone(),
                selected: true,
            });
        }
    }
    
    selections
}
```

## 4. 导入功能适配设计

### 4.1 导入时的范围感知

当导入一个**部分导出**的包时，系统需要：

1. **识别导出范围**：读取 `manifest.json` 中的 `export_scope` 和选择列表
2. **显示范围信息**：在预览对话框中提示用户"这是部分导出包，包含旅行记录页面的 2 个分区"
3. **保持导入粒度**：如果导出的是分区级别，导入时只能将整个分区作为一个单位选择

### 4.2 导入预览增强（四级展示）

```
┌─ ImportPreviewDialog ───────────────────┐
│                                          │
```

### 4.3 空页面/空分区/空项目的导入处理

当导出时上层被勾选但下层全未勾选，导入会得到"空容器"。

**处理策略**：

```rust
/// 检测并处理空容器导入
pub fn handle_empty_containers(
    imported_objects: &[UnifiedObject],
    merge_target: &mut Vec<UnifiedObject>,
) -> Vec<EmptyContainerWarning> {
    let mut warnings = Vec::new();
    
    for obj in imported_objects {
        let has_children = imported_objects.iter().any(|o| {
            o.parent_id.as_ref() == Some(&obj.id)
        });
        
        // 页面/分区被导出但没有子项
        if (obj.type_id == "page" || obj.type_id == "collection") && !has_children {
            warnings.push(EmptyContainerWarning {
                object_id: obj.id.clone(),
                object_name: obj.name.clone(),
                object_type: obj.type_id.clone(),
            });
            
            // 空容器仍然导入，只是没有内容
            // 用户后续可以手动添加内容
        }
    }
    
    warnings
}
```

### 4.4 跨范围引用的处理

当导出范围是"分区级"或"项目级"时，可能存在**跨分区引用**（RelationProperty 指向未导出的项目）。

**处理策略**：

```rust
pub fn handle_cross_partition_relations(
    exported_objects: &mut Vec<UnifiedObject>,
) {
    for obj in exported_objects.iter_mut() {
        for (_, prop) in obj.properties.iter_mut() {
            if let PropertyValue::Relation { target_object_id, .. } = prop {
                // 检查目标对象是否在导出范围内
                let target_exists = exported_objects.iter().any(|o| o.id == *target_object_id);
                
                if !target_exists {
                    // 策略：保留关系但标记为"外部引用"
                    // 导入时显示警告，让用户决定是否保留这个关系
                    // 或转换为纯文本备注
                    *prop = PropertyValue::Note {
                        value: format!("[外部引用: {}]", target_object_id),
                        sensitivity: prop.sensitivity,
                    };
                }
            }
        }
    }
}
```

```rust
/// 执行导出
#[tauri::command]
async fn export_execute(
    state: State<'_, VaultState>,
    scope: ExportScope,
    password: String,
    password_hint: Option<String>,   // 密码提示词（可选，明文存储于 account.enc）
    save_path: String,
) -> Result<String, String> {
    let vault = state.vault.lock().await;
    let profile = vault.load_profile()?;
    let master_key = vault.derive_key(&password)?;
    
    // 筛选
    let filtered = filter_profile_by_scope(&profile, &scope)?;
    
    // 派生 exportKey
    let export_salt = generate_salt(32);
    let export_key = derive_key(&password, &export_salt, &KdfPreset::Balanced)?;
    
    // 打包
    let packer = ExportPacker::new(&save_path);
    let platform_info = PlatformInfo::current();
    packer.write_manifest(
        &scope,
        &export_salt,
        &platform_info,          // 导出平台、OS版本、应用版本
    )?;
    packer.write_account_enc(password_hint.as_deref(), &export_key)?;
    packer.write_profile_enc(&filtered, &export_key)?;
    
    // 根据用户勾选范围写入偏好数据和行为数据
    if scope.includes_preferences() {
        let prefs = vault.load_preferences()?;
        packer.write_preferences_enc(&prefs, &export_key)?;
    }
    if scope.includes_audit_log() {
        let audit_log = vault.load_audit_log()?;
        packer.write_audit_log_enc(&audit_log, &export_key)?;
    }
    if scope.includes_search_history() {
        let search_history = vault.load_search_history()?;
        packer.write_search_history_enc(&search_history, &export_key)?;
    }
    
    packer.write_attachments(&filtered, &vault.attachments_dir(), &export_key)?;
    packer.write_checksums()?;
    packer.finalize()?;
    
    // 设置权限
    set_restrictive_permissions(&save_path)?;
    
    Ok(save_path)
}

/// 执行导入
#[tauri::command]
async fn import_execute(
    state: State<'_, VaultState>,
    identity_selections: Vec<ImportSelection>,
    preference_strategy: PreferenceImportStrategy,   // 偏好导入策略
    behavioral_strategy: BehavioralImportStrategy,   // 行为数据导入策略
    source_path: String,
    password: String,
) -> Result<bool, String> {
    let mut vault = state.vault.lock().await;
    // 先创建静默备份
    vault.create_silent_backup()?;
    
    let decryptor = ImportDecryptor::from_path(&source_path, &password)?;
    
    // 1. 导入身份数据
    let imported_profile = decryptor.decrypt_profile()?;
    vault.merge_import(&imported_profile, &identity_selections)?;
    
    // 2. 导入偏好数据（可选）
    if let Some(imported_prefs) = decryptor.decrypt_preferences()? {
        match preference_strategy {
            PreferenceImportStrategy::KeepCurrent => {
                // 不导入，保持当前配置
            }
            PreferenceImportStrategy::UseImported => {
                // 完全覆盖当前配置
                vault.save_preferences(&imported_prefs)?;
            }
            PreferenceImportStrategy::Merge => {
                // 合并：导入覆盖冲突项，保留未冲突项
                let mut current = vault.load_preferences()?;
                current.merge_from(&imported_prefs);
                vault.save_preferences(&current)?;
            }
        }
    }
    
    // 3. 导入行为数据（只追加不覆盖）
    if let Some(imported_audit) = decryptor.decrypt_audit_log()? {
        if behavioral_strategy.include_audit_log {
            let mut current = vault.load_audit_log().unwrap_or_default();
            current.append_deduplicated(&imported_audit);
            vault.save_audit_log(&current)?;
        }
    }
    
    if let Some(imported_search) = decryptor.decrypt_search_history()? {
        if behavioral_strategy.include_search_history {
            let mut current = vault.load_search_history().unwrap_or_default();
            current.append_deduplicated(&imported_search);
            vault.save_search_history(&current)?;
        }
    }
    
    // 4. 记录导入操作到审计日志
    vault.append_audit_log(AuditLogEntry {
        id: generate_uuid(),
        timestamp: Utc::now(),
        action: AuditAction::ImportCompleted,
        entity_type: Some("import".to_string()),
        entity_id: None,
        description: format!("从 {} 导入数据", source_path),
        performed_by: "user".to_string(),
        sensitivity_level: SensitivityLevel::Sensitive,
    })?;
    
    Ok(true)
}
```

## 7. 与现有功能的兼容性

### 7.1 向后兼容

> **注意**：导入导出功能在 Flutter 版本中未实际上线，Tauri 重构版本为首次完整实现，因此**无需考虑向后兼容**。以下说明仅作记录，开发中可忽略。

- 无需支持任何旧版本导出包格式
- `manifest.json` 直接采用 v2.0 格式，无需处理 `export_scope` 缺失的情况
- `account.enc` 直接采用带 `version` 前缀的新格式（version = 1），无需兼容无版本头的旧格式
- 未来若需升级导出格式（v3.0），再通过 `manifest.version` 字段做版本分支判断

### 7.2 与备份服务的区别

| 功能 | 备份服务 | 导出服务（重构后） |
|---|---|---|
| 目的 | 本地时间点恢复 | 跨设备迁移、分享给第三方 |
| 范围 | 全量（整个 Vault） | 可选（全量/页面/分区/项目） |
| 加密密钥 | 当前 Vault 主密钥 | 导出时输入的密码派生 |
| 存储位置 | `~/.solosoul/backups/` | 用户选择的任意路径 |
| 格式 | 原始 SQLite + 附件 | `.solosoul` ZIP 包 |
| 保留策略 | 自动清理旧备份 | 用户自行管理 |

## 8. 已确认决策

| # | 问题 | 决策 | 理由 |
|---|---|---|---|
| 1 | 导出密码是否必须与主密码相同？ | **允许不同** | 分享场景需要简化密码；UI 用勾选框控制 |
| 2 | 项目级导出时，是否自动包含关联项目（Relation 目标）？ | **不自动包含** | 避免超出用户预期的数据泄露；导入时转为文本备注 |
| 3 | 导出包是否包含操作日志？ | **包含，可选勾选** | 根据「我们不管理'文档'，我们管理'你'」的核心信条，操作日志属于用户行为数据，用户可选择是否导出。默认勾选 |
| 3a | 导出包是否包含用户偏好？ | **包含，可选勾选** | 偏好数据（主题、锁定超时、SensitivityMap 等）属于用户数据，默认勾选 |
| 3b | 导出包是否包含搜索历史？ | **包含，可选勾选** | 搜索历史属于用户行为数据，默认勾选 |
| 3c | 导出范围树是否包含"偏好"和"行为记录"顶级节点？ | **是** | 与身份数据同级，不是附属。用户可独立选择只导出偏好（换设备同步设置） |
| 4 | 是否支持增量导出？ | **不支持** | 当前阶段复杂度收益比不高 |
| 5 | 密码提示词是否可选？ | **可选，纯输入框，无勾选开关** | 不输入则无提示词，最大 200 字符，明文存储于导出包 |
| 6 | 密码提示词谁可见？ | **任何获得导出文件的人** | 提示词以明文写入 account.enc，导入时直接读取展示 |

### 9.4 技术实现

```rust
/// 根据用户选择派生导出密钥
pub fn derive_export_key(
    mode: ExportPasswordMode,
    master_password: Option<&str>,      // 当 mode = MasterPassword
    custom_password: Option<&str>,      // 当 mode = CustomPassword
    export_salt: &[u8],
) -> Result<Zeroizing<Vec<u8>>, ExportError> {
    let password = match mode {
        ExportPasswordMode::MasterPassword => {
            master_password.ok_or(ExportError::VaultLocked)?
        }
        ExportPasswordMode::CustomPassword => {
            let pwd = custom_password.ok_or(ExportError::CustomPasswordMissing)?;
            if pwd.len() < 8 {
                return Err(ExportError::PasswordTooShort);
            }
            pwd
        }
    };
    
    derive_key(password, export_salt, &KdfPreset::Balanced)
        .map_err(|e| ExportError::KeyDerivationFailed(e.to_string()))
}

/// 密码提示词存储结构（明文，位于 account.enc 的明文头部）
/// 
/// account.enc 格式：
/// ├── 明文头部 (前缀不加密，便于导入时直接读取)
/// │   ├── version: u8 = 1
/// │   ├── password_hint_len: u16
/// │   ├── password_hint: bytes (UTF-8，可为空)
/// │   └── salt: [u8; 32]
/// └── 加密主体
///     ├── verify_token: "SOLOSOUL_VAULT_V1" 的加密密文
///     └── 用于验证密码正确性
///
/// 设计理由：提示词以明文存储，导入时无需密码即可展示，
/// 帮助用户回忆密码。提示词本身不包含密码信息，安全可控。
pub fn write_account_enc(
    &self,
    password_hint: Option<&str>,
    export_key: &[u8],
) -> Result<(), ExportError> {
    // 1. 写入明文头部
    let hint_bytes = password_hint.unwrap_or("").as_bytes();
    if hint_bytes.len() > 200 {
        return Err(ExportError::PasswordHintTooLong);
    }
    self.writer.write_u8(1)?; // version
    self.writer.write_u16(hint_bytes.len() as u16)?;
    self.writer.write_all(hint_bytes)?;
    self.writer.write_all(&self.export_salt)?;
    
    // 2. 写入加密主体
    let verify_token = b"SOLOSOUL_VAULT_V1";
    let encrypted = aes_gcm_encrypt(verify_token, export_key)?;
    self.writer.write_all(&encrypted)?;
    
    Ok(())
}

/// 从 account.enc 读取密码提示词（不解密，无需密码）
pub fn read_password_hint(data: &[u8]) -> Result<Option<String>, ExportError> {
    if data.len() < 35 {
        return Err(ExportError::InvalidFormat);
    }
    let version = data[0];
    if version != 1 {
        // v0 格式无提示词，返回 None
        return Ok(None);
    }
    let hint_len = u16::from_le_bytes([data[1], data[2]]) as usize;
    if hint_len == 0 {
        return Ok(None);
    }
    let hint = std::str::from_utf8(&data[3..3 + hint_len])
        .map_err(|_| ExportError::InvalidUtf8)?;
    Ok(Some(hint.to_string()))
}
```

## 10. 关联项目（RelationProperty）处理详解

### 10.1 什么是关联项目？

**关联项目 ≠ 附件**

| 概念 | 说明 | 代码中的类型 |
|---|---|---|
| **关联项目** | 一个项目通过 `RelationProperty` **引用另一个项目** | `PropertyValue::Relation { target_object_id }` |
| **附件** | 项目引用的**文件**（图片、PDF） | `PropertyValue::Attachment { file_id }` |

**示例**：
```json
{
  "id": "passport_cn",
  "name": "中国护照",
  "properties": {
    // 关联项目：指向另一个 UnifiedObject
    "visa_applications": {
      "type": "relation",
      "target_object_id": "visa_us_2026"   // ← 这是关联项目
    },
    // 附件：指向一个文件
    "scan_copy": {
      "type": "attachment",
      "file_id": "att_abc123"               // ← 这是附件
    }
  }
}
```

### 10.2 为什么项目级导出不自动包含关联项目？

**场景**：用户选择导出"中国护照"（项目层），不导出其他内容。

```
中国护照（已选中导出）
├── visa_applications → 指向 "美国签证"（未选中导出）
├── scan_copy → 附件 "att_abc123"（会被导出 ✓）
└── 其他字段 → 全部导出 ✓
```

**如果自动包含"美国签证"**：
- 用户只选了 1 个项目，结果导出包里出现了 2 个项目
- 用户不知道"美国签证"也被导出了
- 违背了"用户精确控制导出范围"的原则

**如果不包含"美国签证"**：
- 中国护照的 `visa_applications` 字段变成孤立引用
- 导入后无法解析目标对象

### 10.3 处理策略（已确认）

**导出时**：保留 `RelationProperty` 不变，在 manifest 中记录 `cross_partition_relations` 数量。

**导入时**：检测孤立引用，转换策略：

```rust
pub fn handle_orphan_relations(
    imported_objects: &mut [UnifiedObject],
    existing_objects: &[UnifiedObject],
) -> Vec<OrphanRelationWarning> {
    let mut warnings = Vec::new();
    let all_known_ids: HashSet<String> = imported_objects
        .iter()
        .chain(existing_objects.iter())
        .map(|o| o.id.clone())
        .collect();
    
    for obj in imported_objects.iter_mut() {
        for (key, prop) in obj.properties.iter_mut() {
            if let PropertyValue::Relation { target_object_id, .. } = prop {
                if !all_known_ids.contains(target_object_id) {
                    // 目标对象不存在，转换为 Note 类型
                    let warning = OrphanRelationWarning {
                        source_object_id: obj.id.clone(),
                        source_object_name: obj.name.clone(),
                        property_key: key.clone(),
                        target_object_id: target_object_id.clone(),
                    };
                    warnings.push(warning);
                    
                    // 转换：Relation → Note（保留信息但不作为链接）
                    *prop = PropertyValue::Note {
                        value: format!("[引用项目未导出: {}]", target_object_id),
                        sensitivity: prop.sensitivity,
                    };
                }
            }
        }
    }
    
    warnings
}
```

**导入预览时提示用户**：

```

│                                          │
│  ⚠️ 检测到 2 个跨分区引用无法解析        │
│                                          │
│  中国护照 → 签证申请: 美国签证           │
│   （美国签证未被包含在导出包中）         │
│                                          │
│  招商银行储蓄卡 → 开户行: 招商银行网点   │
│   （招商银行网点未被包含在导出包中）     │
│                                          │
│  导入后将保留为文本备注，您可手动重建关联│

│                                          │
└─────────────────────────────────────────┘
```

### 10.4 如果用户确实需要一起导出怎么办？

**正确做法**：选择**分区层**导出。

```
旅行记录页面
├── 护照分区（勾选 ✓）
│   ├── 中国护照（自动包含）
│   └── 香港特区护照（自动包含）
├── 签证分区（勾选 ✓）
│   ├── 美国签证（自动包含）
│   └── 日本签证（自动包含）
└── 行程规划分区（不勾选）
```

分区层导出时，分区内的所有项目及其相互之间的 Relation 都会被完整保留，不会出现孤立引用。

**设计原则**：
- **项目层**：精确到单条记录，允许孤立引用（用户明确只想要这一条）
- **分区层**：完整业务单元，保证数据完整性（同一分区内的项目关联被保留）
- **页面层**：完整业务领域，保证数据完整性

**核心设计原则**：让用户对"什么数据离开设备"有完全的控制权。这是 SoloSoul "用户主权"和"最小权限"理念的直接体现。
