# 15 — 用户数据边界定义与加密存储方案

> **前置阅读**：`05_密码学库选型与核心实现.md`、`14_敏感度等级系统重构.md`
> **Manifesto 对齐**：隐私优先 | 用户主权 | 安全默认

## 1. 核心理念

> **「我们不管理'文档'，我们管理'你'」** — 产品使命

凡是与用户个人相关的数据，无论传统分类叫"设置""配置""日志"还是"缓存"，在 SoloSoul 中一律视为**用户数据**，受同等级别的加密保护。

---

## 2. 用户数据的四大类别

### 2.1 身份数据（Identity Data）
- Profile 字段、UnifiedObject、附件、自定义类型定义
- 存储：`profile.enc`、`objects.enc`、`attachments/`

### 2.2 偏好数据（Preference Data）— 等同于用户数据
- 视觉偏好：主题、颜色、字体、界面密度
- 行为偏好：自动锁定超时、生物识别、删除确认
- 内容偏好：语言、日期格式、时区
- 敏感度偏好：SensitivityMap、默认策略
- 插件偏好：已安装列表、授权记录
- AI/LLM 偏好：提供商、模型、**API 密钥（critical 级别）**

### 2.3 行为数据（Behavioral Data）— 等同于用户数据
- 操作日志（CRUD、敏感度变更、导入导出）
- 搜索历史（关键词、过滤器）
- 审计日志（插件访问、密码验证）
- AI 对话历史

### 2.4 关系数据（Relational Data）
- 对象间关联、标签体系、自定义分类

---

## 3. 明确排除的非用户数据

| 数据 | 理由 | 存储 |
|------|------|------|
| 编译日志 | 与"你"无关 | 明文日志文件 |
| 崩溃报告 | 纯技术诊断 | 用户明确同意才收集 |
| 应用更新元数据 | 纯技术信息 | 明文缓存 |
| 插件市场索引 | 公开数据 | 明文缓存 |
| 帮助文档缓存 | 公开数据 | 明文缓存 |

## 4. 存储架构：分层加密

```
~/.solosoul/
├── ui_preferences.json      # 明文：非敏感 UI 偏好（主题/语言/主题色）← 新增
└── {account_id}/
    ├── config.json              # 明文：仅账户元信息（account_id, created_at）
    ├── vault.db                 # SQLite：加密 blob 索引
    ├── profile.enc              # 身份数据（AES-256-GCM）
    ├── objects.enc              # 统一对象（AES-256-GCM）
    ├── preferences.enc          # 敏感偏好数据（AES-256-GCM）← 范围收窄
    ├── audit_log.enc            # 审计日志（AES-256-GCM）← 新增
    ├── search_history.enc       # 搜索历史（AES-256-GCM）← 新增
    ├── ai_conversation.enc      # AI 对话历史（AES-256-GCM）← 新增
    ├── sensitivity_map.enc      # 敏感度映射表（AES-256-GCM）
    ├── sensitivity_log.enc      # 敏感度变更历史（AES-256-GCM）
    └── attachments/             # 附件文件
```

### 4.1 非敏感 UI 偏好（明文存储）

以下偏好**不涉及用户隐私**，存储于 Vault 外的明文文件 `ui_preferences.json`，登录前即可读取：

| 偏好项 | 存储位置 | 理由 |
|--------|---------|------|
| 主题（亮色/暗色/跟随系统） | `ui_preferences.json` | 纯 UI 表现，不泄露任何隐私 |
| 主题色（ocean/amber/forest/rose/custom） | `ui_preferences.json` | 纯视觉偏好，不敏感 |
| 语言（zh-CN/en-US） | `ui_preferences.json` | 界面语言选择，不敏感 |
| 窗口大小/位置 | `ui_preferences.json` | 纯界面布局，不敏感 |
| 侧边栏宽度/折叠状态 | `ui_preferences.json` | 纯界面布局，不敏感 |

> **为什么可以明文存储**：攻击者知道"用户喜欢用暗色主题"能推导出什么？Nothing。相比 Vault 中的护照号码、银行卡信息，主题偏好根本不值得加密保护。
>
> **UX 收益**：登录页面、解锁页面、首次启动引导页均可正确应用用户设置的主题和语言，消除体验割裂。

### 4.2 敏感偏好数据（Vault 内加密存储）

以下偏好**涉及安全策略或隐私推断**，继续存储于 Vault 内的 `preferences.enc`：

| 偏好项 | 存储位置 | 理由 |
|--------|---------|------|
| 自动锁定超时 | `preferences.enc` | 暴露用户安全意识水平 |
| 生物识别启用状态 | `preferences.enc` | 暴露安全策略 |
| 模板属性敏感度定义 | Vault（templates） | 字段敏感度由模板 `sensitivity_level` 定义（SensitivityMap 已废弃） |
| 插件授权记录 | `preferences.enc` | 暴露信任决策 |
| LLM API 密钥 | `preferences.enc` | critical 级别，等同密码 |
| 回收站保留期 | `preferences.enc` | 间接暴露数据管理习惯 |
| 历史记录保留策略 | `preferences.enc` | 间接暴露数据管理习惯 |
| 密码提示词 | `preferences.enc` | 安全相关信息 |

**核心规则**：所有 `.enc` 文件使用同一 Vault 主密钥加密。Vault 锁定后敏感用户数据不可访问，但非敏感 UI 偏好仍可读取。

## 5. 现有设计的修正

### 修正 1：`app_settings` 明文表 → 加密文件

```sql
-- [错误] 旧设计
CREATE TABLE app_settings (
    account_id TEXT PRIMARY KEY,
    settings_json TEXT NOT NULL  -- 明文 JSON！
);

-- [正确] 新设计：独立加密文件 preferences.enc
```

### 修正 2：`settingsStore` localStorage → IPC 加密存储

```typescript
// [错误] 旧设计：Zustand persist → localStorage（明文暴露）
export const useSettingsStore = create(persist(...));

// [正确] 新设计：通过 IPC → Rust Vault 加密读写
export const useSettingsStore = create(immer((set) => ({
  loadSettings: async () => {
    const settings = await commands.userDataGetPreferences();
    set({ settings });
  },
  updateSetting: async (key, value) => {
    await commands.userDataUpdatePreference(key, value);
  },
})));
```

### 修正 3：`operation_logs` 明文表 → 加密 SQLite 表

操作日志不再使用明文的 `operation_logs` 表，改为存储于 SQLite **`audit_log` 表**（内容经 Vault 加密，经 `VaultStore::list_audit_log` 读取并解密）。

## 6. 前端 Store 敏感度保护规则

| Store | localStorage 持久化 | 理由 |
|-------|---------------------|------|
| authStore | [错误] | 认证状态 |
| vaultStore | [错误] | Vault 状态 |
| profileStore | [错误] | 身份数据 |
| settingsStore | [部分正确] | 非敏感 UI 偏好可写入 `ui_preferences.json`；敏感偏好必须通过 IPC → Vault |
| searchStore | [错误] | 行为数据（sensitive） |
| uiStore | [正确]（仅非敏感部分） | sidebarCollapsed、Toast 队列（非用户数据） |

### 6.1 settingsStore 的双层设计

```typescript
// settingsStore 同时管理两类偏好
interface SettingsStore {
  // 非敏感 UI 偏好（明文存储，登录前可读）
  uiPreferences: {
    theme: 'warm-stone-light' | 'warm-stone-dark' | 'system';
    accentColor: 'ocean' | 'amber' | 'forest' | 'rose' | 'custom';
    language: 'zh-CN' | 'en-US';
    sidebarWidth: number;
    sidebarCollapsed: boolean;
  };
  
  // 敏感偏好（Vault 加密存储，解锁后可读）
  sensitivePreferences: {
    autoLockTimeout: number;
    biometricEnabled: boolean;
    trashRetentionPeriod: TrashRetentionPeriod;
    historyRetentionPolicy: HistoryRetentionPolicy;
    // ...
  };
}

// 加载流程（登录前）
async function loadUiPreferences() {
  // 直接读取明文文件，无需解锁 Vault
  const prefs = await commands.loadUiPreferences();
  applyTheme(prefs.theme, prefs.accentColor);
  await i18next.changeLanguage(prefs.language);
}

// 加载流程（登录后）
async function loadSensitivePreferences() {
  // 通过 IPC → Vault 读取加密数据
  const prefs = await commands.userDataGetPreferences();
  set({ sensitivePreferences: prefs });
}
```

## 7. 偏好与行为数据的敏感度分级

关键条目：

| 数据 | 敏感度 | 理由 |
|------|--------|------|
| 主题/字体/密度 | `public` | 可见于界面 |
| 语言/日期/货币格式 | `internal` | 可推断文化背景 |
| 自动锁定超时 | `sensitive` | 暴露安全意识水平 |
| 生物识别启用状态 | `sensitive` | 暴露安全策略 |
| SensitivityMap | `sensitive` | 暴露全部字段安全策略 |
| 插件授权记录 | `sensitive` | 暴露信任决策 |
| **LLM API 密钥** | **`critical`** | 等同于账户密码 |
| 操作日志（CRUD） | `sensitive` | 暴露数据访问行为 |
| 搜索历史 | `sensitive` | 暴露关注点 |
| 密码验证失败记录 | `critical` | 安全事件 |
| AI 对话历史 | `sensitive` | 可能包含身份信息 |

## 8. AI 数据特殊处理

> **审批决策（2026-06-05）**：AI 功能**默认禁用**，用户主动开启后以下规则生效。

- **LLM API 密钥**：`critical` 级别，导出时默认不勾选，勾选时强制安全警告
- **AI 对话历史**：`sensitive` 级别，加密存储于 `ai_conversation.enc`
- **AI 调用审计**：记录 provider/model/timestamp，不记录用户输入内容
- **AI 功能开关状态**：存储于 `preferences.enc` 中的 `ai_features_enabled` 字段，默认全部 `false`
- **风险告知**：用户首次开启任何 AI 功能时，展示风险告知对话框并写入审计日志
- **数据外传控制**：AI 对话内容由用户逐条确认后发送，不自动上传
