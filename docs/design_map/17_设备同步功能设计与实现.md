## 1. 实际架构（2026-08）

### 传输与发现（`crates/solosoul-sync/`）

- **mDNS 发现**：`mdns-sd` 局域网广播/发现（移动端经 NSD 插件），peer 在线 TTL 300s，60s 周期清理
- **加密通道**：Noise XX 握手（每设备独立 x25519 静态密钥对），`snow` crate
- **配对**：扫码 + 双向确认；SAS/PIN 验证码比对，握手密钥指纹与 node_id 绑定
- **设备列表**：已发现设备（一次性 mDNS 扫描）+ 已知设备（持久化于 Vault，含设备名/指纹/客户端类型/最近同步时间）

### 数据同步

- **增量同步**：对象级 HLC（Hybrid Logical Clock）时间戳水印，按 `sync_changes` 表增量拉取（`list_object_changes_since`）
- **冲突检测**：`sync_conflicts` 表记录 local_data / remote_data，字段级 diff UI 对比（差异内容浅红高亮）
- **簿记字段净化**：`version` / `updated_at` 等簿记字段不计入用户可见差异，避免"内容相同却显示多处冲突"
- **附件同步**：批量传输，`attachments.rs` 已实现
- **同步记录**：`sync_with_device` 审计日志（检查/应用/跳过条数），`sync-completed` 事件通知前端

### 自动同步（`src-tauri/src/sync/device_auto_sync.rs`）

- 三类触发：切回前台 / 本地数据变更（10s 防抖）/ 每 60s 周期
- 开关持久化（v2.8.5 起），重启不丢失
- **同步界面偏好勾选**：主题/主题色/窗口大小等 UI 偏好是否随同步交换，由用户决定
- 离线 peer 短超时（2s）TCP 探测后快速跳过，避免拖慢整轮同步

### 安全要点（已实现）

- 会话层严格校验对端静态公钥；信任检查前不回复含 `account_id` 的帧
- 配对/信任为双向确认；撤销信任后拒绝该设备同步
- 移动端冲突回传与桌面端对齐（conflicts 恒为空的历史缺陷已修复）

## 4. 开发注意事项（来自原 sync-roadmap）

### 4.1 HLC 排序规则

```text
remote > local 当且仅当：
  remote.wall_time_ms > local.wall_time_ms
  或 (wall_time 相等且 remote.counter > local.counter)
  或 (wall_time、counter 均相等且 remote.node_id > local.node_id)
```

修改冲突解决逻辑时必须保持此规则一致。

### 4.2 信任策略

- 当前实现是“首次遇到即提示信任”，属于 TOFU（Trust On First Use）。
- 不要自动信任未知 fingerprint。
- `sync_peers.public_key_fingerprint` 变更时应重新提示用户确认。

### 4.3 mDNS 限制

- 服务类型：`_solosoul._tcp.local.`
- TXT 字段：`node_id`、`account_id`、`fingerprint`
- 局域网外或某些网络环境下 mDNS 可能不可用，必须保留手动 `host:port` 同步作为 fallback。

### 4.4 加密与数据安全

- 传输层已由 Noise 加密。
- 同步记录中的 `data` 字段（如 profile data）在传输时使用 base64 编码的**明文**，落地时由接收方用本地 data_key 重新加密。
- 绝对不要在前端或日志中打印 profile data、object properties 等敏感内容。

### 4.5 测试环境约束

- `tokio::net::TcpStream::into_std()` 在测试环境下转换为 blocking stream 不稳定，生产代码已改用 `std::net::TcpListener`。
- 新增网络集成测试时，优先使用两个独立进程或 OS 级 socket，避免在单进程内复用 tokio runtime 导致阻塞。

## 2. 冲突解决策略（已实现）

| 场景 | 策略 |
|------|------|
| 同对象不同字段 | 字段级自动合并（各自字段保留） |
| 同字段同时修改 | 记录为冲突，用户审查解决（本地/远程对比 UI，保留本地或采用远程） |
| 簿记字段（version / updated_at） | 不计入用户可见差异 |
