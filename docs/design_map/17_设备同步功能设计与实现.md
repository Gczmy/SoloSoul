## 1. 实际架构（2026-08）

### 传输与发现（`crates/solosoul-sync/`）

- **mDNS 发现**：`mdns-sd` 局域网广播/发现（移动端经 NSD 插件），peer 在线 TTL 300s，60s 周期清理
- **加密通道**：Noise XX 握手（每设备独立 x25519 静态密钥对），`snow` crate
- **配对**：扫码 + 双向确认；SAS/PIN 验证码比对，握手密钥指纹与 node_id 绑定
- **设备列表**：已发现设备（一次性 mDNS 扫描）+ 已知设备（持久化于 Vault，含设备名/指纹/客户端类型/最近同步时间）

### 数据同步

- **增量同步**：对象级 HLC（Hybrid Logical Clock）时间戳水印，按 `sync_changes` 表增量拉取（`list_object_changes_since`）
- **冲突检测**：`sync_conflicts` 表记录 local_data / remote_data，字段级 diff UI 对比（差异内容浅红高亮）
- **簿记字段净化**：`version` / `updated_at` 等簿记字段不计入用户可见差异，避免"内容相同却显示多处冲突"
- **附件同步**：批量传输，`attachments.rs` 已实现
- **同步记录**：`sync_with_device` 审计日志（检查/应用/跳过条数），`sync-completed` 事件通知前端

### 自动同步（`src-tauri/src/sync/device_auto_sync.rs`）

- 三类触发：切回前台 / 本地数据变更（10s 防抖）/ 每 60s 周期
- 自动同步和偏好同步开关保存在当前账户 Profile 的加密 `preferences.deviceSync` 中；解锁后恢复，切换账户不继承上一账户状态。同步引擎保留本机策略，不允许对端 Profile 覆盖。
- 旧版 `ui_preferences.json` 的两个全局同步键在首个账户解锁后迁入该账户；加密保存成功后才删除旧键。其他账户无已有配置时使用默认值。
- 页面「启用同步」代表本次运行的监听/发现服务状态，不将进程运行状态伪装成持久化偏好。
- **同步界面偏好勾选**：主题/主题色/窗口大小等 UI 偏好是否随同步交换，由用户决定
- 离线 peer 短超时（2s）TCP 探测后快速跳过，避免拖慢整轮同步

### 设备备注与设置存储（2026-09）

- 已知设备详情支持编辑名称（最多 64 个字符），留空恢复自动名称；保存在加密 `preferences.deviceNames`，以设备 node ID 为键。名称不改变指纹、广播名或配对信任，握手刷新不会覆盖备注。
- 常规账户设置（自动锁定、回收站、侧边栏等）与云同步配置已经写入加密 Profile，备份及换密钥沿用既有 Profile 处理流程。
- 主题、语言、减少动画、Android 玻璃等登录前需要的外观设置仍保留本机明文缓存；解锁后以账户加密设置为准。设备备注不写入此缓存。
- `sync_peers` 的 node ID、指纹、信任、地址/时间等连接元数据在账户数据库中保留原格式；本次没有把整个 SQLite 文件改为整库加密。同步活动摘要仍为本机缓存，不包含新增加密设备备注。

### 目录所有权、派发与停止（RF-905）

同步使用原 `Arc<VaultStore>` 的 [root owner](../../tauri/crates/solosoul-vault/src/root_owner.rs)。桌面 GUI/CLI 先规范化真实 Native root 并取得 OS 排他锁，再打开数据库、迁移或写入；获取失败返回错误。独立实例声明同一 canonical root 时竞争，合法同应用多连接显式共享已有 owner。Store、Session、受管 FS 克隆和实际 worker 保留 owner 至各自 Drop，关闭会话或取消 await 不等于目录句柄退出。

[SyncManager](../../tauri/crates/solosoul-sync/src/manager.rs) 的监听/发现 worker 保留 owner；空闲监听不占业务 activity。入站/出站会话在派发前取得 root activity 并登记实际 worker，activity 与原 Store 随真正工作体保留，覆盖数据库/附件操作；维护开始后拒绝新会话，不能在排队后重新选择新 Vault 服务。

`stop()` 只请求停止，不作为释放目录或改密的依据。`stop_and_wait()` 发起独立收尾，在宽限期后关闭网络 IO，并等待会话、监听和发现 worker 实际回收；数据库/附件发布完成后才释放 guard/句柄。取消等待也不丢失旧任务 join，新 start 等待上一轮收尾。Host 改密、解锁升级、删除账户和目录替换先取得 maintenance guard，阻止新会话，再 `disable_and_wait` 退休旧 Manager；维护主体借用同一 guard，随后按新 Store 重建或保持禁用，不继续使用旧钥 Store。

CLI [一次性同步](../../solosoul_cli/src/commands/sync.rs) 已使用 start → sync → stop_and_wait，启动失败也回收可能已派发的任务；仍在 TUI 命令线程通过 `block_on` 等待，后台化归 [RF-213](../REFACTOR_EXECUTION_REPORT_2026-09-25.md#rf-213)，不能因任务回收已接入而称界面不再阻塞。RF-022 journal 存在时仍拒绝 root 迁移，SAF 失效保留原 cache；RF-903 旧未标记附件清理与完整 relocation 未在本项实现。

Android/iOS 的 OS 文件锁为 no-op；本机 activity/maintenance gate 不锁远端 SAF provider。实际执行命令、源码 SHA 与本机 Windows 结果以 [RF-905 验证记录](../verification/rf905-root-ownership-2026-10-01.json) 为准；不据此声称其他平台、Android 真机、可见 GUI 流程或 release 透明 KDF 升级已实测。本文同步实现事实，任务验收状态仍由执行报告和实际证据决定。

### 安全要点（已实现）

- 会话层严格校验对端静态公钥；信任检查前不回复含 `account_id` 的帧
- 配对/信任为双向确认；撤销信任后拒绝该设备同步
- 移动端冲突回传与桌面端对齐（conflicts 恒为空的历史缺陷已修复）

## 4. 开发注意事项（来自原 sync-roadmap）

### 4.1 HLC 排序规则

```text
remote > local 当且仅当：
  remote.wall_time_ms > local.wall_time_ms
  或 (wall_time 相等且 remote.counter > local.counter)
  或 (wall_time、counter 均相等且 remote.node_id > local.node_id)
```

修改冲突解决逻辑时必须保持此规则一致。

### 4.2 信任策略

- 当前实现是“首次遇到即提示信任”，属于 TOFU（Trust On First Use）。
- 不要自动信任未知 fingerprint。
- `sync_peers.public_key_fingerprint` 变更时应重新提示用户确认。

### 4.3 mDNS 限制

- 服务类型：`_solosoul._tcp.local.`
- TXT 字段：`node_id`、`account_id`、`fingerprint`
- 局域网外或某些网络环境下 mDNS 可能不可用，必须保留手动 `host:port` 同步作为 fallback。

### 4.4 加密与数据安全

- 传输层已由 Noise 加密。
- 同步记录中的 `data` 字段（如 profile data）在传输时使用 base64 编码的**明文**，落地时由接收方用本地 data_key 重新加密。
- 绝对不要在前端或日志中打印 profile data、object properties 等敏感内容。

### 4.5 测试环境约束

- `tokio::net::TcpStream::into_std()` 在测试环境下转换为 blocking stream 不稳定，生产代码已改用 `std::net::TcpListener`。
- 新增网络集成测试时，优先使用两个独立进程或 OS 级 socket，避免在单进程内复用 tokio runtime 导致阻塞。

## 2. 冲突解决策略（已实现）

| 场景 | 策略 |
|------|------|
| 同对象不同字段 | 字段级自动合并（各自字段保留） |
| 同字段同时修改 | 记录为冲突，用户审查解决（本地/远程对比 UI，保留本地或采用远程） |
| 簿记字段（version / updated_at） | 不计入用户可见差异 |
