# 27 — 平台能力契约

> RF-205 实施规范。验收进度以[执行报告](../REFACTOR_EXECUTION_REPORT_2026-09-25.md#rf-205)为准；fixture 不代表目标平台原生验收。

## 读取与状态

`get_platform_capabilities` 是启动期只读命令，无参数，不要求账户解锁。响应包含 `os`、`updateMethod`、`update`、`ocr`、`nativeMaterial`、`biometric`、`fileOpen`。后三态能力对象的字段统一为 `status`、`reason`、`implementation`，类型由 Rust 源码生成到 `src/lib/generated/ipcContracts.ts`。

- `supported`：此编译目标有实现且必要桥接可调用；`reason` 为 null，`implementation` 为实现名。
- `unsupported`：没有实现；必须有稳定原因，`implementation` 为 null。
- `unavailable`：有实现但本次运行探测不可用；必须有稳定原因并保留实现名。前端尚未读取、读取失败或畸形响应使用本地 unavailable 回退，OS unknown、更新方式 none、全部动作禁用。

支持不等于用户已授权、账户已配置、模型已安装或材质当前开启。扫描模型缺失仍由原扫描流程说明；生物识别账户配置及身份验证仍走原流程；原生材质最终应用结果仍以外观命令响应为准。

## 后端运行探测

系统命令按当前编译目标构造能力，不接受客户端传入 OS。桌面 updater 的可构建结果在其插件初始化之后记录；查询本身不访问更新网络。桌面扫描及 opener 有编译实现；macOS/Windows 材质要求主窗口存在，实际材质与辅助功能回退独立处理。桌面生物识别只查询设备可用性，不调用凭证迁移命令。

Android 仅在原生编译分支查询已注册的 OCR、APK 安装和 FileProvider 句柄；其他目标的占位句柄不会被当作 Android 桥接。窗口模糊调用已有 capability 查询，生物识别调用已有 Keystore availability 查询。iOS 只读查询生物识别插件 status，不复用 Android 实现。上述读取不启动扫描、拍照、认证、安装、通知权限申请或材质切换；不输出账户或字段内容。诊断日志仅记录完整的非敏感能力响应。

## 前端生命周期与交互

启动渲染前读取能力，使用 Zustand 共享快照和单次在途请求。成功响应缓存，失败不标记已加载；显式刷新重新探测，正在进行的读取共享同一 Promise。能力不持久化到账户或磁盘，重启重新查询。

更新 Store 的检查、下载、安装以及公开 APK helper 都校验能力。未知/暂不可用时不发送更新业务 IPC、不记录成功版本检查、不假装已是最新版；手动检查刷新能力。等待能力期间继续保持原任务身份、取消和单次下载保护。iOS 的 unsupported 提示及原安装渠道建议保持。

OCR 页面、设置说明和快捷扫描订阅同一快照；共享扫描操作在事件监听和业务 IPC 之前再次检查当前能力。未知/暂不可用时说明原因并提供「重试」，恢复后各入口同步更新；unsupported 仅说明原因。模型信息、历史及其他仍可用管理操作不被扫描能力一起关闭。OS 与移动布局 helper 仍服务于视觉设计，不用于推导 APK/OCR 支持。

## 权限与验证边界

新增能力命令进入精确的本应用 ACL 和启动期只读豁免名单，不增加系统文件、网络、插件权限或后端 Vault 豁免。保留原来的会话和业务命令鉴权。

RF-205 关闭必须具备 F、R、CONTRACT、IOS、ANDROID_BUILD 检查及相关运行记录。浏览器 mock、固定 fixture、目标编译和实际原生运行证据分别记录，不能互相冒充。未完成构建或运行验收时保持进行中；不能由本规范推定该项完成。
