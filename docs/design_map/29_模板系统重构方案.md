# 29 — 模板系统重构方案

> **前置阅读**：`09_对象规范.md`、`07_数据库_服务层_Repository迁移.md`、`10_前端技术架构与组件映射.md`
> **Manifesto 对齐**：用户主权 | 最少惊喜 | 本地优先
> **文档定位**：针对当前模板系统 MVP 实现与设计规范之间的显著差距，制定分阶段重构方案。当前模板功能仅实现了最小可用集（前端硬编码系统模板 + Profile JSON 内嵌用户模板），本方案规划其向完整模板系统的渐进式演进。
>
> **关联调研报告**：本方案基于 `docs/research/模板系统调研报告.md`（如存在）或代码仓库实际调研结论制定。

---

## 1. 现状与问题

### 1.1 当前实现（MVP 状态）

| 维度 | 当前状态 |
|------|---------|
| 系统模板 | 7 种，**前端硬编码**于 `ObjectEditorPage.tsx` |
| 用户模板 | 仅支持保存和列出，**无编辑/删除** |
| 存储位置 | `profiles.data.preferences.userTemplates` JSON 数组 |
| 属性类型 | 保存模板时**全部强制为 `"text"`**，原始类型丢失 |
| 类型定义 | TypeScript 中**无模板接口**，靠 `any` 传递 |
| 对象关联 | 对象**无 `templateId` 字段**，创建后与模板完全解耦 |
| 模板检测 | 编辑对象时靠属性名**模糊匹配**猜测模板 |

### 1.2 核心问题清单

1. **数据持久化不规范**：用户模板没有独立数据库表，与 `09_对象规范.md` §3.5 中定义的 `user_templates` 表不一致。
2. **类型信息丢失**：`template_save_from_object` 将所有属性类型强制设为 `"text"`，导致基于用户模板创建对象时，日期、下拉选择等特殊字段退化为普通文本输入。
3. **用户模板不可管理**：只能新增，不能修改名称/字段、不能删除、不能排序。
4. **系统模板无法热更新**：硬编码在前端，修改需重新编译发布。
5. **编辑体验不可靠**：属性名模糊匹配失败时，编辑页面突然回退为简陋的键值对输入。
6. **无模板预览**：用户选择模板前无法预知包含哪些字段。

---

## 2. 总体设计原则

1. **向后兼容**：现有 `profile.data.preferences.userTemplates` 中的数据必须无损迁移到独立表，迁移完成后可清理旧数据。
2. **渐进式改造**：每完成一个阶段即可独立发布，不阻塞其他功能开发。
3. **类型安全**：从 `any/serde_json::Value` 过渡到前后端一致的强类型定义。
4. **解耦保留**：基于模板创建的对象与模板保持解耦（符合 `09_对象规范.md` §3.3），模板变更不强制影响已有对象。

### 3.1 数据库迁移（Schema v8）

### 3.3 Rust 后端：IPC 命令

**[正确]** 完整的 CRUD 命令集，替换现有仅 2 个命令的精简实现：

```rust
// src-tauri/src/commands/template.rs

use crate::state::AppState;
use crate::types::template::{UserTemplate, TemplateProperty};
use tauri::State;

/// 创建用户模板（从空白或从对象）
#[tauri::command]
pub async fn template_create(
    state: State<'_, AppState>,
    name: String,
    icon_id: Option<String>,
    properties: Vec<TemplateProperty>,
) -> Result<String, String> {
    let vault = state.vault.lock().await;
    let template = UserTemplate {
        id: format!("utpl_{}", uuid::Uuid::new_v4().simple()),
        account_id: vault.get_account_id().map_err(|e| e.to_string())?,
        name,
        icon_id,
        properties,
        created_at: chrono::Utc::now().to_rfc3339(),
        updated_at: None,
    };
    vault.save_user_template(&template).map_err(|e| e.to_string())?;
    Ok(template.id)
}

/// 更新用户模板
#[tauri::command]
pub async fn template_update(
    state: State<'_, AppState>,
    template_id: String,
    name: Option<String>,
    icon_id: Option<String>,
    properties: Option<Vec<TemplateProperty>>,
) -> Result<(), String> {
    let vault = state.vault.lock().await;
    let mut template = vault
        .load_user_template(&template_id)
        .map_err(|e| e.to_string())?
        .ok_or_else(|| "模板不存在".to_string())?;
    
    if let Some(n) = name { template.name = n; }
    if let Some(i) = icon_id { template.icon_id = Some(i); }
    if let Some(p) = properties { template.properties = p; }
    template.updated_at = Some(chrono::Utc::now().to_rfc3339());
    
    vault.update_user_template(&template).map_err(|e| e.to_string())
}

/// 删除用户模板
#[tauri::command]
pub async fn template_delete(
    state: State<'_, AppState>,
    template_id: String,
) -> Result<(), String> {
    let vault = state.vault.lock().await;
    vault.delete_user_template(&template_id).map_err(|e| e.to_string())
}

/// 从现有对象保存为用户模板（增强版：保留原始属性类型）
#[tauri::command]
pub async fn template_save_from_object(
    state: State<'_, AppState>,
    object_id: String,
    template_name: String,
) -> Result<String, String> {
    let vault = state.vault.lock().await;
    let object = vault.load_object(&object_id).map_err(|e| e.to_string())?
        .ok_or_else(|| "对象不存在".to_string())?;
    
    // [正确] 从对象的 properties 中保留原始类型信息
    let properties = object.properties.iter().map(|prop| {
        TemplateProperty {
            id: prop.id.clone(),
            name: prop.name.clone(),
            prop_type: prop.property_type.clone(),
            sensitive: Some(prop.sensitivity != SensitivityLevel::Public),
            options: prop.options.clone(),
        }
    }).collect();
    
    let template = UserTemplate {
        id: format!("utpl_{}", uuid::Uuid::new_v4().simple()),
        account_id: object.account_id,
        name: template_name,
        icon_id: Some(object.icon_id.unwrap_or_else(|| "document".to_string())),
        properties,
        created_at: chrono::Utc::now().to_rfc3339(),
        updated_at: None,
    };
    
    vault.save_user_template(&template).map_err(|e| e.to_string())?;
    Ok(template.id)
}
```

```typescript
import { Select, SelectItem } from '@/components/ui/Select';
import { Toggle } from '@/components/ui/Toggle';

interface TemplateFieldInputProps {
  property: TemplateProperty;
  value: unknown;
  onChange: (value: unknown) => void;
}

export const TemplateFieldInput: React.FC<TemplateFieldInputProps> = ({
  property, value, onChange
}) => {
  switch (property.type) {
    case 'text':
      return <Input type="text" value={String(value || '')} onChange={e => onChange(e.target.value)} />;
    case 'multiline':
      return <TextArea value={String(value || '')} onChange={e => onChange(e.target.value)} />;
    case 'number':
      return <Input type="number" value={Number(value) || 0} onChange={e => onChange(Number(e.target.value))} />;
    case 'date':
      return <Input type="date" value={String(value || '')} onChange={e => onChange(e.target.value)} />;
    case 'datetime':
      return <Input type="datetime-local" value={String(value || '')} onChange={e => onChange(e.target.value)} />;
    case 'boolean':
      return <Toggle checked={Boolean(value)} onChange={onChange} />;
    case 'select':
      return (
        <Select value={String(value || '')} onChange={onChange}>
          {property.options?.map(opt => <SelectItem key={opt} value={opt}>{opt}</SelectItem>)}
        </Select>
      );
    case 'multiselect':
      return <MultiSelect options={property.options || []} value={(value as string[]) || []} onChange={onChange} />;
    case 'url':
      return <Input type="url" value={String(value || '')} onChange={e => onChange(e.target.value)} />;
    case 'email':
      return <Input type="email" value={String(value || '')} onChange={e => onChange(e.target.value)} />;
    case 'phone':
      return <Input type="tel" value={String(value || '')} onChange={e => onChange(e.target.value)} />;
    case 'file':
      return <FileReferenceInput value={String(value || '')} onChange={onChange} />;
```

```rust
    pub async fn load() -> Result<()> {
        let resource_path = resolve_resource("resources/system_templates.json")?;
        let content = tokio::fs::read_to_string(resource_path).await?;
        let data: SystemTemplateResource = serde_json::from_str(&content)?;
        
        let mut templates = HashMap::new();
        for tpl in data.templates {
            templates.insert(tpl.key.clone(), tpl);
        }
        
        let registry = SystemTemplateRegistry { templates, version: data.version };
        REGISTRY.set(RwLock::new(registry)).ok();
        Ok(())
    }
    
    pub async fn get(key: &str) -> Option<SystemTemplate> {
        REGISTRY.get()?.read().await.templates.get(key).cloned()
    }

        let registry = REGISTRY.get()?.read().await;
        registry.templates.values()
            .filter(|t| t.category == category)
            .cloned()
            .collect()
    }
```

## 9. 风险与回滚

| 风险 | 缓解措施 |
|------|---------|
| 用户模板数据迁移失败 | 迁移前保留 Profile JSON 备份；失败时回退到旧读取逻辑；下次启动重试迁移 |
| 数据库迁移冲突 | 严格按 `user_version` 顺序执行；每步迁移在独立事务中完成 |
| 前端类型与后端不匹配 | 两端共用 JSON Schema 约定；CI 中增加类型检查 |
| 系统模板 JSON 格式错误 | 启动时验证 JSON Schema；错误时回退到内置默认模板硬编码 |
| `PropertyType` 新增导致旧数据不兼容 | 序列化使用字符串枚举；新增类型时旧版前端降级为文本输入 |
