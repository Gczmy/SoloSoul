## 1. 现状与问题

### 1.1 当前实现（MVP 状态）

| 维度 | 当前状态 |
|------|---------|
| 系统模板 | 7 种，**前端硬编码**于 `ObjectEditorPage.tsx` |
| 用户模板 | 仅支持保存和列出，**无编辑/删除** |
| 存储位置 | `profiles.data.preferences.userTemplates` JSON 数组 |
| 属性类型 | 保存模板时**全部强制为 `"text"`**，原始类型丢失 |
| 类型定义 | TypeScript 中**无模板接口**，靠 `any` 传递 |
| 对象关联 | 对象**无 `templateId` 字段**，创建后与模板完全解耦 |
| 模板检测 | 编辑对象时靠属性名**模糊匹配**猜测模板 |

### 1.2 核心问题清单

1. **数据持久化不规范**：用户模板没有独立数据库表，与 `09_对象规范.md` §3.5 中定义的 `user_templates` 表不一致。
2. **类型信息丢失**：`template_save_from_object` 将所有属性类型强制设为 `"text"`，导致基于用户模板创建对象时，日期、下拉选择等特殊字段退化为普通文本输入。
3. **用户模板不可管理**：只能新增，不能修改名称/字段、不能删除、不能排序。
4. **系统模板无法热更新**：硬编码在前端，修改需重新编译发布。
5. **编辑体验不可靠**：属性名模糊匹配失败时，编辑页面突然回退为简陋的键值对输入。
6. **无模板预览**：用户选择模板前无法预知包含哪些字段。

---

## 2. 总体设计原则

1. **向后兼容**：现有 `profile.data.preferences.userTemplates` 中的数据必须无损迁移到独立表，迁移完成后可清理旧数据。
2. **渐进式改造**：每完成一个阶段即可独立发布，不阻塞其他功能开发。
3. **类型安全**：从 `any/serde_json::Value` 过渡到前后端一致的强类型定义。
4. **解耦保留**：基于模板创建的对象与模板保持解耦（符合 `09_对象规范.md` §3.3），模板变更不强制影响已有对象。

## 3. P1 阶段：独立数据库表与模板生命周期管理

### 3.1 数据库迁移（Schema v8）

**[正确]** 使用独立迁移事务，失败后 `user_version` 不递增，允许重试：

```rust
// src-tauri/src/db/migrations.rs
// 在 migrate_v7_to_v8 中添加

const MIGRATE_V8_SQL: &str = r#"
CREATE TABLE IF NOT EXISTS user_templates (
    id TEXT PRIMARY KEY,
    account_id TEXT NOT NULL,
    name TEXT NOT NULL,
    icon_id TEXT,
    properties_json TEXT NOT NULL,
    created_at TEXT NOT NULL,
    updated_at TEXT,
    FOREIGN KEY (account_id) REFERENCES profiles(account_id) ON DELETE CASCADE
);

CREATE INDEX IF NOT EXISTS idx_user_templates_account
    ON user_templates(account_id);
"#;
```

**[正确]** 纯 SQL 迁移仅创建表结构，数据迁移延迟到 Vault 解锁后执行：

```rust
fn migrate_v7_to_v8(conn: &Connection) -> Result<()> {
    // 步骤 1：纯 DDL，无需解密，可在启动时立即执行
    conn.execute_batch(MIGRATE_V8_SQL)?;
    Ok(())
}
```

**数据迁移逻辑**（Vault 解锁后执行）：

```rust
// src-tauri/src/core/app_initializer.rs 或 vault_service.rs

/// 检查并执行延迟的数据迁移
pub async fn run_pending_migrations(state: &AppState) -> Result<(), String> {
    let vault = state.vault.lock().await;
    let conn = vault.get_raw_connection().map_err(|e| e.to_string())?;
    
    // 检查是否已有 user_templates 数据（防止重复迁移）
    let count: i64 = conn.query_row(
        "SELECT COUNT(*) FROM user_templates", [], |row| row.get(0)
    ).map_err(|e| e.to_string())?;
    
    if count > 0 {
        // 已迁移过，清理旧 JSON 中的残留数据（若存在）
        cleanup_legacy_user_templates(&vault).await?;
        return Ok(());
    }
    
    // 从 Profile 的 data 字段中解密并提取旧模板数据
    let profile = vault.load_profile().map_err(|e| e.to_string())?;
    if let Some(templates_json) = profile.data.preferences.user_templates {
        let templates: Vec<LegacyUserTemplate> = serde_json::from_str(&templates_json)
            .map_err(|e| format!("解析旧模板数据失败: {}", e))?;
        
        for tpl in templates {
            let new_template = UserTemplate {
                id: format!("utpl_{}", uuid::Uuid::new_v4().simple()),
                account_id: profile.account_id.clone(),
                name: tpl.name,
                icon_id: tpl.icon_id,
                properties: migrate_legacy_properties(tpl.properties), // 类型降级处理
                created_at: tpl.created_at.unwrap_or_else(|| chrono::Utc::now().to_rfc3339()),
                updated_at: None,
            };
            vault.save_user_template(&new_template).map_err(|e| e.to_string())?;
        }
        
        // 迁移成功后，从 Profile JSON 中移除旧数据并写回
        cleanup_legacy_user_templates(&vault).await?;
    }
    
    Ok(())
}

/// 清理 Profile JSON 中的旧 userTemplates 字段
async fn cleanup_legacy_user_templates(vault: &VaultStore) -> Result<(), String> {
    let mut profile = vault.load_profile().map_err(|e| e.to_string())?;
    if profile.data.preferences.user_templates.is_some() {
        profile.data.preferences.user_templates = None;
        vault.save_profile(&profile).map_err(|e| e.to_string())?;
    }
    Ok(())
}
```

**[正确]** 延迟迁移的执行时序：

```
应用启动
  → 执行纯 DDL 迁移（创建 user_templates 表，user_version = 8）
  → 用户解锁 Vault
    → AppState 初始化完成
      → 调用 run_pending_migrations()
        → 若成功：清理旧 JSON，记录日志
        → 若失败：记录错误，不阻塞解锁流程，下次启动重试
```

**[错误]** 不要在 Vault 未解锁时尝试解密 Profile data 执行迁移：

```rust
// 错误：启动时 Vault 未解锁，无法解密 data 字段
fn migrate_v7_to_v8(conn: &Connection) -> Result<()> {
    conn.execute_batch(MIGRATE_V8_SQL)?;
    // ❌ 此时 Vault 未解锁，无法解密 profiles.data
    let data = decrypt_profile_data(...)?; // 会失败
    // ...
}
```

```rust
/// 从现有对象保存为用户模板（增强版：保留原始属性类型）
#[tauri::command]
pub async fn template_save_from_object(
    state: State<'_, AppState>,
    object_id: String,
    template_name: String,
) -> Result<String, String> {
    let vault = state.vault.lock().await;
    let object = vault.load_object(&object_id).map_err(|e| e.to_string())?
        .ok_or_else(|| "对象不存在".to_string())?;
    
    // [正确] 从对象的 properties 中保留原始类型信息，缺失时降级/猜测
    let properties = object.properties.iter().map(|prop| {
        let prop_type = prop.property_type.clone()
            .or_else(|| infer_type_from_value(&prop.value)) // 类型缺失时根据值猜测
            .unwrap_or(PropertyType::Text); // 无法猜测时降级为 text
        
        TemplateProperty {
            id: prop.id.clone(),
            name: prop.name.clone(),
            prop_type,
            sensitive: Some(prop.sensitivity != SensitivityLevel::Public),
            options: prop.options.clone(),
        }
    }).collect();
    
    let template = UserTemplate {
        id: format!("utpl_{}", uuid::Uuid::new_v4().simple()),
        account_id: object.account_id,
        name: template_name,
        icon_id: Some(object.icon_id.unwrap_or_else(|| "document".to_string())),
        properties,
        created_at: chrono::Utc::now().to_rfc3339(),
        updated_at: None,
    };
    
    vault.save_user_template(&template).map_err(|e| e.to_string())?;
    Ok(template.id)
}
```

### 3.6 前端：模板管理页面

**[正确]** 提供独立的模板管理入口，支持列表/编辑/删除：


### 6.3 使用场景

1. **创建对象时**：`object_create` 命令接收可选的 `template_id` 和 `template_type`，创建后写入对象记录。
2. **编辑对象时**：优先使用对象自身记录的 `templateId` 加载对应模板渲染表单。
3. **降级处理**（模板被删除或 key 变更时）：

**[正确]** 若 `templateId` 对应的模板已不存在（用户删除了自定义模板，或系统模板 key 变更），则回退到基于属性键集合的模糊匹配（即当前 MVP 行为），同时记录警告日志。编辑页面正常渲染，不阻塞用户操作：

```typescript
async function resolveTemplateForEditing(object: ObjectData): Promise<ResolvedTemplate | null> {
  if (object.templateId) {
    const template = object.templateType === 'system'
      ? await systemTemplateStore.get(object.templateId)
      : await templateStore.get(object.templateId);
    
    if (template) {
      return { source: 'recorded', template };
    }
    
    // [正确] 模板不存在时降级到模糊匹配，并记录日志
    console.warn(`模板 ${object.templateId} 已不存在，回退到属性匹配`);
  }
  
  // 降级：基于属性键集合模糊匹配最佳系统模板
  return detectTemplateByProperties(object.properties);
}
```

**[错误]** 不要因 `templateId` 失效而抛出错误或显示空白页面：

```typescript

  throw new Error(`模板不存在: ${object.templateId}`); // ❌ 阻塞用户

```

4. **模板升级提示**（可选高级功能）：若系统模板资源文件版本更新，可检测基于旧版模板创建的对象，提示用户"是否按新版模板更新字段结构"。

## 9. 风险与回滚

| 风险 | 等级 | 缓解措施 |
|------|------|---------|
| 用户模板数据迁移失败 | 中 | 延迟到 Vault 解锁后执行；失败记录日志不阻塞解锁；下次启动重试；保留 Profile JSON 直至迁移成功 |
| 数据库迁移冲突 | 低 | 严格按 `user_version` 顺序执行；每步迁移在独立事务中完成 |
| 前端类型与后端不匹配 | 低 | 两端共用 JSON Schema 约定；CI 中增加类型检查 |
| 系统模板 JSON 格式错误 | 低 | 启动时验证 JSON Schema；错误时回退到内置默认模板硬编码（保留 MVP 的硬编码作为 fallback） |
| `PropertyType` 新增导致旧数据不兼容 | 低 | 序列化使用字符串枚举；新增类型时旧版前端降级为文本输入 |
| **模板删除造成"孤儿引用"** | 低 | 删除模板不级联删除对象；编辑对象时若 `templateId` 失效，自动降级到属性模糊匹配；模板管理页显示基于该模板的对象数量 |
| 前端 `TemplateFieldInput` 开发工作量低估 | 低 | 分阶段实现：P1 先支持 text/date/boolean/select 四种最常用类型，P2/P3 逐步扩展 |
| 迁移中 Vault 长期未解锁导致旧数据滞留 | 低 | 旧数据保留在 Profile JSON 中不影响功能；解锁后自动清理；升级说明中提示用户首次解锁后需等待迁移完成 |
