# 23 — 回收站功能规范（Trash / Recycle Bin）

> **文档定位**：定义 SoloSoul 回收站的完整业务规则、数据模型、用户交互与实现细节。回收站是用户数据的"安全网"——所有删除操作均为软删除，支持恢复、保留期配置与审计追踪。
>
> **前置依赖**：06（数据库/Repository）、07（IPC 接口）、09（材质与视觉规范）、10（Zustand 状态管理）、12（敏感度等级）、24（扁平数据模型——回收站仅含页面和对象两级，无集合/分组中间层）。

---

## 1. 核心设计原则

| 原则 | 说明 |
|------|------|
| **软删除优先** | 所有项目进入回收站后数据完整保留，不丢失任何用户数据 |
| **可恢复性** | 回收站中的任何项目在保留期内均可一键恢复至删除前的精确位置 |
| **可控保留期** | 用户可配置自动清理周期，支持"永不自动删除" |
| **操作可审计** | 删除、恢复等操作自动记录到操作日志，便于追溯 |
| **查看不记录** | 浏览、筛选、查看详情等只读操作不进入操作日志 |

---

## 2. 软删除与数据保留

### 2.1 删除类型

SoloSoul 采用扁平数据模型（见 06_数据组织模型架构决策.md），页面直接包含对象列表。回收站对应支持两种删除粒度：

| 删除场景 | 行为 |
|----------|------|
| 用户主动删除页面 | 页面从侧边栏移除，进入回收站，页面内所有对象保留 |
| 用户主动删除对象 | 对象从页面列表中移除，进入回收站，对象完整字段数据保留 |
| 用户批量删除 | 每一项独立进入回收站，可独立恢复 |
| 操作日志 30 天清理 | 此为系统内部清理，**不经过回收站**，直接永久删除 |

> **反例**：禁止任何场景执行物理删除（除操作日志外）。错误示例：
> ```typescript
> // 错误：直接物理删除
> await db.delete('objects').where({ id: objId });
> ```

### 2.2 软删除的数据模型

被删除项目在数据库中保留全部数据，仅添加软删除标记：

```rust
// Rust 侧：TrashItem 表结构（SQLite）
struct TrashItem {
    id: String,                 // UUID v4
    item_type: TrashItemType,   // 类型：Page / Object（扁平模型无 Collection）
    original_id: String,        // 原项目 ID（恢复时使用）
    original_parent_id: Option<String>, // 原父级页面 ID（页面无父级，对象有页面父级）
    original_section_type: Option<String>, // 原归属页面 section_type（对象恢复时使用）
    original_sort_order: Option<i32>,   // 原排序位置
    data: EncryptedBlob,        // 完整加密数据快照（删除时的完整状态）
    deleted_at: i64,            // 删除时间戳（Unix ms）
    expires_at: Option<i64>,    // 过期时间戳（根据保留期计算，None = 永不自动删除）
    deleted_by: String,         // 删除来源："user" / "system_auto" / "migration"
    name_snapshot: String,      // 删除时的名称快照（用于回收站列表展示）
    icon_snapshot: Option<String>, // 删除时的图标 ID 快照
}

enum TrashItemType {
    Page,
    Object,
}
```

> **关键设计**：`data` 字段存储删除瞬间的完整加密快照。恢复时直接还原该快照，确保数据一致性。
> 即使原页面已被后续修改，恢复操作也将项目放回其删除前的精确位置。

### 2.3 加密与权限

- `data` 字段使用与 Vault 相同的主密钥加密（AES-256-GCM）
- 回收站数据仅在 Vault 解锁状态下可访问
- 回收站列表展示使用 `name_snapshot` 和 `icon_snapshot`（无需解密完整数据）
- 查看项目详情时才解密 `data` 字段展示完整内容

## 3. 保留期配置

### 3.1 配置选项

用户在**设置 → 安全设置 → 回收站**中配置保留期：

| 选项 | 保留时间 | 说明 |
|------|----------|------|
| 30 天 | 2,592,000 秒 | 默认选项 |
| 60 天 | 5,184,000 秒 | — |
| 半年 | 约 180 天 | 精确计算按 180 天 |
| 一年 | 约 365 天 | 精确计算按 365 天 |
| 关闭自动删除 | ∞ | 回收站项目永不自动删除，只能用户手动彻底删除 |

### 3.2 配置存储

```rust
// 用户偏好中存储（加密于 Rust Vault）
struct TrashPreferences {
    retention_period: TrashRetentionPeriod,
}

enum TrashRetentionPeriod {
    Days30,
    Days60,
    HalfYear,    // 180 天
    OneYear,     // 365 天
    NeverAutoDelete,
}
```

### 3.3 自动清理机制

- **触发时机**：应用启动时 + 每 24 小时后台检查一次
- **清理逻辑**：遍历 `expires_at <= now()` 且 `expires_at IS NOT NULL` 的项目，执行永久删除
- **后台检查**：不阻塞用户界面，使用独立异步任务
- **清理确认**：清理前记录操作日志（"system_auto" 来源）

```rust
// 伪代码：自动清理流程
async fn auto_cleanup(vault: &Vault) -> Result<Vec<String>, Error> {
    let now = current_time_ms();
    let expired = trash_repo
        .find_expired(now)
        .await?;
    
    for item in expired {
        permanently_delete(item.id).await?;
        log_operation(OperationType::AutoPurge, &item).await?;
    }
    
    Ok(expired.into_iter().map(|i| i.id).collect())
}
```

> **反例**：禁止在 UI 线程同步执行清理。错误示例：
> ```typescript
> // 错误：同步阻塞 UI
> useEffect(() => { trashStore.cleanup(); }, []);
> ```
> 正确：后台异步，用户无感知。

### 3.4 保留期变更的影响

- 用户从"30 天"改为"60 天"：已存在的回收站项目 `expires_at` 重新计算（从 `deleted_at + 60 天`）
- 用户从"30 天"改为"关闭自动删除"：所有项目的 `expires_at` 设为 `NULL`
- 用户从"关闭自动删除"改为"30 天"：所有项目的 `expires_at` 从 `deleted_at + 30 天` 计算
- 保留期缩短时，部分项目可能立即满足清理条件，将在下次启动/检查时清理

## 4. 恢复逻辑

### 4.1 恢复操作

回收站中的任何项目在保留期内均可恢复：

| 项目类型 | 恢复行为 |
|----------|----------|
| **页面** | 页面重新出现在侧边栏，恢复至删除前的位置（sortOrder）。页面内的所有对象完整还原 |
| **对象** | 对象恢复到其删除前所在的页面（`original_section_type`）中，字段数据完整还原 |

### 4.2 恢复冲突处理

恢复时可能遇到目标位置已变化的情况：

| 冲突场景 | 处理策略 |
|----------|----------|
| 原页面已被删除 | 对象恢复后标记为未分类（显示于所在页面列表末尾，需用户手动归位） |
| 原位置已有同名项目 | 恢复的项目名称后追加" (恢复的)"，保持两者并存 |
| 原 sortOrder 已被占用 | 插入到最近可用位置，保持原有顺序关系 |

> **注意**：扁平模型下对象直接归属于页面（通过 `section_type`），没有集合中间层，因此不存在"原集合被删除"的冲突。

### 4.3 恢复的数据一致性

```rust
// 伪代码：恢复流程
async fn restore_item(trash_id: &str, vault: &Vault) -> Result<RestoreResult, Error> {
    let item = trash_repo.get(trash_id).await?;
    let decrypted_data = vault.decrypt(&item.data)?;
    
    match item.item_type {
        TrashItemType::Page => {
            let page: Page = deserialize(&decrypted_data)?;
            let target_order = if page_repo.exists(page.id).await? {
                // 同名冲突，重命名
                page.name = format!("{} (恢复的)", page.name);
                page_repo.insert(&page).await?
            } else {
                page_repo.restore(&page, item.original_sort_order).await?
            };
        }
        TrashItemType::Object => {
            let object: Object = deserialize(&decrypted_data)?;
            // 按 section_type 恢复到对应页面
            object_repo.restore(&object, item.original_section_type.as_deref(),
                item.original_sort_order).await?
        }
    }
    
    // 从回收站移除
    trash_repo.delete(trash_id).await?;
    
    // 记录操作日志
    log_operation(OperationType::Restore, &item).await?;
    
    Ok(RestoreResult { id: item.original_id, name: item.name_snapshot })
}
```

### 4.4 恢复的 UI 反馈

- 恢复成功后显示 Toast 通知："[项目名称] 已恢复"
- 若发生重命名冲突，Toast 包含额外提示："因名称冲突，已重命名为 '[新名称]'"
- 恢复后的项目自动在侧边栏/页面中高亮显示 2 秒（`--accent-primary` 背景闪烁动画）

## 5. 分类筛选

### 5.1 时间筛选

回收站页面提供时间筛选器：

| 筛选选项 | 范围 |
|----------|------|
| 全部时间 | 不限制 |
| 1 天内 | `deleted_at >= now - 24h` |
| 3 天内 | `deleted_at >= now - 72h` |
| 7 天内 | `deleted_at >= now - 168h` |
| 30 天内 | `deleted_at >= now - 720h` |
| 半年内 | `deleted_at >= now - 180 天` |

**交互设计**：
- 筛选器位于回收站页面顶部，下拉选择（Dropdown）
- 切换筛选即时生效，无需确认
- 当前筛选条件显示在标题栏："回收站（30 天内）"

### 5.2 类型筛选

| 筛选选项 | 说明 |
|----------|------|
| 全部类型 | 显示所有项目 |
| 页面 | 仅显示被删除的页面 |
| 对象 | 仅显示被删除的对象 |

**交互设计**：
- 类型筛选与时间筛选可组合使用（逻辑 AND）
- 使用标签页（Tabs）或分段控件（Segmented Control）展示
- 每个类型标签旁显示当前数量徽章（Badge）
- 扁平模型下仅有 `页面` 和 `对象` 两种类型，无集合/分组

### 5.3 筛选与搜索的组合

```
[回收站                    ]  ← 页面标题
[🔍 搜索回收站项目...      ]  ← 搜索框（按名称快照搜索）
[全部时间 ▼] [全部类型 ▼]      ← 筛选器

┌─────────────────────────────────────┐
│ [📄] 旅行计划              2天前  │  ← 列表项
│ [📎] 护照扫描件            12天前 │
└─────────────────────────────────────┘
```

> **注意**：搜索范围限于 `name_snapshot`，不搜索完整数据内容。
> 搜索为本地前端过滤，不发起额外 IPC 请求（回收站列表数据已在内存中）。

## 7. 操作日志记录

### 7.1 记录范围

回收站内发生的以下操作**必须**记录到操作日志：

| 操作 | 日志内容 |
|------|----------|
| 删除（进入回收站） | `OperationType::Delete`，记录原项目 ID、类型、名称、删除时间 |
| 恢复 | `OperationType::Restore`，记录原项目 ID、恢复后的新 ID（如重命名）、恢复时间 |
| 彻底删除 | `OperationType::PermanentDelete`，记录项目 ID、类型、名称、删除原因 |
| 自动清理 | `OperationType::AutoPurge`，记录被清理的项目列表、清理时间 |
| 保留期变更 | `OperationType::PreferenceChange`，记录旧值→新值 |

### 7.2 不记录的操作

以下操作**不进入**操作日志：

| 操作 | 原因 |
|------|------|
| 查看项目详情 | 只读操作，无数据变更 |
| 使用时间/类型筛选 | 纯 UI 状态变化 |
| 搜索回收站 | 纯前端过滤 |
| 浏览回收站列表 | 只读操作 |

### 7.3 日志数据结构

```rust
struct OperationLog {
    id: String,
    operation_type: OperationType,     // Delete / Restore / PermanentDelete / AutoPurge / PreferenceChange
    target_type: Option<String>,       // "page" / "object"
    target_id: Option<String>,         // 项目 ID
    target_name: Option<String>,       // 名称快照
    details: Option<String>,           // JSON 序列化的额外详情
    performed_at: i64,                 // 时间戳
    performed_by: String,              // "user" / "system"
}
```

## 11. 数据库迁移

新建 `trash_items` 表（位于 Vault SQLite 数据库中）：

```sql
CREATE TABLE trash_items (
    id TEXT PRIMARY KEY,
    item_type TEXT NOT NULL CHECK(item_type IN ('page', 'object')),  -- 扁平模型：仅页面和对象
    original_id TEXT NOT NULL,
    original_parent_id TEXT,
    original_section_type TEXT,      -- 对象归属页面（扁平模型：identity/travel/financial/professional）
    original_sort_order INTEGER,
    data BLOB NOT NULL,              -- 加密数据快照
    deleted_at INTEGER NOT NULL,     -- Unix timestamp (ms)
    expires_at INTEGER,              -- NULL = 永不自动删除
    deleted_by TEXT NOT NULL DEFAULT 'user',
    name_snapshot TEXT NOT NULL,
    icon_snapshot TEXT
);

CREATE INDEX idx_trash_expires ON trash_items(expires_at) WHERE expires_at IS NOT NULL;
CREATE INDEX idx_trash_deleted_at ON trash_items(deleted_at);
CREATE INDEX idx_trash_type ON trash_items(item_type);
```
