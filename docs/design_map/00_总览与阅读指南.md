# 00 — SoloSoul Tauri 重构开发计划总览

> **文档集定位**：这是 SoloSoul 从 Flutter + Rust FFI 架构迁移到 Tauri + Rust 原生架构的**完整开发执行计划**。
> **不是设计讨论，是开发指令**。每篇文档应提供足够的技术细节、正例与反例、验证标准，使开发者能够无须额外沟通即可按文档完成开发。

## 与 Manifesto 的对齐

每份文档在开篇明确标注与 Manifesto 中理念的对应关系：

- **本地优先**：所有核心功能在无网络下 100% 可用
- **隐私优先**：默认不向任何第三方暴露数据
- **用户主权**：数据完全属于用户，可随时导出脱离
- **安全默认**：加密不可降级，安全不可关闭
- **最少惊喜**：操作可预期，副作用明确告知
- **依赖最小化**：标准库优先，外部依赖须审查

如有理念冲突，归入 `26_矛盾冲突与待审批事项.md` 集中讨论，不在功能文档中直接解决。

## 文档编写规范

1. **每篇文档自包含**：所有必要的类型定义、代码示例、API 签名均在文档内给出，不依赖外部查阅。
2. **正例与反例明确**：使用 `[正确]` 和 `[错误]` 文字标记，确保开发者知道什么该做、什么不该做。产品界面中对应图标须遵循 `11_跨平台材质系统与视觉规范.md` 的图标与图像规范，使用自定义 SVG 图标，禁止直接使用 Emoji。
3. **验证标准清晰**：每篇文档结尾有 "完成标准" 清单（Checklist），用于代码审查和验收。
4. **依赖关系显式**：文档开头 "前置阅读" 列出必须先读的文档。
5. **代码可执行**：提供的代码示例应足够完整，可以直接复制到项目中并编译通过（可能需要调整 import 路径）。
