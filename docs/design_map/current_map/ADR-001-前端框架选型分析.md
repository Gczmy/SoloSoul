# ADR-001: 前端框架选型分析

> **状态**: 已采纳 ✅  
> **决策日期**: 2026-06-04  
> **决策人**: SoloSoul 架构组  
> **影响范围**: 前端技术栈、开发效率、性能、可维护性

---

## 背景

SoloSoul 主项目使用 **Flutter 3.41.6** 作为跨平台客户端框架，配合 **Rust FFI**（flutter_rust_bridge）实现原生加密核心。Flutter 端通过 FFI 直接调用 Rust 代码，无需额外的 HTTP API 后端。

现计划全面迁移至 **Tauri + Rust** 架构，需要重新选择前端框架（Web 技术栈替代 Flutter/Dart）。

## 评估维度

| 维度 | 权重 | 说明 |
|------|------|------|
| Tauri 生态兼容性 | 高 | 框架与 Tauri IPC/API 的集成便利程度 |
| Liquid Glass 实现难度 | 高 | 复刻 iOS 26 Liquid Glass 视觉效果的实现成本 |
| 开发团队熟悉度 | 高 | 团队当前技术栈与目标框架的距离 |
| 性能表现 | 中 | 渲染性能、内存占用、启动速度 |
| 包体积 | 中 | 最终 Release 包大小 |
| 生态系统成熟度 | 中 | 第三方库、社区活跃度、长期维护 |
| 类型安全 | 中 | TypeScript 支持、编译时检查 |
| 可访问性 (a11y) | 低 | 键盘导航、屏幕阅读器支持 |

## 候选方案

### 方案 A: React 19 + Vite（推荐）

**技术栈**: React 19 + TypeScript 5.7 + Vite 6 + Tailwind CSS v4（或纯 CSS）

**优势**:
- **Tauri 官方首推**: Tauri 官方文档和示例均以 React/Vue 为主
- **生态系统最成熟**: npm 生态最丰富，几乎所有需求都有现成方案
- **Liquid Glass 实现灵活**: CSS `backdrop-filter` + WebGL Shader 均可使用
- **团队熟悉度高**: 已废弃的 Web UI（Next.js 15 + React 19）使用过 React，相关经验可复用
- **类型安全完善**: TypeScript 5.7 支持完整，与 Rust 类型可通过 tauri-specta 生成绑定
- **状态管理方案成熟**: Zustand / Jotai / Valtio 等多种选择
- **调试工具完善**: React DevTools + Redux DevTools + Tauri DevTools

**劣势**:
- 运行时包体积相对较大（React 本身 ~40KB gzip）
- 需要额外配置 JSX 转换、HMR 等（Vite 已内置）
- 虚拟 DOM 开销（对高频更新场景有影响，但 SoloSoul 以 CRUD 为主）

**Liquid Glass 实现路径**:
```
基础实现: CSS backdrop-filter + radial-gradient
进阶实现: WebGL Fragment Shader (Three.js / raw WebGL)
库辅助: @react-three/fiber (如需 3D 效果)
```

---

### 方案 B: Vue 3 + Vite

**技术栈**: Vue 3.4 + TypeScript 5.7 + Vite 6 + UnoCSS / Tailwind CSS

**优势**:
- **Tauri 官方支持**: Tauri 官方提供 Vue 插件和示例
- **包体积较小**: Vue 3 runtime ~23KB gzip（比 React 小）
- **开发体验好**: SFC（单文件组件）天然支持 scoped style
- **响应式系统简洁**: `ref()` / `reactive()` 比 React hooks 学习曲线更平缓
- **Composition API 灵活**: 逻辑复用方式与 React hooks 类似

**劣势**:
- 团队有 React 使用经验（来自已废弃的 Web UI 项目），Vue 需要重新学习
- Liquid Glass Shader 在 Vue 中实现与 React 无本质差异
- 生态总量略少于 React（但核心需求都能满足）
- 类型推导在某些场景不如 React + TypeScript 精确

---

### 方案 C: Svelte 5 + SvelteKit（或 Vite）

**技术栈**: Svelte 5 + TypeScript 5.7 + SvelteKit 2 / Vite

**优势**:
- **包体积极小**: 编译时框架，无运行时虚拟 DOM，最终包体最小
- **性能最优**: 编译为原生 DOM 操作，理论性能最好
- **代码简洁**: 语法简洁，`{variable}` 直接绑定

**劣势**:
- **团队学习成本高**: Svelte 语法与 React/Vue 差异大，团队需要重新学习
- **生态规模较小**: npm 包数量、社区活跃度不如 React/Vue
- **Tauri 集成示例少**: 官方和社区 Tauri + Svelte 的参考项目较少
- **TypeScript 支持**: Svelte 5 已大幅改善，但仍不如 React 成熟
- **长期维护风险**: 社区规模小，长期维护不确定性

---

### 方案 D: SolidJS + Vite

**技术栈**: SolidJS + TypeScript 5.7 + Vite

**优势**:
- **性能极高**: 细粒度响应式，无虚拟 DOM，性能接近原生
- **包体积小**: 运行时极小
- **React-like API**: JSX 语法，React 开发者容易上手

**劣势**:
- **生态极小**: 第三方库非常有限
- **团队经验为零**: 需要从零学习
- **Tauri 集成资料极少**: 几乎没有参考项目
- **不适合项目规模**: SoloSoul 是大型应用，SolidJS 更适合小型应用

---

### 方案 E: 继续使用 Flutter Web（不迁移）

**技术栈**: Flutter 3.41.6 + flutter_rust_bridge

**优势**:
- **零迁移成本**: 保持现有代码不变
- **已发布 macOS 版本**: 功能已验证

**劣势**:
- **无法使用 Tauri**: 与 Tauri 架构完全不兼容
- **Web 端体验差**: Flutter Web 包体巨大（5MB+），加载慢
- **平台限制**: iOS Keychain 问题（P0 未解决）
- **热更新困难**: Dart 热重载在复杂场景下不稳定
- **生态隔离**: Flutter 生态与 Web 生态不互通
- **与项目目标冲突**: 用户明确要求"全面转向 Tauri + Rust"

**此方案已被明确排除**。

## 决策

**采用方案 A：React 19 + Vite + TypeScript**

### 决策依据

1. **Tauri 生态最佳适配**: Tauri 官方文档、示例、插件均以 React 为主，集成最顺畅
2. **团队已有 React 经验**: 已废弃的 Web UI 项目使用过 Next.js 15 + React 19，相关经验可复用
3. **Liquid Glass 实现最灵活**: React 生态有大量 WebGL/Shader 库（Three.js, react-three-fiber），CSS-in-JS 方案成熟
4. **迁移成本最低**: 已废弃 Web UI 中的 components、hooks、lib 可作为参考复用
5. **生态最丰富**: 任何边缘需求几乎都有 npm 包解决

### 关键技术选型

| 层 | 选型 | 版本 | 说明 |
|----|------|------|------|
| UI 框架 | React | 19.x | 函数组件 + Hooks |
| 构建工具 | Vite | 6.x | 官方推荐，HMR 极快 |
| 语言 | TypeScript | 5.7.x | 严格模式 |
| 样式方案 | **纯 CSS Modules + 全局 CSS** | — | 与已废弃 Web UI 一致，**不使用 Tailwind** |
| 状态管理 | Zustand | 5.x | 轻量、TypeScript 友好 |
| 路由 | React Router | 7.x | 或使用 TanStack Router |
| 图标 | Lucide React | latest | 或保留自定义 SVG |
| 动画 | Framer Motion | 11.x | 页面过渡、组件动画 |
| 表格 | TanStack Table | 8.x | 通用表格组件 |
| Markdown | react-markdown | latest | LLM Chat 消息渲染 |
| 日期 | date-fns | latest | 轻量日期处理 |
| 表单 | React Hook Form | 7.x | 表单验证 |
| 校验 | Zod | 3.x | Schema 验证（与 Rust serde 对应） |

### 样式方案特别说明

**不使用 Tailwind CSS**，原因：
- 已废弃的 Web UI 使用过纯 CSS Modules + 全局 CSS
- Tailwind 的 utility-first 与 Liquid Glass 的复杂视觉效果不兼容
- 自定义 Design Tokens（OKLCH 色彩系统）需要完整的 CSS 控制
- 团队无 Tailwind 使用经验

**样式架构**:
```
src/
├── styles/
│   ├── tokens.css          # Design Tokens（颜色、间距、圆角）
│   ├── global.css          # 全局样式、字体、滚动条
│   ├── liquid-glass.css    # Liquid Glass 核心效果
│   └── animations.css      # 关键帧动画
├── components/
│   ├── Button/
│   │   ├── Button.tsx
│   │   └── Button.module.css
│   └── ...
```

---

## 替代方案保留

**Vue 3 作为备选**：如果在开发过程中发现 React 在特定场景（如大量表单、复杂响应式）有明显短板，可考虑部分模块使用 Vue 3 实现。Tauri 支持多前端框架共存（通过多 window 或多 page）。
