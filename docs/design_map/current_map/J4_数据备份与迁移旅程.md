# J4 数据备份与迁移旅程

> **旅程定位**：用户保护数据免受丢失、迁移数据到新设备、清理数据的完整流程。这是"本地优先"架构下的关键能力——数据完全由用户掌控，备份/恢复/导出/导入是用户自主权的技术保障。
>
> **核心目标**：让用户能够轻松备份数据、在设备间迁移、清理不再需要的数据，同时保持零知识加密的安全性。
>
> **涉及页面**：DataManagement → ExportImport → Trash → OperationLog（辅助）
>
> **状态依赖**：L1 备份存储、L3 备份/导出服务、L3 操作日志服务、L4 对象状态

### 1.4 创建备份流程

```
用户点击"创建备份"
    │
    ▼
显示进度指示器
    │
    ▼
调用 BackupService.createBackup(accountId, profile)
    │
    ├──→ 1. 从 Vault 导出 Profile JSON
    ├──→ 2. 用当前 master key 加密 JSON
    ├──→ 3. 复制 attachments/ 下所有 .solo 文件
    ├──→ 4. 写入备份目录
    ├──→ 5. 设置文件权限 (chmod 600)
    └──→ 6. 检查保留策略，删除旧备份
    │
    ▼
进度完成 → 刷新备份列表 → 显示成功提示
```

**进度阶段**：
| 阶段 | 进度 | 操作 |
|------|------|------|
| 准备 | 0-10% | 创建备份目录 |
| 导出 Profile | 10-40% | 序列化 + 加密 |
| 复制附件 | 40-90% | 逐文件复制（大文件显示子进度） |
| 完成 | 90-100% | 清理旧备份 |

### 1.5 创建特别备份

```
用户点击"创建特别备份"
    │
    ▼
显示输入对话框："请输入备份名称"
    │
    ▼
用户输入："出国前备份"
    │
    ▼
验证名称：不能含特殊字符，不能为 "special"
    │
    ▼
执行与普通备份相同的流程
    │
    ▼
保存到 special/ 子目录
```

### 1.6 恢复备份流程

```
用户选择备份 → 点击"恢复"
    │
    ▼
显示确认对话框：
"恢复将覆盖当前 Vault 中的所有数据。
建议在恢复前先创建当前状态的备份。
确定要继续吗？"
    │
    ├──→ 用户取消 → 无操作
    └──→ 用户确认
        │
        ▼
    显示进度指示器
        │
        ▼
    调用 BackupService.restoreBackup(accountId, entry)
        │
        ├──→ 1. 读取备份文件
        ├──→ 2. 用当前 master key 解密
        ├──→ 3. 验证 JSON 完整性
        ├──→ 4. 保存到 Vault
        ├──→ 5. 复制附件到 attachments/
        └──→ 6. 重建缓存
        │
        ▼
    进度完成 → 刷新页面 → 显示成功提示
```

**关键约束**：恢复需要 Vault 已解锁（使用备份时的相同密钥）。如果密码已修改，需要先改回旧密码，或创建新备份。

### 1.7 附件池清理

```
用户点击"清理附件池"
    │
    ▼
扫描文件系统：
    - 遍历 attachments/{accountId}/ 下所有 .solo 文件
    - 检查每个 fileId 是否被任何 UnifiedObject.attachments 引用
    - 未被引用的文件标记为"孤儿"
    │
    ▼
显示清理预览：
"发现 5 个孤立附件，共占用 23.4 MB
[查看详情] [立即清理] [取消]"
    │
    ▼
用户确认 → 删除孤儿文件 → 显示释放空间
```

### 3.4 软删除机制

```typescript
function deleteObject(id: string): void {
  const object = getObject(id);
  updateObject(id, {
    isDeleted: true,
    deletedAt: Date.now(),
  });
  logOperation({
    action: 'delete',
    objectId: id,
    objectName: object.name,
    before: objectToString(object),
  });
}
```

**软删除对象的行为**：
- 不出现在正常对象列表中
- 不出现在搜索结果中
- 保留在 Vault 中，仅标记 `isDeleted=true`
- 30 天后可自动永久清理

### 3.5 恢复流程

```
用户点击"恢复"
    │
    ▼
调用 restoreObject(id)
    │
    ├──→ isDeleted = false
    ├──→ deletedAt = null
    └──→ 记录操作日志（action: 'restore'）
    │
    ▼
对象回到原位置（parentId 和 order 保持不变）
```

### 3.6 永久删除流程

```
用户点击"永久删除"
    │
    ▼
显示确认对话框：
"此操作不可撤销。对象及其附件将被永久删除。
确定要永久删除吗？"
    │
    ├──→ 用户取消 → 无操作
    └──→ 用户确认
        │
        ▼
    调用 permanentlyDelete(id)
        │
        ├──→ 从 Vault 删除对象数据
        ├──→ 删除关联的附件文件
        ├──→ 删除字段历史记录
        └──→ 记录操作日志（action: 'permanent_delete'）
```

### 3.7 自动清理

**定时任务**（应用启动时执行）：
```typescript
function autoCleanTrash(): void {
  const THIRTY_DAYS_MS = 30 * 24 * 60 * 60 * 1000;
  const now = Date.now();
  
  const trashedObjects = getAllObjects()
    .filter(obj => obj.isDeleted && now - obj.deletedAt! > THIRTY_DAYS_MS);
  
  for (const obj of trashedObjects) {
    permanentlyDelete(obj.id);
  }
  
  if (trashedObjects.length > 0) {
    showSnackBar(`已自动清理 ${trashedObjects.length} 个过期对象`);
  }
}
```

### 4.4 日志数据结构

```typescript
interface OperationEntry {
  id: string;              // UUID
  timestamp: Date;
  action: 'create' | 'update' | 'delete' | 'restore' | 'backup' | 'import' | 'export' | 'permanent_delete';
  objectType: string;
  objectId: string;
  objectName: string;
  fieldKey?: string;
  before?: string;         // 掩码后的旧值
  after?: string;          // 掩码后的新值
  accountId: string;
  source: 'user' | 'plugin' | 'import' | 'sync' | 'system';
}
```

### 4.5 敏感字段处理

日志中的 `before`/`after` 对敏感字段（敏感度 ≥ `sensitive`）自动掩码：

```typescript
function maskIfSensitive(fieldKey: string, value: string): string {
  const sensitivity = getEffectiveSensitivity(fieldKey);
  if (sensitivity >= SensitivityLevel.sensitive) {
    return '***';
  }
  return value;
}
```

## 数据生命周期

```
创建对象
    │
    ▼
正常使用（多次更新）
    │
    ├──→ 每次更新记录操作日志
    │
    ▼
删除对象（软删除）
    │
    ├──→ 进入回收站
    ├──→ 记录 delete 日志
    │
    ├──→ 恢复 → 回到原位置 → 记录 restore 日志
    │
    └──→ 30天后自动清理
        │
        └──→ 永久删除
            ├──→ 删除对象数据
            ├──→ 删除附件
            ├──→ 删除字段历史
            └──→ 记录 permanent_delete 日志
```

## 异常处理

| 异常场景 | 处理方式 |
|---------|---------|
| 备份创建时磁盘空间不足 | 显示错误"磁盘空间不足，请清理后重试"，保留部分进度 |
| 恢复备份时密码不匹配 | 提示"备份使用不同的密码加密，请先修改密码" |
| 导入文件损坏 | 提示"导入文件损坏或格式不正确" |
| 导入时冲突处理超时 | 显示进度，允许后台继续处理 |
| 恢复已删除的对象但父对象已不存在 | 恢复到根级，并提示"原位置已不存在，对象已恢复到根级" |
| 永久删除时附件文件已被手动删除 | 静默跳过，记录警告日志 |
| 操作日志文件损坏 | 尝试从备份恢复，失败则重置日志 |

## 从零实现顺序

1. **备份服务（Rust）**
   - 备份目录结构管理
   - Profile 加密导出
   - 附件复制
   - 保留策略（自动清理旧备份）
   - 文件权限设置

2. **DataManagementPage**
   - VaultInfoCard（统计展示）
   - 备份列表展示
   - 创建备份（带进度）
   - 恢复备份（带确认对话框）
   - 附件池清理

3. **导出/导入服务（Rust）**
   - 导出加密 JSON
   - 导入解密 + 验证
   - 冲突检测

4. **ExportImportPage**
   - TabBar（导出/导入）
   - 导出范围选择
   - 导入预览对话框
   - 冲突处理选项

5. **TrashPage**
   - 软删除对象列表
   - 按日期分组
   - 恢复操作
   - 永久删除（带确认）
   - 搜索/过滤

6. **OperationLogPage**
   - 日志列表展示
   - 类型过滤芯片
   - 搜索
   - 敏感字段自动掩码

7. **自动清理任务**
   - 应用启动时执行
   - 30 天过期检测
   - 静默清理 + 提示
