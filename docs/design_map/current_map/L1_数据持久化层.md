# L1 数据持久化层

> **层级定位**：所有业务数据的持久化存储，包括加密数据库、文件系统、缓存。对上层（L3 服务层）提供 CRUD 接口，对下层（L2 加密层）调用加解密能力。上层不直接操作文件/SQL，必须通过本层接口。
>
> **核心原则**：数据在落盘时始终是密文，内存中仅在需要时解密；附件分大小文件走不同加密路径；所有 Schema 变更必须兼容旧版本。
>
> **Tauri 迁移方向**：全部下沉到 Rust 后端，前端不持有任何持久化逻辑，仅通过 IPC 调用 Rust 的命令。

## L1.1 Vault 存储（Rust 核心）

### 1.1 架构概述

**模块位置**：`native/src/vault/`

Vault 是 SoloSoul 的核心数据存储单元，每个账户对应一个独立 Vault。Vault 采用**双重加密**：
1. **SQLCipher**：SQLite 数据库级别的 AES-256 加密
2. **应用层加密**：部分敏感字段在存入 SQLite 前额外加密

**目录结构**（以 account_id = `acc_xxx` 为例）：
```
{appSupportDir}/solosoul/acc_xxx/
├── config.json          # 未加密配置（版本、Salt）
├── vault.db             # SQLCipher 加密数据库
│   └── profiles 表      # 加密 JSON 存储
└── index.db             # 可选索引
```

**权限**：目录 `0700`，文件 `0600`（仅所有者读写）。

### 1.2 核心模块

#### `store.rs` — Vault 存储引擎

| 功能 | 接口签名 | 说明 |
|------|---------|------|
| **打开 Vault** | `VaultStore::open(path: PathBuf, account_id: String) -> Result<Self, VaultError>` | 初始化 SQLCipher 连接，设置 PRAGMA key |
| **关闭 Vault** | `store.close() -> Result<(), VaultError>` | 关闭连接，擦除内存中的 SQLCipher key |
| **创建表结构** | `store.init_schema()` | 创建 `profiles` 表（id, name, data_json, created_at, updated_at, version） |
| **执行事务** | `store.transaction(f: Fn) -> Result<T, VaultError>` | 提供原子性操作 |
| **获取统计** | `store.stats() -> VaultStats` | Profile 数量、总大小、最后修改时间 |

#### `profile.rs` — Profile 数据存取

| 功能 | 接口签名 | 说明 |
|------|---------|------|
| **保存 Profile** | `store.save_profile(id: &str, name: &str, data: &str, version: u32)` | JSON 字符串存入 TEXT 字段 |
| **加载 Profile** | `store.load_profile(id: &str) -> Result<ProfileRecord, VaultError>` | 取出 JSON 字符串 |
| **删除 Profile** | `store.delete_profile(id: &str) -> Result<(), VaultError>` | |
| **列出 Profiles** | `store.list_profiles() -> Result<Vec<ProfileSummary>, VaultError>` | 仅返回元数据，不加载完整 data_json |

#### `processor.rs` — 数据处理流水线

| 功能 | 说明 |
|------|------|
| **存入前处理** | JSON 序列化 → 可选压缩 → 可选应用层加密 → SQL INSERT |
| **取出后处理** | SQL SELECT → 可选应用层解密 → 可选解压 → JSON 反序列化 |
| **数据校验** | 检查 JSON 完整性、版本号、必需字段 |

#### `migration.rs` — Vault 级别迁移

| 功能 | 说明 |
|------|------|
| **版本检测** | 读取 `config.json` 中的 schema_version |
| **自动升级** | 启动时检测版本，按序执行迁移脚本 |
| **迁移脚本** | 每个版本一个 `migrate_vN_to_vM()` 函数 |

### 1.3 配置数据（`config.json`）

```json
{
  "version": "1.0",
  "salt": "base64...",           // 32 字节，Argon2id 用
  "master_key": "base64...",     // 验证令牌（"SOLOSOUL_VAULT_V1" 的密文）
  "schema_version": 6
}
```

### 1.4 Vault 状态机

```
Uninitialized → Initialize(password) → Locked
Locked → Unlock(password) → Unlocked
Unlocked → Lock() → Locked
Unlocked → ChangePassword(old, new) → Unlocked
```

**状态定义**：`VaultState { Locked, Unlocked, Corrupted }`

## L1.2 Dart 端 Vault 服务封装

**当前实现**：`lib/core/services/rust_vault_service.dart`

由于 Dart 端不能直接操作 SQLCipher，所有 Vault 操作通过 **FRB（Flutter Rust Bridge）** 调用 Rust 后端。

### 2.1 加密工具接口

| 方法 | 签名 | 说明 |
|------|------|------|
| `encryptBytes` | `Future<Uint8List?> encryptBytes(Uint8List data)` | Vault 解锁状态下，用 master key AES-GCM 加密 |
| `decryptBytes` | `Future<Uint8List?> decryptBytes(Uint8List combined)` | 解密 SOLO blob v2 |
| `encryptFile` | `Future<bool> encryptFile(src, dst, progressPath, cancelPath)` | 流式加密 v3，1MB 分块 |
| `decryptFile` | `Future<bool> decryptFile(src, dst, progressPath, cancelPath)` | 流式解密 v3 |

### 2.2 进度与取消机制

**进度文件**：`progressPath` 指向一个临时文件，Rust 每完成一个分块写入当前进度（如 `"0.42"`）。

**取消文件**：`cancelPath` 指向一个临时文件，Dart 端创建该文件即表示请求取消。Rust 定期检查该文件是否存在，存在则中断并清理。

```dart
// 使用示例
final progressFile = File('${tempDir.path}/progress_$uuid');
final cancelFile = File('${tempDir.path}/cancel_$uuid');

// 启动加密（后台）
await RustVaultService.instance.encryptFile(
  srcPath: originalPath,
  dstPath: encryptedPath,
  progressPath: progressFile.path,
  cancelPath: cancelFile.path,
);

// 监听进度（定时读取 progressFile）
// 用户点击取消：
cancelFile.createSync(); // Rust 检测到此文件即中断
```

### 2.3 Vault 统计

```dart
class VaultStats {
  final int profileCount;
  final int totalSizeBytes;
  final DateTime? lastModified;
  final String? accountId;
}
```

## L1.3 Profile 存储服务

**当前实现**：`lib/core/services/profile_storage_service.dart`

### 3.1 职责

ProfileStorageService 是 Dart 端对 Vault 中 Profile 数据的高层次封装，负责：
- Profile 的序列化/反序列化（JSON ↔ ProfileData）
- Schema 版本迁移
- 内存 LRU 缓存

### 3.2 核心接口

| 方法 | 签名 | 说明 |
|------|------|------|
| `saveProfile` | `Future<void> saveProfile(String accountId, ProfileData profile)` | JSON 序列化 → `RustVaultService` 加密存储 |
| `loadProfile` | `Future<ProfileData?> loadProfile(String accountId)` | 从 Vault 读取 → 解密 → JSON 反序列化 → 迁移 |
| `deleteProfile` | `Future<void> deleteProfile(String accountId)` | |
| `migrateIfNeeded` | `ProfileData migrateIfNeeded(ProfileData profile, Map rawJson)` | 自动升级旧版本数据 |

### 3.3 Schema 版本迁移

**当前版本**：`kSchemaVersion = 6`

| 版本 | 迁移内容 | 触发条件 |
|------|---------|---------|
| v4 → v5 | 内置分区 `typeId` 去页面化：`profile_identity` → `__preset_identity` 等 | `schemaVersion < 5` |
| v5 → v6 | 清除内置类型的英文 `propertyLabels`，让字段标签走 `translateFieldLabel` 动态本地化 | `schemaVersion < 6` |

**迁移实现**（不可变数据，返回新对象）：
```dart
static ProfileData migrateIfNeeded(ProfileData profile, Map<String, dynamic> rawJson) {
  var version = profile.schemaVersion ?? 0;
  if (version >= kSchemaVersion) return profile;
  
  if (version < 5) {
    // v4 → v5 迁移逻辑
    // ...
    version = 5;
  }
  if (version < 6) {
    // v5 → v6 迁移逻辑
    // ...
    version = 6;
  }
  
  return profile.copyWith(schemaVersion: kSchemaVersion);
}
```

### 3.4 LRU 缓存

```dart
static const _maxCacheSize = 3;
final Map<String, ProfileData> _profileCache = {};
final List<String> _cacheOrder = []; // LRU
```

- 加载 Profile 时先入缓存
- 保存 Profile 后更新缓存
- 切换账户时缓存命中可避免重复解密

## L1.4 附件存储系统

**当前实现**：`lib/core/services/attachment_storage_service.dart`

### 4.1 双路径架构

| 路径 | 适用大小 | 加密方式 | 内存占用 | Rust 参与 |
|------|---------|---------|---------|----------|
| **小文件** | ≤ 50MB | SOLO blob v2（一次性内存加密） | 高（整个文件入内存） | `encryptBytes` / `decryptBytes` |
| **大文件** | > 50MB 或任意 | SOLO blob v3（流式分块加密） | 低（1MB 分块） | `encryptFile` / `decryptFile` |

### 4.2 附件元数据（`Attachment`）

```dart
class Attachment {
  final String id;           // UUID v4，元数据 ID
  final String fileId;       // UUID v4，实际文件名（无扩展名）
  final String fileName;     // 原始文件名（含扩展名）
  final String? mimeType;    // MIME 类型
  final int size;            // 原始大小（字节）
  final int encryptedSize;   // 加密后大小
  final DateTime createdAt;  // 创建时间
}
```

元数据存储在 `UnifiedObject.attachments` 列表中，随 Profile 一起存入 Vault。
实际文件存储在文件系统中：
```
{appDocDir}/solosoul_storage/attachments/{accountId}/
├── {fileId_1}.solo       // 加密后的文件
├── {fileId_2}.solo
└── ...
```

### 4.3 小文件保存流程

```
1. 生成 fileId = UUID v4()
2. onProgress(0.1)  // 准备完成
3. 调用 RustVaultService.encryptBytes(bytes) → encrypted
4. onProgress(0.7)  // 加密完成
5. 检查 cancelToken（若取消则丢弃）
6. 写入文件 {attachmentsDir}/{fileId}.solo
7. onProgress(0.9)  // 写入完成
8. 检查 cancelToken（若取消则删除文件）
9. onProgress(1.0)  // 完成
10. 返回 Attachment 元数据
```

### 4.4 大文件保存流程

```
1. 生成 fileId = UUID v4()
2. 创建进度文件 progress_{uuid}
3. 创建取消文件 cancel_{uuid}
4. 调用 RustVaultService.encryptFile(src, dst, progressPath, cancelPath)
5. Dart 端定时轮询 progressFile 读取进度
6. 用户取消时创建 cancelFile
7. Rust 检测 cancelFile 存在，中断并清理
8. 完成后返回 Attachment 元数据
```

### 4.5 附件预览策略

| 场景 | 行为 |
|------|------|
| 小文件（v2） | `loadAttachment()` 加载到内存，直接预览 |
| 大文件（v3）且 ≤ 10MB | `decryptAttachmentToPath()` 解密到临时目录，然后预览 |
| 大文件（v3）且 > 10MB | 拒绝内存加载，提示"文件过大，请导出后查看" |
| PPTX 文件 | macOS 调用 QuickLook 原生预览 |

### 4.6 附件池（`AttachmentPoolService`）

**职责**：管理附件生命周期，自动清理孤儿附件。

**孤儿检测**：遍历所有 `UnifiedObject.attachments`，检查文件系统中是否存在对应的 `.solo` 文件；反之，检查文件系统中是否存在未被任何对象引用的 `.solo` 文件。

### 4.7 附件下载/上传服务

- `AttachmentDownloadService` — 支持取消令牌、进度回调
- `AttachmentUploadService` — 同上

## L1.5 备份数据层

**当前实现**：`lib/core/services/backup_service.dart`

### 5.1 备份目录结构

```
{appSupportDir}/solosoul_backups/{accountId}/
├── backup_2026-06-04_14-30-00_v1.2.3.backup              # 常规备份
├── backup_2026-06-04_14-30-00_v1.2.3.backup.attachments/ # 附件副本
│   ├── {fileId_1}.solo
│   └── {fileId_2}.solo
└── special/
    ├── pre_travel.backup              # 特别备份（用户命名）
    └── pre_travel.backup.attachments/
```

### 5.2 备份内容

| 内容 | 处理方式 |
|------|---------|
| **Profile 数据** | 从 Vault 导出完整 JSON → 用当前 Vault master key 加密 → 写入 `.backup` 文件 |
| **附件** | 复制 `attachments/{accountId}/` 下所有 `.solo` 文件到 `.backup.attachments/` |

### 5.3 保留策略

```dart
static const int maxBackupCount = 5;        // 常规备份
static const int maxSpecialBackupCount = 5; // 特别备份
```

创建新备份时，若超出数量限制，删除最旧的一份。

### 5.4 恢复流程

1. 验证 Vault 已解锁（恢复使用备份时的加密密钥）
2. 读取 `.backup` 文件 → 解密 → JSON 反序列化为 `ProfileData`
3. 将 `.backup.attachments/` 下的文件复制到 `attachments/{accountId}/`
4. 保存 Profile 到 Vault
5. 重建缓存

### 5.5 特别备份

用户可自定义备份名称（如"出国前备份"），命名规则：
- 名称中不能包含路径分隔符
- 不能命名为 `special`（保留字）
- 存储在 `special/` 子目录下

## L1.6 操作日志持久化

**当前实现**：`lib/core/services/operation_logger.dart`

### 6.1 日志格式

每行一个 JSON 对象（JSON Lines）：
```json
{
  "timestamp": "2026-06-04T14:30:00Z",
  "action": "update",
  "objectType": "UnifiedObject",
  "objectId": "uuid",
  "objectName": "My Passport",
  "fieldKey": "number",
  "before": "***",
  "after": "***",
  "accountId": "acc_xxx",
  "source": "user"
}
```

**注意**：`before`/`after` 对敏感字段存储掩码值（`***`），不存储明文。

### 6.2 日志文件位置

```
{appDocDir}/solosoul_storage/logs/
├── operations_2026-06.json
└── operations_2026-05.json  # 按月归档
```

### 6.3 写入策略

- 每次操作立即追加写入文件（同步或异步，视性能而定）
- 失败时记录到 `DebugLogger`，不阻塞用户操作

### 6.4 读取策略

- `OperationLogService.refreshFromDisk()` — 重新加载日志文件到内存列表
- 操作日志页面调用此方法获取最新数据

### 6.5 清理策略

- 软删除对象 30 天后永久清理时，同步清理该对象相关的操作日志条目
- 按月归档，旧月份文件可手动清理

## L1.7 扫描缓存

**当前实现**：`lib/core/services/scan/scan_cache_service.dart`

### 7.1 缓存格式

```json
{
  "version": 1,
  "entries": {
    "/Users/xxx/Documents/file.pdf": {
      "modifiedAt": 1717495800000,
      "size": 1024000
    }
  }
}
```

### 7.2 缓存策略

| 策略 | 说明 |
|------|------|
| **加载** | 扫描开始前加载缓存文件到内存 |
| **命中** | 文件路径存在、修改时间一致、大小一致 → 跳过扫描 |
| **更新** | 扫描完成后更新该文件的记录 |
| **修剪** | 扫描结束后，删除已不存在的文件记录 |
| **保存** | 扫描完成后写回文件 |

### 7.3 缓存文件位置

```
{appDocDir}/solosoul_storage/scan_cache.json
```

## 接口契约

### 对上（L3 服务层）提供的接口

| 接口 | 输入 | 输出 | 约束 |
|------|------|------|------|
| `VaultStore::save_profile` | account_id, profile_json | `Result<()>` | Vault 必须已解锁 |
| `VaultStore::load_profile` | account_id | `Result<ProfileJson>` | Vault 必须已解锁 |
| `VaultStore::delete_profile` | account_id | `Result<()>` | Vault 必须已解锁 |
| `VaultStore::list_profiles` | — | `Result<Vec<ProfileSummary>>` | Vault 必须已解锁 |
| `encrypt_bytes` | plaintext: `Vec<u8>` | `Result<Vec<u8>>` | Vault 必须已解锁 |
| `decrypt_bytes` | ciphertext: `Vec<u8>` | `Result<Vec<u8>>` | Vault 必须已解锁 |
| `encrypt_file` | src, dst, progress_path, cancel_path | `Result<()>` | Vault 必须已解锁 |
| `decrypt_file` | src, dst, progress_path, cancel_path | `Result<()>` | Vault 必须已解锁 |
| `AttachmentStorage::save` | account_id, filename, bytes | `Result<Attachment>` | Vault 必须已解锁 |
| `AttachmentStorage::load` | account_id, file_id | `Result<Vec<u8>>` | Vault 必须已解锁 |
| `BackupService::create` | account_id, profile | `Result<BackupEntry>` | Vault 必须已解锁 |
| `BackupService::restore` | account_id, backup_entry | `Result<ProfileData>` | Vault 必须已解锁 |
| `OperationLog::append` | entry | `Result<()>` | 非阻塞，失败静默 |
| `ScanCache::load/save` | — | `Result<ScanCache>` | — |

### 对下（L2 加密层）依赖的接口

| 依赖 | 用途 |
|------|------|
| `derive_key(password, salt) -> key` | Vault 解锁时派生 SQLCipher key |
| `aes_gcm_encrypt(plaintext, key) -> ciphertext` | Profile JSON 应用层加密 |
| `aes_gcm_decrypt(ciphertext, key) -> plaintext` | Profile JSON 应用层解密 |
| `stream_encrypt_file(src, dst, key, progress, cancel)` | 大附件流式加密 |
| `stream_decrypt_file(src, dst, key, progress, cancel)` | 大附件流式解密 |

## 从零开始实现顺序

1. **实现 `VaultStore`**（Rust）
   - 集成 `rusqlite` + SQLCipher
   - 实现 `open` / `close` / `init_schema`
   - 实现 `save_profile` / `load_profile` / `delete_profile` / `list_profiles`
   - 单元测试：创建 → 写入 → 读取 → 删除 → 统计

2. **实现 `VaultConfig`**（Rust）
   - `config.json` 读写
   - Salt 生成与存储
   - 验证令牌生成与验证

3. **实现 `AttachmentStorage`**（Rust）
   - 小文件路径：`encrypt_bytes` + 文件写入
   - 大文件路径：`encrypt_file` / `decrypt_file` 封装
   - 附件目录管理
   - 孤儿文件检测

4. **实现 `BackupService`**（Rust）
   - 备份目录结构创建
   - Profile 导出加密 + 附件复制
   - 保留策略（自动清理旧备份）
   - 恢复流程（解密 + 导入 + 附件还原）

5. **实现 `OperationLog`**（Rust）
   - JSON Lines 文件追加
   - 按月归档
   - 读取加载
   - 敏感字段自动掩码

6. **实现 `ScanCache`**（Rust）
   - JSON 缓存文件读写
   - 命中/更新/修剪逻辑

7. **暴露 Tauri 命令**
   - 将上述服务封装为 `#[tauri::command]`
   - 前端通过 `invoke()` 调用

## 测试要点

| 测试目标 | 测试方法 | 预期结果 |
|---------|---------|---------|
| **Vault CRUD** | 创建 → 保存 3 个 Profile → 列出 → 加载 → 删除 | 数据完整，统计正确 |
| **Vault 锁定后访问** | 锁定后调用 `save_profile` | 返回 `VaultLocked` 错误 |
| **SQLCipher 加密** | 直接用 sqlite3 打开 vault.db | 显示"file is not a database"或密文 |
| **附件双路径** | 分别测试 10KB 和 100MB 文件 | 小文件走 v2，大文件走 v3，解密后内容一致 |
| **取消机制** | 大文件加密中途创建 cancelFile | 加密中断，不残留部分文件 |
| **备份恢复** | 创建备份 → 修改数据 → 恢复备份 | 恢复后数据与备份时一致 |
| **保留策略** | 创建 6 个常规备份 | 最旧的一个被自动删除 |
| **Schema 迁移** | 构造 v4 格式数据 → 加载 | 自动迁移到 v6，字段标签走本地化 |
| **LRU 缓存** | 加载 3 个 Profile → 加载第 4 个 → 再加载第 1 个 | 第 1 个触发缓存命中，第 2 个被驱逐 |
