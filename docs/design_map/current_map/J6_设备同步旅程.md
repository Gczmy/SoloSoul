# J6 设备同步旅程

> **旅程定位**：用户在多设备间同步个人数据的完整流程。基于局域网 P2P 架构，无需云端服务器，所有通信端到端加密。
>
> **核心目标**：让用户能够在自己的设备（如 MacBook + iPhone）之间安全地同步数据，保持各设备数据一致。
>
> **涉及页面**：SyncPage
>
> **状态依赖**：L3 SyncService、L2 Noise 加密、L1 Vault/附件存储

### 1.3 本机信息

```typescript
interface LocalSyncInfo {
  deviceName: string;       // 用户可自定义
  port: number;             // 固定 9900
  pairingKey: string;       // Base64，用于身份验证
  isAdvertising: boolean;   // 是否正在广播
}
```

**设备名生成**：
- 默认：系统主机名（如 `MacBook-Pro`）
- 用户可自定义
- 需唯一（同一局域网内）

### 1.4 发现设备

```typescript
async function discoverDevices(timeoutMs = 3000): Promise<DiscoveredDevice[]> {
  const devices = await invoke('sync_discover', { timeoutMs });
  return devices.filter(d => d.name !== localDeviceName);
}
```

**发现流程**：
1. 用户点击"发现设备"
2. 调用 `mdns_discover(timeoutMs=3000)`
3. Rust 端通过 mDNS 查询 `_solosoul._tcp.local.`
4. 收集响应的服务实例
5. 过滤掉本机
6. 展示在列表中

## 同步协议详解

### 2.1 mDNS 服务发现

**广播**：
```
服务类型: _solosoul._tcp.local.
实例名: {deviceName}._solosoul._tcp.local.
端口: 9900
TXT 记录: version=1.0, account_hash=xxx
```

**发现**：
- 使用 `dns-sd` 或 `avahi` 库
- 3 秒超时
- 去重（同一设备可能多条响应）

### 2.2 Noise_IK 握手

**协议**：Noise_IK（先验知识静态密钥）

**密钥材料**：
- `pairingKey`：用户设置的配对密钥（32 字节）
- `deviceSalt`：设备唯一 Salt（每次同步生成）

**握手流程**：
```
发起方                          响应方
  │                                │
  ├──→ s, e, es ----------------→│  (消息 1: 发起方静态密钥 + 临时密钥)
  │                                │
  │←────────────────- e, ee, se ──┤  (消息 2: 响应方临时密钥)
  │                                │
  └──→ 加密数据传输 ──────────────→│
```

**安全特性**：
- 前向保密（临时密钥）
- 身份认证（静态密钥）
- 防重放攻击（Salt）

### 2.3 CRDT 同步

**数据模型**：Profile 数据转换为 CRDT（Conflict-free Replicated Data Type）

**状态向量**：
```typescript
interface StateVector {
  [objectId: string]: number;  // 每个对象的版本号
}
```

**同步算法**：
```
1. 发起方发送本机 StateVector
2. 响应方对比：
   - 如果响应方版本 > 发起方：发送差异
   - 如果发起方版本 > 响应方：请求差异
3. 双方交换差异
4. 合并差异（CRDT 合并函数）
```

**冲突解决**：
- 同一对象被双方修改：取时间戳较新的版本
- 删除 vs 更新：保留更新（删除标记为软删除）
- 字段级冲突：保留双方变更（字段级别合并）

### 2.4 附件同步

**流程**：
```
1. 发送方发送附件列表（fileId, hash, size）
2. 接收方对比本地附件
3. 接收方请求缺失的附件
4. 发送方流式传输附件（通过加密通道）
5. 接收方校验 hash
6. 标记不完整传输（网络中断时）
```

**断点续传**：
- 传输中断后，下次同步从中断处继续
- 使用 `attachmentIncomplete` 列表跟踪

## 异常处理

| 异常场景 | 处理方式 |
|---------|---------|
| mDNS 发现超时 | 提示"未在同一局域网发现设备，请确保设备连接同一 WiFi" |
| Noise 握手失败 | 提示"配对密钥不匹配，请检查双方密钥一致" |
| CRDT 同步冲突 | 自动解决（取最新版本），记录冲突日志 |
| 附件传输中断 | 标记为不完整，下次同步自动续传 |
| 磁盘空间不足 | 暂停同步，提示清理空间 |
| Vault 未解锁 | 提示"请先解锁 Vault 才能同步" |
| 同步过程中 Vault 锁定 | 中断同步，清理临时状态，记录失败日志 |
| 设备离线 | 提示"设备离线，请检查网络连接" |
| 版本不兼容 | 提示"对方应用版本不兼容，请更新到最新版本" |

## 从零实现顺序

1. **mDNS 服务**
   - 广播本机服务
   - 发现其他设备
   - 服务解析

2. **Noise 加密通道**
   - IK 模式握手
   - 加密/解密传输
   - 密钥管理

3. **CRDT 数据结构**
   - Profile 到 CRDT 的转换
   - 状态向量
   - 差异计算
   - 合并函数

4. **同步引擎**
   - 发起方逻辑
   - 响应方逻辑
   - 附件同步
   - 断点续传

5. **SyncPage**
   - 本机信息展示
   - 设备发现列表
   - 手动连接
   - 同步进度对话框
   - 同步历史日志

6. **网络监听**
   - 9900 端口监听
   - 连接管理
   - 超时处理
